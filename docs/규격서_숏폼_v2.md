# 규격서 — 트렌디 숏폼(지식전달형) 영상 규격 · 2026 · **v2**

> 이 문서는 영상화 층(P-V0/P-V1)의 **정식 규격 문서**다. 파이프라인 명세(`docs/deviation-render-pipeline.md`)의
> 지시서 스키마·렌더 엔진 (a)에셋→(b)TTS→(c)조립 구조 위에서 그대로 동작하도록 설계했다.
> 구체 상수는 `engine/config.py`(단일 출처)에, 결정·근거는 `docs/deviation-render-pipeline.md`(DV7~DV11)에 있다.
>
> **v1 대비 개정**: (1) 자막 노출-싱크 충돌 로직, (2) 플랫폼별 세이프존 오프셋, (3) 시각 다양성 래더, (4) 더킹 펌핑 방지 — 4건 + **(5) 한/영 이중언어 제작 아키텍처** 신설.
> **주의**: 세이프존/UI 수치는 월 단위 변동 → "보수적 상한값". CPS 등 튜닝값은 **실제 TTS 음성으로 A/B 보정 후 확정**(고정 표준 아님).

## 0. 캔버스 & 세이프존

### 0.1 캔버스
| 항목 | 값 | config |
|---|---|---|
| 해상도 / 비율 | 1080 × 1920 (9:16 고정) | `RENDER_WIDTH`/`RENDER_HEIGHT`, `ASPECT_RATIO` |
| fps / 코덱 | 30 / H.264 · MP4 | `RENDER_FPS` |
| 비트레이트 / 화질 | 8–12 Mbps 이상 / 1080p 이상 | (인코더 기본) |

### 0.2 세이프존 — 마스터 기준(가장 빡빡한 TikTok)
| 여백 | px | 비고 |
|---|---|---|
| top | 220 | 상단 탭·계정 |
| bottom | 480 | TikTok 하단 UI(가장 두꺼움) |
| left / right | 60 / 150 | 우측 버튼 스택 |

- 핵심 콘텐츠 박스: `x = 90~930`(폭 840), `y = 220~1440`. 가로 **중앙 정렬 고정**.

### 0.4 【신규】 화면 레이아웃 — 중앙 밴드 + 상하 바(레터박스)
2026 트렌드: 이미지를 9:16 꽉 채우지 않고 **중앙 밴드(≈4:5~1:1)** 에 넣고 **상하를 검정/블러 바**로
채운다. 상단 바 = 훅/타이틀 자리, 하단 바 = 여백 + 플랫폼 UI 겹침 회피. "프레임된" 프리미엄 룩.
| 항목 | 값 | config |
|---|---|---|
| 레이아웃 | `center_band`(기본) / `full_bleed` | `LAYOUT_MODE` |
| 상단 바 높이 | 220px(세이프존 top 정렬) | `LETTERBOX_TOP_PX` |
| 콘텐츠 밴드 높이 | 1200px(폭 1080) → 하단 바 500px | `LETTERBOX_CONTENT_HEIGHT` |
| 바 색 | 검정 | `LETTERBOX_BAR_COLOR` |
> 구현: `assemble.effect_filter`/`build_clip_cut_command` 가 콘텐츠를 밴드 크기로 렌더 후 전체 프레임에
> 상단 오프셋으로 얹고 상하 바로 pad. 자막은 콘텐츠 하단(플랫폼 앵커 62%)에 유지(바가 아니라 콘텐츠 위,
> 스트로크로 가독). `full_bleed` 로 두면 기존처럼 꽉 채움.

### 0.3 플랫폼별 자막 오프셋 — 일괄적용 금지
TikTok 기준(자막 60~65% 높이)을 Reels/Shorts에 그대로 쓰면 하단 UI가 얇은 플랫폼에서 자막이 화면 중앙을 과하게 침범한다.
→ **자막을 분리 레이어(ASS)로 합성**하고, 플랫폼별로 **자막 앵커 y만** 바꿔 재합성한다(비주얼 베이스·오디오는 재사용 → 재렌더 비용 최소).

| 플랫폼 | 하단 여백(px) | 자막 앵커(높이%) |
|---|---|---|
| TikTok | 480 | 0.62 |
| Instagram Reels | 380 | 0.68 |
| YouTube Shorts | 340 | 0.70 |
| Facebook Reels | 380 | 0.68 |

> config: `PLATFORM_CAPTION_ANCHOR_PCT`, `PLATFORM_SAFE_BOTTOM_PX`, `DEFAULT_PLATFORM`.
> 구현: `subtitles.build_ass(..., platform=...)` 가 앵커%→하단 MarginV(px)로 변환해 자막 레이어를 그 위치에 놓는다.
> 마스터 타임라인(비주얼·음악)은 1개. 자막 레이어만 플랫폼 수만큼 y-오프셋을 달리해 합성 → 산출물 = (언어 × 플랫폼) 조합.

## 1. 자막 규격 【①개정 — 핵심】

### 1.1 스타일
| 항목 | 규격 | config |
|---|---|---|
| 방식 | 단어별/2–3어절 구별 애니(가라오케/Hormozi) | `timestamp_source`(whisper/edge word-level) |
| 표시 단위 | 한 화면 KO 3–6어절 / EN 4–7단어, 한 청크=한 아이디어 | `CAPTION_CHUNK_MAX`, `CAPTION_CHUNK_FAST` |
| 폰트 | KO: Pretendard/NanumGothic · EN: Montserrat | `CAPTION_FONT` |
| 색 | 흰색 + 검은 외곽선, 핵심어 1개만 노랑(#FFE000) | `CAPTION_HIGHLIGHT_COLOR` |
| 활성 단어 | 색변화 + 스케일 1.1–1.3× | (렌더 후속) |
| 스크림 | 복잡 배경 시 반투명 검정 바 | (BorderStyle/BackColour) |

### 1.2 노출 시간 ↔ 싱크 이중 레이어 & Fallback
문제: 빠른 한국어 내레이션은 3–6어절을 2초 안에 발화하는 경우가 많음. "최소 2초 노출"과 "발화 싱크"가 충돌.
해결: **두 타이밍을 분리**하고 **오디오 싱크를 최우선 불가침**으로 둔다. 최소 노출은 렌더가 아니라 **청킹 단계**에서 강제한다.

- **레이어 A — 청크 표시창**: `t_start`=청크 첫 단어 시작, `t_end`=마지막 단어 끝 + `tail_hold`.
  `tail_hold = min(다음 청크까지 간극, CAPTION_TAIL_HOLD_MAX_SEC=0.5)` — 침묵이 있을 때만 살짝 연장, **다음 청크 오디오는 절대 밀지 않음**.
- **레이어 B — 활성 단어 하이라이트**: 각 단어는 **자기 타임스탬프에 정확히 싱크**(불가침).
- **최소 노출은 레이트 기반 청킹으로 강제(2초 고정 폐기)**:
  가독 요구시간 `R = 청크_글자수 / target_CPS`, 자연 표시창 `W = t_end - t_start`.
  `target_CPS` 시작값: **KO ~11, EN ~20**(`CAPTION_TARGET_CPS`, 실측 보정 필수).

**Fallback 결정 트리(우선순위 순)** — `subtitles.chunk_by_rate()` 가 구현.
```
1) W >= R                → 그대로 싱크. 끝.
2) W < R 이고 간극 존재    → tail_hold 로 침묵까지 연장(최대 0.5s). 다시 1) 검사.
3) 여전히 W < R           → 청킹 문제. 청크 단어 수를 줄여 재분할(빠른 KO는 3–4어절).
4) 그래도 하한 미만        → 하드 플로어 min_display=0.7s(`CAPTION_MIN_DISPLAY_FLOOR_SEC`).
                            이보다 짧으면 인접 청크와 병합(발화 유지, 표시만 합침).
```
- **핵심 원칙**: 오디오를 지연시켜 노출을 맞추지 않는다. 노출은 "청크 크기"로 조절한다.

## 2. 편집 페이싱 & 시각 다양성 【③개정】

### 2.1 페이싱
| 항목 | 규격 | config |
|---|---|---|
| 시각 변화 주기 | 2–4초마다 1회 | `PACING_VISUAL_CHANGE_SEC` |
| 데드에어 | >250ms 무음/정적 제거 | `PACING_DEAD_AIR_MAX_MS` |
| 전환 | 첫 5초 디졸브 금지, 하드컷/줌 위주 | `PACING_NO_DISSOLVE_FIRST_SEC` |
| 켄번스 | "정적 컷의 미세 움직임 보정"으로만 강등 | `KEN_BURNS_ROLE` |

### 2.2 시각 다양성 래더 — 켄번스 의존 탈피
**씬 종류(scene_kind) enum** — 컷마다 지정(`SCENE_KINDS`).

| 종류 | 제작 방식 | 렌더 매핑(현행 코드) |
|---|---|---|
| `comic_panel` | 이미지 생성 + 켄번스 | 스틸 |
| `motion_graphic` | Manim(코드) | Manim 클립 |
| `kinetic_typography` | 대형 타이포(코드) | Manim 타이틀/단계 템플릿 |
| `data_viz` | 코드(차트 애니) | Manim 수치비교 템플릿 |
| `broll_stock` | 외부 스톡 API | 스틸 |

**다양성 제약(정규화·렌더러 강제)** — `directive.enforce_scene_variety()`.
- 같은 `scene_kind` **3컷 연속 금지**(최대 2연속, `SCENE_MAX_CONSECUTIVE_SAME`).
- **10초당 최소 1회 "고효율 씬"**(`SCENE_HIGH_EFFORT_KINDS`, `SCENE_HIGH_EFFORT_MIN_PER_SEC`).
- `broll_stock`·`comic_panel` 은 텍스트 지시어와 **의미 연결**(무작위 스톡 금지, `SCENE_SEMANTIC_LINK_REQUIRED`).
- 켄번스는 다양성 수단이 아니라 정적 컷의 최소 움직임 보정으로만.

> **권장(얼굴 없는 논문 채널 ROI 최상)**: `kinetic_typography` 를 1급 씬으로. 코드 기반이라 캐릭터 일관성 문제를
> 원천 회피하고, 비용이 가장 낮다. Manim 도해와 번갈아 쓰면 "고효율 씬"만으로 상당 구간을 채운다.

## 4. BGM & 사운드 【④개정】

### 4.1 기본
| 항목 | 규격 | config |
|---|---|---|
| BGM 성격 | 설명형 인스트루멘탈(가사 트렌딩곡 지양) | `BGM_ENABLED`, `BGM_VOLUME` |
| SFX | 전환 whoosh, 자막 pop, 페이로프 전 riser | (후속) |
| 무음 대비 | 자막만으로 완결 | — |

### 4.2 펌핑 방지 — 엔벨로프 사전계산 더킹
문제: >250ms 무음을 다 잘라내 타이트 편집 → BGM 상승/하강 여유 없어 **펌핑(꿀렁임)** 발생.
해결: 실시간 사이드체인 대신 **VO 스팬으로 더킹 엔벨로프를 사전 계산**하고 **짧은 간극은 병합**해 BGM을 안 띄운다.

**로직** — `assemble.duck_spans_from_words()` + `build_bgm_envelope_duck_command()`.
1. VO 스팬 추출(단어 타임스탬프).
2. **간극 병합**: 인접 스팬 간극 < `DUCK_MERGE_GAP_MS`(800ms) 면 하나의 연속 더킹 구간으로 병합 → 펌핑 원천 차단.
3. 병합된 구간에만 감쇠: 깊이 `DUCK_DB`(-20dB), `DUCK_ATTACK_MS`(8)/`DUCK_RELEASE_MS`(300) 램프.
4. `DUCK_MERGE_GAP_MS` 이상 "의도된 정지"에서만 BGM 원복.

> 결정론 우선 → **사전계산 볼륨 엔벨로프**(`volume` 시간구간 자동화). 실시간 `sidechaincompress` 보다 통제·재현성 우수.

## 5. 【⑤신설】 한/영 이중언어 제작 아키텍처

### 5.1 원칙 — 언어 무관 마스터 ↔ 언어별 레이어
```
[언어 무관]  비주얼 에셋 세트(scene_kind별) + BGM 베드   ← 1회 생성(공유)
     ├─ [KO 레이어]  TTS_ko → 컷길이_ko → 자막_ko(NanumGothic) → 조립_ko → mp4(ko)
     └─ [EN 레이어]  TTS_en → 컷길이_en → 자막_en(Montserrat) → 조립_en → mp4(en)
```
- 현행 렌더 (a)에셋→(b)TTS→(c)조립에서 **(a)만 공유, (b)(c)를 언어별 2회** 실행하면 그대로 이중언어(지시서에 이미 `narration_ko/en` 존재).
- config: `LANGUAGES=("ko","en")`, `EDGE_TTS_VOICE_BY_LANG`, `CAPTION_FONT`. 구현: `render.render_directive_local(d, out, lang=...)`.

### 5.2 타이밍 정책 — "탄력 섹션(elastic sections)"
- EN·KO는 발화 길이가 다름 → **언어별로 타임라인을 독립 재타이밍**(비주얼 에셋 동일, 지속시간만 각자). 컷 길이 = 각 언어 TTS 실측.
- 섹션 경계(훅/전개/페이로프)는 의미 단위로 공유, 그 안의 미세 타이밍·자막 청크는 언어별 독립.
- 결과: 두 산출물 총 길이가 약간 달라질 수 있음(정상). 고정 슬롯에 억지로 맞추지 말 것.

### 5.3 언어별 자막 세부
| 항목 | KO | EN | config |
|---|---|---|---|
| 폰트 | NanumGothic(→Pretendard) | Montserrat | `CAPTION_FONT` |
| 청크 | 3–6어절 | 4–7단어 | `CAPTION_CHUNK_MAX/FAST` |
| target_CPS(시작값) | 11 | 20 | `CAPTION_TARGET_CPS` |
| 오토핏 | 필요 | **필수**(EN 볼드 6–7단어 폭 초과 가능) | `CAPTION_MAX_CHARS`, `CAPTION_AUTOFIT_*` |

### 5.4 훅·CTA는 "트랜스크리에이션"(직역 금지)
- 훅/CTA는 언어별로 각각 관용적으로 재작성. `hook_ko/hook_en`, `cta_ko/cta_en` 을 **독립 생성**.
- 논문 전문용어는 언어별 표준 용어로 정확히(직역 아님).

### 5.5 부가(발행 단계 — 본 라운드 범위 밖, 스펙만)
- TTS 음성은 언어별 자연스러운 별도 보이스.
- AI disclosure 메타·SEO(제목/설명/해시태그)는 **언어 × 플랫폼별** 로컬라이즈.
