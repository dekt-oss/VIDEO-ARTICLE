# Phase 13 — 최종 발행 관문 (QA 통합)

> 작성 2026-10-05. 원 작업지시서 `docs/작업지시서_ExplanationEngine_v2.md` §15.
> 운영자 방향: "먼저 완성, 영상 표현 우선" — **새 차단을 만들지 않고** 흩어진 판정을 한 장의 성적표로 묶는다.

## 1. 무엇을 하나

V2 비교 실행(`scripts/compare_explanation_v2.py`)마다 다섯 질문을 순서대로 판정해 `publish_gate` 로 남긴다.
비교 자료(md) 맨 위에도 같은 성적표가 붙는다. 정본: `engine/publish_gate_v2.py`.

| 순서 | 단계 | 질문 | 읽는 판정 |
|---|---|---|---|
| 1 | 원문 | 이 깊이의 원문으로 이 정도 설명을 해도 되는가? | Phase 2 근거 묶음 · Phase 8 원문 검사(`source_errors`) · Fact Sheet 재검증 필요(STALE/NOT_CHECKED) |
| 2 | 논리 | 질문에 답하는 논리가 실제 근거로 이어지는가? | Phase 3 논증 단위 · Phase 4 선행 개념 · Phase 5 서사 계획 |
| 3 | 대본 | 사실이 맞고, 사람이 들어도 쉬운가? | Phase 6 대본 · Phase 7 의미 충실도 · 코드 교정 기록 |
| 4 | 화면 | 화면이 같은 내용을 설명하는가? | Phase 8·9·10 · 기존 생성기 지시서 승인 차단 · 추적 안 된 컷 · **화면 움직임 계획(새)** |
| 5 | 렌더 | 선언된 변화가 실제 픽셀 변화로 나타났는가? | 렌더 QA(`render_jobs.qa`) — 정지 화면·무음·클립 움직임 등 |

- 단계 판정: PASS / WARN / FAIL / NOT_RUN. **앞 단계가 FAIL 이면 뒤는 NOT_RUN** — 대본이 거절됐는데 화면을 통과라고 적지 않는다.
- 최종 판정: 발행 가능(PUBLISHABLE) / 사람 확인 필요(NEEDS_REVIEW) / 차단(BLOCKED) / 판정 미완(INCOMPLETE, 대개 렌더 전).
- 성적표는 같은 종류의 경고를 쉬운 말 한 줄로 묶는다("풀이 없이 나온 약어 7건 (DRAM, …)"). JSON 에는 원본 코드가 그대로 있다.

## 2. 새로 보는 것 하나 — 화면 움직임 계획 (경고)

S2~S5 로 화면 글자가 늦게 뜨고 숫자가 올라가게 됐다. 그래서 **지시서의 컷 예상 길이 안에서 카드를 읽을 시간이
남는지**(2초 이상), 드러내기 막이 컷보다 길지 않은지를 렌더 전에 본다. 카운트업 중간 프레임(1/15초)은 세지 않는다.
컷 길이는 지시서의 `estimated_sec` 이라 실제 나레이션과 다를 수 있어 경고로만 둔다. 실제 길이 기준 검사는 렌더 때
기존 `overlay_visibility` 가 한다.

곁가지 수정: 그 기존 검사의 사유 글이 움직임 태그(`{\fad…}`)를 그대로 보여 주던 것을 글자만 보이게 고쳤다.

## 3. 렌더 단계를 채우는 법 (최종 렌더 뒤)

```bash
python -m scripts.compare_explanation_v2 report <리포트 id> --render-job-id <렌더 작업 id>
```

렌더 작업 행에 저장된 렌더 QA 를 **읽기만** 해서 다섯째 단계를 판정한다. 파일로 주려면 `--render-qa <json>`.
모델 호출 없이도 돈다(그 경우 대본 단계는 "외부 모델 호출 전 중단"으로 NOT_RUN).

## 3-1. V2 영상을 실제로 렌더하는 순서 (2026-10-05 운영자 결정 "가")

1. **V2 지시서 만들고 저장**(유료 — 리포트 한 건 실측 약 $0.3):
   ```bash
   python -m scripts.compare_explanation_v2 report <리포트 id> --with-model --with-directive --save-directive
   ```
   지시서 표에 `draft` 로 한 건 들어간다(머리말 `explanation_v2` 표시). **승인이 막힌 지시서는 저장하지 않고**
   사유만 출력한다(`saved_directive.refused`) — 대시보드는 가장 최근 지시서를 보여 주므로 렌더할 수 없는 지시서가
   기존 지시서를 밀어내면 안 된다. 출력의 `database_writes.directive_inserts` 가 실제 저장 건수다.
2. **대시보드에서 확인·승인·렌더** — 지시서 칸 위에 파란 "V2 설명 엔진 지시서" 안내가 뜬다(컷 나레이션은 V2 대본이라
   왼쪽 초안 대본과 다르다). 승인 라우트는 대본과 대조하지 않으므로 V2 나레이션 때문에 막히지 않는다.
3. **렌더 뒤 성적표 완성(비용 0)**:
   ```bash
   python -m scripts.publish_gate_v2 <1번에서 나온 .json> --render-job-id <렌더 작업 id>
   ```
   모델을 다시 부르지 않고 렌더 QA 만 읽어 새 파일로 쓴다.

되돌리기: 저장된 V2 지시서는 대시보드에서 [지시서 재생성]으로 새 Production 지시서를 만들면 최신에서 밀려난다.

## 4. 검증 (비용 0)

- 단위 테스트 `tests/test_publish_gate_v2.py`(13건) · CLI 테스트 1건.
- 실데이터 3건(삼성·조선 리포트, 논문 heel strike — DB 읽기만) + 현실형 가짜 모델 + 가짜 지시서 생성기로 끝까지 돌림:
  세 건 모두 원문 PASS · 논리/대본/화면 WARN · 렌더 NOT_RUN → **판정 미완**. 경고 내용은 이미 알던 것들
  (길이 때문에 뺀 논증, 약어, 긴 문장)이다.
- **미검증:** 실제 렌더 QA 를 붙인 판정(렌더 안 함), 실제 모델 대본에서의 경고 분포.
