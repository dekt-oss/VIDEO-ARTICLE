## 0. 한 줄

영상의 기본 단위를 **독립 컷의 나열**에서 **하나의 지속되는 시각 세계가 단계적으로
변하는 Visual Sequence** 로 바꾼다. 단, 스키마부터 만들지 않는다 — **provider 가
그 연속성을 실제로 만들 수 있는지부터 실측한다**(Phase 0).

## 1. 왜 하는가 — 리뷰가 옳다는 실측 증거

리뷰가 금지한 것을 우리 v2 산출물이 이미 저질렀다. 이 계획의 출발점이다.

| 리뷰의 금지 | 우리 v2 실측 (2026-08-29) |
|---|---|
| §12 원문에 없는 코→뇌 분자 이동 금지 | 컷5 가 정확히 그 그림 — 초록에 그 경로가 없다 |
| VSEQ-7 15% 를 동전 개수 은유로 대체 금지 | 컷7 이 정확히 그것 (동전 10개→11~12개) |

### D3 확정 — 골든 2편 (2026-08-29)

| | 논문 | source_depth | 무엇을 검증하나 |
|---|---|---|---|
| **A** | Oxytocin increases trust in men low in dispositional trust (PNAS) | `abstract_only` | **라우터가 후퇴하는가** — 코→뇌 경로·실험 절차 상세가 안 나오는가(작업지시서 §12) |
| **B** | Physical Characterization of Moon Impactor 2025-010D (arXiv:2608.00360) | `full_body` 34,835자 | **기전 시퀀스가 서는가** + 정량 라우팅 |

B 를 고른 이유: 후보 5편을 확보해 전부 full_body 였는데, 나머지 넷은 LLM·시장 논문이라
**물리적 기전이 없다**(3D 시퀀스로 그릴 대상이 없다). Moon Impactor 는
`궤도 역추적 → 물체 식별 → 분광 → 자전 변화 → 충돌 지점 예측` 이 그 자체로 시퀀스이고,
persistent entity(로켓 상단·달·궤도)가 분명하다. 숫자(~7분 자전, 8초 변화, 충돌일)가
있어 **CODE_VIZ 라우팅 분기까지 같은 골든에서 검증**된다.

확보한 5편은 `paper_sources` 에 보관됐다(0041) — 재확보 호출 0.

## 5. 알려진 한계 — 미리 인정하고 들어간다

1. **VSEQ 게이트의 절반은 자기보고다.** `state_before != state_after` 는 LLM 이 쓴 JSON.
   코드는 선언 구조를 검사할 뿐이고, 화면에서 진짜 변했는지는 **렌더 후 멀티모달 QA**(D2)가
   판정한다. 이 2단 구조를 처음부터 설계에 넣는다 — 픽셀 델타는 복붙 탐지용 보조로 격하.
2. **identity 완전 보장은 provider 한계로 불가능할 수 있다.** 숨기지 않고
   `degraded_continuity` 로 기록한다(Paper §9).
3. **clip_fit 미배선**(trim/hold 뿐) — I2V 체인이 길어질수록 길이 보정 품질이 병목.
   Phase 3 범위에 포함할지 Phase 0 실측 보고 정한다.

## 6. Phase 계획

### Phase 0 — Continuity 실측 (GO/NO-GO 관문, ~반나절, ~$2)

- `scripts/probe_continuity.py`: 세계 하나(신뢰게임 테이블·인물 2·토큰)로
  ① canonical frame 생성(gemini-3-pro-image)
  ② 참조 조건 생성으로 상태 변이 3회(같은 인물·같은 테이블, 토큰만 이동/누적)
  ③ Veo I2V 로 stage 간 전환 1회
  ④ 각 stage 를 flash 멀티모달로 "같은 인물·같은 세계인가" 판정 + 콘택트시트로 운영자 확인
  ⑤ stage 당 비용·해상도·글자 번인 기록
- 산출: `docs/실측_continuity_v3.md` — GO/NO-GO 와 근거.
- **NO-GO 면**: Phase 1~4 를 멈추고 procedural hybrid(Blender geometry + generative
  material) ADR 작성으로 전환. 스키마를 먼저 만들지 않았으므로 죽은 필드가 없다.

### Phase 1 — Shared Sequence Core (Paper·Equity 공용)

- `engine/visual_sequence.py`: VisualSequence / VisualWorld / PersistentEntity /
  StateTransition 스키마 + 정규화. Operation·Camera enum 은 `engine/config` 에
  (Paper §5 목록 그대로: REVEAL~ZOOM_INTO, ORBIT~FOLLOW_OBJECT).
- `engine/visual_sequence_contract.py`: VSEQ-1~7 게이트. 차단/경고 분리 원칙 유지
  ("옳게 한 것을 벌하는 게이트는 무시당한다").
- asset_strategy 의미 확장: NEW_WORLD / CONTINUE_WORLD / MUTATE_STATE / CAMERA_REVEAL /
  RETURN_WORLD / REFERENCE_CONDITIONED_NEW_STATE — 기존 new_asset/reuse 와의 매핑을
  정규화가 담당(옛 지시서 무변경).
- 테스트: 정규화·dangling ref·static repeat·유효/무효 재등장.
- DoD: 순수 모듈 + 테스트. **렌더 소비는 Phase 3** — 죽은 필드 여부는 Phase 4 골든이 검증.

### Phase 2 — Paper Planner + Visual Router

- Explanation beats(QUESTION~CONCLUSION 10종): **문장 경계 ≠ beat**(Paper §6).
  cut_skeleton 은 나레이션·타이밍 단위로 존속, beat 가 cut_refs 로 매핑.
- `engine/visual_router.py`: 3D_MECHANISM_SEQUENCE / CODE_VIZ / REALITY / OVERLAY 라우팅.
  **`source_depth` 를 소비한다** — abstract_only 면 절차 상세 기전 시퀀스 금지, 일반적
  실험 구조·결과 시각화로 후퇴(Paper §12). 정확한 수치는 항상 CODE_VIZ/OVERLAY.
- VSEQ-6: 시퀀스가 그리는 구조·경로도 claim 취급 — paper_evidence 의 대조를 태운다.

### Phase 3 — 렌더 배선

- `providers/image.py` 에 참조 조건 생성 경로(Phase 0 에서 검증한 방식 그대로).
- `render.py` I2V 연쇄를 sequence stage 인식으로 확장. RETURN_WORLD 는 crop/파생 우선.
- 멀티모달 QA(D2): stage 전후 프레임을 flash 로 비교, 실패 시 `degraded_continuity` 기록
  (재생성 1회 → 그래도 실패면 기록하고 진행 — 렌더를 죽이지 않는다).
- 비용 원장: stage 단위 기록. world reset 횟수를 원장에 남긴다.

### Phase 4 — 골든 검증 (Paper)

- 옥시토신(abstract_only): **라우터가 후퇴하는가** — 코→뇌 그림이 안 나오는가.
- full_body 논문 1편(Phase 0 기간에 확보해 둔다): **기전 시퀀스가 서는가**.
- v2 지시서·렌더(이미 있음) vs v3 — 콘택트시트 비교 + KPI:
  world_reset_rate ↓ · static_repeat_rate ↓ · persistent_entity_ratio ↑ ·
  transformation_density ↑ · 비용 비교.
- **숫자 KPI 로 성공 판정하지 않는다** — 최종은 운영자 눈(리뷰 §14).

## 9. 코덱스 리뷰 반영 (2026-08-30)

리뷰 판정: **GO WITH CHANGES.** 방향(Visual Sequence)과 Phase 0 실측은 타당하다고 확인됐고,
**Phase 3 렌더 배선은 아래 계약을 고치기 전까지 NO-GO** 다.

### 9-0. 먼저 — 리뷰의 사실 주장을 코드·산출물과 대조했다

이 저장소의 자세("모델의 자기보고를 믿지 않고 코드가 판정한다")를 **리뷰어에게도 그대로**
적용했다. 리뷰 지적 15건 중 **13건은 실재를 확인**했고 **2건은 사실과 달랐다.**

| 리뷰 | 주장 | 대조 결과 |
|---|---|---|
| §13 | 골든A 컷5·6 은 화면 장치를 요구하지 않는데 `"No on-screen text."` 라는 **금지문 때문에** 오탐 차단됐다 | **사실과 다르다.** 부정문 스크럽(`photo_contract._NEGATED`)이 이미 있고 정상 동작한다. 실제 차단 사유를 정규식으로 역추적하니 컷5 = 프롬프트의 `15%`("a stack of coins that is visibly **15%** taller"), 컷6 = motion_prompt 의 **`bar chart`** + `16.9%` 였다. **둘 다 진짜 위반이다** — 생성 이미지에게 정확한 비율을 그리라고 요구한 것이고, VSEQ-7 이 같은 컷을 독립적으로 차단했다. 게이트를 고치지 않는다 |
| §4 | 골든B 컷5·9·10·12 의 `cut_claim_not_in_source` 는 evidence gate 오탐이다 | **결론은 맞지만 원인이 다르다.** 지금 코드로 10개 주장을 재대조하니 **10/10 통과**했다(최저 비율 0.992). 오탐의 정체는 **낡은 판정값**이다 — `validation` 은 초안 단계에서 DB 에 기록되고 지시서 단계는 그것을 **그대로 믿는다.** 골든B 의 fact_sheet 에 박힌 `quote_verified:false` 는 커밋 `c681613`(연속 일치 비율 도입) **이전** 코드가 쓴 값이다. 즉 매칭 알고리즘이 아니라 **원장 신선도**가 문제다 |

실측 근거(대조 대상 = `paper_sources` 의 arXiv 전문 34,835자):

```
C02 quote  `` ``Ghost Riders in the Sky'' ``   원문 “Ghost Riders in the Sky”   (LaTeX 인용부호 vs 활자 인용부호)
C04 quote  `$\sim$7 min`                       원문 `\sim 7 min`
C05 quote  `$\sim$2.4 km s$^{-1}$`             원문 `\sim 2.4 km s -1`
→ 전부 **표기 차이**였고, 연속 일치 비율 도입으로 이미 해소됐다. 낡은 값만 남아 있었다.
```

**교훈(설계로 승격):** 검증 결과를 저장하면 **검증 코드보다 오래 산다.** 원장에는
계약 버전을 찍고, 버전이 다른 판정은 `false` 가 아니라 **판정 불가**로 다룬다.
"판정 불가와 실패를 섞지 않는다"를 시간 축으로 확장한 것이다.

### 9-1. 설계 변경 — 리뷰가 뒤집은 결정 3건

| # | 종전 (§4-3·D-없음) | 변경 후 | 근거 |
|---|---|---|---|
| **R1** | 라우팅은 4종 중 **택1**. "수치가 시퀀스를 이긴다" | **합성**한다 — `base` + `precision_layer`. 수치는 시퀀스를 끊지 않고 **코드 오버레이 레이어**로 얹힌다 | Phase 0 이 실측한 것은 "생성모델은 정확한 개수를 못 지킨다"이지 "수치가 있는 장면은 3D 로 만들면 안 된다"가 아니다. 내가 실측을 과대해석했다. 골든B 15컷 중 4컷이 그래서 세계 밖으로 튕겨 나갔다 |
| **R2** | `source_depth` 가 **미디어 라우팅**을 바꾼다(`depth_blocks_mechanism` → REALITY 후퇴) | `source_depth` 는 **표현 제약**이다 — 기전 시각화 자체는 허용하되, 초록이 지불하지 않는 **구체성**(프로토콜·장비·해부 경로·무작위배정·위약)을 금지한다 | `abstract_only ≠ 기전 금지`. 후퇴는 근거 없는 컷을 못 막으면서(§5 골든A 는 후퇴하고도 "사전 등록된 무작위 실험"을 그렸다) 정상 컷만 벌했다 |
| **R3** | 최종 판정권이 `visual_role`·`visual_treatment`·`photo_contract`·`visual_router` 에 **분산** | 단일 정본 `resolved_visual_plan`. 계약·비용·렌더·QA 가 **같은 객체**를 소비한다 | Phase 3 렌더러가 무엇을 믿을지 지금 정하지 않으면 "schema 필드를 renderer 가 무시한다"가 그대로 재현된다 |

### 9-2. 자기보고를 코드 판정으로 — 리뷰가 찾아준 같은 계열 4건

§6 에 적은 내 오류 3건과 **같은 계열**이다. 리뷰가 넷을 더 찾았고 전부 실측으로 확인했다.

| # | 어디서 자기보고를 믿고 있었나 | 실측 증거 | 조치 |
|---|---|---|---|
| **S1** | `state_before`/`state_after` 를 **둘 다 LLM 이 쓴다** → `sequence_is_progression` 이 결국 자기보고 | 형식만 다르게 쓰면 통과(`standing` → `standing calmly`) | **State Ledger**: LLM 은 `mutations`(개체·속성·연산·가시변화)만 제안하고, **코드가** `이전 상태 + mutation = 다음 상태`를 계산한다 |
| **S2** | `continuity_from` 의 **존재 여부만** 검사 | 골든B `S6_BENCHMARK`: `continuity_from = S1_APPROACH` 인데 `state_before = {"MOON_SURFACE": "Cratered surface after impact."}`. **S1 에는 분화구가 없다** | `vseq_state_lineage_mismatch` — 이어받은 상태가 원본 stage 의 계산된 `state_after` 와 어긋나면 차단 |
| **S3** | 미선언 개체 검사가 `entity_refs` **만** 본다 | 골든A `S5`: `state_after` 에 `FEMALE_CHARACTER_SILHOUETTE`·`HIGH_TRUST_MALE_SILHOUETTE` 가 나오는데 `entities` 에 없다. 게이트는 S6 만 잡았다 | 검사 범위를 `entity_refs` + `state_before/after` 키 + `mutations[].entity_id` 전체로 확장 |
| **S4** | `mechanism_sequences` 지표가 **모델의 `sequence_role` 라벨**을 센다 | 골든B: 라벨 `RESULT_SEQUENCE` → 지표 `0`. 그런데 같은 지시서에서 **라우터는 7컷을 MECHANISM_SEQUENCE 로 판정**했다. 라우터만 고치고 지표는 안 고쳤다 | 지표도 `sequence_is_progression()` **구조 판정**을 쓴다. `sequence_role` 은 진단용 메타데이터로 강등 |

여기에 리뷰가 지적한 **시퀀스 소속의 무조건 신뢰**(§10)를 더한다:

| **S5** | 컷이 stage 의 `cut_refs` 에 있기만 하면 `MECHANISM_SEQUENCE` | 골든B **컷15는 CTA** 다("댓글로 의견을 남겨주세요"). `claim_ids` 가 비었는데 `in_visual_sequence` 로 기전 시퀀스가 됐다 | factual stage 는 `stage.claim_ids ∩ cut.claim_ids ≠ ∅` 를 요구한다. 연결·CTA 컷은 `allow_connective` 로 **명시**하고 세계 배경만 물려받는다 |

### 9-3. 새로 만드는 것 — `resolved_visual_plan` (R3)

Phase 3 렌더러가 받을 **단일 정본**. 계약·비용·렌더·QA 가 전부 이것만 본다.

```json
{
  "cut_no": 9,
  "base": "MECHANISM_SEQUENCE",
  "precision_layer": "CODE_OVERLAY",
  "representation_mode": "SCHEMATIC_PRINCIPLE",
  "sequence_ref": "SEQ1_IMPACT_PREDICTION",
  "world_ref": "SPACE_AND_MOON",
  "stage_ref": "S4_ROTATION_ANOMALY",
  "claim_refs": ["C04"],
  "detail_restrictions": ["protocol", "apparatus"],
  "reasons": ["in_visual_sequence", "number_needs_precision_layer"]
}
```

- `base` — 화면의 세계. `precision_layer` — 그 위에 얹는 **코드 렌더** 정밀 레이어(R1).
- `representation_mode`(§11) — `LITERAL_OBSERVATION` / `SCHEMATIC_PRINCIPLE` / `METAPHOR`.
  **literal 이면 실제 관측 방식이 원문에 의해 지지돼야 한다.** 골든B 분광이 사례다:
  주장(C03)은 맞지만 원문은 **지상 관측**인데 화면은 우주에서 로켓에 빛을 쏘는 그림이다 —
  claim_id 는 맞고 **묘사가 틀린** visual hallucination.
- `detail_restrictions`(R2) — `source_depth` 가 만든 구체성 금지 목록.
- 기존 `visual_role`·`visual_treatment` 는 **입력 메타데이터로 존속**(하위호환).

### 9-4. 실행 순서를 고정한다 (§15)

골든 실측: `visual_routing.CODE_VIZ = 4` 인데 `cost_plan.code_viz_count = 0` 이었다.
`compute_cost_plan` 이 라우팅 **이전에** 돌고, 게다가 라우터 판정이 아니라 모델이 쓴
`asset_strategy` 를 세고 있었다. Phase 3 전에 순서를 못박는다.

```
Evidence → Explanation Beat → Sequence Normalization → State Ledger
  → Visual Routing → Resolved Visual Plan → Contract → Cost Plan → Render → Post-render QA
```

비용 산정기와 렌더러는 **같은 resolved plan** 을 본다.

### 9-5. Phase 3 진입 게이트 (ENTRY-1~6) — 전부 회귀 테스트로 만든다

유료 렌더에 들어가기 전 여섯이 모두 통과해야 한다.

| | 내용 | 대응 |
|---|---|---|
| ENTRY-1 | 골든B 컷5·9·12 의 **정상 주장**이 `cut_claim_not_in_source` 로 오탐 차단되지 않는다 | 원장 계약 버전 + 지시서 단계 재대조(§9-0) |
| ENTRY-2 | 골든A 에서 **초록이 지불하지 않는 구체 절차**가 visual fact 로 확대되지 않는다 | R2 표현 제약 + 원문 대조 기반 구체성 게이트 |
| ENTRY-3 | 수치 포함 시퀀스가 `base + precision layer` 로 표현된다 | R1 합성 라우팅 |
| ENTRY-4 | 골든B `S6` 의 잘못된 state lineage 를 **코드가 탐지**한다 | S2 `vseq_state_lineage_mismatch` |
| ENTRY-5 | 골든A `S5` 의 미선언 state entity 를 코드가 잡는다 | S3 검사 범위 확장 |
| ENTRY-6 | 골든B **CTA 컷15** 가 `in_visual_sequence` 만으로 MECHANISM_SEQUENCE 가 되지 않는다 | S5 claim 교집합 요구 |

### 9-6. 첫 렌더는 전체 영상이 아니라 Mini Render 2편 (§19)

ENTRY 통과 후에도 11~15컷 전체를 바로 만들지 않는다. **3~4 stage 짜리 두 편**으로
연속성·identity·수치 오버레이·I2V 열화·글자 누출을 먼저 본다. 통과해야 full render.
**LLM·생성 호출이 들어가므로 시작 전 예상 비용을 보고하고 승인받는다.**

### 9-7. Phase 0 의 표현을 정정한다 (§20)

`Production GO` 가 아니다. 실측이 확인한 것은 3-stage 참조조건 생성까지다.

```
Architecture Feasibility: GO
Production Sequence Quality: UNVERIFIED
```

미검증으로 남은 것: 4+ stage identity 드리프트 · I2V 최종프레임 연쇄 · 카메라 규격을
뺀 뒤의 구도 유지 · 인물 없는 산업 세계 · 실제 렌더 배선 · Equity 라인.

### 9-8. 후속 백로그 (Phase 3 차단 아님)

- **§21 Temporal Context** — `source_published_at` · `event_date` · `render_date` 비교.
  논문 시점의 미래 사건(달 충돌)을 제작 시점에도 미래형으로 읽으면 시점 오류가 된다.
- **§14 관계 환각** — 문자열 게이트(`glow`·`decorative`)는 스타일만 잡고, 정작 위험한
  "원문에 없는 관계·행동 추가"(골든B 컷14 "다른 궤도들이 기준 궤도에 맞춰 정렬된다")를
  놓친다. 관계는 구조화된 claim·operation 연결로 판단하도록 옮긴다.


### 9-9. 적대적 자기리뷰 (리뷰 §23) — "내 구현이 틀렸다고 가정한다"

리뷰가 지정한 10문항을 코드에 대고 물었다. **셋에서 진짜 구멍이 나왔고 막았다.**
나머지는 남은 한계를 그대로 적는다 — 막았다고 쓰지 않는다.

| # | 질문 | 답 | 조치 |
|---|---|---|---|
| Q1 | 모델이 다른 문자열만 넣으면 progression 을 속일 수 있는가 | **있었다.** `visible_change: true` 는 여전히 자기보고고, 같은 `result_state` 를 다시 선언하면 통과했다 | **막았다** — 코드가 계산한 `state_after_computed == state_before_computed` 면 `vseq_no_progression`. 여기엔 모델이 개입할 수 없다 |
| Q2 | 시퀀스에 넣기만 하면 라우터를 속일 수 있는가 | **부분적으로.** 주장 없는 컷은 이제 못 속인다(ENTRY-6). 다만 CTA 에 아무 claim_id 나 붙이면 기전 컷이 된다 | 남은 한계. `claim_id_invalid` 가 존재하지 않는 id 는 잡지만, **존재하는 남의 claim 을 붙이는 것**은 못 잡는다 → `vseq_cut_claim_mismatch` 경고로만 보인다 |
| Q3 | claim_id 만 맞으면 잘못된 depiction 이 통과하는가 | **통과했다.** 골든B 분광 — 주장은 원문이 지지하는데 원문은 **지상 관측**이고 화면은 우주에서 조사한다 | **부분적으로 막았다** — 초록만 확보한 논문은 `LITERAL_OBSERVATION` 을 선언할 자격이 없다(`vseq_literal_without_source`). **다만 "그림이 그 관측을 옳게 그렸는가"는 코드가 판정 못 한다** — 렌더 후 사람 눈·멀티모달 QA 의 몫이다 |
| Q4 | legacy photo gate 와 v3 plan 이 다른 결론을 낼 수 있는가 | **낼 수 있다.** 옛 `visual_role` 이 하위호환으로 남아 있고 읽는 자리가 있다 | **드러냈다** — `vseq_route_contract_conflict` 경고. 차단하지 않는다(기준이 원래 다르다). 정본이 무엇인지는 코드가 정했다 |
| Q5 | Renderer 가 실제로 새 resolved plan 을 소비하는가 | **아니다. Phase 3 미착수** | **미검증.** 이것이 Phase 3 의 첫 작업이고, 안 하면 정본 문서가 경고한 "schema 필드를 renderer 가 무시한다"가 그대로 된다 |
| Q6 | Cost plan 이 legacy asset plan 을 보고 있지는 않은가 | `code_viz_count` 는 **고쳤다**. `unique_asset_count`·`video_clip_count` 는 여전히 `asset_strategy`·`motion_source` 를 본다 | **의도한 것이다** — 그 둘은 라우팅이 아니라 **렌더 전략** 필드다(생성 API 를 부르는가). 라우팅이 정할 값이 아니다 |
| Q7 | abstract-only 에서 구체적 실험 구조가 몰래 살아나는가 | **살아날 수 있다.** `DETAIL_SPECIFICITY_TERMS` 는 유한 목록이라 같은 절차를 다른 말로 묘사하면 통과한다 | 남은 한계. 그리고 **원문 조회가 실패하면 게이트가 아예 안 돈다**(판정 불가를 실패로 만들지 않기 위해). 그 사실은 `claim_evidence_not_run`·`source_depth` 로 화면에 보인다 |
| Q8 | 정상 paraphrase 가 evidence gate 에 반복 차단되는가 | **차단됐었다** — 원인은 낡은 원장이었다(§9-0) | **막았다** — 계약 버전 + 지시서 단계 무료 재대조 |
| Q9 | 연속성을 이유로 동일 화면 복붙이 다시 허용되는가 | `vseq_static_repeat` 가 이제 **계산된 상태**를 본다. `photo_reuse_*` 도 그대로다 | 다만 `connective_in_world` 컷이 세계 참조를 물려받으므로, **렌더가 그것을 파일 복사로 구현하면** 퇴행한다 → Phase 3 배선에서 반드시 본다 |
| Q10 | quantitative overlay 와 생성 화면이 서로 모순될 수 있는가 | **있다.** 오버레이는 "+15%"인데 그림에서 더미가 줄어들 수 있다 | **막지 않았다.** 방향 어휘(증가/감소)로 판정하는 게이트는 오탐이 크고, 리뷰 §17 이 경고한 "정상 콘텐츠를 벌하는 gate"가 될 위험이 실익보다 크다고 봤다. **렌더 후 QA 항목으로 넘긴다**(§9-8 백로그) |

### 9-10. 자기리뷰 중 새로 발견한 실측 결함 둘 (리뷰 지적 아님)

1. **비용 산정이 합성된 기본값을 판정으로 읽고 있었다.** 라우터는 `beat` 가 비면
   `RESULT` 로 채우고 `RESULT` 의 기본 표현이 `CODE_VIZ` 다. 그래서 v3 라벨을 쓰지 않는
   **만화식 지시서의 3컷이 전부 코드 시각화로 세어졌다.** 내가 정본을 비용에 연결하면서
   "선언한 것"과 "채워 넣은 것"을 구분하지 않아 생긴 것이다. `beat_declared` 로 갈랐다.
   → 교훈: **정본을 만들면 그 정본의 기본값도 정본으로 읽힌다.** 기본값에는 표시가 필요하다.

2. **정규식의 워드 경계가 소스에서 백스페이스(0x08)로 둔갑해 있었다.** 패치 도구를
   거치면서 `\b` 가 제어문자가 됐고, `photo_contract._TEXT_REQUEST` 가 **조용히 아무것도
   매치하지 않았다.** grep 으로도 안 보이고 화면에는 정상으로 보인다.
   이 저장소는 워드 경계로 이미 두 번 사고를 냈다(`%` 뒤 경계, 두 파일에서). 원인은
   달라도 결과는 같다 — **게이트가 조용히 죽는다.**
   → `test_no_control_characters_in_engine_sources` 로 회귀를 박았다.
