## 1. 지금 구조 (실측)

`render.py:872` — **`for i, cut in enumerate(cuts):`**

컷 하나마다:
1. 그림 1장 얻기 (생성 / 앞 컷 복사 / 참조 생성)
2. Veo 클립 1개 생성 (4·6·8초 중 티어가 정함)
3. **나레이션 길이에 맞춰 클립을 자르거나(trim) 마지막 프레임을 정지(hold)**
4. 컷 mp4 로 굽기 → 전부 concat

`visual_sequences` 와 `stages` 는 **라우팅·게이트용 메타데이터일 뿐 렌더 단위가 아니다.**

### 실측이 보여준 결과 (세마글루타이드, 14컷 86초)

| 증상 | 수치 |
|---|---|
| hold(정지) 컷 | **5개** — 컷 1·4·8·10·14 |
| 최악 | 컷 8 = 나레이션 12.7초에 클립 8초 → **4.7초 정지** |
| 클립 원본 움직임 | 0.0008~0.0045 (벤치 0.0117) |
| 이미지 생성 | 8장으로 14컷 |

**컷 경계마다 화면이 끊기고, 나레이션이 클립보다 길면 얼어붙는다.** 이것이
"사진 띄워놓고 나레이션 읽는" 느낌의 구조적 원인이다.

## 2. 물리적 제약 (바꿀 수 없는 것)

| | 값 | 출처 |
|---|---|---|
| Veo 클립 최대 | **8초** | `VEO_CLIP_SEC_TIERS = (4, 6, 8)` |
| Veo 초당 비용 | $0.05 | `VEO_COST_PER_SEC_USD` |
| 연쇄 깊이 상한 | **2** (= 클립 3개) | `MAX_CHAIN_DEPTH` |
| 연쇄 지원 버전 | photo | `I2V_CHAIN_VERSIONS` |

**"시퀀스 = 한 클립"은 불가능하다.** 20초 시퀀스를 한 번에 생성할 수 없다.
가능한 것은 **연쇄**다 — 앞 클립의 마지막 프레임을 다음 클립의 첫 프레임으로 넘긴다.
그 배관은 **이미 있다**(`chain["frame"]`). 지금은 컷 단위로 돌아서 효과가 안 난다.

## 3. 제안 — 시퀀스(stage) = 연속 영상 한 덩어리

### 3-1. 단위를 바꾼다

```
지금:  컷1 클립 · 컷2 클립 · 컷3 클립 …   (컷마다 끊김, 남으면 정지)
제안:  ┌─ stage S1 (연속 영상 14초) ─┐┌─ stage S2 (연속 12초) ─┐
       │ 나레이션 컷1 · 컷2 · 컷3    ││ 컷4 · 컷5              │
       └────────────────────────────┘└───────────────────────┘
```

- **stage 가 렌더 단위**가 된다. stage 길이 = 그 stage 에 속한 컷들의 나레이션 합.
- stage 안은 **연쇄 클립**으로 채운다: `clips = ceil(stage_sec / 8)`.
- **컷은 자막·오버레이 경계로만 남는다.** 화면은 안 끊긴다.
- **hold(정지) 를 없앤다.** 모자라면 클립을 하나 더 만들고, 남으면 자른다(trim 은
  잘라내는 것이라 얼지 않는다).

### 3-2. 컷 → stage 매핑

컷에 이미 `resolved_visual_plan.stage_ref` 가 있다. 없는 컷(훅·CTA)은
**앞 컷의 stage 를 물려받는다** — 새 stage 를 만들지 않는다.

### 3-3. 세마글루타이드에 대입하면

현재 지시서의 stage 6개 기준:

| stage | 속한 컷 | 길이 | 지금 | 제안 |
|---|---|---|---|---|
| S1 훅 | 1, 2 | 13.6s | 클립 2개 + 정지 1 | 연쇄 2클립 (8+6) |
| S2 비교 | 3, 4 | 13.1s | 클립 2개 + 정지 1 | 연쇄 2클립 |
| S3 투여 | 5, 6, 7 | 16.6s | 클립 3개 | 연쇄 3클립 (깊이 2 = 상한) |
| S4 칼로리제한 | 8, 9 | 17.4s | 클립 2개 + **4.7초 정지** | 연쇄 3클립 |
| S5 기전 | 10, 11, 12 | 14.5s | 클립 3개 | 연쇄 2클립 |
| S6 한계 | 13, 14 | 10.6s | 클립 2개 + 정지 1 | 연쇄 2클립 |

**클립 15개 → 14개. 이미지 8장 → 6장(stage 당 1장). 정지 5회 → 0회.**
영상 초수는 86초 → 약 96초(8초 단위 올림) → **비용 +$0.5 안팎.**

### 3-4. 코드 변경 위치

| 파일 | 무엇 |
|---|---|
| `render.py` | `for cut in cuts` → `for stage in stages` (본체). 컷 루프는 자막·오버레이 타이밍 계산용으로 남김 |
| `render.py` | `_gen_cut_assets` → `_gen_stage_clips(stage, cuts_in_stage)` |
| `clip_fit.py` | `hold` 전략 제거(실사형 한정). 부족하면 클립 추가 |
| `config.py` | `MAX_CHAIN_DEPTH` 2 → 3 (16초 stage 대응). **근거 필요** |
| `assemble.py` | 변경 없음 — concat 은 그대로 |
| `subtitles.py` | 변경 없음 — `cut_starts`/`cut_durs` 그대로 씀 |

## 4. 위험 — 정직하게

**① 연쇄 깊이를 늘리면 정체성이 흐려진다.** 마지막 프레임을 다시 첫 프레임으로 쓰는
것을 반복하면 인물·재질이 서서히 변한다. `MAX_CHAIN_DEPTH = 2` 는 그래서 있는 값이다.
3 으로 올리려면 **깊이 3에서 실제로 뭉개지는지 재 봐야** 한다. 안 재고 올리면 안 된다.

**② 이것이 "움직임 부족"을 고치지는 않는다.** 원본 클립이 0.0008~0.0045 인 것은
Veo 가 카메라 지시를 안 따르는 문제다. 시퀀스로 바꾸면 **끊김과 정지**가 사라지지
움직임 자체가 늘지는 않는다. **별개의 문제이고 별개로 다뤄야 한다.**

**③ stage 가 없는 지시서는 그대로 컷 렌더를 탄다.** 옛 지시서·다른 버전 보호.

**④ 비용이 조금 는다.** 8초 단위 올림 때문에 편당 +$0.5 안팎.

## 5. 무엇을 먼저 확인할지

**돈 쓰기 전에 재야 할 것 하나:** 연쇄 깊이 3에서 정체성이 유지되는가.
기존 클립 자산으로 확인 가능한지 먼저 보고, 안 되면 **stage 한 개만** 렌더해서 잰다
(약 $0.4). 그 결과에 따라 `MAX_CHAIN_DEPTH` 를 정한다.

이 설계는 **승인 전까지 구현하지 않는다.**
