# 개발 작업계획서 — 하루 한 편 논문 선별·초안 시스템 (P0-P1)

**기준 문서:** P0-P1 통합 기술 명세서 / `docs/기획안_리뷰.md`
**대상 레포:** `dekt-oss/video-article`
**작성일:** 2026-06-29

> 이 문서는 명세서 9절(구현 순서)을 **실행 가능한 마일스톤**으로 분해한 것이다. 각 마일스톤은 **작업 → 의존성 → 산출물 → 합격기준**으로 구성되며, 명세서 절 번호를 역참조해 추적성을 유지한다. 자동 개발 세션은 항상 **현재 진행 중인 가장 낮은 번호의 미완료 마일스톤**을 기준으로 작업한다.

---

## 0. 전체 흐름

```
M0 결정·환경  →  M1 DB 스키마  →  M2 수집 엔진  →  M3 채점 엔진  →  M4 대시보드 P0
                                                                          │
                                                                  [P0 합격 측정 7일]
                                                                          ▼
                                                M5 P1 파이프라인  →  M6 대시보드 P1
                                                                          │
                                                                  [P1 합격 측정 7일]
```

**디렉터리 규약** (CLAUDE.md와 일치):
- `engine/` — Python 수집·채점·P1 파이프라인 (로컬 수동 실행)
- `web/` — Next.js(App Router) 대시보드 (Vercel 배포)
- `supabase/` — SQL 마이그레이션·RLS 정책
- `docs/` — 명세·계획·리뷰

## M2 — 수집 엔진 (명세 2, 리뷰 2-1·2-2 반영)

**작업**
- [ ] OpenAlex 수집: `works`, `from_publication_date`=윈도우 시작, 페이지네이션, `mailto` 적용. **`abstract_inverted_index` → 평문 복원 함수**(명세 2-1).
- [ ] arXiv 수집: Atom API, `submittedDate` 윈도우, **요청 간 3초 간격**, User-Agent에 연락처.
- [ ] buzz 수집(리뷰 2-2 역방향): r/science 등 최신 글 + HN Algolia(도메인) → **DOI/arXiv ID 추출(정규식) + URL 정규화** → `external_id` 조인 → `buzz_raw` 부착.
- [ ] 병합·중복제거(명세 2-3): 키 우선순위 DOI > arXiv ID > (제목 정규화 + 첫 저자). 기존 `external_id` 대조로 재탕 제외.
- [ ] **1차 필터(리뷰 2-1 재설계):** "초록 존재 + 언어(영/한)"로 통과, buzz는 가점. 발행 최신순 + buzz 가점으로 상위 N(config) 컷오프 → 80~150편.
- [ ] `papers` upsert 적재(멱등). 실행 요약 로그.

**의존성:** M1
**산출물:** `engine/`의 수집 모듈, 로컬 수동 실행 스크립트
**합격기준:** 로컬 실행 시 어제~최근 윈도우 논문이 `papers`에 적재, 재실행해도 중복 없음, 1차 필터 출력이 80~150편 범위.
