# 편차 기록 — 근거가 소재 질문에 답하는가 (2026-11-10)

**운영자:** "제목이 내가 끌려서 그걸 선택한건데 근거에 제목을 맞춘다는게 말이되니... 셰리와 버번의 맛 비교하는걸로 내용 새로 짜세요. 근데 애초에 왜 이렇게 만들어진건지도 분석해서 엔진자체도 수정될수있도록하시구요"

## 무슨 일이 있었나

소재 "버번 캐스크와 셰리 캐스크, 위스키 맛은 어떻게 다를까?"의 승인된 근거 8건이 **전부 미국 위스키 표시 규정(27 CFR §5.143)** 이었다(버번 옥수수 51%·콘 위스키·라이트 위스키·스카치 정의). 셰리도, 맛도 없었다. 대본은 근거 안에서만 말하느라 위스키 종류 정의를 나열하다 스코틀랜드 위스키 한 줄로 끝났다.

## 원인 (엔진)

1. **출처 고르기가 낱말 맞추기다.** 공식 출처 목록(`config.DRINKS_DEVELOP_OFFICIAL_SOURCES`)의 27 CFR 항목 키워드 "버번"이 제목과 맞았다. 캐스크·셰리·맛을 다루는 공식 출처는 목록에 없다.
2. **제목과 딱 맞는 네이버 블로그는 근거로 안 쓰였다.** 발견(discovery) 역할로만 붙었고 본문도 저장되지 않았다(`gather_sources` 가 발견 출처를 건너뛴다 — 설계대로).
3. **"근거가 질문에 답하는가"를 재는 곳이 없었다.** 관문은 주장 **개수**(3건·핵심 2건)뿐이었다. AI 사실 확인도 "주장이 인용과 맞는가"만 봤다 — 규정 주장들은 참이라 통과했다.
4. 초안 검사도 결론이 제목 질문에 답하는지는 보지 않는다.

## 고친 것

- **사실 확인 같은 호출에 `question_answer` 한 칸**(추가 비용 0): "근거 인용만으로 소재 질문 그 자체에 답할 수 있는가. 비교 질문이면 양쪽 모두". 코드가 다시 잰다 — 답했다는데 근거 번호가 없거나 목록에 없으면 답하지 못한 것으로 본다. 응답에 판정이 없으면 막지 않는다(판정 못 함).
- **관문** `save_evidence`: 답하지 못하면 `evidence_off_topic` 으로 멈춘다(blocked). 무엇이 빠졌는지(`missing_ko`)와 할 일(질문을 직접 설명하는 출처를 근거로 붙이기)을 적는다. 추출 결과는 보관해 다음 요청이 다시 사지 않는다.
- 화면: 스튜디오 막힘 화면 "모은 자료가 이 질문에 답하지 못해요", 작업 목록·승인 화면 문구, API 상태 422.
- **0081**: 사실 확인 지시문이 길어져 예상 비용 가정값(입력 글자)을 12,000 → 12,500 으로 올렸다(지출을 작게 적지 않는다).

## 버번 소재는

운영자 지시대로 **제목을 그대로 두고** 질문에 답하는 출처를 근거로 붙였다(2026-11-10).
- Whisky Advocate, "How Casks Contribute to Scotch's Flavor"(2016) — 버번 캐스크: 바닐라·캐러멜·스모크·스파이스 / 셰리로 길들인 유럽 오크: 깊고 진한 과일 풍미. 저작권 기사라 **짧은 인용만**(사용 조건에 적음).
- Frontiers in Chemistry(2018, CC BY) — 버번은 새 오크통, 스카치는 셰리를 담았던 스페인 오크통, 헌 통은 우러나는 성분이 적다.

## 아직 안 되는 것

- 출처 자동 찾기는 여전히 낱말 맞추기다. 맛·향 질문에 맞는 공식 출처가 목록에 없으면 이번처럼 **멈추고**(이제는 엉뚱한 영상 대신) 운영자가 출처를 붙여야 한다.
- 초안 단계의 "결론이 질문에 답하는가" 검사는 아직 없다(근거 관문이 먼저 막는다).
