# 규칙 통합 분석 — "더 자세히"가 아니라 "덜, 대신 맞물리게" (2026-09-28)

운영자 질문: "대본과 지시서는 디테일할수록 좋은 거 아니야? 지금 충분히 디테일하고 일관성 있는 수준이야?"
운영자 결정: "규칙 통합하고 정리하는 작업. 뼈대 묶고 코드 정리한 다음 개선 방향은 다시 고민."

이 문서는 **실측**(저장된 최근 지시서 36장, 실제 조립된 프롬프트)으로 지금 상태를 재고, 무엇을 어떤 순서로
정리할지 적는다. 모든 수치는 `scratchpad/warn_sources.py`·`prompt_blocks.py`·`residual.py`(0원, 읽기 전용)로 쟀다.

## 2. 리포트 라인 버그 — 컷이 시퀀스에 안 묶인다

최근 리포트 지시서 6장 **전부** `visual_routing.in_sequence = 0`, 컷 `base` 가 **100% CODE_VIZ**.

원인: 2026-09-19 "리포트도 모델이 시퀀스 쓰게 해" 이후 `equity_visual.annotate` 가 stage 에는 `claim_ids` 를
붙이지만 **컷에는 안 붙인다**(옛 경로 `assign_cuts` 는 붙였다). 라우터는 "주장 없는 컷 = 연결 컷"으로 보고
세계만 잇고(`connective_in_world`), base 는 beat 기본값 RESULT → CODE_VIZ 로 떨어진다. 리포트 스키마는 `beat`
를 묻지도 않는다.

결과: 리포트 실사형이 **기전 시퀀스 경로(참조 이어 그리기·8초 등급)를 한 번도 안 탄다.** 그리고 `vseq` 게이트가
그 빈 `claim_ids` 를 보고 컷마다 `cut_claim_mismatch` 를 찍는다(132건). 삼성전자 편 화면이 컷마다 갈아엎어진
이유의 절반은 프롬프트가 아니라 여기다.

## 3. 정리 계획 — 세 단계, PR 하나씩

### 1단계 — 뼈대 묶기 (버그·소음. 취향 판단 없음) ← 지금
1. 리포트 컷이 stage 의 `claim_ids` 를 물려받고, `beat` 는 논증 단계 종류(`step_kind`)에서 코드가 정한다
   (과정→MECHANISM · 숫자→RESULT · 리스크→LIMITATION). 라우터가 리포트 컷을 `in_visual_sequence` 로 본다.
2. 경고 분류(`engine/warning_triage.py`): 모든 코드를 **차단 / 고칠 것 / 소재 한계 / 알림** 넷으로 가른다.
   헤더에 `warning_summary = {top(≤3), counts}` 를 남기고, 화면은 **위 3개만** 크게, 나머지는 접는다.
3. `vseq_route_contract_conflict`·`photo_mechanism_structured` 는 경고가 아니라 지표(metrics)로 옮긴다.
4. `audit_*` 미러·게이트 미러는 유지하되(화면·라우트가 읽는다) 분류가 **한 번만** 센다.

### 2단계 — 규칙 글 통합 (운영자 승인 뒤)
같은 뜻을 한 자리에만 두고, "실측 사고 서술"은 프롬프트에서 빼 코드 주석으로 내린다(모델에게는 규칙만 필요하다).

| 지금 흩어져 있는 것 | 합칠 자리 |
|---|---|
| 세계는 하나·장소 하나·축척으로 변화·여는 컷이 세계를 그린다 (ARC, SEQUENCE_GUIDANCE, STAGING, PHOTO_CONTRACT) | [세계] 한 절 |
| 글자·차트·라벨·로고·지도·따옴표 이름·아이콘 금지 + 대안(overlay_plan) (SYSTEM, ARC, VERSION, SCREEN_BAN, PHOTO_CONTRACT ×2) | [화면에 글자 없음] 한 절 |
| 색 규약 amber/blue/coral (VERSION, PHOTO_CONTRACT) | [색] 한 절 |
| 영상 컷 6~8·붙여서·카메라 HOLD 금지·비트 (PHOTO_VIDEO_CLIP, TEMPORAL, ARC, PHOTO_CONTRACT) | [움직임] 한 절 |
| 훅 P1~P5 + hook_promise_check + 첫 3초 규칙 + 반전 평서문 (SYSTEM, ARC, PHOTO_CONTRACT, HOOK_CUT_RULE) | [첫 3초] 한 절 — P1~P5·H1~H4·앵글은 만화식 잔재라 **뺀다** |
| 4막 서사 (narrative.NARRATIVE_ARC ↔ ARC 의 7단계 ①~⑦) | 4막 하나로. 7단계 문구 삭제 |
| 재사용 지침(_ASSET_REUSE) | 실사형에서 **뺀다**(재사용 금지인데 재사용 규칙을 준다) |

목표: 규칙 글 29~32k자 → **12k자 안팎**, ★ 150 → 50 안팎. 게이트는 그대로 두므로 안전망은 줄지 않는다.

### 3단계 — 코드가 정할 칸은 코드가 (2단계와 같이 또는 뒤에)
스키마에서 빼는 칸: `crop` `tone_grade` `asset_strategy` `base_asset_ref` `visual_reuse_group` `state_change`
`style_anchor_ref` `novelty_event` `render_notes` `motion_value` `bgm_cue` `transition` `loop_safe` `effects`
+ 헤더 `hook_type` `hook_reframe_angle` `cta_type` `loop_match` `retention_plan` `science_reliability` `cta_*`.
코드가 채우는 칸: `beat`(arc_stage·step_kind) · `motion_source`(base 가 MECHANISM_SEQUENCE 면 video, 예산 안에서) ·
`estimated_sec`(나레이션 글자수) · `loop_safe`(카메라 토큰) · `transition`(cut).

## 4. 판정 기준
- 1단계 뒤: 리포트 지시서 `in_sequence > 0`, 리포트 `vseq_cut_claim_mismatch` 0, 화면 상단 경고 ≤ 3.
- 2단계 뒤: 프롬프트 길이·★ 수 목표 달성, **차단·고칠 것 경고 수가 늘지 않는다**(같은 초안으로 전후 3벌 비교).
- 품질 판정은 G3 규칙대로 실측 렌더 + `youtube_analytics` 평균 시청 비율(조선업 67.5% 기준)로만 한다.
