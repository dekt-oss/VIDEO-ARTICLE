# 설명형 릴스 1단계 ⓐ — 무료 부분 (2026-11-02)

**한 줄:** "사진에 설명"이 아니라 전부 영상인 설명형 릴스를 만들 틀을 돈 안 쓰고 만들었다. 가짜 클립으로 48초 조립까지 돌렸고, 클립이 없거나 깨졌거나 짧으면 편 전체가 멈추는 것을 확인했다. **실제 영상을 산 적은 없고, 그림 품질을 본 적도 없다.**

근거 문서: `docs/기획_릴스3형식_트렌드보드_v2_2026-10-31.md` §3·§9 D1, `docs/총괄계획_릴스3형식_수집부터게시까지_2026-11-02.md` §4-1·§6.

## 여기서 정한 것 (문서에 없던 것)

- **시각 주장표는 DB 칸을 늘리지 않고 개발 요청 결과(`result.visual_claims`)에 남겼다.** `source_table` 과 같은 자리다. `drinks_validate_plan` 을 다시 정의하면 100줄 넘는 함수를 또 복사해야 하고, 같은 함수를 고칠 수 있는 다른 작업과 부딪힌다. 대가: 운영자가 제작안을 손으로 고쳐 새 버전을 저장하면 그 버전에는 표가 없다. **다음 단계(장면별 지시서)는 표가 없으면 멈춰야 한다** — 그 코드는 아직 없다.
- **설명형 대본에서는 정지 카드(`text_card`)를 막는다**(`explainer_still_card`). E1 과 맞추려고 넣었다. 글자가 필요하면 `overlays` 칸에 쓰고 코드가 영상 위에 얹는다.
- **훅 자막은 화면 위에서 20~25% 띠(384~480px) 안에 넣었다.** 문서의 "위 20~25% 높이"는 "그 띠 안"으로도 "그 위쪽 전부"로도 읽힌다. 띠 안에 있으면 두 해석을 모두 만족한다. 그래서 한 줄만 쓸 수 있다.
- **왼쪽 여백 60px** 은 문서에 없는 값이다. 자막 가운데를 안전 영역 가운데(510px)로 잡았다.
- **화면 표기("설명용 도해"/"CG 연출")를 모든 컷에 띄웠다.** 자리는 왼쪽 위 300px 이다.
- **자막 입히기 전 화면에서도 정지를 따로 잰다**(`freeze_under_captions`). 자막이 바뀌면 최종 영상의 정지 구간이 끊겨 보일 수 있어서다. 문턱은 같은 0.8초를 배속 전 시간으로 바꾼 값이다.
- **재시도 상한은 시도 횟수로 셌다.** 후보당 2회 = 첫 시도 포함 2회다. 슬롯당 4회는 후보 2개 × 2회라 사실상 저절로 지켜진다.
- **`generating` 으로 올린 뒤에 공급자를 부른다.** 그래서 `requested` 에서 멈추면 "안 보냄"(청구 없음), `generating` 에서 멈추면 "보냈는지 모름"(`unknown_billed`)이다.
- **돈이 나간 시도(`failed_billed`, `closed_billed`) 뒤의 재시도는 다른 결재로만** 열린다. 0054 의 결재·항목 유니크 인덱스도 같은 방향이다.
- **컷 나누는 목표 길이 3.2초**(최종 기준). 48초 계획에서 컷이 18개 나온다(문서: 약 17개).

## 윈도우에서 밟은 것

한글 경로의 글꼴을 ffmpeg 필터가 직접 열면 프로세스째 죽는다(0xC0000005, `drawtext` 로 실측). `assemble.filter_path` 는 콜론과 역슬래시만 처리한다. 그래서 번인은 글꼴을 작업 폴더에 복사하고, 그 폴더에서 상대 경로로 실행한다(`prepare_burn_dir`). 계산한 자막 상자가 실제 그림과 맞는지는 시험이 검은 배경에 그려서 잰다.

## 아직 안 된 것 · 미검증

- **그림·움직임 품질:** 시험 화면은 ffmpeg `testsrc2` 다. 자동 검사 통과는 "돌아간다"는 뜻일 뿐이다.
- **길이·속도가 설명으로 충분한가:** 운영자가 `docs/preview-<날짜>/explainer-rehearsal/final.mp4` 를 보고 판정해야 한다(S1 합격 기준). 미판정이다.
- **위험 2(1.2배속이 클립 움직임도 빠르게 만든다):** 배속은 `config.DRINKS_EXPLAINER_PLAYBACK_SPEED` 에 따로 뒀다. 어색한지는 진짜 클립으로만 알 수 있다.
- **공급자 호출 전부:** Omni 의 `input`·`response_format` 안쪽 모양과 응답 모양은 가정이다. 첫 프레임 고정, 길이 지정, 조회 가능 여부, Vertex 의 "1 count = 1초"는 S2 에서 판정한다(코드 주석에 표시).
- **안전 영역 숫자:** 앱에서 확인 전이다(§2-3).
- **정지 문턱 0.8초, 연속성 자동 문턱:** 첫 값이다. 경계별 연속성 숫자 기록은 만들지 않았다 — 가짜 화면으로는 뜻이 없다. 경계 종류만 편집표에 남는다.
- **연결 안 된 것:** 렌더를 부르는 것은 리허설뿐이다. 제작 워커·대시보드는 설명형을 모른다. `drinks_paid.buy` 는 후보 키와 실측만 갖췄고, 시도 표·어댑터를 아직 부르지 않으며, 기본 생성 경로는 종료된 Veo 미리보기 모델 그대로다(S2 전에 연결). 승인된 긴 대본을 옛 이미지 나열식 렌더가 받으면 사진으로 나갈 수 있다 — 형식 표시와 분기는 ⓒ·제작 연결 때 필요하다.
- **`--tts edge`:** 코드는 있지만 돌려 보지 않았다(네트워크를 쓰지 않기로 했다).
- **운영 DB:** 0062 적용 안 했다(§10-6 결재 대상).

## 되돌리기

1. 대본 범위: `config.DRINKS_DEVELOP_SCENES = (5, 7)`, `DRINKS_DEVELOP_SECONDS = (30.0, 40.0)`, `DRINKS_DEVELOP_EXPLAINER_CONTRACT=false`(환경 변수로도 된다). 지시문과 검사가 함께 돌아간다.
2. 렌더: `engine/drinks_explainer.py` 와 `scripts/explainer_rehearsal.py` 를 지운다. 다른 렌더는 이 파일을 부르지 않는다. 단 `engine/drinks_paid.py`(`_measure_clip`)와 `engine/providers/video.py`(`store_parsed_clip`)가 `probe_clip` 을 쓰므로 그 둘도 함께 되돌린다.
3. 표: 아직 운영에 없다. 적용한 뒤라면 `0062` 머리말의 drop 문을 쓴다.
4. `engine/render_qa.py` 의 `parse_freeze_spans` 는 옛 줄 단위 파싱을 함수로 꺼낸 것뿐이라 그대로 둬도 된다.
