# G2 실측 결과 (2026-08-31) — Gemini 웹, API 비용 0

원래 물으려던 것: **"8초가 4초보다 실제로 나은가?"**

## 0. 결론 두 줄

1. **길이 질문에는 답하지 못했다.** Gemini 웹이 요청 길이를 무시하고 **양쪽 다 10.01초**를
   냈다. 조작 변인이 안 바뀌었으므로 이 실험은 그 질문에 답할 수 없다.
2. **대신 더 중요한 것에 답이 나왔다** — 두 팔의 프롬프트는 실제로 달랐다(한쪽만
   연출 계약). **연출 계약이 화면을 바꿨다.**

## 1. 무엇이 통제되지 않았나

| | 요청 | 실제 |
|---|---|---|
| A (계약 없음) | 4초 | **10.01초** |
| B (연출 계약) | 8초 | **10.01초** |

둘 다 720×1280. 웹 UI 에는 길이 선택이 없다 — 고정 10초다.

> **이것 자체가 소득이다.** 웹 경로로는 **길이 축을 실험할 수 없다**는 것이
> 확정됐다. G2 는 9/1 이후 API 로만 가능하다(`durationSeconds` 파라미터를 우리가 보낸다).
> 도구에도 박았다: `judge` 가 이제 **실제 길이를 재서** 요청과 다르면
> "이 실험은 그 질문에 답하지 못한다"고 먼저 말한다. 라벨을 믿고 채점하면
> **도구가 없는 실험을 했다고 기록한다.**

## 2. 그래서 실제로 답이 나온 것 — 연출 계약

두 팔의 프롬프트 차이는 **연출 계약(temporal_plan) 유무 하나**였다:

```
A: …the rocket impacts the surface with a burst of dust…, whip-pan up
B: …shot sequence within the clip:
     0.0-2.5s  the camera pulls back to reveal the whole structure
     2.5-5.5s  the camera moves laterally alongside as the rocket stage travels
     5.5-8.0s  the camera pushes in rapidly as the crater strikes the surface
   …(뒤에 A 와 같은 문장)
```

### 코드 채점 (`clip_candidates` — 렌더가 후보 고를 때 쓰는 바로 그 함수)

| | 정지 비율 | 장면 전환 | 세계이탈 | 점수 |
|---|---|---|---|---|
| A 계약 없음 | 0.0% | **0** | 0.802 | 0.7000 |
| B 연출 계약 | 0.0% | **1** | **1.000** | **0.8500** |

> ★ 나중에 추가한 `world_drift` 로 다시 재니 **계약 쪽이 세계를 가장 많이 떠났다**
> (1.000). 움직임 점수는 가장 높은데 세계 유지는 가장 나쁘다 — 두 지표가 반대
> 방향을 가리킨다. 자세한 것은 `docs/실측_품질/G4/결과.md` §5.

점수차 0.15 — 기준(0.05) 위. **차이 있음.**

### 눈으로 본 것 (프레임 대조)

```
A   0.2s 로켓 하강 → 3.5s 충돌·먼지 → 7.0s 분화구 단면 → 9.5s 분화구 단면(주석선)
B   0.2s 로켓 하강 → 3.5s **로켓 측면 추적(lateral)** → 7.0s 충돌·파편 → 9.5s 분화구 단면
```

**B 의 3.5초 지점에 A 에는 없는 장면이 있다** — 카메라가 로켓 옆으로 붙어 따라가는
구간이다. 계약의 2번째 비트(`2.5-5.5s TRACK`)가 **실제로 화면에 나타났다.**
즉 `temporal_plan` → `build_motion_prompt` → Veo 배선이 **끝까지 작동한다.**

## 3. ★ 그런데 둘 다 심각한 결함이 있다

**두 클립 모두 마지막에 세계를 버린다.** 달 표면 실사에서 시작해 **받침대 위에 놓인
분화구 단면 다이어그램**으로 끝난다 — 완전히 다른 장면이고, B 에는 `DIAMETER` 같은
**글자·치수선까지 박혔다.**

원인은 프롬프트 꼬리의 이 문장이다(양쪽 공통, 원래 지시서에서 온 것):

```
…then a graphic overlay appears indicating a crater diameter, whip-pan up…
```

**우리가 "그래픽 오버레이를 띄워라"라고 시켰다.** 그리고 그 오버레이는 수치를 담고
있어서, 화면에 글자가 박히는 것은 필연이었다. 같은 계열의 사고를 이 저장소가 이미
두 번 기록했다(Phase 0 의 `35°`, 8/30 골든B 의 `GEMINI-3`).

> **판정: 이것은 Veo 의 결함이 아니라 우리 지시의 결함이다.**
> 수치는 코드 정밀 레이어가 그린다는 R1 원칙과, `no text/no numbers` 네거티브가
> 같은 프롬프트 안에서 **서로 모순**돼 있다.
