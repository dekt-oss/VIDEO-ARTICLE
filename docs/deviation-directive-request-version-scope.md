# 편차 기록 — 발주를 눌러도 아무 일도 안 일어나던 이유 (2026-08-05)

관련 코드: `supabase/functions/generate-directive/index.ts`, `web/app/api/directive-generate/route.ts`,
`web/components/VersionOrderBar.tsx`.

## 실측

⑤ 화면에서 만화식·웹툰을 한 번에 발주했는데 **웹툰 지시서가 끝내 나타나지 않았다.** DB 를 보면
요청 두 건이 **같은 밀리초에 나란히 `done`** 으로 찍혀 있고, 지시서는 comic 한 건뿐이다:

| version_type | status | requested_at | updated_at |
|---|---|---|---|
| comic | done | 09:48:19 | **09:49:47.364** |
| webtoon | done | 09:48:50 | **09:49:47.364** |

`directives` 에는 `comic` 한 행(09:49:47.361)만 있다.

## 원인 세 겹

1. **엣지 함수가 요청 행을 `paper_id` 로만 좁혔다.** `generate()` 의 상태 갱신 세 곳이
   `.eq("paper_id", …)` 뿐이라, 한 논문의 **다른 버전 요청까지** 함께 바뀐다. 먼저 끝난 comic 이
   두 행을 모두 `done` 으로 찍었고, 늦게 끝난 webtoon 의 `done`/`error` 갱신은 0행에 걸려
   **사라졌다.** 그래서 실패해도 사유가 어디에도 남지 않는다.
2. **진행 중인데도 함수를 다시 불렀다.** `/api/directive-generate` 는 큐 적재만 건너뛰고 호출은
   그대로 했다 — 버튼을 두 번 누르면 같은 논문·버전으로 LLM 생성이 동시에 여러 벌 돈다.
   실측 로그에 45초 동안 `generate-directive` 호출이 **4회** 찍혔다(비용도 4배).
3. **발주 화면이 결과를 기다리지 않았다.** `VersionOrderBar.submit()` 은 POST 직후 곧바로
   `router.refresh()` 만 했다. 생성에는 약 1분이 걸리므로, 아직 만들어지지 않은 화면이 그대로
   다시 그려진다 — 운영자 눈에는 "눌렀는데 아무 일도 안 일어남"이다.

## 조치

1. 엣지 함수의 요청 상태 갱신 세 곳을 **`paper_id` + `version_type`** 으로 좁혔다.
2. 라우트는 진행 중인 요청이 있으면 **함수를 다시 부르지 않는다.** 단, 15분이 넘도록 응답 없는
   행은 죽은 것으로 보고 `error` 로 닫은 뒤 새로 건다 — 시간 제한이 없으면 굳은 행이 그 논문·버전을
   영구히 막는다(실측: 2026-07-29 부터 `processing` 으로 굳은 행이 남아 있었다).
3. `VersionOrderBar` 가 `/api/directive-status` 를 **버전별로 폴링**한다(4초 간격, 6분 타임아웃 —
   `useGeneration` 과 같은 값). 화면에 "생성 중… Ns 경과"가 뜨고, 끝나면 토스트 + 자동 갱신,
   실패하면 사유를 그대로 보여준다.

## 확인 방법

⑤ 화면에서 두 버전을 체크하고 발주하면 스피너와 경과 시간이 뜨고, 약 1분 뒤 **두 버전이 각각**
지시서를 갖는다. 한쪽이 실패하면 그쪽 사유만 빨간 토스트로 뜨고 다른 쪽은 정상 완료된다.
