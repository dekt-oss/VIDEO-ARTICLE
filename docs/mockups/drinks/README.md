## 사장님의 하루

1. **01 오늘 할 일** → [근거·대본 확인하기]: 위스키 대본을 엽니다.
2. **03 설명형** → 읽었다는 확인 → [승인] → 별도의 [결재 열기 $8.90] → [구매 요청].
3. **02 후보** → [이걸로] → 릴스·밈·카드뉴스 복수 선택·주차 지정 → [이걸로 만들기]: 대본 만드는 중이 보입니다.
4. **02 밈 카드** → [쓰자] → **05** 글 두 줄 → [승인] → [제작 시작].
5. **04 카드** → 8장 확인 → 산출물 승인 → 카드 게시 방식·캡션·내일 12:00(카드 릴스는 음원 필수) → [승인 요청] → [승인] → [예약].
6. **03 상태 전환: 후보 고르기** → 두 영상 재생 → 각각 합격/불합격 → [이 장면으로] → 이유 → 선택 확정 → 조립 → 과정 3항목 → 품질 6항목 → 산출물 승인.
7. **01 상황 전환: 돈 결과 모름** → **07** 구매 내역·파일 확인 안내 → 확인 결과·근거·확인 체크 후 닫기. 다시 구매는 자동 실행되지 않습니다.
8. **06 발행·성과** → 이번 주 예약 3개와 지난주 조회·저장·공유를 확인합니다.

박자 밈은 **05 상태 전환: 앱에서 게시**에서 체험하세요. 앱에서 음원 부착·직접 게시한 뒤 주소를 기록하며, 웹 예약 버튼은 나오지 않습니다. ‘소재 출발 보기’ 버튼으로 밈의 두 출발점도 비교할 수 있습니다.

## 바뀌는 것 / 안 바뀌는 것

- **바뀜:** 고르는 곳을 하나로, 한 소재의 일을 같은 작업공간으로 모읍니다. 다음 행동은 위의 고정 바가 알려 줍니다.
- **유지:** 승인 ≠ 결재 ≠ 제작 시작 ≠ 게시 승인 ≠ 예약. 과정·품질 검수 문구는 기존 항목 그대로입니다. 음원 없는 카드 릴스와 시간 범위를 벗어난 예약은 막습니다. 넘겨 보는 카드뉴스는 음원이 필수가 아닙니다. 설명형의 ‘AI 생성 영상’ 문구도 필수입니다.
- **목업 한계:** 수백 건은 집계 예시이고 후보는 2페이지 8개만 있습니다. 기다림은 ‘완료된 모습 보기’로 건너뜁니다. 기본 데모는 새로 열면 초기화됩니다. 복수 선택으로 시작한 작업은 브라우저 세션 안에서 형식별 진행을 보존합니다(영구 저장 아님). 달력 3개는 고정 예시이며 실제 예약 기록이 아닙니다.
- **파일:** HTML 8개(00–07), 공통 `style.css`·`app.js`, 후보 영상 `candidate-a.webm`·`candidate-b.webm`, 이 설명서. 검증 화면 캡처가 있으면 `preview-*.png`로 함께 둡니다.
