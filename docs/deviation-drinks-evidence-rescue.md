# 근거 막힘 해결안 — 막히면 끝내지 말고 고칠 안을 가져온다 (2026-11-13)

## 운영자 지시
> 만들다가 근거가 막히면 끝내지 않고 해결방안을 가져와서 내가 적용 여부만 확인하게. (Jev 를 쓰든 뭘 쓰든)

## 실측 — 실제로 무엇이 막히나 (2026-11-13 운영 DB)
| 막힘 | 건수 | 이번에 해결안을 붙였나 |
|---|---|---|
| `evidence_off_topic` — 근거는 맞는데 소재 질문에 답하지 못함 | 2 | **붙였다** |
| `evidence_insufficient` — 인용 대조를 통과한 근거가 최소 수 미만 | 1 | 아니다(고칠 재료가 없다 — 출처를 더 붙여야 한다) |
| `script_check_failed` — 대본 검사(근거가 아니라 화면 규칙) | 2 | 아니다(범위 밖) |
| 승인된 근거가 나중에 무효(`drinks_review_blockers`) | 0 | 아니다(지금 0건) |

같은 날 "청주·탁주" 소재의 [근거 재확인] 은 근거 막힘이 아니라 화면 오경보였다(PR #181 — 검수 전 산출물을 차단으로 읽음).

## 무엇을 했나
- **워커**(`engine/drinks_develop.py::propose_reframe`): off_topic 으로 막히면
  ① 모델이 "지금 근거로 완전히 답할 수 있는 질문"을 하나 제안하고
  ② **같은 AI 사실 확인**(`run_factcheck`)으로 그 질문을 미리 판정해 답했고 핵심 주장이 최소 수 이상일 때만
  ③ (Jev 가 켜져 있으면) 답 문장이 인용을 벗어나는지 한 번 더 보고
  막힘 결과에 `rescue` 로 남긴다. 호출은 전부 결재 장부(가잡기→확정)를 탄다. 못 만들면 예전처럼 막힐 뿐이다.
- **DB**(0084 `drinks_apply_rescue`): [해결안 적용] 한 번에 소재 제목·질문을 바꾸고(변경 전 값은 `drink_workflow_events` 에 남는다)
  같은 결재로 근거 요청을 다시 넣는다. 이어 만들기 표시를 잇는다.
  `drinks_develop_context` 는 이 경우에만 막혔던 요청의 추출 결과를 다시 쓴다 — 추출을 다시 사지 않는다.
- **재사용 판정 규칙**: 보관된 사실 확인이 다른 질문으로 판정된 것이면 새 질문으로 다시 판정한다(옛 판정을 넘기지 않는다).
- **화면**: 개발 카드의 막힌 요청 아래에 해결안·이유·근거로 쓴 답과 [해결안 적용] 버튼.

## 왜 자동 적용하지 않나
해결안은 **소재 질문을 바꾸는 일**이다. 원래 질문을 지키고 출처를 더 붙이는 편이 나은 경우가 있어 마지막 선택은 운영자에게 남긴다.

## 비용
막혔을 때만 호출 2번(제안 1 + 사실 확인 1, 사실 확인과 같은 모델). 적용 뒤에는 사실 확인 1번(추출 재사용).
`drinks_develop_estimate_params` 의 예상 비용에는 넣지 않았다 — 막힐 때만 생기는 비용이다.

## 끄기·되돌리기

- 되돌리기: `drop function drinks_apply_rescue(jsonb);` + 0076 의 `drinks_develop_context` 재실행.
