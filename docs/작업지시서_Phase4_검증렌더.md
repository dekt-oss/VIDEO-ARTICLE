## 0. 이 문서가 정하는 것

렌더를 "일단 한 편 돌려 보는 것"이 아니라 **§14-1 하드 게이트를 판정하는 절차**로 만든다.
무엇을 · 어떤 순서로 · 얼마를 쓰고 · 무엇을 보면 합격인지 · 언제 멈출지를 미리 못박는다.

> **왜 미리 정하나:** 지금까지 세 번, "모든 것을 막는 게이트"를 실측 없이 만들었다가
> 되돌렸다(series_split · core_underfilled · 내가 만든 자 두 개). 렌더는 **돈이 나가는
> 실측**이라 같은 실수를 하면 되돌리는 데 돈이 든다. 볼 것을 먼저 적는다.

### 5-1. A(코스피)에서 특별히 볼 것

Phase 0 이 이 건에서 **CORE 충전율 0.235 · `layout_qa` fail 0** 을 실측했다.
지금은 문턱 0.25 로 `core_underfilled` 가 **차단**된다(코드로 확인). 그러므로:

- 기대: 이 건은 **`degraded`(사람 확인)로 떨어져야 한다.** `done` 이 나오면 판정기가
  아직 눈이 먼 것이고, `failed` 로 죽으면 처리 방식이 다시 틀린 것이다.
- 즉 **A 의 합격은 "done" 이 아니라 "degraded + 사유에 core_underfilled"** 다.

   보유**(`source_depth=full_text`, 11,992자):

## 8. 실행 방법

```bash
# 로컬(권장하지 않음 — ffmpeg·폰트 의존, Windows 에서 골든 해시가 달라진다)
python -m engine.report_render

# GitHub Actions (정본 경로)
# Actions → report-video 워크플로 → Run workflow → mode=render
```

★ 워크플로는 `report-video.yml` 이고 입력은 `mode`(directive|render|poll)다 —
  directive_id 를 직접 받지 않고 **큐를 폴링한다**. 그러므로 대상 1건만 돌리려면
  큐에 그 1건만 들어가게 해야 한다(대시보드 ⑤ 화면에서 그 지시서만 발주).

  쌓여 있으면 한 번의 실행이 전부 돌려 버린다. 착수 전 큐를 확인할 것.
  **확인함(2026-09-03): `report_render_jobs` 에 대기 중인 잡 0건** — 지금은 깨끗하다.
