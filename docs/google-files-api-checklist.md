# Google Files API 다운로드 체크리스트

> Veo(I2V) 연동(`741a2d6`→`917456e`→`a30b3e6`→`ef8a54b`, 2026-07-12)에서 실제 렌더 로그로 순차
> 확인한 4가지 실패 모드를 정리한 것. 다음에 Google Files API를 쓰는 외부 생성 연동(TTS·이미지
> API 등)을 새로 붙일 때 이 체크리스트부터 확인하면 같은 시행착오를 반복하지 않는다.

## 요청 단계
- [ ] `generateAudio`/`resolution` 등 파라미터가 **사용 중인 프리뷰/GA 모델에서 실제로 지원되는지**
      확인한다. 미지원 파라미터는 조용히 무시되지 않고 400을 낸다.

## 완료 응답 파싱
- [ ] 완료 응답이 **파일 uri 형태**로 온다는 전제로 파싱한다(바이너리가 바로 오지 않음).
- [ ] 폴링·재시도 로직에서 **이중 과금**이 나지 않는지 확인한다(완료된 작업을 재요청하지 않는다).

## 파일 다운로드
- [ ] 다운로드 URL에 **`alt=media` 쿼리 파라미터가 반드시 포함**돼야 한다. 빠지면 400.
- [ ] HTTP 클라이언트가 **`follow_redirects=True`**로 설정돼 있는지 확인한다. Google Files API는
      서명된 URL로 리다이렉트하는데, 리다이렉트를 안 따라가면 깨진(placeholder) 파일이 그대로
      저장된다 — 에러 없이 조용히 실패하므로 특히 위험하다.

## 저장 후 검증
- [ ] 저장된 파일이 **매직바이트(mp4 등 실제 포맷 시그니처)**로 유효한지 검증한다. HTTP 200이
      떨어졌다고 파일이 정상이라는 보장은 없다(위 리다이렉트 미처리 사례가 실제로 200을 반환하며
      깨진 파일을 저장했었다).
