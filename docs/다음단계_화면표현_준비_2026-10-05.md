# 다음 단계 준비 — 화면 표현 (움직이는 설명 화면 + 실적/전망 구분)

> 작성 2026-10-05. 원 작업지시서(`docs/작업지시서_ExplanationEngine_v2.md`) Phase 11 "Visual Explainer Renderer",
> Phase 12 "Domain Visual Semantics" 에 해당한다. 운영자 방향: **영상 표현 개선이 최우선, 일단 완성 후 조율,
> 렌더(유료 생성)는 하지 않는다.** 검증은 비용 0(코드 단위 테스트 · 기존 그림 재사용 미리보기)으로 한다.

## 1. 지금 영상은 무엇이 움직이나 (2026-10-05 조사)

- 움직임은 둘뿐이다: **유료 생성 영상 클립(Veo)** 과 **정지 이미지 위 줌·이동(Ken Burns)**.
- 코드가 그리는 화면 글자(키워드 카드·전후 캡션 등)는 **전부 정지**다. 엔진에 페이드·이동 같은 애니메이션 태그가
  한 줄도 없었다.
- 지시서의 장면 동작(흐름·변형·확대·나누기…)은 **그림 생성 프롬프트 문장**으로만 쓰인다 — 화면 움직임으로
  바뀌는 코드는 없다. 구조적으로 쓰이는 것은 "상태가 바뀌면 위·아래 전후 분할 스틸" 하나다.
- **쓸 수 있는 자산:** 폐기된 설명판형이 쓰던 코드 애니메이션 엔진(`board_motion`·`board_render`: 숫자 카운트업,
  막대 자라기, 선 그려지기, 게이지 채우기, 이징). 지금은 폐기 경로에서만 불린다.
- 실적·전망·시나리오(금융), 관측·모델·가설(과학)을 **화면에서 구분하는 장치는 없다** — 문구 검사 경고만 있다.

## 2. 단계 순서

| 순서 | 할 일 | 원안 대응 | 상태 |
|---|---|---|---|
| S1 | **화면 숫자 카드** — V2 가 말에서 뺀 숫자를 그 내용을 말하는 컷에 카드로 띄운다. 살짝 늦게 **페이드로 떠오른다**(첫 화면 글자 애니메이션) | REVEAL | **이번에 구현** |
| S2 | 화면 글자에 움직임 기본기 — 키워드·전후 캡션·숫자 카드에 페이드/슬라이드/강조 | MOVE · REVEAL | 다음 |
| S3 | 숫자 카드를 **카운트업**으로 — 설명판 모션 엔진의 `count_up` 을 투명 오버레이 프레임으로 재사용 | COUNT_UP | 다음 |
| S4 | 장면 동작 → 실제 움직임: 흐름(FLOW)=경로·화살표 그려지기, 확대(ZOOM_INTO)=밀어 들어가기, 나누기(SPLIT)=층 분리, 드러내기(REVEAL)=마스크 와이프 | PATH · ARROW · SCALE · MASK · LAYER_SPLIT | 다음 |
| S5 | 실적/전망 구분 — 숫자 카드에 "전망(E)" 배지와 점선 테두리, 과학은 관측/모델/가설 배지 | Phase 12 | 다음 |

원칙(원안): ① 코드가 그리는 움직임 ② 정지 그림 + 합성 ③ 생성 영상은 훅·핵심 장면 등 코드로 어려운 곳만.

## 3. S1 — 화면 숫자 카드 (구현)

- **왜 다시 켜도 되나:** 2026-09-08 운영자가 숫자 카드를 끈 이유는 "나레이션·자막이 이미 말한 숫자를 또 얹는다"였다.
  V2 카드는 **말에서 뺀 숫자만** 보여 준다 — 같은 정보가 두 번 나오지 않는다.
- **범위:** 새 화면 글자 유형 `screen_fact`. V2 브리지만 만든다. Production 지시서 프롬프트의 선택지 목록
  (`OVERLAY_TEXT_TYPES`)에는 넣지 않아 Production 화면은 그대로다. 끄기: `SCREEN_FACT_CARDS_ENABLED`.
- **문구:** 숫자 앞 낱말 두 개를 이름표로("DRAM 가격 18.0% · NAND 가격 16.0%"), 가까운 두 숫자는 범위로
  ("대사 에너지 26%~41%"), 시점 표현은 이름표에서 뺀다.
- **어느 컷에:** 지시서 생성 뒤 V2 추적 정보로 그 비트의 컷을 찾고, 낱말이 가장 많이 겹치는 컷에 단다. 컷당 한 장.
- **움직임:** 컷 시작 0.4초 뒤 나타나고 0.25초 페이드 인, 0.15초 페이드 아웃(ASS `\fad`).
- **검증(비용 0):** 카드 문구·부착·ASS 출력(시간·스타일·페이드 태그)·Production 프롬프트 미노출을 단위 테스트로 고정.

## 4. 검증 방법 (렌더 없이)

- 단위 테스트: ASS 출력(시작·끝 시각, 스타일, 애니메이션 태그)을 문자열로 확인.
- 비용 0 미리보기(`scripts/preview_sequence.py --reuse <지난 그림 폴더>`): 기존 그림 위에 자막·화면 글자·조립을
  실제로 돌린다. **지시서가 DB 에 있어야** 쓸 수 있어 V2 지시서(저장 안 함)에는 바로 못 쓴다 — 필요하면 파일 입력
  미리보기(`scripts/mini_render.py`)로 연결한다. 실행 여부는 운영자 결정(비용 0이지만 "렌더"이므로).

## 5. 나중에 조율할 것 (완성 우선 원칙으로 미룸)

말하기 품질(고정 도입 질문·약어·긴 문장), 선행 개념 자동 찾기, 옛 논문 Fact Sheet 재추출(STALE·NOT_CHECKED·
한계 구절), Production 프롬프트의 "80초를 넘기지 마라" 권고 문구.
