# Explanation Engine v2 설계 점검 (2026-10-05)

> 기준: `main` `d89939b`(PR #100~#103 머지). 원 작업지시서 `docs/작업지시서_ExplanationEngine_v2.md`,
> 단계 문서 `docs/phase*_ExplanationEngine_v2_*.md`, 코드, 그리고 **실제 데이터**(파일럿 후보 6건 무료 실행 +
> 유료 실행 3회 × 2건, 합계 $0.089)를 대조했다. 운영 자료 원문은 싣지 않는다.

## 1. 결론

- **대본 단계(Phase 2~8)는 리포트 기준으로 처음 끝까지 통과했다.** 오늘 고친 단계 간 충돌 4건 덕분이다.
- **그러나 V2 전체는 아직 "대본 + 추적용 지시서 골격"까지다.** 화면을 만드는 쪽(원안 Phase 9~11)은 원안에서
  벗어나 있고 렌더에 쓸 수 없다(§3-A). 원안 Phase 11~13(Renderer·Domain Visual·QA 통합)은 시작 전이다.
- 오늘 막힌 원인은 대부분 **단계를 따로 설계·검증한 진행 방식**에서 나왔다. 단계 문서마다 규칙을 따로 정했고,
  테스트는 입력을 복사하는 가짜 모델만 써서 단계 사이 충돌이 실제 모델 실행 전까지 보이지 않았다.
  → `tests/test_explanation_v2_realistic_model.py` 로 막는다(§4).

## 3. 남은 설계 문제 (심각도순)

### A. 화면 단계가 원안과 다르다 — V2 지시서는 렌더에 못 쓴다 [구조 → ①로 결정·연결, PR #108]

> 2026-10-05 운영자 결정: ①(기존 지시서 생성기 재사용). `engine/v2_directive_bridge.py` 가 V2 대본을 초안 모양으로
> 바꿔 `directive.generate`/`report_directive.generate` 에 넣고(저장 없음), 생성기가 지운 추적 정보를 컷에 다시
> 붙인다. 비용 0 스모크(실제 Samsung V2 대본 재생 + 실제 생성기 코드, 모델 응답만 대역): 장면이 프롬프트에 실림,
> 컷 `reasoning_id` R01/R02 보존, 7/7 컷 추적, 원장 기록 0. 기존 간이 화면 계획은 "추적 골격"으로 이름만 바꿔 남겼다.

원안 Phase 9 는 "새 Visual Beat Schema 를 만들지 않는다. 기존 Visual Sequence·Stage 를 정본으로 쓴다"이다.
구현은 새 결정론적 시각 계획기(`engine/visual_planner.py`)를 만들었고, Phase 10 은 그 결과를 Production 지시서
**모양**으로만 투영한다. 실측(Samsung `READY` 지시서):

- `visual_prompt` 가 장면 묘사가 아니라 틀 문장이다 — "Show only this source-backed statement: <대본 문장>"
  (`explanation_directive._prompt`). Production 은 장면을 쓴다("클린룸 레일을 따라 웨이퍼 포드가 이동").
- 컷 3개(Production 10컷). 한 컷에 세 문장(약 170자)이 들어가는데 길이가 8초로 적힌다 — `_duration` 이
  3~8초로 자른다.
- Production 의 장면 설계 장치(실사형 계약·화면 구성 계약·`photo_prompt`)를 전혀 쓰지 않는다.

**결정 필요:** ① 원안대로 V2 대본 + 추적 ID 를 **기존 지시서 생성기**(`engine/directive.py`/`photo_prompt`)에
입력으로 넣는다(추천 — 화풍·장면 계약을 다시 만들 필요가 없다), 또는 ② Phase 9/10 을 장면 설계까지 확장한다.

### B. 검증 상태 처리가 거꾸로다 [안전 → 수정됨, PR #105]

`explanation_ir.DISALLOWED_POSITIVE_STATES = {UNSUPPORTED, STALE}`. `NOT_CHECKED` 는 경고만 붙고 근거로 쓰인다.

- retinotopic(`6b2d092a`): 근거 6/6 `NOT_CHECKED` → V2 근거로 그대로 사용(골드셋이 지적한 "청각→시각 전이 발명"
  사례다).
- GWAS(`372055db`): 근거 10/10 `STALE`(옛 검증 규칙으로 검증됨) → V2 가 아예 시작되지 않음.

"한 번도 검증 안 된 근거"가 "옛 규칙으로 검증된 근거"보다 통과가 쉽다. **추천:** `NOT_CHECKED` 도 근거로 쓰지
않고, 두 상태 모두 "Fact Sheet 재검증 후 사용"으로 안내한다(재검증은 기존 파이프라인 비용).

### C. 연구 한계·리스크가 빠진다 [사실 보존 → 리포트는 E 로 해결(PR #109), 논문은 (가)로 해결(PR #110)]

어댑터가 주장에 직접 붙은 한계(논문)와 `RISK_PATH` 단위(리포트)만 읽는다. 실데이터에서 빠진 것:
heel strike 한계 3, GWAS 한계 5, Samsung 리스크 1, Shipbuilding 리스크 4. 원안 §0 "불확실성·정보 삭제" 원칙과
어긋나고, Samsung 은 기존 대본(피크아웃 우려)보다 후퇴했다.

### D. V2 에 길이·분할 판단이 없다 [구조 → 수정됨, PR #110]

Phase 8 은 Production 이 저장한 계획을 입력으로 받는다(Phase 8 문서). 파일럿 논문 3건이 모두 `series_split` 이라
V2 논문 지시서는 나올 수 없다. V2 가 Production 을 대체하려면 V2 자신의 길이 판단이 있어야 한다 — 원안에는
정의가 없다.

### E. 리포트 논증 단계에 근거 ID 가 안 붙어 있다 [데이터 → 수정됨, PR #109]

`report_step_without_evidence_id`·`reasoning_unit_without_evidence` 경고: Samsung 16건, Shipbuilding 29건.
증권사 논리 단계(`financial_reasoning.steps`)의 `fact_ids` 가 비어 근거 없는 단위가 빠지고 V2 대본이 짧아진다
(Samsung 5단위 → 3비트, Shipbuilding 2단위).

### F. 말하기 품질 [품질]

고정 도입 질문("이 연구는 무엇을 보여 주는가?"), 설명 없는 약어, 60자 초과 문장, 비트마다 증권사 귀속 반복.
전부 경고만 낸다.

### G. 선행 개념 자동 탐지 없음 [원안 대비 공백]

원안 Phase 4 는 "시청자가 모를 개념을 먼저 푼다"이지만 구현은 명시 요청만 해결한다. glossary 2개 항목.

### H. 작은 것

- 연도 단독 표기("1998")를 값으로 센다(NH 실데이터) — `spoken_numbers` 의 시점 패턴은 "년"이 붙어야 한다.
- 리포트 V2 에 면책 문구가 없다 — Production 연결 전 필수.
- Phase 2: `quote_verified=false` 인 claim 이 `SUPPORTED` 로 남는다 — 의도 미확인.

## 4. 재발 방지

`tests/test_explanation_v2_realistic_model.py` — 실제 모델이 파일럿에서 **실제로 한 일**(어미 변형, 존댓말,
화면 숫자를 말로 풀기, 완곡 표현, 귀속 덧붙이기)을 흉내 내는 가짜 모델로 Phase 2~10 을 한 번에 돌린다.
뜻이 같은 변형은 어느 단계도 막지 않아야 하고, 뜻이 바뀌는 변형(연관→결정, 귀속 삭제, "모든", 화면 숫자 읽기,
숫자 값 변경)은 계속 막혀야 한다. 오늘 이전 엔진(`4dcc041`)에 돌리면 첫 유료 실행이 막힌 바로 그 오류
(`rhetorical_exemption_invalid:SC01`)를 비용 0 으로 재현한다.

## 6. A 실측 후속 — 대사 고정 (2026-10-05, 운영자 결정 ①)

- **실측(Samsung, $0.32):** 기존 리포트 생성기가 V2 대본을 다시 썼다 — 14컷 중 V2 문장과 같은 컷 0개, 말하는 숫자
  2→5개, V2 에 없던 주주환원·피크아웃 문장 추가. 원 작업지시서 원칙("독립 검증자는 **최종 대본**을 대조"
  §9.4, "검증된 논리 밖의 새 이야기 금지" Phase 6)에 어긋난다 — 새 문장은 검증을 받지 않았다.
- **원인:** 논문 생성기의 컷 골격(`cut_skeleton`, 2026-08-29 리뷰 §6)은 "한 컷 = 한 문장"으로 **컷 개수·순서**를
  고정하지만 "문장을 다듬는 것은 허용"한다. 리포트 생성기에는 골격 자체가 없고 "흐름은 계승하되 다듬어라"고 지시한다.
- **조치(새 장치):** `cut_skeleton.lock_block` / `lock_narration`. 초안에 `narration_lock` 표시가 있을 때만
  ① 프롬프트에 "각 칸의 대사는 이 문장 글자 그대로" ② 모델 응답의 대사를 정규화 **앞**에서 골격 문장으로 덮어씀
  (화면 검사가 고정 대사로 돈다) ③ 컷 수가 다르면 `narration_lock_cut_count` 로 승인 차단. 표시는 V2 브리지만
  넣는다 — Production 초안에는 없어서 Production 프롬프트·동작은 그대로다(테스트로 고정).
- **남은 것:** Production 논문 생성기도 "다듬기 허용"이라 자기검증 이후 대사가 바뀔 수 있다 — V2 와 별개의
  Production 점검 거리.

## 7. C·E 후속 (2026-10-05)

- **E 원인:** 증권사 논리 단계 중 숫자 없는 설명·리스크 단계(Samsung 13단계 중 7개)에 숫자 근거 번호가 없다.
  그런데 그 단계들에도 원문 인용이 있고, Production 이 원문 전문과 대조해 `verified` 를 찍는다
  (`report_reasoning.audit`). Production 은 "근거 번호 또는 인용이 있으면 근거 있는 단계"로 세는데 V2 만
  숫자 근거 번호를 요구했다.
- **조치:** 인용이 확인된 단계를 근거로 싣는다(`evidence_pack._report_step_claims`, `quote_presence` 만 참 —
  뜻 일치는 Phase 7 독립 검증 몫). 확인 안 된 인용만 있는 단계는 여전히 근거 없음.
- **실데이터(무료 실행):** Samsung 논리 단위 5→13·리스크 장면 생김, Shipbuilding 2→15·리스크 3, NH(일부 원문) 3→3(상한 유지).
  근거 없는 단계 경고 0. → 리포트 C(리스크 누락)도 함께 해소.
- **논문 C 는 남는다:** 논문 Fact Sheet 의 연구 한계는 모델이 한국어로 요약한 문장이고 원문 인용이 없어 코드로
  대조할 수 없다. 선택지는 운영자 결정.
- **새로 드러난 것 — D(길이 판단)가 급해졌다:** 재료가 Samsung 890자·Shipbuilding 898자로 늘었다(기존 대본
  518자·42초). V2 에는 아직 "한 편에 무엇을 넣고 무엇을 뺄지" 고르는 단계가 없다. Phase 8 은 Production 계획만
  보고 대본 길이는 재지 않는다 → 80초 상한을 넘는 V2 대본이 나올 수 있다.

## 8. 운영자 지시와 후속 (2026-10-05)

> "너무 완벽할 필요는 없어. 우리는 논문을 읽어주는 사람이지 논문을 쓰는 사람이 아니야 … 일단 완성시키고 그다음에
> 조율. 지금은 논문 내용의 완결성보다 **영상 표현 자체의 개선**에 초점을 최우선으로." 그리고 "80초 상한은 없애".

- **80초 상한 제거:** `CONTENT_MODE_HARD_MAX_SEC` 기본 0(=없음, 엔진·웹 동기), 원문이 충분한 소스 정책도 0.
  얕은 원문(35·50초)은 유지. Production 프롬프트의 "80초를 넘기지 마라" 권고 문구는 그대로(게이트가 아니고,
  초안 프롬프트는 엣지 함수 쌍둥이가 있어 따로 정리).
- **D — 한 편에 담을 내용 고르기:** 핵심 흐름 → 결론 → 첫 리스크 논리 전체 → 나머지 순, 목표 520자
  (`V2_NARRATION_TARGET_CHARS`). 빠진 단위는 `excluded_reasoning_ids` 로 남는다. 실데이터(비용 0, 현실적 가짜 모델):
  Samsung 568자·Shipbuilding 526자 모두 끝까지 READY.
- **숫자 규칙 보정:** "조선 3사"·"4행정"·"8.6세대"처럼 단위 아닌 한글이 붙은 숫자는 이름(조사 제외),
  화면으로 보낸 숫자의 "약 N" 은 말에서 함께 빠져도 된다.
- **논문 C (가):** Fact Sheet 추출이 한계마다 원문 구절(`limitation_quotes`)을 함께 뽑고(파이썬·엣지 동시),
  `paper_evidence` 가 원문에서 찾아 `verified` 를 찍는다. V2 는 구절이 있는 한계만 한계 장면으로 넣는다 —
  기존 논문은 Fact Sheet 를 다시 뽑아야 한계가 들어간다.
