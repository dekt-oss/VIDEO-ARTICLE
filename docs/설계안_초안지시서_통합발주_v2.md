# 설계안 v2 — 초안·지시서를 **한 화면·한 발주·한 승인**으로 (2026-09-11)

v1(`설계안_초안지시서_통합발주_v1.md`)은 "발주만 합치고 화면은 둔다"였다. 운영자 결정:
> "화면까지 하나로 합쳐라."

이 문서는 v1 의 §2(초안에서 화풍 제거)·§3(큐 컬럼)·§4(워커가 초안 뒤 지시서를 잇는다)를
**그대로 포함**하고, 그 위에 화면 통합을 얹는다. **구현은 승인 뒤에 한다.**

---

## 0. 먼저 알아야 할 역사 — 이 화면은 한 번 합쳐져 있다가 나뉜 적이 있다

`web/app/review/[paperId]/page.tsx` 머리말과 `docs/deviation-flow-draft-to-directive.md`:

> "이전에는 ④ 초안 검수와 ⑤ 지시서가 한 화면에 세로로 이어붙어 있었다. 씬 수·컷 수에 비례해
> 페이지가 길어지고 저장 지점이 4개라 **'지금 눌러야 하는 버튼'이 화면 밖으로 사라졌다.**"

그래서 2026-08-19 에 `?step=4|5|6` 으로 나눴다(개선지시서 FLOW-01, 합격기준: "페이지 길이가
씬+컷 합산 길이가 되지 않음"). **그냥 다시 붙이면 그 문제가 그대로 돌아온다.**

이번 통합은 "세로로 붙이기"가 아니라 **결정 바 하나 + 두 칸 배치**다. 아래 §2 가 그 답이다.

## 1. 무엇이 어떻게 바뀌나 — 한 표

| | 지금 | v2 |
|---|---|---|
| 화면 | ④ 초안 · ⑤ 지시서 · ⑥ 렌더, `?step=` 으로 하나씩 | **작업 화면 하나.** 왼쪽 대본·근거, 오른쪽 컷. ⑥ 은 아래 접힌 패널 |
| 발주 | ④ [초안 생성] → 읽고 → [승인하고 ⑤ 만들기(버전 체크)] → 기다림 → ⑤ | **[초안+지시서 생성(버전 체크)]** 한 번. 초안이 끝나면 지시서가 이어서 자동 |
| 승인 | ④ 승인(대본 아카이브) 따로, ⑤ 승인(렌더 발주) 따로 | **[승인 → 렌더] 한 번** — 대본 확정 + 지시서 승인 + 렌더 발주를 한 확인창에서 |
| 저장 | 대본 · 씬 · 컷 각각(저장 지점 4개) | **[변경사항 저장] 하나** — 대본·씬·컷을 한 번에 |
| 초안 프롬프트 | 웹툰 화풍이 박혀 나옴 | 화풍 없음(코드가 렌더 때 붙인다). 기본 접힘 |
| 버튼 위치 | 페이지 끝 | **상단 고정 결정 바** — 스크롤과 무관하게 항상 보인다 |

## 2. 화면 설계

### 2-1. 배치 (데스크톱 ≥ 1200px)

```
┌──────────────────────────────────────────────────────────────────────────┐
│ 논문 제목                                                   ← 목록      │
│ ● 초안 ✓   ● 지시서 3D그래픽 ✓ / 만화식 —   ● 렌더 —        (상태 띠) │
├──────────────────────────────────────────────────────────────────────────┤
│ 결정 바(sticky top): ⛔근거없는 씬 0 · 컷 2   [변경사항 저장]  [승인 → 렌더 ▾] │
├────────────────────────────┬─────────────────────────────────────────────┤
│ 대본·근거 (옛 ④)           │ 지시서 (옛 ⑤)                              │
│  Fact Sheet (접힘)         │  [3D 그래픽] [만화식 · 미생성]  ← 버전 탭   │
│  대본 (편집)               │  헤더 · 차단/경고 요약                     │
│  씬 1…N (기본 접힘,         │  컷 1…M (기본 접힘, 근거없는 컷만 펼침)     │
│   근거없는 씬만 펼침)       │                                             │
│  ▸ 씬별 이미지 프롬프트(접힘)│                                             │
├────────────────────────────┴─────────────────────────────────────────────┤
│ ▸ 렌더 결과 (접힘 · 잡 N건)                              (옛 ⑥)         │
└──────────────────────────────────────────────────────────────────────────┘
```
- 두 칸은 **각자 스크롤**한다. 왼쪽에서 문장을 고치며 오른쪽 컷을 보는 것이 이 배치의 목적이다.
- 결정 바가 **화면 위에 붙어** 있으므로 FLOW-01 이 걱정한 "버튼이 화면 밖으로"가 생기지 않는다.
- 좁은 화면(< 1200px)은 두 칸을 **탭**([대본] [지시서])으로 바꾼다. 결정 바는 같다.

### 2-2. 결정 바 — 버튼 하나, 상태에 따라 이름이 바뀐다

| 상태 | 주 버튼 | 하는 일 |
|---|---|---|
| 초안 없음 | **[초안 + 지시서 생성 (N건)]** + 버전 체크 | `draft_requests.version_types` 로 발주. 진행: Fact Sheet → 대본 → 자기검증 → 지시서(버전별) |
| 초안 있음, 지시서 만드는 중 | (비활성) "지시서 만드는 중 · 3D 그래픽 1m 20s" | 폴링 |
| 초안·지시서 있음, 검수 필요 | **[승인 → 렌더]** | 한 확인창: 대본 확정(published) + 체크한 버전 지시서 승인 + 언어 선택 + 비용 → 렌더 잡 |
| 대본을 지시서 이후에 고쳐 저장함 | **[지시서 재생성]** (주) · [그대로 승인] (부) | 낡은 지시서 경고. 재생성이 기본, 그대로는 흔적 남김 |
| 지시서 승인됨/렌더 중 | **[렌더 결과 보기]** | 편집 잠금(지금과 같다) |
| 승인이 차단됨 | **[차단 사유 보기]** → 강제 승인(흔적) | 지금 ⑤ 의 2차 확인 그대로 |

▾ 메뉴(부차 동작): 초안 재생성(세부 요청 포함) · 지시서 재생성 · 대본만 아카이브 · 버전 추가 발주.

### 2-3. 승인 확인창 하나에 무엇을 보여주나
```
승인하면 렌더가 시작됩니다(비용 발생).
· 대본: 씬 7 · 근거 없는 씬 0 · 한국어 검수 통과
· 지시서(3D 그래픽): 컷 13 · 근거 없는 컷 2 · 예상 생성비 $2.4
· 차단: 없음  / ⛔ 있으면 사유 나열(강제 승인 체크)
· 렌더 언어: 한국어 + 영어
[승인하고 렌더 시작]
```
지금 ④ 확인창 + ⑤ 확인창의 내용을 합친 것이다. 빠지는 정보는 없다.

### 2-4. 저장 하나
`[변경사항 저장]` 이 대본(`script_md`)·씬(`video_prompts`)·컷(`cuts`)을 순서대로 저장한다.
하나라도 실패하면 어느 것이 실패했는지 말하고 나머지는 저장된 채 둔다. 미저장 이탈 방지는
지금의 `UnsavedGuard` 를 하나로 합쳐 쓴다.

### 2-5. URL
- `/review/[id]` 가 곧 작업 화면. `?step=4`·`?step=5` 는 **그대로 열리되** 같은 화면(왼쪽/오른쪽
  칸으로 스크롤 위치만 이동). `?step=6` 은 렌더 패널을 펼친 채 연다. 홈 카드·목록 링크가 전부 이
  주소를 쓰므로 깨지지 않는다.
- `?v=` 는 오른쪽 버전 탭 선택으로 그대로.

## 4. 코드 구조 — 새로 짜지 않고 **재배치**한다

| 새 컴포넌트 | 어디서 오나 |
|---|---|
| `WorkspaceClient` | 페이지 한 장의 상태 주인: dirty 집계 · 결정 바 · 확인창 · 폴링 두 개(초안·지시서) |
| `ScriptPane` | `ReviewClient` 의 본문(Fact Sheet·대본·씬·다듬기 배지)을 떼어낸 것. 승인/발주 버튼은 뺀다 |
| `CutsPane` | `DirectiveClient` 의 본문(헤더·컷·차단 요약)을 떼어낸 것. 버전 탭은 상위가 준다 |
| `DecisionBar` | 새로 만든다(§2-2). `VersionOrderBar` 의 발주 로직·`orderCost` 를 가져온다 |
| `RenderPanel` | `RenderList` 를 접힌 `<details>` 에 넣은 것 |

`ReviewClient`·`DirectiveClient` 는 **당분간 남긴다**(다른 진입점이 없는지 확인한 뒤 지운다 —
`grep` 으로 호출부 0 이 되면). 페이지 파일은 데이터 로딩을 그대로 두고 `WorkspaceClient` 하나만
렌더한다.

### API 는 거의 그대로
- `/api/generate-draft` — `version_types` 받음(추가)
- `/api/approve` + `/api/directive-approve` — 결정 바가 **순서대로** 부른다(대본 아카이브 → 지시서 승인).
  두 라우트를 합치지 않는다 — 각자 게이트(운영자 키·차단 재계산·강제 흔적)를 갖고 있고 그대로 유효하다.
- `/api/draft-status` — `directive` 필드 추가.

## 5. 리포트 공장

같은 설계를 `/finance/review/[id]` 에도 적용한다(CLAUDE.md: 두 공장 동일). 컴포넌트가 이미 짝으로
있다(`ReportReviewClient`·`ReportDirectiveClient`·`ReportRenderList`). **순서**: 논문 공장을 먼저
만들어 운영자가 실물로 보고, 그 배치를 확정한 뒤 리포트에 같은 `WorkspaceClient` 를 얹는다
(리포트는 `validated_script_hash`·컴플라이언스 게이트가 더 있어 결정 바 항목이 두어 개 는다).

## 6. 위험과 대응

| 위험 | 대응 |
|---|---|
| 페이지가 다시 길어져 버튼이 사라진다(FLOW-01 재발) | 결정 바 sticky top · 두 칸 각자 스크롤 · 씬/컷 기본 접힘 · ⑥ 접힘. 합격기준을 그대로 다시 쓴다: "결정 바가 스크롤과 무관하게 보인다" |
| 대본을 고쳤는데 옛 지시서로 렌더한다 | `drafts.updated_at > directives.created_at` 이면 주 버튼이 [지시서 재생성]으로 바뀌고 [그대로 승인]은 흔적을 남긴다 |
| 승인 한 번이 두 가지를 하는데 하나만 성공한다 | 대본 아카이브 → 지시서 승인 순서. 뒤가 실패하면 "대본은 확정됐고 렌더는 안 나갔다"를 그대로 말하고 다시 누르게 한다(지금 ④ 의 실패 의미론과 같다) |
| 버전을 여러 개 체크해 비용이 는다 | 기본 만화식 1건(CLAUDE.md 결정 유지). 확인창에 버전별 비용 합계 |
| 두 공장이 어긋난다 | 논문 먼저 → 실물 판정 → 리포트 |
