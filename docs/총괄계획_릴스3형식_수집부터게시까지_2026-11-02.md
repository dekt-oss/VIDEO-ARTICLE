## 0. 한눈에 보기

```
[매일 자동]  ① 수집 ─ 소재 후보(질문·이슈·밈) + 형식 추천(설명형/카드뉴스/밈)
                │
[사람 1]     ② 소재 고르기 ─ 후보 카드에서 [이걸로] + 형식 확정            ← 버튼 1번
                │
[자동]       ③ 내용 초안 ─ 근거(원문 인용) → 대본 → 장면 지시서 → 견적
                │           (Apify: 같은 주제 인기 릴스의 길이·훅 참고 / 밈은 원본 영상 형식 분석)
[사람 2]     ④ 내용 승인 ─ 근거표·대본·장면 지시서·금액을 한 화면에서 [승인]   ← 버튼 1번
                │
[자동]       ⑤ 제작 ─ 설명형: 결재 금액 안에서 영상 클립 구매 → 조립
                │      카드뉴스·밈: 로컬 렌더(0원)
                │      → 자동 검사(규격·길이·정지·사진 대체 0·안전 영역)
[사람 3]     ⑥ 게시 승인 ─ 완성본 보고 품질 체크 + 캡션 + 음원 + 게시 시각 [예약]  ← 버튼 1번
                │
[자동]       ⑦ 예약 게시 → ⑧ 성과 수집(24시간·72시간·7일) → ⑨ 다음 편성 제안(주 1회)
```

- 사람이 누르는 곳은 **세 번**이다: 소재 고르기, 내용 승인, 게시 승인.
- 설명형만 한 번 더 있다. 훅 장면(도해)은 후보 2개를 사서 **사람이 하나를 고른다**(기획 v2 §3-3 — 자동 점수로 고르지 않는다).
- 돈이 나가는 자리는 정해져 있다: ③ 대본 초안(한 편 약 $0.1), ③ Apify 조사(한 편 $0.01~0.03), ⑤ 설명형 영상 구매(한 편 약 $8), ⑤ 밈 반응 장면(한 장면 약 $0.45). 나머지는 0원이다.

## 2. 소재 수집 — 형식마다 무엇을 어디서 모으나

**원칙: 후보는 하나의 풀(pool)로 모으고, 후보마다 코드가 형식을 추천한다.** 운영자는 고를 때 형식을 바꿀 수 있다.

| 형식 | 좋은 소재 | 어디서 | 주기 | 상태 |
|---|---|---|---|---|
| **설명형** | "왜 그런가"가 있는 질문 — 고도주는 왜 안 상하나, 막걸리는 왜 트림이 나나 | 커뮤니티·SNS 질문 발견(기존), 커뮤니티 언급(기존), 운영자 링크 | 매일 06:30 | 있음 |
| **카드뉴스** | 저장해 둘 정보 — 비교·보관법·체크리스트·세금·규제·신제품 소식 | 같은 질문 발견 + 주류 뉴스 이슈(기존) | 매일 06:30 | 있음 |
| **밈형** | 지금 인스타에서 도는 형식 — 인기 음원, 관찰 계정의 뜨는 릴스 | 트렌드 보드: T1 인기 음원(공식 API), T2 관찰 계정(공식 API), T3 운영자 링크 | 매일 07:30 | **새로 만든다** |

**형식 추천 규칙(코드, 0원)** — 처음 값이고 운영자 선택 기록으로 고친다.
- 설명형: 질문 유형이 "왜/원리"이고, 승인된 수집원에서 근거가 2개 이상 잡힌 후보. 근거가 40초 분량에 못 미칠 것 같으면 카드뉴스로 내린다.
- 카드뉴스: 비교·보관·선택·이슈 유형. 근거 1개 이상.
- 밈형: 트렌드 보드의 밈 카드(근거가 필요 없는 농담이 기본. 정보 주장이 들어가면 근거 규칙을 그대로 탄다).

**하지 않는 것:** 인스타 해시태그 검색 상시 수집(앱 심사 필요), 개인 계정 수집, 남의 영상 저장·재게시.

## 3. Apify 로 강화하는 것 — "사실"이 아니라 "형식"을 강화한다

대본의 사실은 **원문 근거에서만** 나온다(Fact Sheet 규칙). Apify 는 사실 근거로 쓰지 않는다.
Apify 가 메우는 것은 공식 API 로는 볼 수 없는 **남의 릴스의 길이·편집·영상 자체**다. 그래서 쓰는 자리는 둘이다.

| 자리 | 언제 | 무엇을 하나 | 한 번 비용 | 결과가 들어가는 곳 |
|---|---|---|---|---|
| **A. 설명형 형식 참고** | ③ 내용 초안을 만들 때, 소재 하나에 1회 | 그 주제의 해시태그(예: #위스키) 인기 릴스 10개의 길이·첫 화면 글자·컷 수를 잰다 | 약 $0.03 | 장면 지시서 옆 "같은 주제 인기 릴스: 가운데값 N초, 첫 화면 훅 예시" 참고 칸 |
| **B. 밈 틀 정밀화** | 운영자가 밈 카드에 [쓰자]를 누를 때 | 공식 API 가 고른 그 릴스 1~3개의 영상을 받아 비트 수·컷 길이·반전 시점·글 위치를 재고, **바로 지운다** | 릴스 3개 약 $0.01 + 영상 분석비 | 밈 카드가 "참고 카드"에서 "정밀 틀"로 승격(기획 v2 §6-5) → 밈 엔진 입력 |

- B 가 핵심이다. 공식 API(Business Discovery)는 남의 릴스 영상을 주지 않는다. 그래서 지금 설계로는 운영자가 원본을 보고 칸을 손으로 채워야만 정밀 틀이 됐다. B 는 그 손 작업을 대신한다.
- **한 달 예상:** 설명형 8편 × $0.03 + 밈 [쓰자] 20장 × $0.01 = 약 **$0.45**. Apify 무료 크레딧(월 $5) 안이다. 유료 플랜(Starter $19/월)은 필요 없다.
- **지켜 온 규칙은 그대로다:** 실행마다 금액 상한(`maxTotalChargeUsd`) · 남의 영상은 분석 뒤 삭제, 우리 저장소에 넣지 않음 · 입력은 공식 API 가 고른 주소·해시태그만.
- **시험에서 배운 것을 반영한다:** 술 브랜드·판매 계정은 18세 연령 제한으로 막힌다(막혀도 돈이 나간다). 그래서 계정마다 릴스 1개를 먼저 보내 막힘을 확인하고, 막힌 계정은 목록에서 뺀다. 해시태그 결과는 대부분 오래된 인기물이라 "지금 뜨는 것" 발견에는 쓰지 않는다.
- **바뀐 원칙 하나(2026-11-02 승인, §7 결정 1):** "**월 상한 $3 안에서, 운영자의 [이걸로]·[쓰자] 클릭을 그 1회 실행의 승인으로 본다.**" 실행 상한은 A $0.05, B $0.02다. 클릭 없이 도는 정기 수집은 여전히 하지 않는다. 기획 v2 §6-1 에 반영했고, 코드가 없으므로 개발 전에는 작동하지 않는다.
- **하지 않는 것:** 댓글 수집(개인 정보 성격, 승인 범위 밖), 매일 정기 수집, 술 계정 숫자 조사(공식 API 로 본다).

### 4-3. 밈형 — 트렌드 보드부터 새로 만든다

| 항목 | 내용 |
|---|---|
| 길이 | 6~15초. 시험 2 실측 가운데값 13초. |
| 화면 틀 3종 (시험 2 실측) | ① 검은 바탕 위쪽 글 한 줄 + 가운데 가로 장면(인기 24편 중 12편) ② 세로 꽉 찬 장면 + 크고 굵은 제목, 핵심 낱말 강조색(7편) ③ 글 없는 세로 장면(5편). 우리는 ①②부터 만든다 — 글은 코드가 그리고, 장면은 글만 + 배경(0원) 또는 우리가 산 짧은 반응 장면(약 $0.45). 남의 장면은 쓰지 않는다. |

| 새로 만드는 것 | 트렌드 보드 수집(T1·T2·T3, 수집 상태 5종), 밈 보드 화면([쓰자]/[넘기기]/[나중에]), 형식 분석(Apify B + 영상 분석 모델), 밈 틀 엔진(틀 → 글 → 렌더) |
| 한 편 비용 | 글만: 0원 / 반응 장면 1개: 약 $0.45 |

## 7. 사장님이 정할 것

**결정 1 — Apify 자동 실행 범위. → 확정(2026-11-02, 운영자 "그렇게 해").**
월 상한 $3 안에서, [이걸로](설명형 형식 참고)와 [쓰자](밈 틀 정밀화) 클릭을 승인으로 본다. 정기 수집은 하지 않는다.

**결정 2 — 내용 승인을 한 번으로 합칠지. → 확정(2026-11-02, 운영자 "한 번으로 합쳐").**
근거·대본·지시서·견적을 이어서 만들고 한 화면에서 한 번 승인한다. 근거가 틀렸으면 그 뒤에 만든 대본 초안 값(한 편 $0.1 미만, 1단계 실측은 소재 2편에 근거+대본 합계 $0.22)을 버린다.

구현 조건(코드 대조 결과 — 화면만 합쳐서는 안 된다):
- **DB 규칙을 바꿔야 한다.** 지금 DB 는 승인된 근거가 없으면 대본 초안 요청을 거부한다(`review_not_approved`, `0060_drinks_develop.sql:261`·`:265`·`:341`). 승인 전 근거 초안으로 대본을 만들 수 있게 새 마이그레이션이 필요하고, 운영 적용은 결재 대상이다.
- **안전 장치는 약해지지 않는다.** 승인 전 대본은 초안일 뿐이고 제작·지출로 넘어갈 수 없다. [승인] 한 번이 근거와 제작안을 **한 트랜잭션으로** 승인하며, 둘 중 하나라도 무효면 둘 다 승인되지 않는다.
- **승인 화면에서 근거를 고치면** 그 근거로 만든 대본은 무효가 된다. 대본을 다시 만든 뒤에야 승인할 수 있다.
- **사람이 하던 일이 화면으로 옮겨 온다.** 핵심 메시지 한 줄과 주장별 뒷받침 확인(`support_review`)은 지금 근거 승인 때 운영자가 채운다. 핵심 메시지는 초안을 미리 채워 주되, 근거표 확인은 자동으로 대신하지 않는다.
- 편성 단계는 [이걸로]에 포함한다. 이어 만들기 중 어디서 막히면(근거 부족·대본 검사 차단) 거기서 멈추고 이유를 화면에 띄운다.

**결정 3 — 첫 달 발행 속도. → 확정(2026-11-02, 운영자 "제안대로 해").**
카드뉴스 주 5 · 밈 주 3 · 설명형 주 1~2(월 약 $60, 추정).
- 이 값은 **목표 속도**이지 지출 승인이 아니다. 설명형 영상 구매는 편마다 내용 승인 화면에서 금액을 결재한다.
- 첫 달은 각 형식이 합격 기준을 통과한 날부터 센다. 설명형은 첫 편이 품질 판정 6항목을 통과하기 전에는 두 번째 편을 사지 않는다.

**결정 4 — 밈 가짜 카드 구성. → 확정(2026-11-02, 운영자 "그렇게 바꿔").**
분위기 음원 4장 · 박자 맞춤 1장 · 정보 포함 1장(종전 3 · 2 · 1). 근거는 시험 2 실측이다 — 인기 밈 24편 중 22편이 원본 소리여서 박자 맞춤 밈은 드물다. 박자 맞춤 밈의 자동 게시 차단 확인은 1장으로 그대로 한다.
