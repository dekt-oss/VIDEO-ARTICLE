# 주류 제작 흐름 단순화 — 계획 (2026-11-17)

## 운영자 지시 (원문 요지)
"소재 → 내가 승인과 종류 선택 → 초안 생성(장면별 구성과 대략적인 시나리오) → 초안 승인 또는 수정 → 장면별 세부 작업지시서 → 최종 승인 또는 수정 → 산출물 확인 후 게시 혹은 예약 게시. 이렇게 흐름을 단순화하고, 그 과정에서 내가 버튼 하나 눌러서 승인되도록 하라. 수정해야 하는 경우는 그냥 바로 수정하거나, 수정 방향을 입력할 수 있게 하라. 막힌 이유를 나한테 보여 주고 끝내지 마라. 뭘 어떻게 막혔으니 어떻게 고치겠다가 있어야 한다. 같은 요청을 몇 번째 하는지 아느냐. 코덱스와 리뷰를 주고받으며 제대로 하라."

## 지금 실제로 무엇이 문제인가 (코드로 확인함)
1. **단순화한 화면(스튜디오)이 이미 있는데 운영자가 그 화면으로 못 간다.**
   메뉴 "만들기"(`web/lib/nav.ts:70`)는 옛 목록 `/drinks/work`로 간다. 그 목록과 홈의 [다음 할 일] 버튼이 `workHref(it, panel)`로 `?panel=` 을 붙인다. 그런데 `/drinks/work/[id]`는 `!sp.panel && !sp.plan` 일 때만 스튜디오로 넘긴다(`web/app/drinks/work/[topicId]/page.tsx:60`). 그래서 운영자는 늘 옛 8단계 화면(초안·근거·대본승인·결재·구매·판정…)에 떨어진다.
2. **옛 목록은 막힌 이유를 내부 코드로 보여 준다.** 예: "개발 요청(evidence)이 blocked: evidence_off_topic". 무엇을 하면 되는지가 없다.
3. **장면 글을 바로 고칠 길이 없다.** 스튜디오는 11-08에 직접 편집을 지우고 [코멘트대로 다시 만들기](대본 전체 재작성, 유료)만 남겼다. 옛 직접 편집(`drinks_save_plan`)은 근거가 승인된 소재에서만 저장된다. 그래서 1번 장면 한 줄을 바꾸려 해도 대본 전체를 다시 쓰고, 다른 장면까지 바뀐다(11-15 위스키 소재 실측).
4. **릴스 만드는 방식 기본값이 서버에서 '영상 클립(omni)'이다.**
   `drinks_explainer_request_plan` 이 provider 를 안 받으면 `'omni'`(`0067:253`). 스튜디오는 clay 를 보내지만 옛 화면은 안 보낸다. 그래서 '막걸리, 어떻게 만들어지고…' 편이 omni 로 만들어졌고, omni 전용 검사(훅 자막 한 줄)에 걸려 지시서가 실패했다(`hook_text_overflow`). 한 번 정한 방식은 바꿀 수 없다(`drink_explainer_episodes_guard`).
5. **지시서 단계에서 막히면 원문 오류가 그대로 뜬다**(`ex.episode.last_message`). 고치는 버튼이 없다.

## 할 일
### A. 길을 하나로 (화면만)
- `workHref`: 릴스·카드뉴스는 **언제나** `/drinks/studio?topic=&lane=` 로. 밈만 옛 작업공간.
- `/drinks/work/[id]`: `?detail=1` 이 아니면 전부 스튜디오로 넘긴다(panel·plan 이 있어도).
- 메뉴 "만들기": `/drinks/studio?tab=mine`(스튜디오의 '내 소재' 탭) — 목록 화면 `/drinks/work` 는 같은 곳으로 넘긴다. 홈 요약 타일 링크도 바꾼다.
- 스튜디오 하단 [자세히 보기(근거·이력)]만 옛 화면을 연다.

### B. 장면 바로 고치기 (DB 함수 1개 + 화면)
- 새 마이그레이션 `0087_drinks_studio_edit_scene.sql`: `drinks_studio_edit_scene(p)` — `plan_revision_id, expected_version, n, field, text`.
  - field: 릴스 `narration`, 카드뉴스 `heading`·`body`. 글 2~400자.
  - 작성 중 초안(근거 승인 전·후 모두): 그 자리에서 고친다. `drinks_validate_plan` 을 그대로 지난다. 버전 충돌 검사.
  - 승인된 초안(지시서 단계): **새 작성 중 초안**을 만든다(옛 승인본·지시서는 그대로 기록에 남는다). 이미 돈을 쓰기 시작한 편(구매 이후 상태)이면 막는다. 같은 결과물에 작성 중 초안이 이미 있으면 그것을 고치라고 막는다.
  - 근거에 없는 숫자 검사는 지금처럼 승인 때(`drinks_studio_approve_draft`) 돈다.
- 스튜디오 ②·③ 장면 카드에 [고치기] → 글 칸 → [저장](0원). ③에서 고치면 ②로 돌아가 [이 초안 승인] 한 번이면 지시서를 다시 만든다.

### C. 만드는 방식 기본값과 바꾸기 (DB)
- 같은 마이그레이션에서 `drinks_explainer_request_plan` 기본값을 `'clay'` 로.
- 지시서가 아직 없는(plan_draft) 편은 방식을 바꿀 수 있게 가드를 푼다. 돈은 아직 0이다.

### D. 막혔을 때: 무엇이 / 어떻게 고치겠다 / 버튼 하나
- 지시서 단계 실패: 원문 오류 대신 쉬운 말 + 처방 버튼.
  - omni 편이 막힘 → "영상 클립 방식 검사에 걸렸어요. 사진클레이로 바꿔 다시 만들게요(0원)" [사진클레이로 다시 만들기].
  - 대본 검사 실패(대본 내용 문제) → "N번 장면이 …라서 막혔어요" + 그 장면 [고치기] / [코멘트로 다시 쓰기].
- 근거 막힘(evidence_off_topic·insufficient): 스튜디오 막힘 화면에 #182 의 해결안(질문 좁히기)을 그대로 보여 주고 [해결안 적용하고 다시 만들기] 한 번. 해결안이 없을 때만 "다른 소재 고르기".
- 내 소재 목록·홈의 막힘 문구: 코드명 대신 쉬운 말(무엇이 막혔고 무엇을 누르면 되는지).

### E. 운영 데이터 정리 (배포 후, 0원)
- '막걸리, 어떻게 만들어지고…' 편: 사진클레이로 바꿔 지시서 다시 만들기.

## 안 하는 것
- 승인·결재 규칙(DB 검사)은 하나도 풀지 않는다. 화면이 순서를 묶을 뿐이다.
- 밈 흐름, 카드 릴스 동시 게시, 옛 상세 화면 제거.

## 검증
- 단위: `workHref`·리다이렉트, `decision`/`studio` 순수 함수 테스트, 새 SQL 함수는 `web/lib/drinks/*.db.test.ts` 하네스(로컬 Postgres)로 — 작성 중 수정·승인본에서 새 초안·구매 후 거부·버전 충돌·provider 전환.
- `npm run lint && npm run build`, `pytest` 전체.
- 운영: 배포 후 운영 DB 에 0087 적용 → 막걸리 편 정리 → 화면 확인은 운영자 키가 필요해서 운영자에게 확인 순서를 드린다.

## 코덱스 리뷰 기록
- **계획 리뷰(1차)**: High 4 · Medium 3. 반영 — 승인본을 고친 새 초안이 시각 주장표를 이어 쓰게(`drinks_plan_visual_claims`), 새 초안을 만들면 옛 승인본을 막아 제작에 못 쓰게, 지시서 작업이 도는 중에는 방식 전환 거부, `?plan=` 링크(옛 제작안 이력)는 옛 화면 유지, 해결안을 상태에 싣기. 직접 고친 글은 Jev(AI 검토)를 다시 거치지 않는다 — 지시서를 만들 때 대본 코드 검사(`plan_problems`)와 승인 때 숫자 검사만 다시 돈다(화면에 적어 둠).
- **코드 리뷰(2차)**: P2 5건 — 잠금 순서(topic → plan 으로 통일), 승인된 카드 편집 버튼, 복구 링크 `?detail=1`, 한 장의 칸을 한 번에 저장(반쪽 저장 없음), 시각 주장표 주인을 직접 적어 깊이 한도 없앰. 전부 반영.
- **재검사(3차)**: 5건 해결 판정. 새 P1 — 저장 안 한 글로 [승인하고 제작]이 눌림 → 편집기가 열려 있으면 승인·제작 버튼 잠금.
- 남은 미검증: 실제 Postgres 두 세션 동시 실행(PGlite 는 단일 세션), 브라우저 클릭 경로.
