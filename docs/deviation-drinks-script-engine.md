# 주류 대본·화면 엔진 — 1단계(무료): 코드 검사 · 2026-10-27

## 결정(운영자)

- 2026-10-26: "대본을 단순 수정하기보다 대본이 저렇게 나오고 화면이 구성되는 엔진 자체를 개선해야 하는 거 아니야?" → 예.
- 같은 날: "응 무료부터 진행해." → 돈이 들지 않는 부분(코드 검사·회귀 시험·연결)만 했다. LLM 대본 생성·화면 계획·Jev 는 다음 결재.

## 왜

주류 공장에는 대본 엔진이 없었다. 근거 승인 → **사람이 제작안(대본+화면) 손작성** → 렌더. 시험에서 제작자(Claude)가 쓴 대본이
원문을 넘었고(원문에 없는 처방 "30ml에 물 세 티스푼", 계산 근거, 근거 없는 "~해 보세요", 질문과 답의 어긋남), 막는 장치가 없었다.
논문 공장의 불변식(대본은 근거에 있는 것만)이 주류에는 코드로 걸려 있지 않았다.

인용 원문에 없는 숫자 · 인용 원문에 없는 양(티스푼·ml·방울·잔…) · 근거 없는 권고 · 그림 지시문 없음 · 잘못된 이어 그리기 ·
그림에 글자 요구 · 근거 없는 '시청자 결론'.
알림: 문어체 · 첫 질문 없음 · '시청자 결론' 없음 · 긴 문장 · 긴 자막 줄 · 잠긴 화풍과 싸우는 어휘.
화풍·글자 판정은 엔진 실사형 검사(`photo_contract._TEXT_REQUEST`·`_QUOTED_LABEL`·`_RENDER_STYLE_RE`)를 그대로 쓴다.

## 한계(정직하게)

- 문장 **뜻**의 비약(v1 "한두 방울 → 45% 아래로")은 코드가 못 본다 — Jev 근거 판정과 사람 대조표 몫.
- DB 근거 묶음의 주장 종류가 4개(product_fact·process·comparison·opinion)뿐이라 '실제 습관·권고' 종류가 없다 →
  DB 제작안의 권고 문장은 지금 전부 막힌다(안전한 쪽). 종류를 늘리려면 0050 근거 묶음 검사를 다시 정의해야 한다.
- 제작안 저장(0054 `drinks_validate_plan`)은 `viewer_conclusion` 을 아직 보존하지 않는다 → DB 제작안은 '결론 없음' 알림만 뜬다.
- 숫자 일치는 문자열 비교다(59 ↔ "60% 가까이"도 막는다). 바꿔 말한 수치는 원문 숫자를 그대로 쓰게 한다.

## 2단계(무료) — 엔진 실사형 화면 규칙 도입 · 2026-10-27

운영자: "세 화면이 너무 떡같은데?? 기존 엔진에서 보고 배운 게 이런 거니??" → "응 기존 엔진 규칙 도입해줘".
위스키 1단계 3장($0.402)은 제작자 손 지시문이었다 — 엔진에서 가져온 것은 화풍 문구 하나뿐.

- `engine/drinks_screen.py`: 주류 장면 → 엔진 컷(answers_ko·staging_ko·mechanism·visual_role) → **엔진 자동 보정**
  (`normalize_optics/style_words/glow/prompt_labels/prompt_numbers`) → **엔진 게이트** `photo_contract.evaluate` (Jev 끔 = 0원).
  쇼츠에 안 맞는 길이 규칙(컷 8개 이상·영상 컷 수·Fact Sheet 원리 공급량)은 뺀다(`NOT_FOR_SHORTS`).
- 대본 검사(`drinks_script_check.check`)가 이 게이트의 막힘·알림을 함께 낸다 → 주문서·구매·유료 렌더 전에 막힌다.
- 그림 주문(`drinks_paid.image_item`)이 엔진 컷을 그대로 싣는다 → 엔진 그림 프롬프트가 도해 구조를 읽어
  "A·B·C 가 한 장면에 다 보이고 X 가 설명 대상"과 이어 그리기의 "바뀌는 것"을 붙인다.
- 제작안 저장(0054 `drinks_validate_plan`)이 `answers_ko`·`staging_ko`·`mechanism` 을 보존한다.
- 상표 문구를 긍정 묘사로 바꿨다(옛 "plain blank paper labels … no logos" 가 잔의 빈 라벨·빈 상자를 불렀다 — 엔진 교훈 "부정어로는 못 막는다").

**검증:** 위스키 v5(산 그림의 화면 계획)는 대본 문장은 통과하지만 엔진 게이트가 `photo_mechanism_spec_missing`(장면 3·4·5)로 막는다 —
산 그림이 실패한 원인 그대로다. v6(엔진 규칙으로 다시 짠 화면: 16자 훅, 장면마다 답하는 질문·연출, 3번은 알아볼 실사 "이탄 연기 위 보리",
4·5번 도해는 부품·강조·3색 구조)은 통과한다. 1단계 주문서 $0.307(실사 1 + 도해 2).

**아직:** 엔진의 Jev 화면 판정(장면이 답하나·부품을 알아보나·밋밋한가·원인이 보이나)은 돈이 들어(한 편 1센트 미만) 돌리지 않았다.
