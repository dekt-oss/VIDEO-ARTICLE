# 기획 — 리포트 영상 '모션그래픽' 방식 엔진화 (v1, 승인 대기)

> 2026-11-24 · 운영자 지시: "하이퍼프레임 활용해서 이런 식으로 만드는 체계가 좋다 — 리포트 영상도 이렇게 만들도록 엔진 수정".
> 근거 작업: 삼성증권 자동차 2027 리포트로 손으로 만든 3편(메인·중고차·중국차, `content_samsung_auto_2027/`).
> 상태: **설계안. 코드 아직 안 바꿈.** 운영자 승인 → (코덱스 계획 리뷰) → 구현.

## 1. 한 줄 목표
리포트 지시서 승인 → **그림 생성 API 없이(렌더 0원)** HTML 모션그래픽 + Edge 현수 내레이션 + 자막·효과음·배경음악으로
1080×1920 쇼츠를 자동으로 뽑는다. 기존 방식(photo·comic)은 그대로 남겨 고를 수 있게 한다.

## 2. 왜 이 방식인가 (손으로 만든 3편에서 확인된 것)
| | 지금(photo/comic) | 모션그래픽 |
|---|---|---|
| 그림 비용 | 장당 이미지·영상 API 비용 | **0원** (로컬/워커 렌더) |
| 숫자 정확도 | 그림이 숫자를 틀리게 그릴 수 있음 | 숫자는 **텍스트로 찍힘** → Fact Sheet 값 그대로 |
| 출처·전망 꼬리표 | 오버레이로 덧붙임 | 장면 안에 "자료: p8", "(전망)" 고정 |
| 일관성 | 컷마다 화풍 흔들림 | 같은 템플릿·색·글꼴 |

## 3. 핵심 설계 — "LLM은 템플릿을 고르고 칸만 채운다"
자유 HTML을 LLM에게 쓰게 하지 않는다(깨짐·환각 위험). 대신 **검증된 장면 템플릿 묶음**을 엔진에 두고,
지시서의 각 컷이 `template` 하나와 `slots`(글자·숫자)만 고른다.

### 3-1. 장면 템플릿 1차 목록 (3편에서 실제 쓴 것)
| 템플릿 | 쓰임 | 예 |
|---|---|---|
| `hook_number` | 큰 숫자 카운트업 + 칩 + 도장 | 164조 / NEUTRAL |
| `bar_compare` | 막대 2~4개 (값 표기 or 상대 높이만) | 74.5조 vs 164조, 모델Y 그래프 |
| `vs_split` | 좌우 대비 카드 | 완성차 부담 vs 계열사 기회 |
| `icon_ratio` | 아이콘 N개 vs M개 (1개=단위) | BYD 5명 vs 현대 1명 |
| `card_stack` | 체크 카드 2~4장 순서대로 | 튼튼함·잔고장·오래 감 |
| `strike_vs_fact` | 줄 그은 오해 → 실제 | ~~이익~~ → 산업 패권 |
| `flow_chain` | A → B → C 사슬 | 부품 → 핵심부품 → 완성차 |
| `cycle3` | 3단 순환 (악순환) | 중고값↓→판매↓→신차값↓ |
| `scale_tilt` | 저울 기울기 | 내구성 → 업데이트 |
| `stamp_card` | 도장 + 정보 카드 | 전망 · 실적 아님 |
| `end_card` | 출처(리포트 제목·날짜·작성자)·투자 권유 아님 | **고정, LLM이 못 바꿈** |

### 3-2. 지시서 컷 스키마(추가분)
```json
{ "cut_no": 3, "narration_ko": "...", "source_facts": ["F12"],
  "motion": { "template": "bar_compare",
              "slots": { "title": "...", "items": [{"label":"지난 5년","value":"74.5조"},{"label":"앞으로","value":"164조"}],
                         "badge": "2.2배", "source": "p17" },
              "cue_words": ["2.2배", "앞으로"] } }
```
- `cue_words`: 내레이션 속 낱말. 그 낱말이 **들리는 순간** 애니메이션이 터진다(Edge TTS 단어 시각 사용 — 손작업 때의 글자 비례 추정보다 정확).
- **숫자 검문(코드)**: `slots` 안의 숫자는 그 컷 `source_facts` 가 가리키는 Fact Sheet 값에 있어야 한다. 없으면 그 칸을 비우고 경고(fail-open, 차단 안 함 — 기존 원칙).
- `source` 쪽수는 Fact Sheet `source_page` 로 확인된 것만(지어낸 쪽수 금지 규칙 그대로).

## 5. 단계 (끝까지 이어서 진행, 돈·공개만 끝에 모아 묻기)
1. **M1 템플릿·렌더 모듈** — 손으로 만든 중고차 편을 지시서 JSON 으로 옮겨 엔진이 **같은 영상을 재현**하는지(로컬, 0원). 템플릿별 골든 테스트.
2. **M2 지시서** — motion 프롬프트·정규화·숫자 검문. 기존 리포트 1편으로 지시서 생성(LLM 1회, 약 $0.1 수준) → 렌더 → 눈으로 확인.
3. **M3 워커·대시보드** — 워크플로 설치 단계, 버전 선택지, 기본값.
4. **M4(선택)** — VS 공식 썸네일 자동 생성, 업로드 예약(`publishAt`, 업로드 때 함께 넣기).

## 7. 위험과 대응
- 템플릿에 안 맞는 내용 → LLM이 가장 가까운 템플릿 + `card_stack` 폴백. 장면이 단조로워질 수 있음 → 템플릿을 늘려 대응.
- 워커 렌더 시간: 70초 영상 기준 로컬 약 2~4분. GitHub Actions 무료 분 안.
- `npx` 네트워크 설치 실패 → 버전 고정 + 캐시. 실패 시 잡 `failed` + 사유 기록.
- 화풍 고정 테스트(`test_photo_style_is_locked`)는 photo 전용이라 건드리지 않음.
