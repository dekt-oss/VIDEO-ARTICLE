# 째리의 술 수업 엔진 구현 계획

> 상태: 계획 검토 중. 기준: `docs/핸드오프_째리의술수업_엔진_2026-11-26.md`, `assets/templates/jjeri-class/README.md`.

## 목표와 경계
샘플 편 지시서에서 정답 화면과 시간표를 재현하고, 승인된 주류 근거로 새 편을 만들어 같은 엔진에 연결한다. 기존 리포트 motion의 1.2배속과 동작은 유지한다. 그림·영상 생성 API, 가격 표시, 게시·크론 실행, 원격 마이그레이션 적용은 범위 밖이다. 유료 LLM 실호출은 별도 명시 승인 전 금지. M6 소유자 판정과 운영 화면 검증은 실행 환경과 소유자 확인을 각각 요구한다.

## 변경 위치와 인터페이스
- `engine/motion/jjeri_class/` 신규: 정규화·검증, 템플릿 12종과 아이콘 등록, 시간표·오디오·HyperFrames 조립. 외부 진입점은 `render(episode, work_dir, *, voice_assets=None) -> {mp4, duration, timeline, warnings}`. 정답 재현용 음성은 명시적으로 주입하며 운영 경로의 근거 게이트를 우회하지 않는다.
- `engine/config.py`: 주류 전용 음성·시간·음량 상수; 공용 도구 분리는 리포트 회귀 검사 후에만 한다.
- `engine/drinks_script_check.py` 및 새 지시서 생성 모듈: beat 및 화면 문구별 근거 연결, 출처 메타에서 출처 칩 생성. 자유 텍스트와 제목·칩·캡션도 검토 대상. 생성 응답은 mock으로 검증한다.
- `engine/drinks_produce.py`, 주류 큐 RPC/마이그레이션, `engine/drinks_publish.py`, `.github/workflows/drinks-produce.yml`: renderer/content_format 계약, 실패·취소·lease·저장·QA·권리 정보를 기존 흐름에 연결. 변경 전 실제 SQL 함수와 호출자 전체를 확인한다.
- `web/` 주류 제작 화면·API·형식 타입 및 테스트: 선택, 미리보기, 차단·경고 표시. 기존 기본 선택은 유지한다.
- `tests/`: 각 단계의 실패 경로와 기존 motion 회귀. `docs/deviation-*.md`: 승인된 형식 예외와 롤백.

## 단계 및 합격 기준
1. **M1 정답 재현** — 샘플 `tools/build.py`의 12개 장면과 공통 무대를 입력 기반 템플릿으로 옮긴다. 샘플 VO와 `vo.json`을 주입한 실행에서 시간표 12개 시작 각각 ±0.05초, 12개 golden과 동일 시점 프레임을 나란히 비교하고 차이·판정을 남긴다. 1080×1920/30fps, HyperFrames 0.9.72 check 오류 0, LUFS −16~−14, true peak ≤−1 dBTP, clipping 0을 실측한다. 0초 초기 요소·안전 영역·모션·SFX도 확인한다. ffmpeg/Node/Chromium 미설치 또는 렌더 불가 시 미검증으로 멈춘다.
2. **M2 입력 차단** — 형식/version, 필수 칸과 타입, ID 참조, beat 참조, 등록 아이콘, 앞 질문·마지막 투표·직전 검색, 8~14 장면·5~8 제목, 2줄/줄당 17자, 가격 미표시를 fail-closed 검증한다. 검색 `show_prices=false` 누락/true와 모든 화면 텍스트의 가격 노출을 검사하고 정답 1교시 번호 등 비가격 숫자는 허용한다. 재생시간은 음성 측정 후 55~75초 검사; 요약 예외칩 누락은 경고. 악성 HTML은 escape. 각 실패 사례 및 경계값 pytest.
3. **M3 근거와 대본** — 승인된 claims만 입력으로 템플릿과 칸을 생성; 응답 스키마 검증 후 beat·화면 사실별 claim 해석, unknown/derived/인용 없음 차단. 기존 `drinks_script_check.check`의 차단 규칙을 각 beat에 적용하는 어댑터를 만들고 이미지 전용 검사는 이 형식에 맞게 분리한다. 사실 여부를 모델의 임의 `content_kind`에만 의존하지 않는다. 출처 칩은 검증된 claim 출처에서 코드로 생성하며 매칭 실패는 차단한다. mock 응답으로 근거 없음·잘못된 숫자/양/권고·위조 출처·근거 우회 차단을 테스트한다. 검사기는 의미상 지지 여부를 보장하지 못하므로 원문 대조와 사람 판정을 QA에 남긴다.
4. **M4 큐·DB** — 실제 마지막 로컬 번호는 0090이며 0089 중복이 있다. 원격 `schema_migrations` 읽기 전 번호를 확정하지 않는다. 새 마이그레이션은 로컬로만 검증하고 원격 적용은 별도 승인. 신규 renderer가 기존 무료 경로의 경고 전용 검사로 빠지지 않게 전용 분기에서 fail-closed 처리한다. 취소·lease 상실·TTS 실패/재시도 2회·저장 실패·QA와 비용 0 기록을 모의 RPC로 테스트한다. 로컬 storage에 무료 렌더 1편을 적재하고 QA를 확인한다. Actions의 Node/Chromium 설치 및 버전 고정 확인; 실제 Actions 결과는 실행한 경우에만 기재.
5. **M5 화면** — `/drinks/production`의 실제 형식 상태·요청 라우트·미리보기·에러를 연결하고 기존 형식 회귀를 확인한다. 로컬 테스트 후 운영 화면 검증은 배포·접근 가능할 때만 별도 증거로 판정한다.
6. **M6 판정** — 근거가 승인된 새 주제의 지시서와 무료 렌더를 만들고 근거 대조표·화면·소리 결과를 제시한다. 유료 생성이 필요하면 mock으로만 리허설 후 해당 호출 승인 대기. 소유자 OK 전 품질 합격으로 표시하지 않으며 게시하지 않는다.

## 주요 위험과 검증
- 샘플 `claim_ids`가 비어 있으므로 정답 비교용 재현과 실제 제작 검사를 분리하되 외부 입력으로 재현 모드를 임의 선택할 수 없게 한다.
- 매번 Edge 음성이 동일하지 않을 수 있다. M1은 저장된 VO로 결정적으로 비교하고 새 음성은 측정한 시간표로 별도 검사한다. +10%, atempo 1.055 고정; 빈 파일·무음·변환 실패는 작업 실패.
- 문장별 사실 검사는 문장과 화면의 전체 텍스트를 빠짐없이 검사해야 한다. 숫자 검사만으로 사실 여부를 보증하지 않는다.
- 소스/폰트/BGM/SFX 라이선스와 필수 캡션 출처를 보존한다. 자산 경로·분리된 임시 디렉터리·명령 인자 및 HTML 삽입을 검증한다.
- 임대가 렌더 중 만료되거나 취소될 때 저장·등록되지 않게 기존 RPC 계약을 재확인한다.

## 배포·되돌리기
먼저 로컬 테스트와 독립 코드 검사를 마친다. 원격 DB 현황 확인 → 마이그레이션 승인·적용 → 워커 및 UI 배포 승인·실행 → 운영 확인 순서. 이전 형식과 기본 선택을 유지한다. 되돌릴 때는 `DRINKS_JJERI_ENABLED=0`으로 신규 적재를 막고 운영자가 대기 중인 째리 작업을 취소한다. 현재 워커에서 실행 중인 째리 작업도 완료 또는 취소가 확정되어 대기·실행 중 0건임을 확인한 뒤 옛 워커로 전환한다. 옛 워커가 째리 작업을 기존 영상으로 처리할 수 있기 때문에 이 순서가 필요하다. DB 제약 복구는 신규 작업과 저장 자산 현황을 확인한 별도 마이그레이션으로 처리한다. 이번 수정에서는 되돌리기 절차만 기록했다.

## Codex 계획 리뷰 반영 (2026-11-27)
판정: **계획 수정 필요**. 별도 Codex 검토의 다섯 지적을 모두 반영한다.

1. **입력 반응성**: 12개 템플릿 각각 다른 slots·beat·장 제목으로 입력을 바꿔 해당 텍스트/그림/사건 시각이 바뀌는 독립 렌더 또는 프로젝트 산출물 테스트를 추가한다. 샘플 하드코딩을 감싼 방식은 불합격이다.
2. **시간·가독성**: 첫 문장 0.2/0.15초, 문장 간 0.27초, 템플릿 최소 길이, 검색·마지막 꼬리, beat 기준 사건, 입력 글자당 0.12초와 완료 후 `line_unread`(0.5초 + 낱말당 0.3초)를 경계 테스트한다. 긴 검색어는 입력 종료와 읽기 시간이 확보되도록 장면을 연장하고, 전체 75초를 넘으면 차단한다.
3. **출처 계약**: 사실 문구마다 승인 claim의 검증된 source_refs/source ID를 해석한다. 여러 출처는 결정적인 순서로 실제 연결된 출처만 표기하고 칩에 맞지 않으면 잘라내지 말고 차단한다. 출처가 없는 질문·투표 등 비사실 문구는 칩을 생략할 수 있으나 이를 이용한 사실 주장 우회를 차단한다. 미확인 출처, 다중 출처, 질문 예외를 각각 테스트한다.
4. **소리**: BGM 0.16, fade 0.3/2.0초, 유형별 SFX 볼륨 및 검출 피크 보정, 자막과 음성의 문장별 일치와 실제 유음 여부를 별도 검사한다. 통합 LUFS만으로 합격시키지 않는다.
5. **환경 판정**: Actions에서 Node·Chromium으로 실제 렌더한 증거를 M4 별도 합격 항목으로 둔다. 실행하지 못하면 미검증이다. 원격 DB·운영 통합, M5 운영 화면, M6 소유자 판정은 로컬 성공과 별도 게이트다.

### 페이블 3회차 재검사 후속 수정

- E1·E2는 통화·수량 단위 뒤의 조사와 활용이 닫힌 목록에 없을 때 숫자 후보까지 버리던 결함이다. 새 로직은 숫자와 단위 핵심부를 먼저 인식한다. 실제 일반 낱말로 이어지는 단위의 앞부분은 어휘 경계에서 제외한다. `원주`·`불꽃`·`도수`·`달콤`·`프로그램`이 그 예다. 명시적인 통화와 지원 단위는 일반적인 어미 허용 목록 없이 인식하되, 일반 낱말과 표기가 겹치는 일부 어미는 별도로 구분한다. 통화 없는 금액과 건강 표현의 일부 문맥에서는 조사·어미 규칙을 사용한다. 식별한 금액은 원문에 있어도 화면에서 차단하고, 수량은 인용의 값과 단위를 대조한다. 아라비아 수사는 기존 공용 수치 검사도 받는다.
- E4에서 `이 불로`·`이 도로`·`이 배로`처럼 형태가 겹치는 경우에는 가리키는 물건과 같은 문장에 있는 동작·문맥을 본다. `한 병에 이 모든 향`·`가격은 이 통`에서 외따로 나온 한 음절은 액수로 취급하지 않는다. `병당 이`·`이 원쯤`·`이 배일까요`처럼 여전히 구분하기 어려운 경우에는 `price_ambiguous` 또는 `number_ambiguous`로 막는다. 오류와 모의 생성 교정에 금액 생략, 단위가 분명한 숫자 표기, 지시 대상 명시 안내를 넣었다. 라벨 확인과 댓글 투표 안내는 기존 중립 문구 범위에 포함한다.
- E3의 `숙취예방`·`암예방 효과`·`혈압강하 효과` 같은 효능 합성어도 발견하면 차단한다. 질병 단어가 일부만 들어간 `암석`·`암호`처럼 일반 낱말을 보호한다. 발행처명·제목으로 만든 출처 칩에도 같은 건강 규칙을 적용한다.
- 보고서 가격 꼬리 84종 및 수사 꼬리 86종을 여러 핵심부와 조합했다. 보고서 밖의 `하더라고요`, `인들`, `은커녕`과 `3만 5천 리터더라고요` 같은 비통화 수량도 확인했다. 첫 RED에서 508건이 실패했고, 명시된 비통화 단위가 가격 문맥에서 탈락하는 추가 3건을 따로 재현했다.
- 이 방식은 단위 핵심부·알려진 어휘 충돌·제한된 문맥·효능 어휘를 보는 분류 규칙이다. 미등록 복합어와 비유, 모든 자연어 의미나 단위 환산을 보장하지 않는다. 금액 없는 가격 수준, 게시 캡션의 금액 및 실제 인용의 의미는 사람 검수에 남긴다. 사람 원문 검수와 소유자 게시 차단을 유지한다. 범위 밖 밈 청소는 기존 원인 기록을 유지한다.

RED·GREEN과 프로브는 `%TEMP%/jjeri-round4-codex-red.log`, `%TEMP%/jjeri-round4-codex-green.log`, `%TEMP%/jjeri-round4-codex-probe.log`에 있다.
