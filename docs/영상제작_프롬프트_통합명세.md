# 영상 제작 프롬프트 통합 명세 — 초안 → 영상지시서 → 렌더 (단일 참조본)

> **목적:** 논문 1편이 낙점된 뒤 **초안(대본+미디어 프롬프트) → 영상지시서(컷별) → mp4 렌더**까지
> 파이프라인의 **모든 단계에서 실제로 실행되는 LLM 프롬프트 원문·모델·출력 스키마·체이닝**을 한 문서에 모은다.
> 프롬프트가 코드(`engine/*.py`)에 하드코딩돼 여러 파일에 흩어져 있어, **품질 개선을 위해 한눈에 보고 분석**하기 위한 참조본이다.
>
> **성격:** 이 문서는 *기존 명세를 대체하지 않는다.* 규격(수치)은 `규격서_숏폼_v2.md`, 결정 근거는
> `deviation-render-pipeline.md`, 비용 불변식은 `shorts-cost-video-guidelines.md`가 원본이다.
> 이 문서는 그 위에서 "실제 돌아가는 프롬프트 텍스트"를 집약한 **횡단 색인 + 개선 분석**이다.
>
> **주의(이중관리):** 프롬프트는 Python 엔진과 Supabase Edge Function(TS)에 **양쪽 존재**한다.
> 아래 원문은 전부 **Python 엔진 소스**에서 축자 인용했다. 엣지 함수 진입점으로 실행될 때 실제 문구는
> `supabase/functions/generate-draft/index.ts`·`generate-directive/index.ts`와 diff 대조가 필요하다(§6).

## 1. 파이프라인 전체 흐름 (낙점된 논문 → mp4)

각 단계는 큐 기반 체인이다. `⇒` = 한 단계 출력이 다음 단계 입력이 되는 프롬프트 체이닝 지점.

| # | 단계 | 진입점 | 모델 호출 | 출력 ⇒ 소비처 |
|---|---|---|---|---|
| 0 | 수집·중복제거·1차필터 | `python -m engine.collect` | 없음(코드) | `papers` ⇒ 채점 |
| 1 | **5축 채점(선별)** | `python -m engine.score` | `SCORING_SYSTEM` (+번역 폴백) | `scores`·`daily_batch` ⇒ 사람 낙점 |
| 1b | 제목 한글 백필 | `python -m engine.translate` | `TRANSLATE_SYSTEM` | `scores.title_ko` |
| 2 | **Fact Sheet 추출** | `python -m engine.draft [paper_id]` | `FACTSHEET_SYSTEM` | `fact_sheet` ⇒ (3) |
| 3 | **대본 + 미디어 프롬프트(초안)** | 같은 draft 호출 (`scriptgen.generate`) | `SCRIPT_SYSTEM` | `script_md`+`scenes[]` ⇒ (4)(5) |
| 4 | **자기검증(환각)** | 같은 draft 호출 (`selfcheck.check`) | `SELFCHECK_SYSTEM` | 빨간깃발 ⇒ `drafts` |
| 5 | **영상지시서(컷별)** | `python -m engine.directive [paper_id] [version]` | `DIRECTIVE_SYSTEM_BASE`+`VERSION_GUIDANCE` | `directives`(header+cuts) ⇒ (6)(7) |
| 5b | (대안) 초안→지시서 직결 | `python -m engine.render_draft <paper_id>` | **LLM 없음**(결정론 매핑) | directive ⇒ 렌더 |
| 6 | 이미지 배치 프리웜(선택) | `python -m engine.image_batch [directive_id]` | Gemini 이미지 | `render_assets` 캐시 ⇒ 렌더 |
| 7 | **렌더 → mp4** | `python -m engine.render [directive_id] [ko\|en]` | Gemini 이미지 + Veo I2V + Manim + Edge TTS + ffmpeg | 최종 `.mp4`(+`render_qa`) |

**체이닝 요약:**
`초록 ⇒ Fact Sheet ⇒ 대본 scenes ⇒ 지시서 cuts ⇒ 컷별 visual_prompt ⇒ 이미지/영상 생성 프롬프트.`

**환각 방화벽:** 대본(3)의 유일한 사실 입력은 **Fact Sheet(2)뿐**이다. 자기검증(4)은 **나레이션만** 검사한다
(image/video 프롬프트는 오탐 방지 위해 제외 — `draft.generate_draft`가 `[{scene, narration_ko}]`만 전달).
`attribution.build_source(paper)`가 `fact_sheet["source"]`로 주입돼, 대본이 기관·저자를 **지어내지 않고** 지칭한다.

**전역 LLM 기본값** (`engine/llm.py`, `engine/config.py`): 기본 `max_tokens=8192`, JSON 파싱 재시도 1회
(`LLM_JSON_RETRY=1`) 후 하드 실패. Anthropic 호출은 **temperature 미지정**(SDK 기본). `gemini`로 시작하는
모델 ID는 Gemini REST 경로(`temperature=0.4`, `responseMimeType=application/json`), 그 외는 Anthropic.

## 2. 단계별 프롬프트 원문

> 아래 `<...>`는 스키마 플레이스홀더, `{...}`는 f-string 치환(코드가 config 값을 삽입)이다. 전부 소스 축자 인용.

### 2.1 Fact Sheet 추출 — `engine/factsheet.py`
- **모델:** `MODEL_FACTSHEET` = `claude-sonnet-4-6` · max_tokens 8192(기본) · temperature 없음
- **입력:** `title`, `venue`, `abstract` · **출력:** 대본(2.2)·지시서(2.4)의 **유일한 사실 소스**
- **상수:** `FACTSHEET_SYSTEM`(`factsheet.py:14`), user `factsheet_user_prompt`(`:28`), 호출 `extract`(`:48`)

**System:**
```
너는 사실 검증관이다. 아래 논문 초록에서 "검증 가능한 사실"만 추출한다.
추측·일반상식·초록에 없는 내용 금지. 항목별로 초록에 근거가 없으면 빈 배열로 둔다.
JSON only. 설명 문장·마크다운·코드펜스 금지.
{
  "what_found": ["<핵심 발견들>"],
  "how": ["<방법 요약>"],
  "numbers": ["<구체 수치와 그 의미>"],
  "limitations": ["<한계·표본·조건>"],
  "claim_strength": "<저자 주장의 강도: 강/중/약 + 근거>"
}
```
**User:**
```
제목: {title}
게재처: {venue or '(미상)'}
초록: {abstract}
```
> 출력에 `source` 블록(기관/저자/게재처)이 다운스트림에서 부착된다(LLM이 아니라 `attribution.build_source`).

### 2.2 대본 + 씬별 미디어 프롬프트(초안) — `engine/scriptgen.py`
- **모델:** `MODEL_SCRIPT` = **`claude-opus-4-8`** · **max_tokens 6144** · temperature 없음
- **입력:** `fact_sheet`(source 포함) + 선택적 사용자 `instruction`
- **출력:** `drafts` 행 — `upload_title_ko/en`, `script_md`, `video_flow`, `video_prompts`(=`scenes`)
- **상수:** `SCRIPT_SYSTEM`(`scriptgen.py:23`), user `script_user_prompt`(`:128`), 호출 `generate`(`:205`)

**System (축자):**
```
너는 대중 과학 숏폼 대본 작가 겸 영상 연출자다. 입력으로 주어지는 것은 오직 "Fact Sheet"(JSON)뿐이다.
★ 절대 규칙: Fact Sheet에 없는 내용을 추가하지 마라. 수치·주장·예시는 Fact Sheet에 있는 것만 사용한다.
각 씬에는 그 씬이 근거한 Fact Sheet 항목 키를 source_facts 로 남긴다(예: "what_found[0]", "numbers[1]").
근거가 없으면 그 씬을 만들지 마라.

산출물은 "단계별로 미디어화 가능한 제작 지시서"다. 세 가지를 만든다:
(1) video_flow — 전체 세부 영상 흐름(스토리보드). 영상이 처음부터 끝까지 어떻게 흘러가는지.
(2) scenes — 주요 장면마다 [이미지 프롬프트 → 영상 프롬프트 → 나레이션]. 제작 순서는
    각 장면의 스틸 이미지를 먼저 만들고 → 그 이미지를 움직여 영상화 → 나레이션으로 진행한다.
(3) script_md — 사람이 읽는 전체 대본(나레이션 흐름 전문).

대본 구조(숏폼 규격, 순서 고정 — video_flow.beats 와 scenes 가 이 흐름을 따른다):
1) 후크(3초): 멈칫하게 만드는 한 마디
2) 개념 한 줄: 무엇에 대한 연구인가
3) 놀라운 사실/수치: Fact Sheet의 what_found/numbers 기반
4) 일상 연결: 시청자 삶과 연결
5) ⚠️ 한 줄 의심: Fact Sheet의 limitations 기반(없으면 claim_strength 기반 신중 멘트)
6) CTA: 행동 유도 한 줄

[★ 나레이션 서사 규칙]
- 한 씬 = 한 메시지. 한 씬에 여러 사실·여러 수치를 몰아넣지 마라.
- 앞뒤 문맥 연결: 각 씬 나레이션은 이전 씬을 자연스럽게 이어받아라(그래서/하지만/즉 등). 순서대로 읽으면 하나의 이야기가 되게.
- 데이터 절제: 소리 내 읽는 숫자는 대표값 1개만(여러 수치는 "최대 ~"처럼 요약). 숫자 나열·괄호·기호 금지, 친구에게 말하듯 구어체.
- 마지막 씬은 후크에서 던진 궁금증에 답한다.
- ★출처 구체화: "한 연구/어떤 연구"처럼 추상적으로 말하지 말고, Fact Sheet의 source로 구체적으로 지칭하라.
  ★지칭 우선순위: 기관 > 저자명 > 게재처. 기관(institutions)이 있으면 "스탠퍼드 연구팀이"처럼, 없으면
  저자명(authors)으로 "제인 도 연구진이", "○○○ 팀이"처럼 사람 이름을 써라. 게재처만으로 "arXiv에 발표된
  연구"처럼 밋밋하게 끝내지 마라 — 저자명이 있으면 반드시 사람 이름을 넣는다(예: "제인 도 등 연구진의
  이번 arXiv 논문은"). 저자·기관이 모두 없을 때만 게재처/분야로 특정한다("국제 학술지에 실린 연구").
  ★source에 있는 것만 써라 — 없는 기관·저자를 절대 지어내지 마라. 최소 1회는 도입부에서 누가 한 연구인지 밝혀라.

[image_prompt 작성 규칙 — 텍스트-투-이미지 AI(Midjourney/Imagen/Flux 등 도구 무관)에 그대로 붙여
스틸 한 장을 뽑을 수준으로. 영어로, 콤마로 이어지는 하나의 리치 프롬프트. "정지 이미지" 관점.]
반드시 아래 정적 요소를 순서대로 구체적으로 포함:
1) shot/framing — 예: extreme close-up, wide establishing shot, macro, split-screen
2) main subject + 구체적 외형 묘사
3) setting/environment
4) lens/optics — 예: 35mm, shallow depth of field, macro
5) lighting — 예: volumetric, soft rim light, chiaroscuro, high-key
6) color palette / mood
7) ★art style/medium — 만화식(웹툰) 화풍으로 통일하라. 모든 씬에 아래 앵커 문구를 넣어라:
   "modern Korean webtoon/comic style, bold clean ink outlines, soft cel shading, flat muted pastel palette,
   consistent character design across scenes". 데이터·개념 장면도 사진/3D 대신 '만화 인포그래픽 패널'(웹툰 톤의
   도해·아이콘·말풍선 없는 다이어그램)로, 일상·현실 장면도 웹툰 컷으로 그린다. 사진(photorealistic)·3D 렌더는 쓰지 마라.
   ★씬마다 같은 화풍·같은 인물 디자인·같은 색조를 유지(화풍이 튀면 안 됨).
8) technical tags — "vertical 9:16, 4K, high detail, no on-screen text"

[video_prompt 작성 규칙 — 이미지-투-영상 AI(Runway/Kling/Veo 등 도구 무관)에 그대로 붙여
위 스틸을 "움직이는 영상"으로 만들 지시. 영어로, 콤마로 이어지는 하나의 리치 프롬프트.
"animate the still image" 관점 — 정적 요소는 반복하지 말고 '움직임'만 지시.]
반드시 포함:
1) camera movement — 예: slow dolly-in, orbit, crane-up, whip-pan, rack-focus, parallax push
2) subject motion/action — 화면 안 피사체·요소의 구체적 움직임
3) pacing/speed — 예: slow-mo, steady, quick burst
4) 지속시간감과 루프 여부(예: seamless subtle loop)
공통 제약:
- 시각은 Fact Sheet 사실의 "시각화·은유"만. Fact Sheet에 없는 구체 수치·결과·객체를 지어내지 마라.
- 화면 안에 읽히는 글자/숫자/자막/워터마크 렌더 금지("no on-screen text" 명시).
- 영상이므로 정지컷 금지 — video_prompt엔 반드시 카메라 무빙과 모션 포함.
- ★만화 그림을 그대로 애니메이션하는 관점(웹툰 화풍 유지) — 실사화·3D화 금지, 정적 요소의 화풍은 image_prompt와 동일하게.

[한국어 설명 병기 — image_prompt_ko / video_prompt_ko]
image_prompt·video_prompt는 툴에 그대로 붙일 "영문"이고, 각각에 대응하는 한국어 설명을
image_prompt_ko(어떤 스틸 장면인지)·video_prompt_ko(어떻게 움직이는지)에 1~2문장으로 적어라.
사람이 영문을 안 읽어도 무엇을 만들지 이해하도록. 영문 프롬프트의 충실한 한국어 요약이어야 한다.

[★ 유튜브 업로드용 제목 — upload_title_ko / upload_title_en]
숏폼(유튜브 Shorts) 업로드 제목을 한국어·영어로 각각 만든다. 논문 원제는 밋밋하니 쓰지 마라.
- 클릭을 부르는 자극적·호기심 유발형 훅. 시청자가 "뭐라고?" 하고 멈추게.
- 짧게(한국어 대략 15~30자, 영어 대략 40~70자). 한 줄, 문장부호 최소.
- 언어별 독립 트랜스크리에이션(직역 금지) — 각 언어에서 자연스럽고 강한 표현으로.
- ★환각 금지: Fact Sheet에 없는 수치·주장·결과를 지어내지 마라. 과장 표현은 되지만 없는 사실은 금지.
- 낚시성 거짓(clickbait 허위)은 금지 — 영상 내용과 어긋나면 안 된다.

출력은 JSON only. 설명·마크다운·코드펜스 금지.
{
  "upload_title_ko": "<자극적 한국어 업로드 제목 한 줄>",
  "upload_title_en": "<자극적 영어 업로드 제목 한 줄>",
  "video_flow": {
    "logline": "<이 영상 한 줄 컨셉(한국어)>",
    "total_duration_sec": <int>,
    "beats": [
      { "order": <int>, "label": "<후크/개념/수치/일상연결/의심/CTA 등>",
        "summary": "<이 비트에서 화면에 무엇이 보이고 무엇을 전달하는가(한국어)>",
        "transition": "<다음 장면으로의 전환 방식(예: 매치컷, 페이드, 급속 줌)>" }
    ]
  },
  "script_md": "<읽기용 대본 전문(한국어 나레이션 흐름)>",
  "scenes": [
    {
      "scene": <int>,
      "title": "<장면 짧은 제목(한국어)>",

[버전=이미지 나열식 image_sequence] 각 컷의 핵심을 대표하는 사실적/일러스트 이미지 1장을 지정한다. visual_prompt 는 주제를 직접 표현하는 리치 프롬프트. 강조가 필요한 컷엔 effects(ken_burns/텍스트오버레이/highlight)를 적극 지정하라. global_style 은 톤 앵커(예: 'clean editorial illustration, cohesive palette').
```

**(e) User 템플릿 (`directive_user_prompt`, `{guidance}` = (c/d)+(b)):**
```
{guidance}

대본(script_md):
{script_md}

Fact Sheet:
{json.dumps(fact_sheet, ensure_ascii=False, indent=2)}

기존 장면들(scenes — 나레이션 초안이다. 흐름·근거를 최대한 계승하되, 위 [연출·서사 규칙]에 맞게
다듬어라. 문맥이 끊기거나 한 컷에 메시지가 여러 개면 쪼개고 이어라. 통째로 버리지 말 것):
{json.dumps(scenes, ensure_ascii=False, indent=2)}
```
> 정규화(`normalize_directive`): enum 강제, `total_estimated_sec`를 컷 합으로 **재계산**(모델 자기보고 불신),
> 근거 없는 컷은 `ungrounded_cuts`로 플래그(승인 화면 빨간 표시), 씬 다양성 3연속 자동 교정.

## 3. 프롬프트 체이닝 & 환각 방화벽 (한눈에)

```
초록 ──FACTSHEET──▶ fact_sheet(검증가능 사실만) ──┐
                                                  ├─ SCRIPT(opus) ──▶ scenes[image/video_prompt, narration]
   attribution.build_source(paper) ─▶ source ─────┘         │
                                                            ├─ SELFCHECK(나레이션만) ──▶ 빨간깃발
                                                            ▼
                        script_md + scenes ──DIRECTIVE──▶ cuts[visual_prompt, effects, source_facts]
                                                            │
                          ┌── image.py ──▶ Gemini 이미지 프롬프트 ──┐
              motion=still │                                        ├─▶ ffmpeg 컷 ──▶ mp4
              motion=video └── video.py ──▶ Veo I2V 프롬프트 ──────┘
```

- **사실 입력은 오직 Fact Sheet.** 대본·지시서 모두 "Fact Sheet에 없는 내용 금지"를 시스템 프롬프트에 명시.
- **각 씬/컷은 `source_facts`로 근거 키를 남긴다.** 근거 없는 컷은 승인 화면 빨간 표시.
- **화면 텍스트는 항상 자막 레이어**(visual_prompt엔 `no on-screen text` + `BURN_IN_NEGATIVE_PROMPT`) — 이미지/영상은 언어 무관 공유.
- **모델 자기보고 불신:** `all_grounded`·`total_estimated_sec`는 코드가 실제 데이터로 재계산.

## 4. 개선 기회 분석 (품질 향상 후보)

> 아래는 **프롬프트/코드 원문 근거가 있는 관찰**이다. 각 항목은 "왜 품질에 영향" + "어디를 손보나"를 명시했다.
> 우선순위는 대략 리텐션 영향 × 구현 난이도로 매겼다. **미검증 가설** 표기는 실제 렌더 A/B가 필요한 것.

### 4-1. 화풍 일관성 — 지금이 가장 약한 고리 (근거 있음)
- **관찰:** comic 경로는 "모든 컷 visual_prompt가 global_style로 시작"하게 하지만, 실제 이미지 생성은
  **컷마다 독립 호출**(`image.py`, content-hash 캐시는 컷 단위)이다. 인물/캐릭터 시각 일관성을 보장하는
  레퍼런스 이미지 재주입이 없다 — `deviation-render-pipeline.md`도 M-V7 잔여로 "버전1 만화 화풍 일관성(레퍼런스+seed)"을 명시.
- **개선안:** ① 첫 컷 이미지를 **캐릭터 시트/스타일 레퍼런스**로 고정하고 이후 컷 생성에 image-to-image 참조로 재주입,
  ② `style_anchor_ref` 필드(이미 스키마에 있음)를 렌더러가 실제로 소비하도록 배선, ③ seed 고정.
- **손보는 곳:** `engine/providers/image.py`(레퍼런스 주입), directive 스키마의 `style_anchor_ref`(현재 텍스트 설명만).

### 4-2. 이미지 프롬프트의 이중 규격 충돌 (근거 있음)
- **관찰:** 대본 단계 `image_prompt`는 "8) technical tags: 4K, no on-screen text"까지 **완결형**으로 만든다.
  그런데 실사용 렌더 입력은 대본 image_prompt가 아니라 **지시서 `visual_prompt`**(`render_draft` 직결 경로는 예외).
  `research-comic-media-prompts.md` §2가 지적한 대로, 운영자가 초안 화면에서 보는 프롬프트와 최종 렌더 프롬프트가
  **다른 필드**라 체감 불일치가 남는다.
- **개선안:** 초안 검수 화면에 "이건 참고용, 최종은 지시서 visual_prompt"를 명시하거나, 두 필드를 한 화면에서 대조 표시.
- **손보는 곳:** `web/components/ReviewClient.tsx`(표시), 문서화. 프롬프트 자체 변경은 불필요.

### 4-3. 대본(opus)과 지시서(sonnet)의 서사 규칙 중복 (근거 있음)
- **관찰:** "한 씬=한 메시지 / 앞뒤 연결 / 데이터 절제 / 출처 구체화"가 `SCRIPT_SYSTEM`과 `DIRECTIVE_SYSTEM_BASE`에
  **거의 동일하게 두 번** 들어간다. 지시서 단계가 대본을 "다듬어라"라고 하므로, 두 프롬프트의 규칙이 미세하게
  어긋나면(예: 데이터 절제 강도) 지시서가 대본을 재작성하며 뉘앙스가 흔들릴 수 있다.
- **개선안:** 공통 서사 규칙을 config의 단일 상수(`NARRATIVE_RULES`)로 뽑아 두 프롬프트가 같은 문자열을 import.
  드리프트 원천 차단 + 유지보수 1곳.
- **손보는 곳:** `engine/config.py`(공통 상수), `scriptgen.py`·`directive.py`(참조). **이중관리 TS도 동일 반영.**

### 4-4. 훅·리텐션 게이트가 "기록"만 하고 "차단"은 안 함 (근거 있음 — 미검증 효과)
- **관찰:** 【P3】는 `hook_promise_check.pass`·`science_reliability`를 header에 **기록**하게 하지만,
  `normalize_directive`가 `pass=false`인 지시서를 **재생성/거부**하는 하드 게이트인지는 코드 확인 필요.
  기록만 하고 통과시키면 낚시성 훅이 그대로 렌더될 수 있다.
- **개선안:** `pass=false` 또는 (강주장 훅 × evidence_strength≠high)면 승인 화면에 **경고 배지 + 재생성 유도**,
  또는 자동 1회 재생성. 자기검증(2.3)처럼 "모델 자기보고 불신 → 코드 재판정" 패턴을 훅에도 적용.
- **손보는 곳:** `engine/directive.py` `normalize_directive`, 승인 UI. **(구현 전 현재 동작 코드 확인 필요 — 미검증)**

### 4-5. Veo 프롬프트가 얇다 (근거 있음)
- **관찰:** 대본 `video_prompt`는 카메라무빙·피사체모션·pacing·루프까지 요구하는데, 실제 Veo 호출 프롬프트는
  `{global_style, visual_prompt}, vertical 9:16, {negative}`로 **모션 구절이 visual_prompt 안에 있길 기대**한다.
  지시서 `_VIDEO_CLIP_GUIDANCE`는 "모션 구절 1개 포함"을 요구하지만, 대본의 풍부한 `video_prompt`(모션 전용 필드)는
  렌더 경로에서 **소비되지 않는다**(directive는 visual_prompt만 씀).
- **개선안:** motion_source=video 컷에서 대본 `video_prompt`(또는 별도 `motion_prompt` 필드)를 Veo 프롬프트에 합류.
  모션 지시가 이미지 프롬프트와 분리돼야 I2V 품질이 산다.
- **손보는 곳:** directive 스키마에 `motion_prompt` 추가 or `video.py`가 컷의 모션 구절을 별도 수용.

### 4-6. `image_sequence`(레거시)와 comic 분기의 유지비 (근거 있음)
- **관찰:** UI는 comic 단독 운영인데 `image_sequence` 가이드·정규화 분기가 남아 프롬프트/테스트 표면을 넓힌다
  (`research-comic-media-prompts.md`도 image_sequence는 "UI 미사용, 엔진 잔존"으로 명시).
- **개선안:** 실사용이 comic 단독으로 확정이면 image_sequence를 명시적 deprecated 처리(제거는 별도 결정).
- **손보는 곳:** 결정 문서화 우선. 코드 제거는 범위 밖.

### 4-7. temperature 미지정 (근거 있음 — 효과 미검증)
- **관찰:** 창의성이 중요한 대본(opus)과 사실 정확성이 중요한 Fact Sheet(sonnet)가 **같은 SDK 기본 temperature**를 쓴다.
- **개선안(가설):** Fact Sheet/자기검증은 저온(0~0.2)으로 결정성↑, 대본 훅은 약간 고온으로 다양성↑ — A/B로 확인.
- **손보는 곳:** `engine/llm.py` 호출부에 단계별 temperature 노브. **미검증 — 실측 A/B 필요.**

### 4-8. 이중관리 드리프트 (근거 있음 — 상시 리스크)
- **관찰:** 대본·지시서 프롬프트가 Python과 Edge Function(TS)에 양쪽 존재. 프로덕션이 엣지 함수로 돌면
  **실제 실행 문구가 이 문서의 Python 원문과 다를 수 있다.**
- **개선안:** CI에 "프롬프트 문자열 diff 0" 회귀 테스트(`research-comic-media-prompts.md` §4.4가 이미 권고).
- **손보는 곳:** `tests/`에 diff 가드, 또는 프롬프트를 단일 소스에서 생성.
