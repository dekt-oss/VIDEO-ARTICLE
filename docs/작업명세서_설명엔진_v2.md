## 0-1. 환각 방지 불변식과의 관계 (CLAUDE.md)

- **숫자·화면 수치·출처 표기는 지금처럼 Fact Sheet(원장)만.** 이 명세는 그 불변식을 건드리지 않는다.
- 바뀌는 것: 대본·설명 모델의 **입력이 초록에서 원문 전문으로 확장**된다. 리포트 라인이 이미 하는 방식(전문=맥락, 화면 수치=원장)을 논문 라인에 이식하는 것이다.
- 새 규칙: 설명 모델의 모든 factual step 은 `claim_ids` + `source_refs`(chunk id + 원문 인용) 필수. 인용은 **코드가 원문 대조로 검증**한다(리포트 라인의 원문 인용 대조와 같은 방식).

## 2. Phase 0 — 실측 (코드 작성 전. GO/NO-GO 게이트)

### 0-A. 논문 원문 확보율
최근 낙점·후보 논문 **100편**에 arXiv(HTML/PDF) → OpenAlex OA → PMC → Unpaywall 순서로 확보를 시도한다.
기록: provider · license · content_format · char_count · source_depth(`full_body / partial_body / abstract_only`) · 파서 실패.

**GO 기준: 낙점 후보군에서 `full_body + partial_body ≥ 50%`.** 미달이면 논문 라인 설명 엔진은 보류하고
리포트 라인(원문이 이미 있음)만 Phase 5 이하를 진행한다.

### 0-B. 동일 논문 paired test
v2 리뷰의 정정을 수용한다 — **서로 다른 논문 20 vs 20 비교 금지.**
원문 확보된 **같은 논문 20편**에 대해 A=초록만 / B=전문을 현재 파이프라인에 넣어 비교한다.

### 0-C. 아키텍처 기여도 분리
같은 논문으로 3안 비교:
- A = 현행(초록 → 현행 파이프라인)
- B = 전문만 주입(현행 하류 그대로)
- C = 전문 → Ledger → Explanation Model → script → visual plan

**이걸 해야 "원문 효과"와 "설명 모델 효과"를 분리할 수 있다.** B≈C 면 설명 모델 계층은 만들지 않는다(v2 §22-Q6 의 의심을 실측으로 해소).

### 평가
v2 §17 루브릭 10항목 × 0~2점(20점 만점), 평가자 프롬프트 고정.
- **GO: C−A ≥ +4점 그리고 목차/장식형 컷 비율 절반 이하.**
- C−B < +2 면 Phase 3(설명 모델)을 접고 Phase 1~2(원문 주입)만 남긴다.

비용: LLM 약 140회, $5 미만. 산출물: `docs/실측_0ABC_설명엔진.md`.

## 4. Phase 2 — Scientific Evidence Ledger 확장

- `engine/factsheet.py` 입력에 원문 주입(있을 때). claim 에 `claim_kind / study_design / causal_strength / source_section / source_refs[{chunk_id, quote}] / evidence_grade` 추가.
- **인용 검증 코드**: quote 가 해당 chunk 원문에 실제로 존재하는지 문자열 대조. 불일치 claim 은 `unverified` 표시(원장에서 제외하지 않되 게이트 E1 에서 걸림).
- 원칙(v2 §4): 초록만이면 초록 수준 등급까지만 · 본문 확보 ≠ 자동 A등급 · association → causal 승격 금지.
- **엣지 동기화:** `generate-draft` 에는 이식하지 않는다(D6 — 엣지는 abstract_only 폴백이므로 기존 스키마 유지). `tests/test_prompt_sync.py` 에 "워커 전용 필드" 목록을 명시해 앵커 오탐을 막는다.

**DoD:** 전문 확보 논문의 Fact Sheet 에 source_refs 가 실리고 인용 대조 통과율이 기록된다.

## 5. Phase 3 — Scientific Explanation Model (대본보다 먼저)

- 신규 `engine/scientific_explanation.py`: Ledger + 원문 → explanation units (v2 §5 스키마: `unit_type / subtype / title / explains_claim_ids / carries_primary / steps[{step, text, claim_ids, source_refs}]`).
- 저장: `drafts.scientific_explanations`(JSONB, versioned) — D7.
- `engine/scriptgen.py`: Story Plan 이 explanation units 를 입력으로 받는다. **대본이 설명 모델을 소비하지, 반대가 아니다**(D2).
- `engine/selfcheck.py`: 자기검증 축에 "설명 단위 step 이 source_refs 를 갖는가" 추가.
- 참고지식 provenance(D3/D3′): `TARGET_SOURCE / CITED_REFERENCE / ILLUSTRATIVE_ONLY` 3종. ILLUSTRATIVE_ONLY 는 새 사실 주장 금지 + 화면에 "비유" 라벨.
- **파이프라인 전환(D6):** 대시보드 초안 버튼 → `draft_requests` 큐(기존) → `draft.yml` 워커가 원문 포함 전체 체인 실행. 엣지는 원문 없는 논문만. `draft.yml` 에 크론 추가는 하지 않는다(수동/dispatch 유지 — 빈 폴링 비용, `docs/deviation-cron-cost.md` 참조).

**DoD:** 전문 논문 1편이 워커 경로로 초안+설명 모델까지 생성되고, 초록만 논문은 엣지 폴백으로 기존과 동일하게 동작.

## 6. Phase 4 — Visual Explanation Plan + 게이트

- 신규 `engine/visual_plan.py`: explanation units → 컷 배치(`explanation_id / cut_range / sequence`). **한 설명 = 1~3컷, 매체 혼합 허용**(실사 전경 → 3D 내부 → 실사 설비, v2 §10).
- 매체 판단은 "카메라로 찍을 수 있는가" 단독이 아니라 **화면 부담 5종**(v2 §11):
  `EXPLAIN→3D / PROVE→실사 / QUANTIFY→코드 그래픽 / ORIENT→지도·실사·코드 / COMPARE→3D·코드`.
- `engine/directive.py` + 엣지 `generate-directive`: 컷에 `explanation_id`(리포트는 `reasoning_id`) 필드. **지시서 엣지는 계속 쓰므로 이식한다** — `tests/test_prompt_sync.py` 확장.
- 게이트(v2 §12):
  - S1 source_depth 기록 · E1 factual step 은 claim+source_ref 필수 · E2 association 으로 causal chain 금지
  - E3 핵심 claim 에 "왜/어떻게" 설명 존재(단순 언급 ≠ coverage) · E4 외부 참고가 결론 확대 금지
  - V1 MECHANISM 컷은 explanation_id 필수 · V2 visual_prompt 에 설명 단위에 없는 구조·인과 추가 금지
  - V3 연속 메커니즘은 continuity group(→ I2V 연쇄. 역할 경계 연쇄 차단은 구현 완료, 커밋 `f51fa72`)
- **승인 차단은 E3·V1 만.** 나머지는 warning + ⑤ 화면 표시(운영 마찰 최소화. 강제 승인은 허용하되 흔적을 남긴다는 기존 원칙 유지).

**DoD:** 게이트 위반 케이스별 테스트 + ⑤ 화면에 설명 단위·배분·위반 표시.

## 7. Phase 5 — 리포트 라인: Financial Reasoning Model

- 신규 `engine/report_reasoning.py`: 기존 `report_factsheet / report_evidence` 위에 reasoning units(`DRIVER_CHAIN / EARNINGS_BRIDGE / VALUATION_LOGIC / CATALYST_PATH / RISK_PATH / SCENARIO / COMPARISON`, v2 §8).
- 저장: 리포트 draft JSONB `financial_reasoning`(versioned). 논문 스키마와 합치지 않는다(D1).
- `report_draft.py` · `report_directive.py` 가 소비.
- 리포트 라인은 원문·워커·인용 대조가 **이미 있으므로** Phase 1~2 해당 없음 — 가장 빨리 성과가 나는 라인이다. **0-A 가 NO-GO 여도 이 Phase 는 진행한다.**

**DoD:** 리포트 1건이 reasoning units 를 거쳐 explainer/photo 지시서까지 생성되고, 컷이 reasoning_id 를 갖는다.

## 8. Phase 6 — MECHANISM 멀티모달 QA (조건부)

- `QA_COST_ESTIMATE` → **0원(무료 quota 내)일 때만**: MECHANISM 컷 프레임 → 검사(핵심 구성요소 존재 / 구조 순서 / 흐름 방향 / 전후 상태 / 미설명 물체 / 가짜 숫자·라벨) → fail 시 재생성 1회 → 재실패 시 스틸 폴백 + human review.

## 9. 실패 조건 · 성공 기준 (v2 §18·§19 그대로)

**실패:** factual hallucination · causal overreach · source 없는 factual mechanism · primary explanation coverage 없음 · 목차형 MECHANISM · 단순 배경을 MECHANISM 으로 위장 · 리포트 숫자 가짜 생성 · 외부 참고가 대상 결론 강화 · **Python/Edge 계약 불일치**.

**성공은 "3D 컷 개수"가 아니다.** 시청자가 (무엇을 발견 / 왜·어떻게 / 연구가 실제로 말한 범위 / 이해용 참고 설명)을 **구분해서** 이해할 수 있어야 한다. 리포트는 (전망 / 근거 / driver→실적 연결 / 실제 리포트 수치 / 전제와 risk).
