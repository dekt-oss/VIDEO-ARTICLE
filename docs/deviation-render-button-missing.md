# 편차 기록 — "렌더 지시 버튼이 없다" (2026-09-17)

> **운영자 보고:** "웹 대시보드에 초안 생성하면 작업지시서 같이 생성되는데 그다음 렌더
> 지시하는 버튼이 없다."
> **한 줄:** 버튼이 없어진 게 아니라, 결정 바가 **엉뚱한 버전을 보고 있었다.**

## 1. 무엇이 보였나 (실측)

논문 `e826a5fa…` 화면:

```
④ 초안 검수 [✓]   ⑤ 영상 지시서 [검수 필요]   ⑥ 렌더 결과 [렌더 없음]
만화식  3D 그래픽   [변경사항 저장]  [지시서 생성 (만화식)]
```

오른쪽 칸에는 **3D 그래픽 지시서의 컷이 제대로 보인다.** 그런데 주 버튼은 만들지도 않은
만화식을 만들라고 한다. 그래서 "지시서는 있는데 렌더 버튼만 없다"로 보인다.

## 2. 원인

화면은 버전을 두 군데서 따로 고른다.

| 자리 | 무엇을 보나 | 결과 |
|---|---|---|
| **오른쪽 지시서 칸** | `activeVersion` = `slots.find(s => s.directive)?.key` — **있는 지시서** | photo 를 제대로 보여줌 |
| **결정 바(주 버튼)** | `versions` = localStorage ?? 기본값 `comic` — **있는 지시서를 안 봄** | "지시서 생성(만화식)" |

초안 발주가 `photo` 로 나가면 지시서도 `photo` 로 만들어진다(0046 연쇄). 그런데
`VersionOrderBar` 기본 체크는 **만화식 하나**다(CLAUDE.md, 3버전 통째 발주 사고의 처방).
둘이 어긋나면 승인만 누르면 렌더로 갈 수 있는 지시서가 결정 바에서 사라진다.

실측: 2026-09-16 에 만들어진 논문 지시서 5건이 **전부 `photo`** 였다. 즉 그날 이후
초안을 만든 논문은 **하나도 렌더 버튼을 볼 수 없었다.**

## 3. 고친 것

체크해 둘 버전을 고르는 규칙을 순수 함수로 빼고(`web/lib/work/versionSelection.ts`)
우선순위를 셋으로 못박았다.

1. **지시서가 실제로 있는 버전** ← 새로 추가된 것. 지금 눌러야 할 일이 거기 있다.
2. 마지막 선택(localStorage) — 아직 아무것도 안 만든 화면에서 습관을 이어준다.
3. 기본값 한 건 — 손대지 않고 눌렀을 때 3버전이 통째로 발주되던 사고의 처방(그대로 유지).

`useState` 초기값에서부터 ①을 본다 — 서버 렌더에도 같은 버튼이 찍혀서, 하이드레이션 전까지
잘못된 버튼이 깜빡이지 않는다.
