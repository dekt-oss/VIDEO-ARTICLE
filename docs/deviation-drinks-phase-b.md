## 안전 요청(SSRF) — 실제 요청 경로에서

`SafeFetcher.get` 이 **요청마다·리다이렉트 단계마다** 검사한다: https·기본 포트만, 계정 정보·IP 리터럴·내부 이름 금지,
허용 호스트(등록부가 수집 주소에서만 만든 목록) 밖 금지, DNS 결과 전부 공개 주소, 연결된 상대 주소(server_addr)도
공개 주소(재바인딩 대비), 리다이렉트 3회, 응답 2MB(스트리밍 중 중단)·연결 10초·읽기 15초·전체 30초, 콘텐츠 종류 허용 목록,
robots.txt(RFC 9309: 4xx = 제한 없음, 5xx·연결 실패 = 전부 금지), 프록시 환경변수 무시.

남은 위험(알고 둔 것): DNS 확인과 실제 연결 사이 재바인딩은 연결 뒤 상대 주소 확인으로 잡는다 — 그 사이에 TLS 핸드셰이크와
요청 한 번이 나갈 수 있다. 허용 호스트가 운영자가 승인한 공개 도메인뿐이라 받아들였다.

수집 본문은 텍스트로만 저장하고 화면은 React 텍스트로 그린다(HTML 을 그대로 넣지 않음).

## 일부러 하지 않은 것

- LLM 후보 생성(명세 기본 12건/실행): **연결하지 않았다.** 호출 0회. 상한 값도 코드에 두지 않았다(쓰지 않는 설정을 만들지 않음).
  비슷한 소재 후보는 글자 조각 겹침 규칙(판정 아님)으로만 보여준다.
- 사이트 전체 크롤링·SNS·댓글·DM·OCR·번역·렌더·발행.
- 예약 실행은 워커(`--schedule`)만 만든다. 화면 요청은 라우트가 운영자 요청으로 고정한다.
- 재시도 실행은 워처마크를 올리지 않는다(실패분만 다시 본 것이라 전체를 다 봤다는 뜻이 아니다).
