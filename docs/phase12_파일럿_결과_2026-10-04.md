## 2. 발견한 결함 ① — 도입 질문 계약 충돌 (이 브랜치에서 수정)

- Phase 6 은 도입 질문을 "어간 60% 유지"면 통과시켰고, Phase 7 은 "핵심 질문과 글자 그대로"만 수사적
  예외로 인정했다. 실제 모델은 "…보여 주는가?" 를 "…보여 주는 걸까요?" 로 어미만 다듬었고 2/2건이
  `rhetorical_exemption_invalid:SC01` 로 막혔다. 검증 모델은 나머지 사실 절에서 문제를 찾지 않았다.
- 가짜 모델은 문장을 그대로 복사하므로 단위 테스트·골드 재현에서는 드러날 수 없었다.
- 수정: 두 단계가 `spoken_narration.hook_matches_core_question` 하나를 쓴다(내용은 그대로, 문장 끝
  어미만 변형 허용). 모델이 어기면 도입 질문만 핵심 질문으로 되돌리고 `repairs` 에 원문을 남긴다.
- **검증(비용 0):** 파일럿에서 실제로 받은 모델 응답을 그대로 재생해 수정 코드에 넣었다 — 두 건 모두
  Phase 7 `PASSED`. 다음 관문은 아래 ②다.

## 3. V2 대본 품질 문제 정리 (② 이하, 아직 수정하지 않음)

심각도: **차단** = 이것 때문에 V2 지시서가 구조적으로 나올 수 없다 / **품질** = 나와도 쓰기 어렵다.

### ② 숫자 개수 — 풀 수 없는 3단계 충돌 [차단]

| 단계 | 규칙 | 위치 |
|---|---|---|
| Phase 5 | 근거 단위의 문장을 숫자째 모두 대본 재료(`content_points`)에 넣는다 | `engine/narrative_planner.py:186-194` |
| Phase 6 | 재료의 숫자를 하나라도 바꾸거나 빼면 거절(`numbers_changed`) | `engine/spoken_narration.py:130` |
| Phase 8 | 소리 내 읽는 숫자가 2개(`MAX_SPOKEN_NUMBERS`) 넘으면 `REGENERATE_NARRATION` | `engine/content_complexity_gate.py:185` |

파일럿 대본의 숫자는 논문 16개, 리포트 15개. 다시 생성해도 같은 재료라 줄어들 수 없다 — 재생 결과
리포트는 **이것 하나** 때문에 막힌다. 해결의 자리는 Phase 5 다: 영상 전체에서 말로 읽을 대표 숫자
2개를 고르고, 나머지는 화면 카드로 넘기거나 빼는 선택 단계가 필요하다(원안 §10 의
`too_many_spoken_numbers → Narration regenerate` 는 재료가 바뀔 때만 의미가 있다).

### ③ 한계·리스크 누락 [품질, 사실 보존 원칙 위반]

- 논문: Evidence Pack 에 Fact Sheet 상단의 연구 한계 3건이 있었지만 대본 계획에 없었다. 논문 어댑터는
  **주장(claim)에 직접 붙은** 한계만 근거 단위로 만든다(`engine/paper_reasoning_adapter.py:67-77`).
- 리포트: Evidence Pack 에 리스크 1건이 있었지만 빠졌다. 리포트 어댑터는 증권사 논리 중
  `RISK_PATH` 단위만 리스크로 쓴다(`engine/report_reasoning_adapter.py:14`). 기존 Production 대본에는
  리스크(피크아웃 우려)가 있었다 — **V2 가 기존보다 후퇴한 지점**이다.
- 원안 §0 "불확실성·정보 삭제"를 공통 관심사로 둔 것과 어긋난다.

### ④ 도입 질문이 고정 문구 [품질]

핵심 질문을 만들 근거가 없으면 어댑터가 "이 연구는 무엇을 보여 주는가?" / "왜 이 증권사는 이런 전망을
하는가?" 를 쓴다(`paper_reasoning_adapter.py:87`, `report_reasoning_adapter.py:137`). 실데이터 2건 모두
이 고정 문구였다. 기존 대본은 콘텐츠별 질문("삼성전자, 63만원?")을 썼다. ①의 수정으로 어미는 말투가
되지만 질문 자체는 여전히 일반적이다.

### ⑤ 설명 없는 약어 [품질]

경고만 낸다(`unexplained_abbreviation`). 논문 FSA·IPF·MLR·MVF, 리포트 DRAM·NAND·HBM4·BPS·PBR·DS.
Phase 4 는 명시 요청만 해결하고(자동 탐지 없음) 검토된 glossary 는 2개 항목뿐이다
(`gwas_association`, `polygenic_trait`).

### ⑥ 문장 길이·한 비트에 여러 근거 [품질]

60자 초과 문장이 논문 5비트, 리포트 2비트. 원인은 Phase 5 가 같은 역할의 연속 근거 단위를 한 비트로
묶는 것(논문 NB06 = 결과 단위 4개)이다(`narrative_planner.py:186-191`). 경고만 낸다.

### ⑦ 면책 문구 없음 [Production 연결 전 필수]

리포트 V2 대본에 "정보 제공 목적이며 투자 권유가 아닙니다" 류의 문구가 없다. 기존 리포트 파이프라인은
컴플라이언스 단계가 붙인다. Shadow 비교에서는 문제가 아니지만 Production 연결 전에 반드시 필요하다.

### 잘 된 것 (기존 대비 개선)

- 논문: 기존 대본은 골드셋이 지적한 과장("모든 유인원 중 유일하게")을 그대로 반복했다. V2 는 원문 범위를
  지켰다("침팬지는 발뒤꿈치 착지가 적었다").
- 리포트: V2 는 비트마다 증권사 귀속을 유지했다. 원문 대조 결과 수치(DS부문 100.0조원, 전사 약 100조원)도
  맞다.
