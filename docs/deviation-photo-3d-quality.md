# 편차 기록 — 실사형 3D 도해 품질 상향 (2026-08-28)

## 지시

> "실사풍은 완전히 새로운 스타일로 비용이 좀 들더라도 퀄리티를 높혀야 해.
>  요즘 숏츠는 퀄리티 높은 AI만 살아남습니다."
> "아니 화질보다는 그냥 **3d 영상 퀄리티**를 올려달라는 말입니다. **화질 비율은 좀 낮아도 돼요.**"

두 번째 문장이 이 변경의 범위를 정했다. 올리는 것은 **구조 묘사력**이지 픽셀이 아니다.
그래서 해상도(720p)·Veo 티어(lite)는 **손대지 않았다**.

## 무엇이 3D 품질을 막고 있었나

### ① 도해를 그리는 모델이 구글이 "legacy" 로 분류한 모델이었다

`gemini-2.5-flash-image` 는 공식 문서(ai.google.dev/gemini-api/docs/image-generation)가
**"legacy pioneer"** 로 표기하고 전환을 권고하는 모델이다. 빠르고 싸지만 단면·층 경계처럼
정밀한 구조를 그리는 데 약하다.

| 모델 | 구글 설명 | 단가(장) |
|---|---|---|
| `gemini-2.5-flash-image` (기존) | "legacy pioneer" | $0.039 |
| `gemini-3.1-flash-image` | "generalist workhorse" | $0.067 |
| **`gemini-3-pro-image`** (도입) | **"복잡한 시각 작업을 위한 프리미엄"** | $0.134 |

단가는 **해상도별**이다(2026-08-28 공식 확인). 위는 우리가 쓰는 1K/2K 기준이고,
4K 로 올리면 pro 가 $0.24 가 된다. "화질 비율은 낮아도 된다"는 지시대로 4K 는 쓰지 않는다.

3D 단면·분해·조립 순서는 정확히 "복잡한 시각 작업"이다.

**역할별로만 올렸다** — `IMAGE_MODEL_BY_ROLE = {"MECHANISM": "gemini-3-pro-image"}`.
실사(REALITY) 컷은 지금도 충분히 나오고, 전부 올리면 편당 비용만 3배가 된다.
돈을 **설명력이 갈리는 곳에만** 쓴다.

### ② 화풍 문구가 일부러 뭉개고 있었다

기존 `VISUAL_ROLE_STYLE["MECHANISM"]` 의 **"matte clay materials"** 는 의도적으로
부드럽고 디테일 없는 룩이다. 그래서 단면을 그려도 층 경계가 뭉개져 "무엇이 어떻게 되는지"가
안 보였다 — 3D 도해의 값어치가 정확히 거기 있는데.

재질·경계·조명을 정밀 렌더 어휘로 교체했다(PBR·샤프 베벨·볼류메트릭 조명·앰비언트 오클루전).
**유지한 것(의도된 설계):** 앰버 강조 1색 · 중립 배경 — 설명할 부분에만 눈이 가게 한다.

### ③ 3D 도해가 정지 화면으로 나가고 있었다

실측(8/21 지시서): MECHANISM 컷 4개 중 **2개가 스틸**이었다.
단면이 열리고 층이 분리되고 흐름이 이동하는 것 — **그 움직임 자체가 이 버전의 설명력**이다.
정지된 3D 도해는 그냥 그림이고, 말로 하는 설명을 도로 가져간다.

계약에 "영상 컷은 **MECHANISM 에 먼저** 배정하라"를 넣었다(엔진·엣지 양쪽).

## 함께 고친 것 — 안 고쳤으면 위 전부가 렌더 도중에 죽었다

`engine/render.py` 의 예산 가드가 **전역 캡 $1.2 를 직접 읽고 있었다.**
`config.render_budget_cap(version_type)` 이 실사형용 캡을 따로 들고 있는데 **논문 라인만**
그 함수를 안 썼다(리포트 라인 `report_render.py:77` 은 처음부터 쓴다).

실사형 예상비는 $3.5 다. 캡은 **하드 스톱**이라 터지면 그때까지 쓴 돈은 못 돌려받는다.
실사형이 한 번도 렌더된 적이 없어서(`render_jobs` 0건) 드러나지 않았을 뿐이다.

> 실사형에서 **세 번째로 반복된 같은 패턴**이다 — 버전별 값은 만들어 뒀는데 강제하는 지점이
> 그것을 안 본다. 앞의 둘: enforce/cap/preflight 세 겹(8/21), 프롬프트의 `[비용 예산]` 문장(8/21).
> `test_기본_캡은_photo_캡과_다르다` 가 이 층을 고정한다.

캡도 함께 올렸다: `PHOTO_COST_CAP_USD` **$3.0 → $4.0**.
산식: 영상 48초 × $0.05 = $2.40 + 새 스틸 ~6장(도해 4장 $0.54 · 실사 2장 $0.08) ≈ **$3.01**.
예상비의 약 1.3배 — 너무 빠듯하면 렌더가 죽고, 너무 헐거우면 가드 구실을 못 한다.

## 비용

| | 전 | 후 |
|---|---|---|
| 편당 예상 | (렌더 불가 — 캡에서 죽음) | **약 $3.01** |
| 벤치마크 채널 실측 | | 편당 3,500~4,200원 ≈ $2.6~3.1 |

벤치마크와 같은 급의 지출로 **도해 품질만** 올린 셈이다. 해상도·Veo 티어를 올리면
$6~$19 로 뛰지만, 운영자가 "화질은 낮아도 된다"고 정했으므로 하지 않았다.

> ⚠️ 작업 중 정정: 처음에 pro 단가를 **$0.24 로 잘못 넣었다**(그건 4K 가격이다).
> 공식 문서를 다시 확인해 1K/2K $0.134 로 고쳤고, 캡도 $4.5 → $4.0 으로 다시 잡았다.

## ⚠ 검증되지 않은 가정 하나

**요청이 출력 해상도를 지정하지 않는다.** `_image_request_body` 는 `aspectRatio` 만 싣고
크기는 API 기본값에 맡긴다. 그래서 위 단가($0.134)는 **"기본값이 1K/2K"** 라는 가정이다.
4K 로 나오면 장당 $0.24 가 되어 편당 $3.44 — 캡($4.0) 안이긴 하나 여유가 줄어든다.

첫 렌더 후 `generation_attempts` 의 실제 과금과 대조해 확인한다. 종횡비 파라미터도 같은
성격의 미검증 항목이라(`IMAGE_ASPECT_CONFIG_SHAPE`) 그때 함께 실측하는 편이 효율적이다.

## 안 한 것 (의도적)

- **해상도 720p → 1080p**: 지시가 명시적으로 제외했다.
- **Veo 티어 lite → fast/standard**: 같은 이유. 필요해지면 `VEO_MODEL` 한 줄이다
  (lite $0.05 / fast $0.10 / standard $0.40 per sec, 720p 기준. 2026-08-28 공식 확인).
- **T2V 경로 신설**: `providers/video.py` 는 `start_image` 가 필수라 I2V 만 된다.
  벤치마크 채널은 이미지 없이 영상 프롬프트로 바로 만든다 — 이게 남은 가장 큰 구조적 차이다.
  다만 우리 I2V 연쇄(앞 컷 마지막 프레임 → 다음 컷)는 그들이 포기한 연속성을 얻는 장치라
  통째로 버릴 수 없다. **장면 시작 컷만 T2V, 이어지는 컷은 I2V 연쇄**가 다음 후보다.

## 되돌리는 법

```
IMAGE_MODEL_MECHANISM=gemini-2.5-flash-image   # 모델만 되돌리기
PHOTO_COST_CAP_USD=3.0                          # 캡 되돌리기
```
화풍 문구는 `config.VISUAL_ROLE_STYLE["MECHANISM"]`, 계약 문구는 `_PHOTO_VIDEO_CLIP_GUIDANCE`
(+ 엣지 `PHOTO_VIDEO_CLIP_GUIDANCE`) 에서 되돌린다.
