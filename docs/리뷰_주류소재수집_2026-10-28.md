# 리뷰 — 주류 소재 수집 방법 (2026-10-28)

대상: 주류 공장(인스타 계정 술째리고)의 **소재 수집 층** — "사케·전통주·위스키에 대해 사람들이 실제로 묻는 질문"을
얼마나 가져오는지, 그리고 전략 고리(성과 → 다음 편성)가 수집에서 무엇을 받아야 하는지.
코드를 읽고 실제로 돌려 본 것만 사실로 적었다. 못 본 것은 `(미검증)`. 코드·DB·설정은 바꾸지 않았고, 운영 DB 는 읽기만 했다.

## 1. 한 줄 판정

**수집 장치는 안전하게 잘 지어졌지만, 지금 운영에 들어오는 "진짜 사람의 질문"은 0건이다.** 키 없이 도는 유일한
자동 채널(Stack Exchange)은 영어이고 최근 1년 새 글이 **0건**이라 켜도 아무것도 안 들어온다. 한국어 질문을 줄 수 있는
네이버·유튜브 채널은 코드가 있지만 **키가 저장소 시크릿에 없고** 수집원도 등록돼 있지 않다. 운영 DB 에는 수집원 0 ·
실행 0 · 발견 자료 0 이고, 소재 1건은 손으로 만든 발행 시험용이다. 전략 고리는 "주종·형식·갈래·시간대"만 보고,
**질문 유형·출처 채널·인기 신호는 소재에 남지 않아** 수집이 전략에 주는 것이 사실상 주종 하나뿐이다.

## 4. 판정 항목별 결과

### 4-1. 범위(coverage)
- 강점: 근거용(고정 페이지·목록·피드)과 발견용(API 3종 + 수동)을 **표부터 갈라** 놓았고(`0052_drinks_discovery.sql:3-5`),
  발견 자료는 근거가 될 수 없게 DB 가 막는다. 수집원 등록·검증·활성·중지 상태 기계(`0051:77`)와 실행 기록이 있다.
- 구멍: ① 운영에 **수집원 0개** — 장치는 있는데 아무것도 안 돈다. ② 키 없이 도는 채널은 SE 하나뿐이고 그 채널이 비어 있다.
  ③ 피드 0개, 목록 1개는 이용 조건 미확인. ④ 명세 §5.1 의 세 경로 중 "상시 지식(공식 자료에서 질문 발굴)"은 **사람이 제목·질문을
  새로 쓰는 길밖에 없다**(`0051:807-808`, `0052:428`) — 자동으로 질문을 뽑는 코드가 없다(LLM 0회가 설계 원칙, `engine/drinks_collect.py:10`).
  ⑤ 명세 §6.4 가 권한 "수동 질문 30개 부트스트랩"은 아직 0건.

### 4-2. 한국어 질문 비중
- 수집기가 **가져올 수 있는** 것 중 한국어는 네이버(카페·블로그 검색 요약)와 유튜브(검색어가 한국어일 때 제목·설명·댓글)뿐이고,
  둘 다 지금 꺼져 있다. 그래서 **현재 한국어 질문 비중은 0%** 다.
- 질문 문장 추출 규칙은 **물음표로 끝나는 문장만**(`engine/drinks_discover.py:53-72`; 한글은 6자 이상). 신호 규칙은 '왜·어떻게·궁금'
  같은 한국어 낱말도 본다(`:35`). 네이버 검색 요약은 문장이 잘려 물음표가 드물어 `questions` 가 비고 `signals` 만 붙을 가능성이 크다(미검증 —
  실호출 안 함).
- `audience_question`(소재의 `question`)의 출처: **항상 사람이 쓴다.** 후보 카드의 `key_question` 은 원문 그대로(번역 없음,
  `:445-448`)이고, 소재로 올릴 때 운영자가 한국어 제목·질문을 새로 쓴다(`0052:428-441`). 수동 URL 등록도 같다. LLM 은 어디에도 없다.

### 4-3. 근거 출처(공식·전문 자료) 경로
- 자동 경로: 승인 수집원(approved_page/listing/feed)에서 본문을 받아 스냅샷(본문 해시)으로 저장 → 사람이 소재에 붙인다
  (`drinks_link_snapshot`/`drinks_create_topic_from_snapshot`, `0051:795-820`). 붙을 때 역할은 `discovery` 이고 **근거(`evidence`)로
  올리는 것은 조사 단계에서 사람이** 한다(`0051:807-808`).
- **PDF 는 본문을 뽑지 않는다**(`engine/drinks_collect.py:166-168`, OCR·추출 없음 — 명세 §5.4-7). 실제 첫 편의 근거(국세청 PDF)는
  운영자가 **발췌 106자를 손으로 붙여** 넣었다(`0050 drinks_add_source_internal:1043-1050` 은 URL 없이도 본문을 받는다; 서버는 URL 을 열지 않는다).
- "질문 → 근거 찾기"를 잇는 자동 경로는 없다. 후보 카드는 "확인할 사실" 문구만 만든다(`engine/drinks_discover.py:459-461`).
- 연결 확인된 공식 출처: 국세청(활성 가능), SWA(조건 미확인), NRIB(403·재게재 금지)·더술닷컴(약관 없음)은 연결 안 함(`deviation-drinks-phase-b.md:25-28`).

### 4-4. 중복·신선도
- 강점: URL 정규화(`engine/drinks_parse.py:35`) → 본문 해시로 new/changed/unchanged 판정, 다른 URL 의 같은 본문은 `same_body_count` 로
  센다(`0051:650-690`). 이미 본문이 있는 글은 `drinks_known_urls` 로 빼고 **처음 보는 글에 예산을 먼저** 쓴다(`drinks_collect.py:195-197`).
  피드는 워처마크 − 3일 겹침(`:142-146`, `config:4309`). 워처마크는 **성공·정상 0건 수집 실행만** 올리고(`0051:770`), 상한에 걸리면
  `partial/limit_reached` 로 남겨 다음 실행이 이어 간다(`drinks_collect.py:199,213`, `0051:758-760`). 재시도 실행은 워처마크를 안 올린다.
  발견 채널은 오래된 것부터 받아 "빠짐없이 본 데까지"만 전진(`drinks_discover.py:138-140`, `0052 finish_run`). 네이버는 날짜만 있어 KST
  날짜로 비교하고 같은 날 글은 URL 로 거른다(`:294-298`). 발견 자료는 URL 유일(`0052:403-411`).
- 구멍: ① 발견 첫 실행 365일 소급(`config:4318`)이 SE 에서는 0건이라 실행이 `empty` 로 끝나고 워처마크만 전진 — 옛 글은 영영 안 들어온다.
  ② 유튜브는 최신순이라 상한에 걸리면 부분 전진이 안 된다(`:217-219`). ③ 근거 수집원은 나이 상한이 없어 같은 고정 페이지를 매일 다시 읽는다
  (변경 감지 목적이라 의도된 것). ④ 소재 수준 중복은 주종+질문+대상+각도 키(`0050:1125-1138`)인데 질문을 사람이 쓰므로 표기 차이로 못 잡을 수 있다.

### 4-6. 이용 조건
- 요청기 규칙(`engine/drinks_fetch.py:1-16, 278-317`): https 만, 승인 호스트만, 호스트마다 robots.txt(5xx 면 전부 금지), 연락처 있는 UA, 로그인·우회 없음.

## 5. 전략 고리와의 연결

전략(`engine/drinks_strategy.py`, `0055_drinks_publish_loop.sql:853-950`)이 지금 보는 것:

- **묶음(차원)** 주종(`categories`)·형식(`post_type`)·소재 갈래(`lane`)·게시 시간대(`slot`)(`:24`, `0055:857-860`).
- **문턱** 묶음 3편·전체 6편·한 번에 ±0.2·상한 ±0.5(`0055:35-39`). 미달이면 "표본 부족" 제안만. 운영자 [반영]으로만 새 버전.
- **순서** `drinks_strategy_rank`: 선별 전 소재의 `provisional_score × (1+가점)`; 가점은 주종·갈래·형식(적합성 ≥2)에서만(`0055:924-950`).
- 돌리는 곳: `drinks-publish.yml:56` 수동 실행에서만(크론 없음). 운영에는 발행 1편·성과 스냅샷 0 → 지금 돌리면 표본 부족.

|---|---|---|
| 주종 `categories` | 수집원 등록·소재 등록 때 사람이 고름 | 있음 |
| 소재 갈래 `lane`(상시/시의/독자질문) | 소재로 올릴 때 사람이 고름(발견 후보는 기본 `reader_question`, `0052:441`) | 있음. 단 "질문 유형"이 아니라 공급 경로 |
| 형식 `post_type`·시간대 `slot` | 발행 요청·게시 시각 | 있음(발행 쪽) |
| 형식 적합성 `fit_video/fit_carousel` | 후보 카드 규칙(`drinks_discover.py:423-426`) → 소재 경량 평가는 **사람이** 입력(`0051:822`) | 사람 입력 |
| **질문 유형**(보관·오해·선택·논쟁…) | 후보 `signals`(`0052:79`)에 있으나 **소재 표에 칸이 없다**(0050 에 `signals` 0건) | **없음** — 핸드오프가 ⑤ 차원으로 적은 "질문 유형"(`handoff:58`)이 구현에선 `lane` 으로 바뀜 |
| **출처 채널·플랫폼** | 후보 `discovery_path`; 소재엔 `relation_note` 문구로만(`0052:452`) | **없음**(구조화 안 됨) |
| **인기·수요 신호** | 후보 `interest`(독립 출처 수·플랫폼별 최댓값); 소재엔 `reader_signal_count` 뿐이고 운영자 버튼으로만 +1(`0050:1372`) | **0** |
| 언어·시장(국내/해외 질문) | 수집원 `language` 만; 소재엔 없음 | 없음 |

즉 지금 전략이 수집에서 실제로 받는 것은 **주종 하나**다. 질문 유형·채널·관심 신호가 소재까지 안 내려오니 "어떤 질문이 저장을 부르나"는 잴 수 없다.

## 6. 우선 개선 3개

1. **네이버 발견 채널을 켠다(한국어 질문의 유일한 자동 입구).** 무엇: GitHub 시크릿 `NAVER_CLIENT_ID`·`NAVER_CLIENT_SECRET` 등록(술째리고 API HUB 키) →
   `/drinks/discover` 에서 네이버 수집원 등록(검색어 예: "사케 보관", "위스키 입문 추천", "막걸리 유통기한", "전통주 선물") → [검증 실행] → 활성.
   같이 고칠 것: 네이버 요약엔 물음표가 드물어 질문 추출(`drinks_discover.py:53-59`)이 비게 되므로 '~인가요/~할까요/궁금' 로 끝나는 문장도 질문으로 치는 규칙 한 줄.
   왜: 지금 한국어 질문 0%. 품: 운영 1시간 + 코드 반나절. 비용: $0(한시 무료, 월 775,000건 합산). 위험: 술째리고와 쿼터 공유, 카페 글은 날짜만·회원 본문 없음.
2. **후보 → 소재로 올릴 때 질문 유형·채널·관심 신호를 소재에 남기고, 전략 차원에 "질문 유형"을 더한다.** 무엇: `drink_topics` 에
   `question_kind`(보관/오해/선택/논쟁/신제품/행사/일반)·`discovery_platforms`·`interest` 칸(또는 `provisional_scores` jsonb 안) → `drinks_promote_candidate`
   가 후보 값을 복사 → `drinks_strategy_inputs`/`DIMENSIONS` 에 `question_kind` → 테스트. 왜: §5 표의 "없음" 세 칸이 채워져야 전략이 주종 말고 다른 것을 배운다.
   품: 1일(마이그레이션 1개·함수 2개·테스트). 비용: $0. 위험: 표본 6편 전엔 효과 없음 — 칸을 **먼저** 만들어 두지 않으면 나중 성과를 되짚어 붙일 수 없다.
3. **상시 지식 질문 30개 부트스트랩 + SE 소급 기본값 수정.** 무엇: 명세 §6.4 권장대로 운영자가 주종별 10개 질문을 `/drinks` 에서 등록(또는 CSV 일괄 스크립트, 0원)
   하고, §3 의 보관 질문 3건처럼 SE 옛 글은 종자로만 쓴다. SE 는 365일 소급이면 0건이라 `since` 를 전체로 두거나(발견 수집원별 소급일 설정) 아예 등록하지 않는다.
   왜: 발행 가능 소재 6개 확보 목표(§6.4)에 지금 0개(테스트 1건 제외). 품: 입력 2시간 + 코드 1시간. 비용: $0. 위험: 운영자 취향 편향 — 1번 네이버 신호로 보정.
