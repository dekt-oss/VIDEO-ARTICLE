## 2. 실측 (코드 판정, 렌더 전)

저장된 photo 지시서 40편·기전 컷 198개에 새 게이트를 돌린 결과는 §4 에 적는다(구현 직후 측정).

## 3. 알아야 할 것

- **옛 지시서는 재생성해야 한다.** 구조 필드가 한글이면 `photo_mechanism_prompt_detached` 로 막힌다 — 의도다(한글 구조는 그림에 못 간다). 되먹임 처방이 "영어로 적어라"를 말한다.
- **T2 는 정지 화면을 만든다.** 상태가 바뀌는 stage 가 전부 스틸이 되므로 기전 시퀀스에 움직임이 줄어든다. 운동(MOVE·ROTATE·IMPACT)은 여전히 I2V. 너무 정적이면 `MECHANISM_SPLIT_OPERATIONS` 를 좁히거나 `MECHANISM_SPLIT_BEFORE_AFTER=false`.
- **분할 스틸의 위/아래가 무엇인지는 label_pair 가 말한다.** 모델이 안 넣으면 경고만 뜨고 화면엔 캡션이 없다(차단 아님 — 새 어휘라 첫 실측 전엔 차단하지 않는 저장소 규칙).
- `EVIDENCE_OVERLAY_ENABLED` 가 꺼져 있으면 legend/label_pair 도 안 나간다(기존 카드와 같은 스위치).
- 화풍: REALITY 문자열은 그대로. MECHANISM 만 "앰버 1색" → "앰버 + 비교용 두 색". 재질·조명·배경 공유는 `test_the_two_roles_still_share_one_visual_language` 가 계속 지킨다.

## 4. 실측 기록

### 4-1. 게이트 히트율 (저장된 photo 지시서 40편 · 기전 컷 198개, 2026-09-18)

- 설계 전 측정(T1-b 문턱 결정용): 구조가 완전하고 재사용이 아닌 기전 컷 140개 중 **영어 구성요소만** 가진
  117컷에서 구성요소 0겹침 = **4컷(3.4%)**, 넷 다 진짜(entity_id·데이터셋명을 구성요소로 적음). 오탐 0 → 차단.
- 한글 구성요소는 105/473(22%) — 구조 필드 중 subject/transformation/state 는 **84% 가 한글**이었다.
  즉 지금까지의 구조는 그림에 실을 수 없는 언어로 적혀 있었다 → 지시서 프롬프트를 영어 요구로 바꿨다.
- 구현 후 전체 재판정: `photo_mechanism_prompt_detached` **12/40편(42컷)** — 대부분 한글 구성요소.
  옛 지시서는 재생성 대상이므로 의도한 결과. `photo_mechanism_unlabeled` 경고 33/40편(새 어휘라 당연).
- T1-c(여는 컷이 배우를 무대에 안 세움): 91 시퀀스 중 **0건** → 게이트를 추가하지 않았다.
- T2 적용 범위: 뒤따르는 stage 중 상태 변화 선언 71개, 그 71개 **전부** `continuity_from` 이 있어 분할 가능.

### 4-2. 재생성·렌더 판정 (2026-09-18, 총 비용 ≈ $1.9)

**① 지시서 재생성** — 논문 6b2d092a(청각 상실·시각 피질) → 지시서 `5c770756`, $0.08.
- mechanism 필드 **전부 영어**, `mechanism_ko` 채워짐, 컷3 visual_prompt 가 muted blue / muted coral 로 두 뇌를
  구별하고 `legend`(blue=청각인 / coral=청각 장애인)를 넣었다. `photo_mechanism_prompt_detached` 0건.
- 그래도 승인 차단은 남았다(기존 종류): `photo_mechanism_spec_missing:5`(연결 컷을 MECHANISM 으로 라벨),
  `photo_style_word_in_prompt:컷3(rendered in)`, `vseq_no_actual_mutation`, `cut_claim_not_in_source`.
  "rendered in" 은 **내 색 안내가 부른 어휘**였다 → 안내를 "표면색으로 써라, rendered/glow 금지"로 고쳤다(커밋 c64d0f7).
- 이 지시서의 기전 stage 는 HIGHLIGHT·APPEAR·MOVE 뿐이라 **T2(분할 스틸) 대상이 없다** — 논문이 시점 비교이지
  시간 변화가 아니라서 옳은 읽기다. T2 는 아래 ③ 으로 따로 확인했다.

**② 기전 시퀀스 4컷 유료 렌더** (`scripts/mini_render.slice_directive` 로 SEQ2 4 stage, Gemini+Veo, ≤$1.69)
- 렌더는 끝까지 돌았다(stage 4개, 참조 3, degraded 0, 범례 ASS 이벤트 1건).
- **그런데 4장 전부 세로 3단 스토리보드였다** — `docs/review-2026-09-18/01_before_fix_storyboard_stage0.png`.
  원인: 첫 판 구조 문장이 `before: …; after: …` 를 나열했고 Gemini 가 그것을 칸으로 그렸다.
  프롬프트는 이제 `render_assets.meta.prompt` 로 남으므로 이런 진단이 다음부터는 코드 없이 된다.
- 고침: `mechanism_prose` 에서 전·후 나열을 빼고 "One single scene (no panels, no grid, no storyboard)" 을 명시,
  문장꼴 필드(마침표·12단어 초과)는 싣지 않는다(커밋 71c231d).
- 재확인(스틸 1장, $0.13): `02_after_fix_single_scene.png` — **한 장면, 두 뇌, 파랑 vs 산호, 산호 뇌의 설명
  부위만 앰버.** 색 규약(T5)이 프롬프트만으로 화면에 나왔다. 화풍(무광·아웃라인 없음)은 유지.

**③ T2 분할 스틸·label_pair 끝단 검증** (placeholder provider, 비용 0)
- 같은 지시서의 stage 하나에 TRANSFORM 을 넣은 합성 미니 지시서로 렌더 → `stage_1_split.png` 합성,
  `seq_decision.split_before_after=true`, 위/아래 캡션 "변화 전 / 변화 후"가 분할선 기준 제자리에 구워짐
  (`03_split_still_with_label_pair_placeholder.png`), 범례는 좌하단(`04_legend_placeholder.png`).
- 실제 그림으로 분할이 **읽히는지**(위·아래 반쪽 크롭이 도해를 잘라먹지 않는지)는 아직 못 봤다 — 상태 변화를
  선언하는 지시서가 나오면 그때 판정한다.

**아직 판정 못 한 것**
- 운영 렌더 워크플로에 `EVIDENCE_OVERLAY_ENABLED` 가 없다 → **켜기 전까지 범례·캡션·수치 카드가 화면에 안 나간다.**
  켜면 `photo_number_without_overlay`·`photo_mechanism_unlabeled` 검사도 같이 살아난다(같은 스위치).
- T2 가 실제 그림에서 어떻게 보이는지(위 ③).
- 참조 컷(2·3·4번째 stage)의 "amber glow" 는 모델 어휘라 무광 부정어와 싸운다 — 안내를 고쳤으니 다음 재생성에서 본다.
