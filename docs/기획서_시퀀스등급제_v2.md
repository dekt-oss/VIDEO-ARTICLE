# 기획서 — 시퀀스 등급제 v2 (최종, 코덱스 리뷰 반영)

작성 2026-08-31 · 상태 **확정 — 구현 착수 가능** · 실행: `docs/작업명세서_시퀀스등급제_v2.md`

> **v1.1 → v2 를 가른 두 입력:**
> 1. **코덱스 리뷰(조건부 반려)** — "8초 클립을 주는 것과 8초를 고품질 숏츠 문법으로
>    사용하는 것은 다른 문제다." P0 4건 + 품질 축 3건. 사실 주장을 코드와 전수 대조한
>    결과 **오류 0건**(§1) — 전부 수용한다.
> 2. **운영자 확정** — "가장 중요한 건 영상 퀄리티다. 높은 수준으로 뽑는다 생각하고
>    만들고, 그다음 비용을 보면서 조절한다." → 품질 장치는 **기본 켬**, 비용은 관측
>    + 발주 전 차단(fail-fast)만. 자동 절약은 없다.

## 0. 한 줄

시퀀스가 **품질 의도**를 정하고, 컷이 **실행 품질**을 받는다. 투자 컷은
"8초"가 아니라 **8초 + 시간축 연출 계약(비트 2~3개·카메라 플랜·상태 변화) + 후보
2개 생성·선택**을 받는다. 돈은 발주 전에 한 번 보여주고 넘치면 멈춘다 — 렌더
도중에 죽지 않고, 몰래 깎지도 않는다.

## 1. 리뷰 사실 대조 (§9-0 규율 — 리뷰어의 주장도 코드로 검증했다)

| 리뷰 주장 | 대조 결과 |
|---|---|
| 강등·차단 경로는 3겹이 아니라 최소 7개 | **사실.** `enforce_motion_value_gate`(675) · `enforce_mode_video_budget`(700) · `enforce_video_clip_cap`(750) · `preflight_video_budget`(774) — 전부 `engine/directive.py` 실재. + `web/lib/approvalGate.ts:41`(`video_budget_exceeded`) + `providers/video.py:115`(pick_clip_tier 재클램프) + `config.render_budget_cap`(2300) |
| 렌더 **도중** 캡 초과로 죽는다 | **사실.** `render.py:894` `raise RuntimeError("예산 초과: …")` — 이미 쓴 돈은 못 돌려받는다 |
| photo 하드캡 $4.0 — 8s 투자 설계와 충돌 | **사실.** `PHOTO_COST_CAP_USD = 4.0`(config:1245). 품질 우선 구성은 $5~6/편(§8)이라 그대로면 전 편이 렌더 중 사망 |
| provider 가 tier·model·길이를 재판단 | **사실.** `_veo_i2v` 가 `pick_clip_tier` 재호출 + 전역 `VEO_MODEL` 사용(video.py:115-116) |
| 벤치마크 핵심은 "8초 뽑아 좋은 3초" + 멀티샷 + 카메라 비트 | **사실.** `benchmark-realistic-shorts-2026-08-19.md:54-55` 그대로 |
| ⑤ 소비자는 DirectiveClient·VersionOrderBar·orderCost·approvalGate | **사실.** 전부 실재 확인 |

**v1.1 의 오류를 인정한다:** "상한 3겹"은 과소 집계였다. 문서가 실행 경로를 소유하지
못한 상태로 리뷰에 나갔다 — 이번 작업명세서는 7개 경로 전수 처리표를 갖는다.

## 2. 품질 모델 — 등급은 필요조건이지 충분조건이 아니다

리뷰가 제시한 벤치마크 품질 함수를 채택한다:

```
품질 = 장면 기획 × 영상 생성력 × 시간축 연출 × 후보 선택 × 편집
```

v1.1 은 이 중 "어떤 장면에 8초를 줄 것인가"(장면 기획의 일부)만 다뤘다.
v2 는 세 축을 추가한다 — **운영자 확정에 따라 전부 v1 범위다**(측정 후 추가가 아니라
켜고 시작해서 측정으로 조절):

| 축 | v2 장치 | 근거 |
|---|---|---|
| 시간축 연출 | **Invest Temporal Contract** — 비트 2~3개·카메라 플랜·상태 변화 필수 | 리뷰 §7·§8: 같은 8초라도 "고정 카메라 1피사체"와 "wide → lateral → push-in"은 다른 영상이다 |
| 후보 선택 | **Candidate Selection** — invest 컷은 2회 생성, 판정으로 선택 | 리뷰 §9 + 벤치마크 "8초 뽑아 좋은 3초만". 생성은 확률적이다 — 1발과 2발 중 선택은 품질 상한이 다르다 |
| 편집 기준 | **Quality Parity Gate** — 벤치마크 상대 정량 지표로 판정 | 리뷰 §16: 지표 없으면 "8초라서 좋아 보인다" 인상평을 못 벗어난다 |

## 3. 등급 구조 — Quality Intent → Effective Tier (P0-1)

v1.1 의 결함: `tier_of()` 가 시퀀스 소속만 보면 **같은 기전 시퀀스의 연결 컷·CTA 도
8초 invest 를 받는다.** 라우터가 이미 컷 단위로 가른 판정(`connective_in_world`)을
등급제가 우회하는 것 — "canonical router 를 우회하지 않는다"가 v2 의 제 1 원칙이다.

```
Visual Sequence ──→ sequence_quality_intent   (시퀀스 = 품질 의도)
                        ↓
resolved_visual_plan (라우터 정본 — base·reasons)
                        ↓
                  effective_tier               (컷 = 실행 품질 + 시간)
```

**invest 는 여섯 조건의 교집합이다** (리뷰 §6 채택):

```
invest iff
  ① sequence_is_progression(sequence) == true      (구조 판정 — 자기보고 아님)
  ② sequence_role == MECHANISM_SEQUENCE
  ③ resolved_visual_plan.base == MECHANISM_SEQUENCE (라우터 정본)
  ④ "connective_in_world" ∉ plan.reasons            (연결 컷 제외)
  ⑤ claim 연결 유효 (claim_ids ≠ ∅, 원장 대조 통과)
  ⑥ cut↔stage claim 불일치 경고 없음
```

하나라도 미달이면 standard/economy 로 내려가고 `tier_reasons` 에 사유가 남는다
(기본값도 정본으로 읽힌다 — §9-10 교훈. 판정 불가와 미달을 섞지 않는다).

## 4. 등급표 v2 — 길이가 아니라 Quality Profile (P1-1)

| | **invest** | **standard** | **economy** |
|---|---|---|---|
| 대상 | §3 여섯 조건 통과 컷 | RESULT·REALITY_ANCHOR + 기전 시퀀스 내 연결 컷 | FRAMING·CTA·시퀀스 밖·판정 불가 |
| 클립 길이 | **8s** | 4s | 4s |
| 시간축 계약 | **비트 2~3개 필수** · 카메라 플랜 필수 · 상태 변화 필수 | 비트 1~2 · 카메라 선택 | 단순 모션 |
| 후보 생성 | **2회 → 판정 선택** | 1회 | 1회 |
| 모델 | Lite (Fast 는 단가 확정 + G2 실측 후 표만 교체) | Lite | Lite |

> "8초를 주는 것과 8초를 제대로 사용하는 것은 다른 문제"(리뷰 §7) — 이 표의 실체는
> 길이 열이 아니라 **시간축 계약 + 후보 열**이다.

### Temporal Contract 의 형태 (요지 — 상세는 작업명세서 Phase E2)

invest 컷의 지시서는 `temporal_plan` 을 선언한다: 비트마다 [시간 구간 · 대상 개체 ·
변화(mutations 어휘) · 카메라(CAMERA_OPERATIONS 닫힌 enum)]. 예:

```
0.0–2.5s  구조 전체 wide reveal          (DOLLY_OUT)
2.5–5.5s  작동 부위 lateral follow       (TRACK)     + ORDER_BLOCK APPEAR
5.5–8.0s  핵심 부위 rapid push-in        (DOLLY_IN)  + BACKLOG_QUEUE GROW
```

★ **자기보고로 끝나지 않는다**(리뷰 §8 조건): `build_motion_prompt` 가 이 비트를
실제로 소비해 프롬프트를 만들고, 게이트가 [비트 수 · enum 준수 · 상태 변화 존재]를
검사한다. 만들어 놓고 prompt builder 가 안 읽으면 아홉 번째 "한쪽만 연결"이다.

### Candidate Selection 의 형태 (요지 — 상세는 Phase E3)

invest 컷은 같은 스펙으로 **2회 생성**하고, flash 멀티모달 판정(Phase 0 에서 검증된
경로)이 [선언한 변화가 보이는가 · 비트가 있는가 · 글자 번인 없는가 · 정지 비율]로
채점해 선택한다. 두 후보 모두 원장에 남는다(선택 근거 포함). 판정 실패 시 1번 후보
+ 경고(판정 불가 ≠ 실패).

## 5. 실행 계약 — VideoSpec 이 단일 진실원 (P0-2)

가장 위험한 "만들어 놓고 소비자가 안 읽는" 지점: provider 가 재판단한다.

```
Sequence / Router → Effective Tier
        ↓
   VideoSpec { tier, model, clip_sec, candidates, resolution, unit_price, generation_mode }
        ↓
   ┌─ cost_plan            (⑤ 가 보여주는 예상)
   ├─ 캐시 키              (등급 변경 = 의도된 재생성)
   ├─ generation ledger    (원장 — 예상 대 실제 대조 가능)
   └─ provider 실행        (재판단 금지 — pick_clip_tier 재호출·전역 모델 참조 제거)
```

> **예상한 스펙 = 발주한 스펙 = 기록한 스펙.** 넷이 갈라지는 순간 "예상 비용을 보고
> 조절한다"(운영자 확정)가 성립하지 않는다.

## 6. Legacy 강등·차단 경로 — 7개 전수 재분류 (P0-3)

"상한 3겹"을 폐기하고 실행 경로 전체를 인벤토리로 다룬다. 각 경로는
[삭제 / 경고화 / 사전 fail-fast / 유지] 중 하나로 분류하고 **유지 사유를 코드
위치와 함께** 기록한다. 분류표는 작업명세서 Phase C 에 있다 — 요지:

- 품질을 몰래 바꾸는 것(선착순 강등·motion 게이트의 video→still)은 **삭제 또는 경고화**
- 돈이 나가기 전에 멈추는 것(preflight·approvalGate)은 **fail-fast 로 강화·유지**
- 렌더 도중 죽는 것(render_budget_cap RuntimeError)은 **사전 검사로 이동** — §7

## 7. 비용 정책 — 자동 강등 금지 + 사전 fail-fast (P0-4)

리뷰가 지적한 최악 시나리오: 운영자가 ⑤ 에서 승인했는데 **렌더 도중** $4 캡을 넘어
RuntimeError — 쓴 돈은 사라지고 영상은 없다. "조용한 강등보다 나쁜 실패"에 동의한다.

| 정책 | 내용 |
|---|---|
| 품질 | 비용 이유의 자동 강등 **금지** (8s→4s 금지 · video→still 금지 · 후보 2→1 금지) |
| 발주 전 | `preflight` 가 VideoSpec 합산 예상비를 캡과 대조 — 넘으면 **첫 유료 호출 전에 중단**. 운영자 명시 override(`?force=` 아님 — 서버 기록 남는 기존 강제승인 관례)로만 진행 |
| 렌더 중 | 기존 RuntimeError 는 **최후 안전선으로 유지하되** 캡을 품질 구성 예상비 + 여유로 상향(작업명세서 Phase C 값) — 정상 편이 도중 사망하지 않게 |
| 관측 | ⑤ 가 시퀀스별 표 + 편 총액 표시(§14 wiring matrix 전체 배선) · 원장으로 예상-실제 대조(G1) |

## 8. 예상 비용 (품질 우선 구성 — 관측치, 강제 아님)

12컷 photo 편, video-first 구성 가정:

| 항목 | 계산 | 비용 |
|---|---|---|
| invest 4컷 (8s × 2후보) | 4 × 2 × 8s × $0.05 | $3.20 |
| standard 4컷 (4s) | 4 × 4s × $0.05 | $0.80 |
| economy 4컷 (4s) | 4 × 4s × $0.05 | $0.80 |
| 시작 이미지 ~12장 | 혼합 단가 | ~$0.5–1.2 |
| **편당 합계** | | **~$5.3–6.0** |

현행 photo 캡 $4.0 초과 → 캡 상향 필수(Phase C). 운영자 확정 원칙: **이 숫자를 보고
등급표·후보 수·캡을 조절한다** — 조절 손잡이는 전부 config 상수다.

## 9. video-first (전부-영상이 아니라) — 리뷰 §10 채택

목표는 "모든 컷의 video 플래그"가 아니라 **시청자가 정적이라고 느끼는 순간이 없는 것**:

- 핵심 설명·기전 진행·결과 reveal → 생성 영상
- 단순 브릿지 → 짧은 영상 / 크롭·카메라 파생 / 재사용 (Veo 를 CTA 에 쓰지 않는다)
- 숫자·근거 → 오버레이 (기존 원칙 유지)

`ALL_VIDEO_VERSIONS` 스위치는 `VIDEO_FIRST_VERSIONS` 로 바꾼다 — 의미가 다르다.

## 10. I2V 연쇄 — world_ref 만으로 부족 (P1-2)

- 연쇄 허용: `prev.world_ref 존재 ∧ cur.world_ref 존재 ∧ 동일` — **None==None 은
  연쇄가 아니다**(리뷰 §11 문제 1).
- **`max_chain_depth = 2`**: 생성물을 다시 anchor 로 쓰는 깊이를 제한하고, 초과 시
  원본 anchor 로 rebase(리뷰 §11 문제 2 — 8s 가 길수록 드리프트 누적 위험).
- 원장 기록: `chain_depth · chain_reset_reason · world_ref · sequence_ref · anchor_asset_ref`.
- 연속성 ≠ 품질 전체(리뷰 §12): G3 평가에 motion richness 가 연속성과 **동급**으로
  들어간다 — 연속성 제약이 화면을 정적으로 만드는지 명시적으로 본다.

## 11. 실측 설계 (리뷰 §15~16 채택 — 상세는 작업명세서 Phase G)

- **G1 무료:** 배선·비용 정합(cost_plan = VideoSpec = 원장).
- **G2 유료:** **동일 시작 이미지·프롬프트·모델에서 4s vs 8s paired A/B** — 비교
  대상 없는 1편 렌더로는 8초 효과를 말할 수 없다.
- **G3 유료:** **Quality Parity Gate** — 벤치마크 영상과 나란히 놓고 정량 지표
  [Visual Change Rate · Static Hold Ratio · Camera Beat Density · Repetition Rate ·
  Mechanism Progress Coverage] + 운영자 정성 판정.
- **G4 유료:** invest 1발 vs 2발-선택 paired 비교 — **후보 선택의 효과가 길이 효과보다
  크면 v2 예산은 길이가 아니라 후보 수에 투자한다**(리뷰 §9 그대로).

표본 1~2의 한계를 안다: G2~G4 는 "효과 있음/없음"의 방향만 판정하고, 크기는 운영
누적 데이터로 본다. 지표가 인상평을 대체하는 것이지 운영자 눈을 대체하지 않는다
(리뷰 §14 원칙 — "최종은 운영자 눈" 유지).

## 12. 리뷰 최종 질문 3개에 대한 답 (§22)

1. **invest=8s 만으로 품질 차이가 만들어지는가?** 아니다. temporal_plan·카메라 비트를
   **tier 계약에 포함**했다(§4). 길이는 시간 예산이고 계약이 연출이다.
2. **후보 생성/선택 계층이 필요한가?** 필요하다. 운영자 품질 우선 확정에 따라
   **v1 부터 invest 에 기본 켬**(2후보), G4 가 효과 크기를 측정해 후보 수를 조절한다.
3. **Quality Parity Gate 통과를 v1 완료 조건으로 보는가?** 그렇다. G3 통과 전에는
   "돌아간다"고만 말하고 "품질이 됐다"고 말하지 않는다.

## 13. 운영자 확정 사항 (이 기획의 전제)

- **품질 우선.** 품질 장치(8s·temporal contract·2후보)는 기본 켬. 비용은 관측하고
  나중에 조절한다.
- 조절 손잡이: 등급표(§4) · 후보 수 · 캡 — 전부 config. 실측 후 운영자가 고친다.
- 유료 실측(G2~G4)은 기존 규율대로 **착수 전 예상 비용 보고·승인**.

## 14. 하지 않는 것

- 컷 → 시퀀스 구조 전환(TTS·자막·clip_fit 은 컷 유지 — 리뷰도 동의)
- 새 파이프라인 · 새 DB 테이블(전부 기존 JSONB·meta 확장)
- Fast 모델 활성화(단가 미확정 + G2 전)
- 자동 예산 배분·강등 사다리(v2 유보 — G 실측 데이터가 입력)
- 만화식·설명판형 라인 변경(등급제는 `SEQUENCE_TIER_VERSIONS` 에 든 버전만)
