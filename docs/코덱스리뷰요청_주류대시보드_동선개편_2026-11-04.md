| **한 소재의 일이 다섯 화면에 흩어진다** | 고르기 `/discover` → 근거·대본 `/review/[id]`(탭 7개) → 제작 `/production/[planId]` → 발행 `/publish` → 성과 `/analytics` | 논문 공장은 2026-09-11 에 이것을 한 화면(`WorkspaceClient`)으로 합쳤다. 주류는 합치기 전 모양 그대로다 |
| **홈에 "다음 할 일"이 없다** | `/drinks`는 필터·탭·카운터가 있는 목록. 논문 홈의 `NextActionCard`(다음 작업 한 장) + 타일 3개가 없다 | 들어와서 무엇부터 눌러야 할지 화면이 말해 주지 않는다 |
| **"수집" 메뉴가 운영자용과 개발자용이 섞여 있다** | 커뮤니티 동향(읽기만)·수집 문서·수집원·실행 기록은 매일 볼 필요가 없는 자료·설정이다 | 메뉴 여섯 개 중 넷이 결정과 무관 |
| **승인 두 번, 결재 따로** | 근거 승인(브리프 탭) + 제작안 승인(형식 탭)이 따로. 0064 `approve_content`가 한 번으로 합쳤지만 화면은 "내용 승인" 탭 하나로만 노출 | 총괄계획 §7 결정 2("한 번으로 합쳐")가 화면에 다 반영되지 않았다 |

### 1-3. 이미 있는 것 — 다시 만들지 않는다

- **DB·RPC:** 소재 고르기 `drinks_pick_topic`([이걸로] — 승격·조사 시작·형식 의도·주차·예산·초안 요청을 한 트랜잭션으로), 내용 승인 `drinks_approve_content`(근거·편성·제작안 승인을 한 번에), 제작 `request_render`/설명형 큐, 발행 `create_publication`/`publication_action`, 밈 `meme_*`. 전부 있다.
- **형식 추천 규칙:** `web/lib/drinks/formatRecommend.ts`(0원, 질문 모양·신호·근거 수로 설명형/카드/밈/모름). 후보마다 이미 계산된다.
- **소재별 다음 행동:** `web/lib/drinks/model.ts::nextAction()`. 작업함 목록과 상세 배너가 쓴다.
- **논문 공장의 틀:** `WorkspaceClient`(결정 바 하나 + 본문 + 접힌 렌더 패널), `lib/work/decision.ts`(상태표 → 주 버튼 하나, 시험으로 고정), 홈 `NextActionCard`+`WorkSummary`.
- **쓰기 경로:** 모든 버튼이 `POST /api/drinks` 하나로 간다(`DRINKS_ACTIONS` 허용 목록). 새 화면도 이 길만 쓴다 — 새 쓰기 권한을 만들지 않는다.

## 2. 목표 — 사람이 누르는 자리 셋을 한 줄로

```
[홈]  오늘 할 일 한 장 ──┐
                        ▼
[소재]  후보 530건 중 고른다 ─── [이걸로 + 형식] ──▶ 자동: 근거 → 대본 → 지시서 → 견적
                                                          │
[작업공간 /drinks/work/<소재>]  대본·근거·견적을 한 화면에서 보고 ── [승인] ──▶ 자동: 제작
                                                          │            (설명형만: 훅 후보 2개 중 1개 [선택])
                                 완성본 재생·캡션·음원·시각 ────────── [예약] ──▶ 자동: 게시 → 성과
```

- 사람이 누르는 버튼은 **[이걸로] · [승인] · [예약]** 셋이다(설명형은 [선택] 하나 더). 총괄계획 §0 과 같다.
- 세 버튼이 **두 화면**에만 있다: [이걸로]는 소재 화면, [승인]·[선택]·[예약]은 그 소재의 작업공간.
- 형식 3개는 **소재 화면에서 갈라져(형식 칩) 작업공간 안에서 레인으로 이어진다.** 밈도 소재(topic)로 승격시켜 같은 작업공간을 쓴다(0064 가 이미 `format_intent=meme` 소재를 허용한다 — 다만 밈은 `selected` 상태로 가지 않으므로 레인이 다르다).

## 4. 화면 명세

### 4-1. 홈 `/drinks` — "오늘"

위에서 아래로:
1. **다음 작업 카드** (논문 `NextActionCard` 와 같은 자리). 우선순위:
   ① 게시 직전 막힘·실패(paused/failed) → ② 결과 불명·결재 소진(unknown_billed·budget) → ③ 설명형 훅 후보 선택 대기 → ④ 완성본 게시 승인 대기 → ⑤ 내용 승인 대기(대본 완성) → ⑥ 이번 주 목표에 못 미친 형식의 소재 고르기. 카드에는 소재 제목·형식 칩·버튼 하나(해당 작업공간으로).
2. **타일 3개**: [고를 후보 N] → `/drinks/topics` · [승인 기다리는 것 N] → `/drinks/work?filter=approve` · [게시·확인 필요 N] → `/drinks/work?filter=publish`.
3. **이번 주 진행표**: 형식 3줄(설명형 0/1~2 · 카드 0/5 · 밈 0/3 — §7 결정 3 의 목표 속도). 칸마다 고름/승인/제작/게시 네모. 
4. **수집 건강 한 줄**(지금 있는 `loadRunHealth` 그대로) + 막힌 것(토큰 만료 임박·결재 소진·크론 꺼짐).

### 4-2. 소재 `/drinks/topics` — "고르는 곳"

- **탭:** 후보 / 내 소재 / 밈 카드 / 보류·제외. 기본은 **후보**. 상단에 형식 필터 칩(전체·설명형·카드·밈)과 주종 필터.
- **후보 카드**(지금 `/discover` 카드 + 정리): 질문 한 줄 · 추천 형식 칩(이유 한 줄, `formatRecommend`) · 근거 수(`drinks_candidate_evidence_counts`) · 신호(어디서 몇 번) · 중복 경고. 버튼은 **[이걸로 ▾]** 하나 — 누르면 형식(추천값 기본)·주차·예산을 확인하는 작은 모달 → `pick_topic`. [넘기기]는 보조 메뉴.
- **밈 카드 탭**: IG 트렌드 카드(`drink_ig_board_cards`). [쓰자] = `ig_card_decide(use)` + 밈 소재 승격(`pick_topic` format=meme) → 작업공간으로. 카드가 0장이면 **왜 0장인지**(관찰 계정 체크 여부·마지막 수집 결과)를 카드 자리에 띄운다 — 지금은 빈 화면이다.
- **내 소재 탭**: 진행 중 소재를 형식 칩·단계 칩(고름/대본/승인/제작/게시)·다음 행동과 함께. 클릭 → 작업공간.
- 손으로 넣는 소재·링크(`RegisterForm`, `add_discovery`)는 탭 위 접힌 영역으로.

### 4-3. 작업공간 `/drinks/work/[topicId]` — "만들기"

논문 `WorkspaceClient` 와 같은 뼈대. **공통 결정 바(sticky)** + **레인 본문** + **접힌 패널 2개(제작 / 게시)**.

**결정 바:** 왼쪽에 형식 칩·단계 칩·경고(근거 철회·대본 재검사 필요·결재 잔액·결과 불명). 오른쪽에 **주 버튼 하나**(§5 결정표가 정한다)와 ▾ 메뉴(다시 쓰기·보류·되돌리기).

**레인 본문 — 형식마다 다르다:**

| 단계 | 설명형 | 카드뉴스 | 밈 |
|---|---|---|---|
| 근거 | 근거표(원문 인용·뒷받침 확인 `support_review`) — 공통 | 같음 | 정보 밈만. 농담 밈은 "근거 없음(농담)" 표시 |
| 대본 | 40~55초 장면표(나레이션·시각 주장·그림/영상 지시·근거 번호) + **견적**(장면별 단가·합계·상한) | 카드 4~12장(제목·본문·근거 번호) + 릴스 훅·공유 문장 | 비트 2~3개 글 + 틀(위 글/꽉 찬 제목) + 소리 등급 |
| 승인 | **[승인 $N]** — 승인이 곧 결재(approved_amount_usd) | **[승인]** (0원) | **[승인]** (0원, 반응 장면 사면 $0.45) |
| 제작 패널 | 후보 2개 재생 → **[이 장면으로]** 선택 · 시도/결과 불명/닫기 | 렌더 상태·페이지 미리보기·릴스 미리보기 | 렌더 상태·미리보기 |
| 게시 패널 | 완성본 재생 · 품질 6항목 · 캡션(AI 표기 필수) · 시각 → [예약] | 캡션 · **음원 고르기(필수)** · 시각 → [예약] | 캡션 · 시각 → [예약] / 박자 밈은 "앱에서 붙이기" 안내 |

- 근거를 고치면 대본 레인이 "무효 — 다시 쓰기"로 바뀌고 주 버튼이 [대본 다시 쓰기]가 된다(§7 결정 2 구현 조건).
- 지금 `/review/[id]` 의 탭 7개(요약·내용 승인·근거·공통 기획·영상·카드뉴스·이력)는 **없앤다.** 이력은 ▾ 메뉴의 접힌 패널로.
- `/production/[planId]` 의 제작 화면(`ProductionControls`·`ExplainerProduction`)은 **그대로 제작 패널 안으로 들어간다**(컴포넌트 재사용).

### 4-4. 발행 `/drinks/publish` — "큐"

- 발행안 만들기 폼을 작업공간으로 옮기고, 여기는 **예약 달력(이번 주 07:00~23:30 칸)·계정 상태·게시됨/실패** 만 남긴다.
- 지금 있는 탭(확인 필요·작성·예약·게시됨·취소)은 유지.

### 4-5. 자료·설정 `/drinks/data`

커뮤니티 동향·수집 문서·수집원·실행 기록·트렌드 수집 상태(관찰 계정·음원·토큰)를 **탭 하나의 화면**으로. 기능은 지금 그대로, 자리만 옮긴다.

## 7. 하지 않는 것

- 승인·결재·게시 규칙을 약하게 하지 않는다. 버튼을 합치는 것이지 검사를 빼는 것이 아니다. 막는 것은 여전히 DB 다.
- 유료 실행·공개 게시·크론 켜기는 이 작업에 없다. 화면만 바꾼다.
- 설명형 영상 엔진·밈 엔진·수집기는 건드리지 않는다(이번 리뷰 수정 PR #142 범위와 겹치지 않게).
- 새 쓰기 경로를 만들지 않는다. 모든 버튼은 `POST /api/drinks` 허용 목록을 지난다.
- 라이트 모드·접근성·논문 공장 쪽 변경은 범위 밖.
