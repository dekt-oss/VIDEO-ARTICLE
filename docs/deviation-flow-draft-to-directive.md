# 편차 기록 — ④ 초안 → ⑤ 지시서 동선 통합 (2026-08-19)

## 무엇이 문제였나 (운영자 보고 + 실측)
"초안 생성하고 작업지시서 세부로 넘어갈 때가 잘 안 된다. 한 화면에서 한 번에 안 되고
메뉴 들어가서 다음으로 넘어가는 일이 많다."

코드·DB·화면을 확인해 원인을 5개로 갈랐다.

1. **진행 상태가 브라우저 메모리에만 있었다.** `useGeneration` 이 폴링을 들고 있어서,
   새로고침하거나 다른 메뉴를 다녀오면 상세 화면이 "아직 초안이 없습니다"로 돌아갔다.
   목록 화면은 `request_status` 로 "생성 중"을 보여주는데 상세만 몰랐다.
2. **폴링 제한이 6분이었다.** 큐 실측(초안 59건·지시서 37건)의 중앙값은 46초·80초지만
   상위 10%가 203초·276초다. 조금만 느려지면 "지연되고 있습니다"가 떴다.
3. **④ → ⑤ 이동이 긴 페이지 맨 아래 링크 하나였다.** 논문 라인에는 승인 후 안내 배너가
   있었지만 리포트 라인에는 없었다.
4. **⑤ 화면이 공장마다 둘이었다.** 논문은 `/review/[id]?step=5`(단계 표시줄 + 발주 바)와
   `/directive/[id]`(둘 다 없음)가 공존했고, **상단 메뉴는 기능이 적은 쪽**으로 갔다.
   리포트는 ⑤ 가 아예 다른 라우트(`/finance/directive/[id]`)였다.
5. **리포트 홈이 12일 전 배치를 열었다.** 홈 기본값이 "확인 처리 안 한 가장 오래된 날"이라,
   확인이 밀리면 계속 과거가 뜬다(실측: 미확인 8일).

## 무엇을 바꿨나
- **큐 상태를 서버가 내려준다.** `getReportDraftPending` / `getReportDirectivePending`
  (논문은 `getDraftPending` / `getDirectivePending`). 화면은 이 값을 `useGeneration` 의
  `resumeFrom` 으로 받아, 누른 적이 없어도 진행 중이면 폴링을 이어붙인다.
- **폴링 제한 6분 → 12분.** 타임아웃 문구도 "다시 열면 이어집니다"로 바꿨다.
- **④ 에 [승인하고 ⑤ 지시서 만들기 →] 를 만들었다.** 승인 + 지시서 발주 + ⑤ 이동이 한 번에
  일어난다. 승인만 하고 싶으면 [승인만] 버튼이 따로 있다.
- **리포트도 한 라우트로 통합.** `/finance/review/[id]?step=4|5|6`. 기존
  `/finance/directive/[id]` 와 논문 `/directive/[id]` 는 새 주소로 넘긴다(라우트 유지).
- **홈 기본값을 최신 배치로.** 밀린 날은 새 상단 바에서 정리한다.

## 홈 상단 배치일 바(BatchDateBar) — 운영자 요청
확인 처리 버튼이 페이지 **맨 아래 접힌 패널** 안에만 있었고, 확인 → 다음 날짜 이동이 두
동작이었으며, 며칠 밀리면 하루씩 열어 하루씩 눌러야 했다. 셋을 한 줄로 합쳤다:

    [←] 오늘 (2026-08-19) [→] [오늘로]      [밀린 9일 한번에 확인] [✓ 확인하고 다음 날짜로 →]

- `[✓ 확인하고 다음 날짜로]` = 확인 처리 + 남은 미확인 중 가장 오래된 날로 이동(한 번에).
- `[밀린 N일 한번에 확인]` = 날짜 체크 목록 모달 → 선택한 날을 한 번에 확인 완료.
  API 는 `batch_dates: string[]` 를 받는다(기존 `batch_date` 단건도 그대로 받는다).
- 확인 완료 상태에서는 `[✓ 확인 완료 · 되돌리기]` 로 바뀐다(잘못 눌렀을 때).

## 함께 고친 것 — "세부 수정 요청"이 버려지던 문제
리포트 ④ 화면의 수정 요청 입력칸은 **아무 데도 저장되지 않았다**(라우트가 읽기만 하고 큐에
넣지 않았고, 큐 테이블에 칸도 없었다). `0038` 로 `report_draft_requests.instruction` 을
추가하고 라우트 → 큐 → 워커 → `report_scriptgen.generate(fact_sheet, instruction, …)` 까지
이었다. 파리티는 `tests/test_schema_parity.py::test_draft_request_queue_carries_instruction`
이 지킨다.

### 배포 순서 (중요)
`0038` 을 **먼저** 적용하고 웹을 배포하는 것이 정상 순서다. 다만 거꾸로 돼도 화면이 죽지
않도록 양쪽에 폴백을 뒀다 — 라우트는 컬럼이 없으면 지시 없이 큐에 넣고 경고를 로그에
남기고, 워커도 `instruction` 없는 select 로 후퇴한다. 폴백이 도는 동안 수정 요청은 무시된다.
