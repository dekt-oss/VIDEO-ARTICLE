# 벤치마크 구조 분석 — 신비한 건축사전 「죽음의 호수가 세계 최대 발전소가 된 방법」

분석 **2026-09-04** · 운영자 제공 화면녹화 3편(37.1s + 33.1s + 35.0s = **105초**)
방법: 프레임 추출(1.5초 간격 72장) + 장면전환 검출 + 프레임간 변화량 실측

> 앞선 Apify 벤치마크(`benchmark-realistic-shorts-2026-08-19.md`)는 **메타데이터와 제작법**을
> 봤다. 이 문서는 **화면 자체**를 본다 — 그때 못 본 것이 여기 있다.

---

## 1. 서사 구조 — 105초가 하나의 인과 사슬이다

| 구간 | 초 | 무엇 | 기능 |
|---|---|---|---|
| **훅** | 0~4 | "세계 최대 조력발전소, 시화호" | 결론을 **먼저** 보여준다 |
| **반전** | 4~10 | "30년 전엔 **썩었습니다**. 철새도 떠난 바다" | 예측 오류 — 최고↔최악 |
| **배경** | 10~19 | 1987년부터 7년, 12.7km 방조제, 농업용수 계획 | 왜 그렇게 됐나의 전제 |
| **원인** | 19~22 | "물길이 끊긴" → 폐수·생활하수 유입 | **기전 1** |
| **증거** | 22~29 | 손으로 뜬 물 → 유리병 → 계기판 **17.4mg** → "두 배가 넘는" | 수치를 실물로 |
| **실패한 시도** | 29~37 | 수질개선 투입 → **✕ "효과가 없었습니다"** | 긴장 유지 |
| **원인 재정의** | 37~45 | "오염이 아니라 **호수 자체**가 문제" | **기전 2 — 진짜 원인** |
| **포기** | 45~52 | 2001년 민물 호수 계획 **공식 포기** | 바닥 |
| **딜레마** | 52~60 | "되돌리지도 ✕✕ 못한다" | 왜 쉬운 답이 없나 |
| **해결 원리** | 60~72 | 방조제에 **구멍** → 그 구멍에 **터빈** → 밀물이 돌린다 | **기전 3 — 해법** |
| **공사** | 72~80 | 2004년 착공, 3,551억 원 | 규모 |
| **결과** | 80~92 | 254MW · 552GWh · 50만 도시 · **세계 1위** | 숫자로 증명 |
| **부수 효과** | 92~102 | 큰고니 등 천연기념물 복귀, 전망대 | 감정 마무리 |
| **닫기** | 102~105 | "바다를 막아서 그 바다를 다시 얻어냅니다" | 훅과 수미상관 |

**핵심: 기전이 세 번 나온다.** 원인(물길 차단) → 재정의(호수 자체) → 해법(구멍+터빈).
"3D 도해로 원리를 설명한다"가 곧 **이 세 지점을 그리는 것**이다.

## 2. 시퀀스 구성 — 세계는 하나, 축척만 바뀐다

105초 내내 **시화호라는 단 하나의 세계**에 머문다. 장면 전환 검출로도 하드 컷이
샘플당 6~9회뿐이었다(37초에 6회). 나머지는 **같은 세계 안에서 카메라가 이동**한다.

바뀌는 것은 **축척**이다:

```
광역 부감(방조제 12.7km 전체)  ←→  중경(농지·도시 배치)  ←→  근접(물 한 컵·터빈 날개)
```

- 22.5s 손이 물을 뜬다 → 24.0s 유리병 클로즈업 → 25.5s 계기판
  **광역에서 손바닥까지 3초 만에 내려온다.**
- 60s대 방조제 외벽 → 단면 절개 → 터빈 내부 → 물이 통과
  **바깥에서 안으로 파고든다.**

우리 지시서가 시퀀스마다 **다른 세계**(MODERN_OFFICE → AD_REVIEW_STATION → SOCIAL_MEDIA_USER
→ CONFERENCE)를 만든 것과 정반대다.

---

## 3. 컷 리듬 — 자막 1.5초, 카메라는 안 끊긴다

- 자막이 **약 1.5초마다** 바뀐다(72장 표본에서 거의 매 장이 다른 문장).
- 그런데 **화면은 안 끊긴다** — 카메라가 계속 흐르고 그 위에 문장만 갈린다.
- 즉 **"컷 = 자막 한 줄"이 아니라 "샷 하나 안에 자막 여러 줄"**이다.
  Apify 문서가 말한 "한 컷에 2~3샷"의 실체가 이것이다 — 반대로 **한 샷에 자막 2~3줄**.

우리는 컷마다 클립을 새로 생성해 4~6초씩 붙인다. 그래서 컷 경계마다 세계가 흔들린다.

프레임간 변화량 중앙값(자막·UI 영역 제외, 화면 중앙 72%만):

| | 중앙값 | 상위 10% | 거의 정지 프레임 |
|---|---|---|---|
| 벤치 샘플1 | 0.0078 | 0.057 | 7.6% |
| 벤치 샘플2 | 0.0134 | 0.067 | 3.8% |
| 벤치 샘플3 | 0.0150 | 0.095 | 2.8% |
| **벤치 전체** | **0.0117** | — | — |
| **우리 첫 렌더** | **0.0012** | 0.0028 | — |

**9.5배.** 우리 컷별 값은 0.0005~0.0028인데, 가장 많이 움직인 컷조차 벤치 중앙값의 1/4이다.
운영자가 말한 "역동적으로 움직여야 한다"가 이 숫자다.

## 5. 3D 도해가 "이해하기 쉬운" 이유 — 넷

**① 지형을 실제 지도처럼 그린다.** 추상 도형이 아니라 **시화호의 실제 형태**를 위에서
   본다. 방조제 12.7km가 화면을 가로지르고, 어디가 바다이고 어디가 호수인지 한눈에 보인다.

**② 단면을 열어 안을 보여준다.** 방조제 외벽 → 콘크리트 단면 → 그 안의 터빈 → 물이
   통과하는 경로. 60~72초 구간이 통째로 이 절개다.

**③ 수치를 실물 크기로 만든다.**
   - `12.7km` — 방조제 위에 **붉은 선**을 긋고 그 옆에 숫자
   - `17.4mg` — **계기판 다이얼**을 그려 바늘을 그 위치에
   - `254MW`·`552GWh` — 화면 상단에 **화면 폭의 60%** 크기로
   우리 오버레이 카드는 화면 하단에 작게 들어간다. **크기 자체가 메시지다.**

**④ 붉은색 하나로만 강조한다.** 붉은 원(오염 지점) · 붉은 화살표(물 흐름) · 붉은 ✕(실패) ·
   붉은 사각(터빈 위치) · 붉은 치수선. **다른 강조색이 없다.**
   우리는 앰버 강조 + 파란 홀로그램 + 초록 UI가 섞였다.

## 6. 우리 첫 렌더와의 차이 — 표로

| | 벤치 | 우리 |
|---|---|---|
| 세계 | **1개**(시화호), 축척만 변화 | 4개(사무실·리뷰대·폰·회의실) |
| 화면 변화량 | 0.0117 | **0.0012** (1/9.5) |
| 기전 도해 | 3회(원인·재정의·해법) | 2컷, 그나마 아이콘 등장 |
| 수치 표현 | 화면 폭 60% + 실물(계기판·치수선) | 하단 작은 카드 |
| 강조색 | 붉은색 **하나** | 앰버 + 파랑 + 초록 혼재 |
| 컷↔자막 | 한 샷에 자막 2~3줄 | 컷 1개 = 자막 1줄 |
| 사람 | 손·실루엣 정도, 주인공은 **구조물** | 마네킹이 화면 중앙 |
| 서사 | 인과 사슬 1개(105초) | 나열(연구→결과→시사점) |

## 7. 계약에 넣을 것 (제안)

이번에 이미 넣은 것:
- ✅ 카메라 최소 하나는 `HOLD` 아님 · 비트마다 다른 카메라 · 실제 변형 최소 1개

여기서 새로 나온 것:

1. **세계 수 상한** — 60초 영상에 세계 4개는 너무 많다. `world_reset_rate` 경고가 이미
   있으나 실사형 기준선이 없다. 벤치는 105초에 **1개**다.
2. **축척 이동을 계약에** — 시퀀스 안에서 `광역 → 중경 → 근접`이 최소 한 번 일어나야
   한다. 지금 `camera_base` 토큰(`close_detail` 등)은 있는데 **요구하지 않는다**.
3. **수치 오버레이 크기** — `number_punch` 를 화면 폭 기준으로 크게. 지금은 카드다.
4. **강조색 1개 강제** — 실사형 화풍에 이미 "single amber accent" 가 있는데, 생성 이미지의
   파란 홀로그램·초록 UI가 그것을 무시했다. 세계 게이트가 홀로그램을 막았으니 절반은 해결.
5. **움직임 하한을 렌더 QA로** — `motion_median < 0.004` 면 경고(벤치의 1/3). 지금
   `clip_metrics` 가 기록만 하고 문턱이 없다. **표본이 생겼으므로 이제 정할 수 있다.**
6. **서사 골격을 대본 단계에** — 훅 → 반전 → 원인 → 증거 → 실패한 시도 → 해법 → 결과.
   지금 `content_plan` 은 근거 단위(E1~E7)만 보고 **인과 순서를 요구하지 않는다.**

## 8. 정직하게 — 이 분석의 한계

- **화면녹화라 UI가 섞여 있다.** 변화량은 중앙 72%만 잘라 쟀지만 자막 애니메이션이
  일부 포함된다. 다만 9.5배 차이는 그 오차로 뒤집히지 않는다.
- **3편이 한 영상의 연속 구간**이다. 다른 편·다른 채널로 일반화하지 않는다.
- **제작 도구를 모른다.** Apify 문서의 튜토리얼이 "Veo 계열, 8초 생성 후 좋은 3초"라고
  했으나 이 영상이 그 방식인지는 확인 못 했다.

## 9. 적용 — 이 분석으로 실제로 고친 것 (2026-09-04)

분석만 남기지 않는다. 같은 날 코드에 들어간 변경이다.

### ★ 가장 큰 발견은 움직임이 아니라 **대본에 원리가 없다**는 것이었다

이 저장소의 지시서 JSON **20개를 전부 세어 보니 `evidence_role='mechanism'` 이 0개**였다.
100%다. 그런데 같은 프롬프트가 **그림에는** "MECHANISM 도해 컷 5~7개"를 요구한다.

> **말은 원리를 한 번도 설명하지 않는데, 그림에만 원리를 그리라고 시켰다.**

운영자가 첫 렌더를 보고 한 말 — "3d 도해나 원인과 원리를 설명하는 내용과 전혀 상관없는
의미없는 화면" — 은 화풍 문제가 아니었다. **그릴 원리가 대본에 없었다.**

실제 그 지시서 13컷의 흐름:

```
훅 → 출처 → 규모 → 결과 → 결과 → 결과 → 규모 → 시사점
```

인과가 한 번도 없는 **결과 나열**이다. 벤치가 기전을 세 번 설명한 것과 정반대다.

| 고친 것 | 어디 | 무엇 |
|---|---|---|
| 서사 골격 처방 | `engine/directive.py` `PHOTO_NARRATIVE_ARC` | 훅→반전→원인→증거→시도→**원리**→결과. `mechanism` 컷 최소 2개(원인 하나, 해법 하나). 좋은 예/나쁜 예를 문장으로 못박음 |
| 감시 | `engine/photo_contract.py` | `photo_narrative_no_mechanism` — **경고**(차단 아님) |
| 상수 | `engine/config.py` | `PHOTO_MIN_MECHANISM_EVIDENCE_CUTS = 2` |

**왜 차단이 아니라 경고인가:** 20/20이 걸린다. 지금 차단하면 생산이 통째로 멈춘다 —
`series_split` 이 근거 있는 초안 10건을 100% 막았던 사고와 같다. 프롬프트를 먼저 고쳤고,
**새 지시서 10건 중 8건이 mechanism 컷 2개 이상을 낼 때 차단으로 승격**한다(조건을
코드 주석에 적어 뒀다).

### 움직임 — 기준선이 생겨서 문턱을 걸 수 있게 됐다

| 고친 것 | 값 | 근거 |
|---|---|---|
| `CANDIDATE_MOTION_MEDIAN_TARGET` | 0.0037 → **0.0117** | 그 상수의 주석이 직접 "더 좋은 클립이 나오면 올린다"고 예고했다. 벤치가 그 클립이다 |
| `CLIP_MOTION_MEDIAN_FLOOR` (신설) | **0.0039** (벤치의 1/3) | 우리 첫 렌더 13컷이 전부 여기 걸린다(최고 0.0028) |
| `render_qa.evaluate_clip_motion` (신설) | 경고 | `clip_metrics` 가 **기록만** 하고 문턱이 없었다 |

### 놓칠 뻔한 부작용 하나 — 테스트가 잡았다

타깃을 올리자 점수 단위가 0.316배로 압축돼, **눈으로 확인된 차이가 있던 클립 쌍이
"차이 없음"으로 넘어갔다**(G2 격차 0.1297 → 0.0410, 문턱 0.05 아래).
자를 바꿔 놓고 눈금을 안 옮긴 것이라, `CANDIDATE_MEANINGFUL_GAP` 을 같은 배수로
재교정했다(0.05 → 0.0158). **이 변경으로 어떤 쌍의 판정도 달라지지 않는다** — 그게 목적이다.

> 나는 이 상향이 "랭킹을 뒤집지 않으니 안전하다"고 적었다. 랭킹은 맞았지만
> **"의미 있는 격차"의 판정은 안전하지 않았다.** 두 상수가 묶여 있다는 사실을
> `tests/test_clip_candidates.py` 의 실측 격차 검사가 잡아냈다.

### 아직 안 한 것 (§7 제안 중)

- **세계 수 상한** — 벤치 105초에 1개, 우리 60초에 4개. `VSEQ_WORLD_RESET_WARN` 은 있으나
  실사형 기준선이 없다.
- **축척 이동 요구**(광역→중경→근접) — `camera_base` 토큰은 있는데 요구하지 않는다.
- **수치 오버레이 크기** — 벤치는 화면 폭 60%, 우리는 하단 카드.
- **강조색 1개 강제**.

## 10. §7 나머지 적용 완료 + 전체 재점검 (2026-09-04, 2차)

### 적용한 것 넷

| 항목 | 지표 | 문턱 근거 | 히트율 |
|---|---|---|---|
| **세계 밀도** | `worlds_per_minute` | 벤치 0.57/분 · 좋았던 달 클립 지시서 0.86~1.25/분 · 화면이 나빴던 성격조합 3.38~6.12/분 | **50%** — 판별력 있음 |
| **축척 사다리** | `close_detail` 유무 | 벤치는 광역 12.7km→손바닥까지 3초 | 94% → 경고 |
| **수치 크기** | 72px → **110px** | 실측 48건 중 73%가 110px에서 한 줄 | — |
| **수치=문장 금지** | `overlay_text_lines` | number_punch 최장 28자였다 | 소수 |

**세계 밀도는 다른 셋과 성격이 다르다.** 100%가 아니라 50%만 걸리고, 결정적으로
**알려진 좋은 것(달 클립 지시서 4종)을 통과시키고 나빴던 것(성격조합 5종)만 잡는다.**
문턱이 실제로 판별하는 유일한 지표다.

> 이름을 `world_reset_rate` 로 하지 **않았다** — `visual_sequence_contract` 에 같은 이름의
> 다른 지표(new_worlds / stage 수)가 이미 있다. 두 곳이 같은 이름으로 다른 숫자를 말하면
> 이 저장소가 반복해 겪은 이중 정의 사고가 된다.

### 재점검이 찾아낸 것 — 만들어 놓고 안 쓰던 것 셋

**① 경고가 화면에 코드 이름 그대로 나가고 있었다.**
`mode_warnings` 를 `join(" · ")` 로 뿌려서 운영자가 `photo_world_churn:3.38/분` 을 봤다.
`blockLabels.ts` 에는 **차단 라벨만** 있고 경고 라벨이 없었다.
→ `WARNING_LABEL` + `warningLabel()` 신설, 두 화면이 실제로 호출하도록 배선.

**② 차단 사유도 절반은 코드로 나가고 있었다.**
`DirectiveClient` 가 `blockLabel()` 을 import 해 놓고 두 곳에서 `BLOCK_LABEL[r] ?? r` 로
맵을 직접 찾았다. `photo_cut_count_low:11<12` 처럼 **접미사가 붙으면 못 찾는다.**
→ 둘 다 `blockLabel()` 로. 그리고 접미사가 컷 목록인지 값인지 구분하게 고쳤다
(안 그러면 `photo_world_churn:3.38/분` 이 "(컷 3.38/분)" 으로 나간다).

**③ 오버레이 좌우 마진이 두 군데에 따로 있었다.**
`subtitles.py` 에 `60,60` 하드코딩, 폭을 계산하는 쪽은 없었다.
→ `OVERLAY_SIDE_MARGIN_PX` 로 뽑아 양쪽이 같은 값을 쓴다(출력 바이트 불변).

### 재점검에서 **문제 없음**으로 확인한 것

- 선언만 되고 읽는 코드가 없는 컷 필드: `_origin_cut_no`(디버그 표시) 하나뿐
- 라우터·연출계약 3종·움직임 QA 가 전부 실행 경로에 있음(문자열 존재가 아니라 호출 확인)
- **새 신호 넷 중 어느 것도 승인을 막지 않음** — 실측 지시서 20개로 대조
- 되먹임이 넷 다 처방 문장을 준다(코드 이름 나열이 아니라)

### 남은 것

- **강조색 1개 강제**는 별도 코드가 필요 없다고 판단했다 — 화풍 문자열에 이미
  `single amber accent color` 가 있고, 파란 홀로그램의 출처였던 추상 세계 선언은
  세계 게이트가 이미 차단한다. 새 게이트를 더하면 오탐만 는다.
- **이 변경들이 실제로 먹히는지는 지시서를 새로 뽑아야 안다.** 기전 컷이 나오는지,
  세계가 재사용되는지, 근접 시점이 생기는지. API 비용이 든다.
