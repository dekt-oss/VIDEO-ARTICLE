# 설명형 릴스 — 제작 큐 연결 (2026-11-02)

**한 줄:** 승인된 설명형 제작안이 큐에서 [장면별 지시서 → 결재 → 클립 구매 → 후보 검수·선택 → 조립 → 자동 검사 → 사람 검수 → 게시 대기]까지 간다. 가짜 공급자로 한 편을 끝까지 돌렸다. **실제 영상·그림을 산 적은 없고, 공급자 요청 모양은 여전히 미검증이다.**

근거 문서: `docs/기획_릴스3형식_트렌드보드_v2_2026-10-31.md` §3, `docs/총괄계획_릴스3형식_수집부터게시까지_2026-11-02.md` §4-1. 앞 단계: `docs/deviation-drinks-explainer-stage1.md`.

## 흐름

| 작업(`renderer`) | 돈 | 하는 일 | 끝나면 |
|---|---|---|---|
| `explainer_plan` | 0원(edge TTS) | 나레이션 길이 실측 → 편집표 → 장면별 지시서·금액. 사기 전 검사가 전부 여기 있다 | `directive_ready` |
| `explainer_buy` | 결재 안에서 | 슬롯 순서대로 시작 그림 + 후보 클립 → 자동 판정 | 사람 차례에서 파일 없이 닫힌다 |
| `explainer_render` | 0원 | 선택된 클립만 조립 → 자동 검사 → 파일 묶음 | `auto_qa_pass` |

그 뒤: 과정 검수 → 품질 검수 6항목 → 파일 승인 = `ready_to_publish`. 상태표는 `drink_explainer_episodes`, 전이 규칙은 `engine/drinks_explainer.py can_transition` 과 SQL 이 같다(시험이 대조).

## 구매 한 시도의 순서 (`drinks_paid.buy_clip_attempt`)

가잡기 → 시도 행(`requested`) → `generating` → 공급자. 가잡기가 먼저라서 상한에 걸려도 시도 횟수를 쓰지 않는다.

| 공급자 결과 | 시도 상태 | 가잡기 |
|---|---|---|
| 안 보냄·4xx(`ExplainerNotSent`) | `failed_unbilled` | 해제 |
| 받았는데 못 씀(`ExplainerBilledBadFile`), 실측 실패 | `failed_billed` | 예상 금액으로 확정 |
| 그 밖의 전부 — 끊김·제한시간·5xx·읽을 수 없는 200 | `unknown_billed` | **유지.** 운영자가 billed/void 로 닫을 때 확정·해제 |

자동으로 다시 사지 않는다. 실패하면 작업을 닫고, 운영자가 [이어서 구매]를 눌러야 다음 시도가 열린다.

## 실호출 스위치

`DRINKS_EXPLAINER_PROVIDER_SEND_ENABLED`(기본 꺼짐) **그리고** 열린 결재가 둘 다 있어야 한다. `LiveAdapter.check_ready` 가 가잡기·시도 행보다 먼저 잰다. 꺼져 있으면 작업이 `provider_send_disabled` 로 닫히고 가잡기·시도 0건이다. 그림 경로(`LiveAdapter.image`)도 같은 스위치 뒤에 있다. `drinks-produce.yml` 에는 스위치도 키도 없다 — GitHub Actions 는 지시서·조립만 처리하고, 구매 작업을 집으면 아무것도 사지 않고 실패로 닫는다. 화면의 구매 요청은 워크플로를 깨우지 않는다.

## 기획과 다르게 정한 것

- **경계 종류 `cut` 을 더했다.** §3-5 표에는 넷뿐인데, 대본이 이어짐을 선언하지 않은 같은 역할 장면 사이를 `match` 로 적으면 슬롯마다 사람 선택을 기다려야 하고 "같은 세계"라는 거짓 표시가 된다. `match` 는 `continuity: ref:N` 을 쓴 장면만이다.
- **승인이 곧 결재가 아니다.** 총괄계획 §4 는 "내용 승인 금액 = 결재"인데, 0064 의 승인은 금액을 기록만 한다. 결재는 지시서를 본 뒤 운영자가 문장을 적어 연다. 대본을 승인할 때는 아직 실측 금액이 없기 때문이다. 화면은 지시서의 제안 상한을 채워 둔다.
- **구매 작업을 일부만 돌릴 수 있다(`through_n`).** S2 는 두 자산만 산다(§3-10). 결재 금액으로만 멈추면 다음 슬롯 그림까지 사 버린다.
- **훅 구간은 근사한다.** 대본에 "결정적 순간" 칸이 없어 훅 자산의 사용 끝 0.3초 앞에서 1.8초를 쓴다(§3-6 의 수치와 같은 위치). 틀리면 운영자가 조립본에서 본다.
- **훅 자막은 소재 질문, 안 들어가면 첫 나레이션.** 한 줄에 안 들어가면 사기 전에 멈춘다. 자르지 않는다.
- **꼬리 0.6초에 글자가 없다.** "보낼 이유 한 줄"을 담을 칸이 저장된 제작안에 없다(0054 검증기가 안 남긴다).
- **`motion_prompt` 를 필수로 올렸다**(`visual_claim_checks`). 대본 지시문은 "선택"이었는데, 움직임 문장 없는 대본을 승인한 뒤에는 고칠 길이 없다(손으로 고치면 시각 주장표가 사라진다).
- **금지할 오해를 그림 문장에 한국어 그대로 붙였다**(§3-4 "프롬프트 부정어"). 그림에 글자로 나오는지는 S2 에서 본다.
- **후보 판정 규칙을 한 줄 고쳤다.** 0062 는 자동 불합격 후보에도 사람 판정을 기다려서, 살아남은 후보를 고를 수 없었다.
- **`drinks_plan_renderable` 은 다시 유효성만 잰다.** 그 함수를 쓰는 곳(하트비트·끝내기·검수·게시)이 전부 막혀 있었기 때문이다. 옛 렌더 차단은 `drink_production_jobs` 삽입 트리거로 옮겼다 — 어느 함수로 들어와도 표에서 막힌다.

## 멈추는 경우 (전부 시험함)

클립 삭제 → `clip_missing`, 끝을 잘라 손상 → `clip_corrupt`, 나레이션이 길어져 모자람 → `clip_short`: 셋 다 `blocked_assets`, 새 가잡기 0, 파일 묶음 0, 사진 대체 0. 결재 상한 초과 → `blocked_budget`, 공급자 호출 0. 결과 불명 → `unknown_billed`, 닫기 전 구매 요청 거부. 후보 전부 불합격 → `blocked_no_pass`. 옛 렌더 요청 → `not_renderable`.

## 아직 안 되는 것 · 미검증

- **공급자 호출 전부:** Omni 요청·응답 안쪽 모양, 시작 그림 첫 프레임 고정, 길이 지정, 청구 단위, 요청 ID 조회. 첫 유료 시험(S2)에서 판정한다. 모양이 다르면 "모름"으로 멈춘다(돈은 나갔을 수 있다).
- **Veo(Vertex):** 요청 모양만 있고 전송·인증·폴링이 없다. 지시서 단가는 낼 수 있어도 살 수 없다. `provider_not_wired`.
- **그림·움직임 품질:** 본 적 없다. 자동 검사 통과는 "돌아간다"일 뿐이다.
- **S2 일부 조립:** 두 자산만 산 상태로 훅만 조립하는 경로가 없다(자동 검사가 40~55초를 요구한다). S2 는 후보 영상을 화면에서 보고 판정한다.
- **`no_pass` 슬롯 재촬영:** 슬롯이 닫힌다. 새 제작안 버전(새 슬롯)으로만 갈 수 있고, 그 대본은 소재 개발로 다시 만들어야 시각 주장표가 붙는다.
- **unknown_billed 조회 정정(2026-11-03 일부 해소):** 두 가지를 고쳤다. ① Omni 가 "아직 만드는 중"으로 답하면 interaction id 가
  예외 문장에만 실리고 버려졌다 — 이제 `ExplainerOutcomeUnknown.request_id` 로 실려 시도 행 `provider_request_id` 에 남는다(마이그레이션 없음,
  0062 의 `drinks_explainer_attempt_event` 가 이미 받는 칸). ② 조회 명령 `python -m engine.drinks_explainer_lookup <attempt_id>` 가 그 id 로
  `GET interactions/{id}` 를 보내 완성·진행 중·실패를 판정하고 닫기 금액(토큰 기준)을 **보여 주기만** 한다. 쓰지 않는다 — 닫기는 여전히 운영자가
  `/drinks/production` 에서 한다. 전송 스위치·결재 게이트는 구매와 같다. **남은 것:** 완성된 영상을 시도에 다시 붙이는 정정(`received` 로 되살리기)은
  없다 — 지금은 완성됐어도 billed 로 닫고 새 시도로 다시 산다. id 없이 끊긴 시도(응답 자체를 못 받음)는 여전히 청구서로만 닫는다.
  조회가 정말 무료인지·실패한 생성이 청구되는지는 [미검증](첫 실제 호출 전).
- **캡션 "AI 생성 영상" 한 줄(§3-4):** 코드가 넣지 않는다. 화면이 안내만 한다.
- **글자 나타남 자동 신호(Jev):** 후보 자동 판정에 없다. 사람이 본다.
- **연속성 숫자:** 기록만 한다. 문턱 없음.
- **화면:** 타입·린트·빌드만 통과했다. 운영 데이터로 열어 본 적 없다(0067 미적용).

## 적용 순서

1. 코드를 먼저 합친다. 옛 워커가 `explainer_*` 작업을 집으면 그림 나열식으로 렌더하므로 거꾸로 하면 안 된다. 화면은 0067 전에도 열린다(함수 없음 = 설명형 아님).

3. 0067 적용(별도 결재).
