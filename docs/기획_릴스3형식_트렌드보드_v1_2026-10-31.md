## 2. 세 형식 공통 원칙 — "인스타에서 먹히는" 기준

인스타 순위의 큰 신호는 **시청 유지(끝까지 보나)·공유(DM 보내기)·도달 대비 좋아요**이고, 2026 우선순위에 **원본성**이 있다고
보도됐다(모세리 발언을 인용한 업계 글 — 1차 출처 미확인). 이것을 화면 규칙으로 바꾼다.

| 신호 | 화면 규칙 |
|---|---|
| 시청 유지 | 첫 1.5초 안에 멈추게 할 것(가장 강한 장면 + 상단 훅 자막). 2~4초마다 화면이 바뀐다. 답은 끝에서 두 번째 장면. 마지막 장면이 첫 장면으로 이어져 다시 보게(루프). 길이 20~35초. |
| 공유 | "친구한테 보낼 이유" 한 줄로 끝낸다("위스키 따 놓고 몇 년 둔 사람한테 보내 주세요"). 저장할 만한 정보 한 줄. |
| 무음 시청 | 자막 없이 이해 안 되는 장면 0개. 훅은 글자로도 선다. |
| 원본성 | 남의 영상·소리를 잘라 붙이지 않는다. 밈은 **형식만** 빌리고 화면은 우리가 만든다. |
| 안전 영역 | 하단 340px·오른쪽 120px 비움(좋아요·캡션 자리). 훅 자막은 위 20~25% 높이. |

자막 배치 두 층(세 형식 공통 렌더 기능으로 만든다):
1. **상단 훅 자막**: 첫 장면 위쪽에 굵은 큰 글자 한두 줄 — 질문형("위스키는 왜 안 상할까?") 또는 POV형("POV: 10년 묵힌 위스키를 땄다").
   첫 장면 동안 유지, 이후 작은 크기로 맨 위에 주제 꼬리표로 남기기(선택).
2. **하단 말 자막**: 뜻 단위 끊기(기존), **핵심 낱말 강조색**(`OVERLAY_ANNOTATION_COLOR_ASS` 공유) + 낱말 단위로 톡 튀어나오기.

## 3. 설명형 엔진 — "실사·3D 도해 영상으로 왜를 보여 준다" (★ 최우선)

### 3-1. 목표
- **모든 장면이 움직이는 영상**이다. 사진에 확대·흔들림을 준 장면 0개(운영자 규칙 2026-10-09 "사진+떨림 금지"와 같다).
- 화풍은 2026-09-08 확정 무광 CG(`VISUAL_ROLE_STYLE`). 실사(REALITY)와 3D 도해(MECHANISM)가 재질·조명을 공유한다.
- 장면 사이가 끊기지 않는다 — 시작 그림을 앞 장면 그림에 이어 그려(같은 잔·같은 테이블) 한 세계로.
- 대본은 '왜'가 뼈대(운영자 2026-10-30), 근거 규칙 그대로(원문 밖 숫자·처방 금지).

### 3-2. 설명형 장면 문법 (엔진이 강제하는 틀)

| 비트 | 시간 | 화면 | 자막 |
|---|---|---|---|
| ① 훅 | 0~1.5초 | 가장 강한 영상: 도해의 결정적 순간이나 실사의 이상한 장면(병 속으로 카메라가 빨려 들어감 등). **8초 클립 하나를 1.5초 컷과 본문 컷으로 나눠 쓴다** | 상단 훅 자막(질문/POV) |
| ② 약속 | 1.5~5초 | 실사 — 시청자 상황(선반 위 오래된 병) | "답은 잔 속에 있어요" 류 한 줄 |
| ③ 본문 | 5~25초 | 실사 ↔ 도해 번갈아 3~4장면, 장면당 4~6초 클립, 클립 안에서도 2~3초마다 컷(길이 맞춤·앞당겨 자르기 기존 기능) | 하단 말 자막 + 키워드 강조 |
| ④ 답 | 25~30초 | 3D 도해 클라이맥스(미생물이 막히는 순간 등) | 답 한 줄 크게 |
| ⑤ 마무리 | 30~35초 | 첫 장면과 같은 구도로 돌아오는 실사(루프) | 보내기/저장 한 줄 |

- 3D 도해 장면은 "과정"이 있을 때만(기존 `mechanism_spec_complete`: 주인공·부품 2개 이상·관계·변화·전/후 상태).
- 엔진이 대본을 받으면 위 틀에 장면을 배치한 **촬영 계획(shot plan)**을 만든다: 장면마다 시작 그림 문장, 움직임 문장,
  카메라(밀기·당기기·돌기·단면 진입), 길이(4/6/8초), 이어 그릴 앞 그림, 비트 번호.

### 3-3. 생성 흐름

```
대본(기존 소재 개발 엔진) ─▶ 촬영 계획(신규: drinks_shots) ─▶ 화면 검사(기존 photo_contract + Jev)
   ─▶ 운영자에게 "장면별 지시서" 먼저 보여 주기(그림 문장·움직임 문장·길이·금액) ─▶ 결재
   ─▶ 시작 그림 사기(기존 drinks_paid, 이어 그리기) ─▶ 영상 클립 사기(기존 clip_item, 신규 배선)
   ─▶ 클립 검사(정지 화면·깨짐·길이 — 기존 후보 채점) ─▶ 조립(신규: 클립을 릴스 장면으로)
   ─▶ 상단 훅 자막·키워드 강조·효과음·BGM(신규 공통) ─▶ 품질 검사 ─▶ 운영자 미리보기 ─▶ 게시
```

새로 만들 것(코드):
1. `engine/drinks_shots.py` — 대본 → 촬영 계획(§3-2 틀). 규칙은 코드 검사로(비트 순서·장면 길이 합·도해 조건).
2. `drinks_render.render_video(clips=…)` — 산 클립을 장면 영상으로 쓴다. `plan_to_directive` 가 그 장면을 `motion_source=video` 로 만들고,
   엔진 렌더가 **새로 사지 않고** 그 파일을 쓰도록 재사용 디렉터리를 넘긴다(그림의 `IMAGE_REUSE_DIR` 와 같은 방식, `CLIP_REUSE_DIR`).
   클립이 없는 장면이 있으면 **렌더를 멈춘다**(사진으로 몰래 대체하지 않는다 — 운영자 규칙).
3. 주문서에 클립 등급 선택: 훅·도해 = `veo-3.1-fast`, 나머지 = `veo-3.1-lite`. 훅 클립은 후보 2발 뽑아 채점 높은 쪽.
4. 공통 자막 두 층(§2), 효과음(전환 '휙'·강조 '톡' — 저작권 정리된 효과음 묶음, 운영자 선택 §9).

### 3-4. 소리
- 나레이션: 지금 무료 TTS(edge, 1.2배속). 인기를 노린다면 목소리가 크다 → **무료 vs 유료 목소리(ElevenLabs) 같은 대본으로 비교**를
  유료 시험 B 단계에 묶는다(약 $0.1).
- BGM: 설명형 기본 = 우리 쪽에서 까는 저작권 정리된 음악(나레이션 아래 -20dB 이하, 기존 덕킹). 인기 음원 부착은 선택(§7).

### 3-5. 비용 (위스키 6장면·33초 대본 기준, 정가표)

| 구성 | 시작 그림 | 클립 | 편당 |
|---|---|---|---|
| 훅·도해 fast + 나머지 lite (기본안) | 도해 1 × $0.134 + 실사 5 × $0.039 = $0.33 | fast 2 × 6초 × $0.10 = $1.20 · lite 4 × 6초 × $0.05 = $1.20 | **약 $2.7** |
| 기본안 + 훅·도해 후보 2발 | 같음 | +$1.20 | **약 $3.9** |
| 전부 fast | 같음 | 36초 × $0.10 = $3.60 | 약 $3.9 |

실패 재시도는 항목당 3회 상한(기존 0054). 편 결재 상한은 예상의 1.3배로 받는다.

### 3-6. 품질 합격 기준 (운영자 판정 — 이게 통과해야 "됐다"고 한다)
1. 첫 1.5초에 손가락이 멈추는가(운영자 체감 + 우리 계정 3초 시청률 지표가 쌓이면 그걸로).
2. 사진처럼 보이는 장면 0개, 정지 화면 0개(기존 정지 검출).
3. 장면 사이 세계가 이어지는가(같은 잔·테이블).
4. 3D 도해가 '왜'를 보여 주는가(소리 끄고 봐도 이해).
5. 글자 깨짐·화면 속 가짜 글자 0개.
6. 끝에서 다시 첫 장면으로 자연스럽게 이어지는가.

### 3-7. 시험 순서 (돈은 단계마다 따로 결재)
- **A (0원)**: 촬영 계획·조립 배선을 **가짜 클립**으로 끝까지 리허설. 자막 두 층·효과음·루프·안전 영역을 실제 1080×1920 결과로 확인.
- **B (약 $1)**: 위스키 훅 장면 1개를 lite·fast 로 각각 + 목소리 무료·유료 비교. 운영자가 등급·목소리 결정.
- **C (약 $3~4)**: 위스키 한 편 전체. 운영자 판정(§3-6).
- **D**: 합격하면 그 구성을 기본값으로 고정, 사케 편으로 재현.
- 돈 쓰기 전 매번 장면별 지시서를 먼저 보여 준다. 샘플은 **이어진 장면**으로 뽑는다(2026-10-09 규칙).

## 4. 카드뉴스형 엔진 — "넘기는 맛 + 음원"

두 출력:
1. **캐러셀**(운영 중) — 그대로. 게시할 때 인기 음원을 붙이는 기능은 캐러셀에 지원되는지 미확인(§11).
2. **카드뉴스 릴스** — 카드 페이지가 장면인 영상(#128 코드, 0057 적용 필요).

카드뉴스 릴스에 추가할 것:
- 페이지 전환 움직임: 옆으로 밀기·살짝 확대(로컬 ffmpeg, 0원). 페이지당 2.5~4초.
- 첫 페이지 = 큰 훅 제목(상단 자막 규칙과 같은 글꼴·위치), 마지막 페이지 = 저장/보내기 한 줄.
- **음원 필수**: 기본 = 게시할 때 인기 음원 부착(§7, 나레이션 없음). 박자에 맞춘 전환이 필요하면 우리 쪽 라이선스 음악(박자 정보가 있는 곡)으로 렌더에 깐다.
- 운영 흐름: 소재 → 카드 문안(기존) → 카드 그림(기존) → **트렌드 보드가 추천한 음원 3곡 중 선택**(화면에서 미리듣기 링크) → 렌더 → 게시.
- 비용: 0원(카드 그림을 산 경우만 그림값).

## 5. 밈형 엔진 — "유행 형식을 우리 술 이야기로 6~15초" (신규)

- 입력: 트렌드 보드에서 운영자가 [쓰자] 누른 밈 카드(§6).
- 밈 카드 → **밈 틀**: 비트 수, 비트별 길이, 자막 위치(상단 POV / 가운데 큰 글자 / 전·후 비교 좌우), 화면 종류(반응 장면 / 텍스트만 / 전후), 음원 id.
- 화면은 우리가 만든다(원본 재사용 금지):
  - 텍스트만 + 배경(로컬, 0원) — 많은 밈이 글자 + 음원만으로 성립한다.
  - 우리 실사형 그림을 짧게 움직인 반응 장면(Veo lite 4초 ≈ $0.2).
- 글: 밈 문장을 LLM 이 쓰되 **정보 주장이 들어가면 근거 규칙을 그대로 탄다**(원문 밖 숫자·처방 금지). 정보 없는 농담은 근거 검사 대신
  음주 조장·미성년·과음 미화 금지 검사(기존 `drinks_script_check` 에 밈 규칙 추가).
- 음원: 밈 음원 필수, 게시할 때 Audio API 로 부착. 나레이션 없음이 기본.
- 속도: 밈은 1~2주면 식는다 → [쓰자]부터 게시까지 **48시간** 목표(카드 → 틀 → 글 → 렌더 → 운영자 확인 → 게시).
- 비용: 편당 $0~0.5.

## 6. 트렌드 보드 — 인스타 유행 밈을 매일 모으고 밈 카드로 관리 (신규)

### 6-1. 원칙
- **인스타 공식 API 만** 쓴다(이번에 받은 페이스북 로그인 토큰). 긁어오기(스크래핑) 금지.
- 남의 영상은 **형식을 분석하는 데만** 쓰고 저장·재게시하지 않는다. 받은 영상 파일은 분석 직후 지우고(최대 24시간),
  형식 설명·링크·수치만 남긴다.

### 6-2. 매일 수집 (GitHub Actions `drinks-ig-trends.yml`, KST 07:30, 0원)
| 수집원 | 무엇을 | 양 |
|---|---|---|
| T1 인기 음원 | `ig_audio` 노래·원본 소리 각 앞 4쪽(약 100개) — 순위·제목·만든 계정·길이 | 하루 8회 호출 |
| T2 관찰 계정 | 관찰 목록(30~80개)의 최근 릴스 25개 — 캡션·조회·좋아요·댓글·표지 그림·영상 파일(있으면) | 계정당 1회 |
| T3 운영자 링크(선택) | 대표님이 본 릴스 링크 붙여넣기 → 그 계정이 비즈니스/크리에이터면 T2 로 찾아 같은 처리 | 수시 |

### 6-3. "뜨는 릴스" 고르기
- 계정마다 최근 25개 조회수의 중앙값을 평소값으로 두고, **평소의 3배 이상**이거나 올린 지 48시간 안에 평소를 넘은 릴스 = 뜨는 릴스.
  (3배는 첫 값 — 2주 쌓인 분포를 보고 다시 정한다.)
- 인기 음원: 어제보다 순위가 오르거나 처음 들어온 곡 = 오르는 음원. 원본 소리는 제목(챌린지 이름)을 밈 이름 후보로 쓴다.

### 6-4. 형식 뽑기 (인스타 릴스 자체를 본다)
- 영상 파일이 온 뜨는 릴스: **Gemini 가 영상을 직접 보고** 형식을 JSON 으로 뽑는다 — 비트 수·컷 길이·자막 위치·화면 종류·
  구조(POV / 전후 / 반전 / 리스트 / 반응)·음악 쓰임·첫 1.5초에 무엇이 나오나.
- 파일이 안 온 릴스: **표지 그림 + 캡션 + 수치**로 같은 칸을 채우되 `근거=표지` 로 표시(신뢰 낮음). 표지에 훅 글자가 박혀 있는 경우가 많아 자막 위치·훅 문장은 표지로도 잡힌다.
- 비용: Gemini flash 로 릴스 1개 약 $0.002~0.01 → 하루 20개 상한이면 **하루 $0.2 이하, 월 $6 이하**. config 로 하루 상한을 둔다.

### 6-5. 밈 카드 만들기 (하루 1회 묶기)
- 같은 음원 이름·같은 챌린지 이름·같은 구조와 비슷한 훅 문장을 가진 것끼리 묶어 카드 1장.
- 카드 내용: 밈 이름, 한 줄 설명, 구조, 같이 쓰이는 음원(있으면 audio_id), 예시 릴스 3개(링크·조회·계정), 유행 신호(관찰 계정 수·조회 배수·음원 순위 추이),
  상태, **우리 술 버전 아이디어 2개**, 주의(음주 조장·미성년 위험).

### 6-6. 수명 관리
| 상태 | 들어가는 조건 |
|---|---|
| 새로 뜸 | 처음 묶인 날 |
| 오르는 중 | 2일 연속 예시·계정 수 증가 또는 음원 순위 상승 |
| 정점 | 증가가 멈춤 |
| 식음 | 7일 동안 새 예시 없음 → 자동 보관 |
운영자가 [쓰자]를 눌러도 '식음'이 되면 화면에 "식었음" 표시(만들지 말지 다시 판단).

### 6-7. 운영자 화면 (`/drinks/trends` 에 "밈 보드" 탭)
- 카드 목록(상태별), 카드마다 [쓰자] / [넘기기] / [나중에]. [쓰자] → 밈형 소재로 넘어간다(§5).
- "오르는 음원" 목록(미리듣기 링크) — 카드뉴스·밈 음원 고를 때 같은 목록.
- 관찰 계정 관리: 엔진이 후보를 낸다(뜨는 릴스 캡션의 @언급, 같은 음원 쓰는 계정) → Business Discovery 로 존재 확인된 것만 → 운영자 체크로 추가.
  **첫 목록은 개발 때 제가 후보 40~60개를 만들어 존재 확인까지 해 두고, 대표님은 체크만** 하신다.
- 하실 일: 주 1~2회 카드 고르기, 처음 한 번 관찰 계정 체크.

### 6-8. 범위 밖 / 나중
- 해시태그 인기 게시물: 앱 심사(사업자 인증·개인정보처리방침·시연 영상, 몇 주) 필요 → 트렌드 보드가 2주 돌아간 뒤 부족하면 결정.
- 개인 계정 릴스: 공식 통로 없음.

### 6-9. 토큰 관리
- 만료 14일 전부터 화면 상단 경고 + 수집 로그 경고.
- 자동 연장은 Meta 앱 비밀키가 필요하다(`fb_exchange_token`) → 대표님이 `META_APP_SECRET` 을 GitHub 비밀로 넣으면 매주 자동 연장. 안 넣으면 60일마다 손으로 연장.

## 7. 음원(BGM) 공통 설계

| 경로 | 쓰는 형식 | 장점 | 한계 |
|---|---|---|---|
| A. 인스타 인기 음원 게시 때 부착(`audio_configuration` — audio_id·음원 볼륨·영상 볼륨) | 카드뉴스 릴스·밈형 기본, 설명형 선택 | 진짜 유행 음원, 외부 사용 허가된 곡만 와서 저작권 걱정 적음 | **게시 전에 들어 볼 수 없다**(Meta 문서). 음원 시작 지점 지정 가능 여부 미확인. 박자를 모른다. |
| B. 우리 쪽 라이선스 음악을 렌더에 깔기 | 설명형 기본, 박자 맞춤이 필요한 카드뉴스 | 미리 듣고 박자 맞춤 가능, 덕킹 | 유행 음원이 아님. 상업적 사용 가능한 출처를 정해야 한다(§9). |
| C. 없음 | — | — | — |

- 경로 A 를 쓰려면 **게시도 페이스북 로그인 토큰으로** 해야 한다(Audio API 는 인스타그램 로그인 방식에서 안 된다).
  → 게시 계정에 페이스북 로그인 연결을 하나 더 등록하고(엔진은 `facebook_login` 연결을 이미 안다), 음원을 붙이는 게시만 그 연결로 보낸다.
- 볼륨 기본값: 나레이션 있는 영상 = 음원 15~25 / 영상 100, 나레이션 없는 영상 = 음원 80~100 / 영상 0~30. 첫 시험 게시에서 귀로 판정.
- ⚠ API 로 하는 시험 게시는 **공개 게시**다(인스타 API 에 비공개 게시가 없다). 지우는 것은 앱에서 손으로. 첫 음원 시험 게시는 따로 승인받는다.

## 9. 운영자가 정할 것
1. 설명형 BGM·효과음 출처(상업적 사용 가능 라이브러리) — 후보 2~3개를 P2 에서 가격·약관과 함께 올린다.
2. 관찰 계정 첫 목록 체크(P1 끝).
3. 목소리: 무료 TTS 유지 vs 유료(시험 B 결과로).
4. `META_APP_SECRET` 넣어 토큰 자동 연장할지.

## 10. 위험
- 관찰 계정이 비즈니스/크리에이터가 아니면 못 본다 — 큰 밈 계정은 대부분 비즈니스/크리에이터지만 개인 계정 밈은 놓친다.
- 영상 파일 비율(28%)이 낮으면 형식 분석 신뢰가 떨어진다 — 표지 기반 분석 정확도를 P1 에서 20개로 재 본다.
- Meta API 호출 한도(사용자당 시간당 약 200회로 알려짐 — 미확인) — 관찰 80개·음원 8회면 여유.
- 영상 생성 등급 차이를 아직 아무도 안 봤다 → 시험 B 전에는 "기본안"이 가설이다.

## 11. 확인 안 된 것 (미검증)
- 음원 부착 게시가 우리 앱(개발 모드)·우리 계정에서 실제로 되는지.
- 캐러셀에 음원 부착 가능 여부, 음원 시작 지점 지정 가능 여부.
- 시험 게시 전용 "체험 릴스"(팔로워에게 안 보이는 게시)를 API 로 할 수 있는지.
- 업계 글의 순위 신호·수치(1차 출처 아님).
