## store·조회에 대해 (리뷰 §6)

- `store=true` 는 요청 ID 가 **있을 때** 다시 묻고 AI Studio 로그로 사람이 조사하는 데 도움이 됩니다.
- 응답 전에 연결이 끊기면 지금 방식(동기 호출)으로는 요청 ID 를 아예 못 받습니다 — `store=true` 만으로 해결되지 않습니다. 그때는 청구 내역으로 대조합니다.
- `background=true` 는 ID 를 먼저 받고 폴링하는 방식이라 복구에 유리하지만, Omni 가 그 조합을 지원하는지는 **확인하지 않았습니다(미검증)** — 확인 없이 바꾸지 않습니다. 첫 접수 응답이 유실되는 경우는 그 방식으로도 남습니다.
- interaction 보관 55일은 **생성된 영상 파일을 55일 내려받을 수 있다는 보장이 아닙니다.**
- 이번 수정으로 ID 가 있는 모든 실패(잘못된 사용량·모양·base64·파일)에서 ID 가 남고, 조회 명령은 진행 중·완료·실패·취소·해석 불가를 가르고 DB 에 쓰지 않습니다.

- 발견 화면에서 "사케 유통기한"이 카드뉴스로 추천되는데, 공식 출처 표에서는 사케 보관이 비어 있습니다. 낱말만 맞은 추천일 수 있어 [이걸로]를 누르면 모델 비용을 쓰고 근거 부족으로 멈출 수 있습니다(미검증).
- 설명형 영상 요청의 보관 설정을 켰습니다(`store`). 결과를 모를 때 다시 물어보려면 필요하기 때문입니다. 대신 구글이 interaction 을 유료 등급 기준 55일 보관합니다(영상 파일 다운로드가 55일 보장된다는 뜻은 아닙니다). 원치 않으시면 `DRINKS_EXPLAINER_OMNI_STORE=false` 로 끕니다. 이 경우 조회가 되지 않을 가능성이 큽니다.
- 응답 전에 연결이 끊긴 경우에는 요청 ID 자체가 없어 조회할 수 없습니다. 그때는 청구 내역으로 대조합니다.
