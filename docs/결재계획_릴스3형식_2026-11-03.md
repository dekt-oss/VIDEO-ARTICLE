## 먼저 풀 문제 — GitHub 예약 실행이 몇 시간씩 늦습니다

| 작업 | 예정(KST) | 실제 | 늦은 정도 |

게시는 **예약 시각보다 2시간 넘게 늦으면 올리지 않고 멈춥니다**. 수집·트렌드 정도로 늦으면 예약한 편이 멈추게 되어, 크론 변수를 켜도 5단계 합격 기준을 넘지 못합니다. 수집과 트렌드는 늦어도 괜찮습니다.

| 안 | 내용 | 돈 | 필요한 것 |
|---|---|---|---|
| **A (추천)** | Supabase 예약 기능(`pg_cron`·`pg_net`, 설치 가능, 아직 안 켬)이 5분마다 "시각이 된 예약"을 보고, 있을 때만 게시 워크플로를 깨웁니다 | 0원 | 마이그레이션 적용, GitHub 토큰을 Supabase 금고에 저장(토큰 변경이라 승인 대상) |
| B | 예약하지 않고, 올릴 때 사람이 수동 실행 | 0원 | 없음. 지금도 가능. 자동화는 아닙니다 |
| C | 유예를 2시간에서 6시간으로 | 0원 | 마이그레이션 1건. 시각이 크게 어긋나 추천하지 않습니다 |

A 는 아직 만들지 않았습니다. 고르시면 파일까지 0원으로 만듭니다. 게시 크론은 꺼진 채로도 "건너뜀" 기록을 남기니, 며칠 뒤 다음 명령으로 다시 잴 수 있습니다.

```bash
gh run list --workflow drinks-publish.yml --event schedule --limit 100 --json createdAt -q ".[].createdAt"
```
