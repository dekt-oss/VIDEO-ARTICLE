# 실측 — 9:16 완성본 (웹 발주 B, 2026-08-30)

실행: `python -m scripts.web_order build B`
입력: 운영자가 Gemini 웹에서 만든 **영상 5개**(1번~5번) — API 비용 **0원**
산출: `docs/발주_B/완성_B_ko.mp4` · **1080×1920** · 31.03초 · 8.9MB

> 핸드오프가 "유일하게 남은 미검증 항목"으로 지목한 **9:16 을 실측했다.**
> 결론: **파이프라인은 9:16 을 제대로 낸다. 깨진 것은 입력(생성 산출물) 쪽이다.**

---

## 0. 세 줄

1. **9:16 은 통과다.** 산출 1080×1920. 자막·훅·오버레이·타이틀 전부 제자리.
2. **그런데 웹에서 받은 영상 5개가 전부 1280×720(16:9)이다.** 파이프라인이 9:16 프레임에
   맞추느라 **가로의 53%를 잘라낸다.** 앞선 1080×1300 은 여기서 온 착시였다.
3. **컷 6 에서 선언한 변화가 화면에 안 나갔다** — 코드가 조용히 앞 그림을 **바이트 복사**했다.
   계획서 §9-9 **Q9 가 예고한 그 퇴행**이다. **같은 세션에서 고치고 회귀 테스트로 박았다**(§3).

## 1. 9:16 — 통과

| | 값 |
|---|---|
| 산출 크기 | **1080×1920** (9:16) |
| 길이 | 31.03초 · 컷 6 · 자막 12큐 |
| 레이아웃 | `center_band` — 콘텐츠 밴드 1080×1300 + 상단 200px 바 |

**앞서 1080×1300 이 나온 것은 조립 코드 결함이 아니었다.** 확인 방법 두 가지:

- 필터 문자열을 직접 뽑아 보니 pad 가 정상이다 —
  `scale=1080:1300:…,crop=1080:1300,pad=1080:1920:0:200:color=black`
- **1080×1920 합성 입력**으로 드라이런하니 산출도 1080×1920 이었다
  (`scratchpad/probe916.py`, 생성 호출 0).

즉 파이프라인은 입력이 무엇이든 1080×1920 을 낸다. 이전 산출물의 1300 은
**그때 코드에 letterbox pad 가 없었던 흔적**이며, 지금 코드로는 재현되지 않는다.

## 2. ★ 진짜 결함 — 웹이 돌려준 영상이 16:9 다

```
docs/발주_B/입력/cut01.mp4 … cut05.mp4   →  전부 1280×720 (16:9 가로)
운영자가 만든 스틸 PNG                    →  1536×2752 (세로)
```

**세로 그림을 첨부해 영상을 만들었는데 가로로 돌아왔다.** 발주서는 프롬프트에
`vertical 9:16` 을 명시했지만 지켜지지 않았다.

파이프라인의 `_clip_fit_geometry` 는 이것을 세로 밴드에 **채워서(increase+crop)** 맞춘다:

```
1280×720 → 2311×1300 으로 확대 → 가운데 1080 만 남기고 crop
         = 원본 가로의 46.7% 만 화면에 남는다 (53.3% 소실)
```

컷 4 의 분광 그래프가 왼쪽에서 잘려 나간 것이 그 결과다.

**게이트는 옳게 잡았다** — 스틸 4컷에서 코드가 먼저 소리쳤다:

```
ERROR 컷 1 이미지가 9:16 이 아니다(1280x720) — 종횡비 파라미터를 확인하라
ERROR 컷 2 · 컷 3 · 컷 5 동일
```

> **해석:** 이것은 조립의 실패가 아니라 **생성 단계의 실패**다. 그리고 `IMAGE_ASPECT_*`
> 토글(CLAUDE.md)이 아직 미확정인 이유와 같은 뿌리다 — 종횡비가 요청대로 나오는지를
> 우리가 아직 코드로 강제하지 못한다.

## 3. ★★ 컷 6 — 선언한 변화가 화면에 없다 (계획서 §9-9 Q9 재현)

지시서가 컷 6 에 대해 선언한 것:

```json
{"entity_id": "TRAJECTORY_LINE", "operation": "HIGHLIGHT",
 "visible_change": true,
 "result_state": "One trajectory line stands out as a benchmark"}
```

화면에 나간 것: **stage S1 의 그림 그대로.** 강조된 궤적선은 **없다.**

원인은 `engine/render.py::_derive_from_stage` 다:

```python
if crop.has_work(cut.get("crop"), cut.get("tone_grade")):
    crop.derive_image(...)
else:
    shutil.copyfile(base, img_path)      # ← crop 이 없으면 바이트 복사
```

컷 6 은 `crop: None`, `tone_grade: "none"` 이라 **복사 분기로 간다.**
`mutations` 는 읽히지 않는다. 즉 **RETURN_WORLD 컷은 어떤 변화를 선언하든 앞 그림이 나간다.**

### 고쳤다 (2026-08-30, 같은 세션)

**결정 계층에서 고쳤다** — 복사하는 함수만 막으면 텍스트 전용 생성으로 떨어져
**세계가 오히려 사라진다**(RETURN_WORLD 의 정반대 결과다).

`sequence_render.reference_decision` — RETURN_WORLD 는 **변화를 선언하지 않은 컷만**
파생으로 보낸다. 변화가 있으면 **참조 조건 생성**으로 간다: 같은 그림을 시작 프레임으로
주므로 세계는 유지되고 변화만 일어난다(Phase 0 이 실측한 그것이다).

판정은 `visual_sequence.stage_has_progress` **정본 하나**로 한다 — 같은 질문에 두 벌의
답을 만들면 한쪽만 고쳐지는 날이 온다(코덱스 리뷰 S4).

`render._obtain_still` — **파생이 실패해도 참조를 붙인다.** 종전에는 `kind == "reference"`
일 때만 참조를 실어서, 파생 실패가 곧 세계 상실이었다. 같은 결함 계열의 하나 더였다.

재조립으로 확인(생성 호출 0):

```
전:  reference_conditioned 4 · derived 1     ← 컷6 이 바이트 복사
후:  reference_conditioned 5 · derived 0     ← 컷6 이 참조 생성으로
```

컷 6 자리에 넣어 둔 자홍색 자리표시자가 **이제 화면에 나온다**(t=29.0s 중앙 픽셀
`(254,0,253)`). 종전에는 안 나왔다 — 그림이 생성기를 거치지 않고 복사됐다는 증거였다.
운영에서는 이 자리에 참조 조건 생성 결과가 들어간다.

회귀 테스트 3개로 박았다(`tests/test_sequence_render.py`):
`test_returning_to_a_world_while_declaring_a_change_is_not_a_copy` ·
`test_the_declared_change_reaches_the_prompt_of_a_returning_cut`(프롬프트까지 배선됐는가) ·
`test_a_failed_derive_keeps_the_world_instead_of_starting_over`.
전체 1,298 통과 / 1 실패(Windows Pillow raqm — 원래 실패).

**비용:** RETURN_WORLD 컷 하나당 이미지 생성 1회가 는다. 운영자가 §8 에서 확정한
"편당 비용 2배 허용" 범위 안이고, 선언한 변화가 조용히 사라지는 것보다 낫다.

---

계획서 §9-9 Q9 가 정확히 이것을 예고했다:

> "`connective_in_world` 컷이 세계 참조를 물려받으므로, **렌더가 그것을 파일 복사로
> 구현하면** 퇴행한다 → Phase 3 배선에서 반드시 본다."

**그 우려가 맞았다.** 그리고 이번에도 **지시서 JSON 만 봐서는 안 보였다** —
게이트는 전부 통과했고(`degraded_continuity: {}`), 조립해서 눈으로 봐야 나왔다.
핸드오프 §2 의 "일곱 번 나온 결함"과 같은 계열의 **여덟 번째**다:
`mutations` 를 만들어 놨는데 파생 경로가 그것을 안 읽는다.

> 검증 보조 사실(고치기 **전**): 컷 6 자리에 **자홍색 자리표시자**(1536×2752 단색)를 넣고
> 돌렸는데 화면에 나오지 않았다 → 그 그림이 생성기를 **한 번도 거치지 않는다**가 코드로
> 확인됐다. 고친 뒤에는 같은 자리표시자가 화면에 나온다 — 그것이 배선의 증거다.

## 4. ★ 수치가 화면에서 두 번, 서로 다르게 말한다 (§9-9 Q10 재현)

컷 4 한 프레임 안에 숫자가 **두 출처**로 있다:

| 출처 | 화면에 뜬 값 |
|---|---|
| 우리 정밀 레이어(ASS 오버레이, 하늘색) | **`+8초 이상 변화`** |
| 생성 영상에 **구워진 글자** | 타이머 `2.4` · 그래프 축 `260 190 … 750` |

프롬프트는 `no text, no numbers` 를 명시했는데 지켜지지 않았다.
컷 1·6 에는 로켓 동체에 **`GEMINI-3` + NASA 로고**가 구워져 있다 — 원문은 **팰컨 9 상단부**이므로
글자 번인인 동시에 **사실 오류**다.

§9-9 Q10 은 이 위험을 "막지 않았다 — 렌더 후 QA 로 넘긴다"고 적어 뒀다.
**렌더 후 QA 가 지금 이것이다.** 실측으로 재현됐음을 기록한다.

## 5. clip_fit 판정 분포

```
길이보정 = {'trim': 5}
컷1 clip=10.01s narration=3.00s → trim      컷4 clip=10.01s narration=8.00s → trim
컷2 clip=10.01s narration=4.00s → trim      컷5 clip=10.01s narration=8.00s → trim
컷3 clip=10.01s narration=4.00s → trim
```

웹 생성 클립이 전부 10초 고정이고 나레이션이 3~8초라 **전부 trim** 이다. 정상 동작이다.
(운영 티어는 4/8초라 분포가 다를 것이다 — 이건 9/1 이후 실서비스에서 다시 잰다.)

### 처음에는 이 숫자가 거짓이었다 — 도구 결함을 고쳤다

1차 실행은 `{'flagged': 5}` 에 `clip=0.00s` 였다. 파이프라인의 답이 아니라 **측정 실패**다:

- `imageio-ffmpeg` 는 **ffmpeg 만 번들하고 ffprobe 는 없다.**
- `assemble.probe_duration` 이 전부 `0.0` 을 돌려주고, 길이 보정이 "클립이 나레이션보다
  훨씬 짧다"로 읽어 **전 컷 flagged** 가 됐다.

`scripts/web_order._ensure_ffprobe` 를 넣어 **ffprobe 가 없을 때만** mvhd 박스에서 길이를
직접 읽게 했다. **프로덕션 코드는 건드리지 않았다** — CI·운영에는 ffprobe 가 있다.

> 이 저장소의 자세 그대로다: **0.00s 를 판정으로 읽으면 원장이 거짓말을 한다.**

## 6. 자막·오버레이·컷 전환 — 이상 없음

- 타이틀 `하루 논문 한 편`(상단 바) · 훅(노랑, 2줄) · 근거 오버레이 카드(하늘색) ·

- 오버레이 카드가 자막 **바로 위**에 붙는다. 겹치지는 않지만 여유가 적다(컷 6 에서 가장 빠듯).
- 컷 전환 6개 이음새 정상. `degraded_continuity: {}`.
- 시각 시퀀스(고침 후): `stages_rendered 6 · reference_conditioned 5 · derived 0 · world_reset 1`.

## 7. 미검증 — "됐다"고 말하지 않는 것

- **스틸 6장을 원본 PNG 로 넣은 조립은 안 했다.** 이번 컷 1~5 스틸은 영상의 **첫 프레임**
  (1280×720)을 썼다. 운영자가 준 1536×2752 PNG 6장은 어느 것이 몇 번 컷인지
  **파일명으로 확정되지 않아** 임의로 매핑하지 않았다.
- **컷 6 은 이제 입력이 필요하다.** 파생이 참조 생성으로 바뀌었으므로 웹 발주 흐름에서는
  `cut06.png`(발주서 6번 프롬프트, 앞 그림 첨부)를 실제로 만들어야 한다. 지금 완성본의
  컷 6 은 **자홍색 자리표시자**다 — 고침이 배선됐음을 보여 주는 증거이지 산출물이 아니다.
- 클립 길이 티어(4/8초) · Batch↔실시간 · 업로드 · 크론 — 9/1 이후.
- 영상 **연쇄 누적 드리프트**는 이번에도 못 쟀다(컷 4 하나만 I2V 연쇄).
