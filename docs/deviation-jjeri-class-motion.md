# 째리의 술 수업 로컬 모션그래픽 제작

## 적용 범위

승인된 주류 영상 제작안에는 선택적으로 편 지시서를 `plan_json.jjeri_class`에 함께 저장한다. 지시서도 승인된 제작안의 해시에 포함된다. 운영자는 기존 영상 제작 방식과 째리의 술 수업 중 하나를 선택한다. 째리의 술 수업은 등록된 SVG, HyperFrames, 무료 Edge 음성을 사용한다. 검색 장면에는 검색어만 입력되고 가격은 표시되지 않는다. 정답 샘플의 가격 수준 칩은 금액 없이 비교를 표현한다.

편 지시서 생성 함수는 응답 공급자를 인자로 받는다. 승인 근거의 핵심 주장 중 원문 인용이 검증된 것만 제공한다. 사실을 말하는 자막, 화면 문구, 제목, 캡션을 연결된 원문과 함께 검사한다. 화면의 출처 칩은 검증된 스냅샷 메타데이터로 만든다. 사람은 문장이 원문 의미를 넘는지 대조한다. 지시서가 없거나 차단되면 렌더 단계에 들어가지 않는다.

## 운영자 웹에서 새 주류 편 만들기

1. 주류 제작 스튜디오의 **째리의 술 수업 지시서**에서 현재 승인 근거를 연다. 영상 필수 주장이 있는 승인본으로 소재 상세에서 영상 편성을 마친 뒤 생성 요청을 한다.
2. 교시, 유효한 주류 개발 결재, 요청 금액 상한을 지정하고 최초 작성과 형식 교정을 포함해 요청당 최대 2회 호출에 동의한다. 전송 한 번마다 기존 비용 원장에 보수적으로 계산한 금액을 가잡기한다. 요청 한도는 기존 건당 한도(로컬 기본 $0.50)와 주간 결재 잔액을 모두 적용한다. 응답을 받지 못해 청구 여부가 모호하면 비용 원장은 예상 금액을 정산한다. 재시도에는 실패 작업 선택과 별도 동의가 필요하다.
3. 스튜디오에서 대기·생성·오류·미리보기를 확인한다. 자동 검사 결과와 원문을 직접 비교하여 아래 사람 검수 항목을 모두 확인한 뒤 승인한다. 승인은 최신 승인 근거와 제작안 해시·버전을 다시 비교하고 기존 영상 제작안 저장·제출·승인을 수행한다. 미리보기 상태에서는 영상 제작안과 렌더 작업이 만들어지지 않는다.
4. 승인된 제작안을 열어 째리 렌더 방식을 선택하고 별도로 제작을 요청한다. 운영자의 승인과 렌더 요청은 서로 다른 작업이다. 소유자 게시 차단은 제작 뒤에도 적용된다.

근거의 현재 상태를 가잡기, 결과 저장, 사람 승인 시점에 다시 확인한다. 변경이 이미 가잡기를 통과한 호출과 겹치면 전송과 과금이 발생할 수 있으며 결과 저장은 차단한다. 비용 상한은 개발 원장이 잠그는 추정액 기준이며 공급자 실청구와 신규 편의 품질은 모의 시험으로 확인할 수 없다.

## 정답 재현과 제작

정답 파일에는 기존 손작업 자막 1줄이 18자로 남아 있다. 로컬 비교 명령에서 저장된 음성을 주입할 때 해당 한 줄을 허용한다. 실제 제작의 한 줄 한도는 17자다. 리포트 음성은 1.2배속 설정을 사용하며 째리의 술 수업에는 +10% Edge 음성에 1.055배속을 적용한다.

제작의 최종 파일과 커버는 기존 임대·자산·검수 흐름을 사용한다. 비용 원장에 Edge 음성과 로컬 HyperFrames를 각각 0 USD로 남긴다. QA에 출처, 재생 시간표, 음량과 권리 정보를 남긴다. 소유자 판정 전에는 이 형식의 발행 상태 전이를 DB와 워커에서 차단한다.

## 사람 원문·게시 전 검수

제작 지시서와 최종 영상·커버를 승인한 근거와 대조한다. 제목, 화면 문구와 출처 칩, 내레이션·자막, 게시 캡션까지 확인한 뒤 소유자가 최종 판정한다.

- **가격** — 붙여 쓴 `원주고`, 고유어 수사로 쓴 외화, 통화 없는 `3만`·`3만 선`, 비교·할인 문구를 가격 문맥에서 확인한다. 화면의 금액을 제거하고, 게시 캡션의 금액과 금액 없는 가격 수준 표현도 직접 검토한다.
- **건강 효능** — 원문에 인용할 수 있는 문구여도 영상과 게시물에서 건강 효능·치료·예방을 암시하지 않는지 확인한다. `항암`, `숙취완화`, `면역증강` 등 자동 규칙이 잡지 못한 표현도 확인한다.
- **수사** — 값, 단위, 측정 대상과 조건이 원문과 같은지 확인한다. 어림 수사, 복합 고유어 수사, 분수, 앞말에 붙여 쓴 수사와 환산을 직접 대조한다.
- **오탐 교정** — `달달한 향`, `이 배치`, `원재료`처럼 정상 표현이 단위로 읽히면, 지시어를 덜거나 뜻이 분명한 단어로 바꾼다. 실제 수량은 아라비아 숫자와 단위를 함께 써서 원문에 맞추고 자동 검사를 다시 실행한다. 모의 교정 응답은 확인했으며 실제 모델의 교정 성공률은 미검증이다.

자동 검사는 숫자와 지원 단위의 핵심부에 어휘·문맥 규칙을 적용한다. 일부 조사·어미 규칙이 통화 없는 금액, 건강 합성어·문맥 및 어휘 충돌 판정에 쓰인다. `도` 뒤의 `지만`, `면`, `지요`, `구나`, `기에`는 한글 수치 대조에서 일반 낱말과 겹치는 경우를 따로 구분한다. 자동 검사를 통과한 제작안에도 위 사람 검수 항목이 적용된다.

## 로컬 확인과 적용 순서

- 정답 재현은 `python -m scripts.jjeri_preview <output-directory>`로 실행한다.
- 로컬 SQL 후보는 `supabase/local/jjeri_class.sql`이다. 원격의 마이그레이션 등록 현황과 대조한 뒤 번호를 부여한다.
- `python -m pytest -q tests/test_drinks_loop_e2e.py -k jjeri`는 로컬 DB의 요청, 임대, 자산 저장, 검수, 발행 차단을 검증한다. `JJERI_LOCAL_REAL_RENDER=1`을 추가하면 검증용 기존 음성을 주입하고 실제 HyperFrames 렌더를 호출한다.
- 원격 스키마 적용, 워커·UI 배포, 새 주제 원문 대조, 소유자 판정은 각각 확인이 필요하다.

되돌릴 때는 먼저 `DRINKS_JJERI_ENABLED=0`으로 새 선택과 렌더 요청을 끈다. 운영자가 제작 화면에서 대기 중인 `jjeri_class` 작업을 취소한다. 실행 중인 째리 작업은 현재 워커에서 완료하거나 취소가 확정될 때까지 기다린다. 대기·실행 중인 째리 작업이 0건임을 확인한 뒤 옛 워커로 전환한다. 옛 워커는 렌더러를 가리지 않고 큐에서 작업을 받으므로 전환 순서를 지킨다. 생산된 파일과 이력을 보존한다. 원격 스키마를 적용한 이후라면 실제 작업 및 자산 상태를 확인한 다음 별도로 승인된 되돌리기 마이그레이션을 작성한다. 이번 수정에서는 이 절차를 문서화했다.

### 웹 지시서 생성 후보의 적용과 되돌리기

- 번호 없는 후보는 `supabase/local/jjeri_generation.sql`이다. `jjeri_class.sql` 적용이 선행된다. 운영 main `93ce78823d17501f1cff28c4667c56565b635e7f`에 다른 `0091`이 존재하며 운영 등록부 조회는 권한 거부 상태다. 번호 확정 전 담당자가 등록부와 운영 함수 정의를 확인한다. 후보의 공유 함수 `drinks_start_develop`, `drinks_develop_status`, `drinks_studio_status_0076`를 운영 최신 정의에 맞춰 비교·합성하고 기존 큐·스튜디오 및 새 기능 로컬 회귀를 다시 실행한다.
- 후보 SQL과 권한을 검증·적용한 뒤 워커와 웹을 생성 플래그가 꺼진 상태로 배포한다. 공급자 설정과 예상 과금, 기존 렌더와 게시 차단을 확인한 뒤, 호출 수와 상한에 대한 명시 승인이 있을 때 워커 저장소 변수와 웹 런타임의 `DRINKS_JJERI_GENERATE_ENABLED=1`을 켠다. 배포·실결재·실호출·원격 쓰기는 운영 담당자가 수행한다.
- 되돌릴 때 웹과 워커의 `DRINKS_JJERI_GENERATE_ENABLED`를 끈다. 운영자가 `kind='jjeri'`인 대기 요청 ID를 확인해 기존 운영자 API의 `cancel_develop` 동작으로 취소한다. 패널이 비활성화되더라도 이 동작을 사용할 수 있다. 실행 중인 요청도 종료 또는 취소가 확정될 때까지 확인한다. 활성 작업이 0건이면 이전 워커·웹으로 전환한다. 요청 결과, 원장, 승인된 제작안은 보존한다. DB도 되돌려야 하면 현재 운영 정의와 의존성에 맞는 별도 마이그레이션을 검토한다. 렌더도 되돌릴 경우 위의 별도 `jjeri_class` 렌더 큐 절차를 사용한다.


## 술 해부 재검사와 운영 경계

- `jjeri_anatomy`는 로컬 SQL 후보의 별도 워커 지원 신호로 처리한다. 웹 생성 요청은 기존 째리 생성 스위치와 해부 스위치가 모두 필요하다. 승인 원문 해시·금액과 최대 2회·lease·사람 승인·제작안 버전을 기존 경로로 확인한다.
- 술 해부는 승인 인용에 포함된 텍스트의 정규화 부분 문자열만 받는다. 영어 원문에 한국어 재서술을 연결하는 기능은 별도 검토 대상이다. 퀴즈 질문과 유도 음성에 현재 적용하는 자동 검사는 가격·건강·형식이며, 답은 그전에 표시되고 발화된 같은 승인 주장으로 대조한다.
- 사람은 실제 새 주제에서 인용과 주장 관계, 수치·가격·건강 효능의 누출·오탐, 질문의 전제와 보기를 확인한다. 자체곡 저역 피크와 음원 시작 후보 중 어느 쪽이 자연스러운지는 소유자 청취를 기다린다. 게시 DB와 워커 차단은 적용 전제다.
- 원격 SQL 등록과 마이그레이션 번호는 운영 등록부 대조 후 정한다. 후보의 함수 wrapper는 이후 같은 RPC를 재정의할 때 가드 보존을 확인한다.
