# 주류 소재 자동 개발 (0단계) — 2026-10-30

**한 줄:** 운영자가 고른 소재에 대해 워커가 ① 원문 그대로 인용이 붙은 근거 초안, ② 그 근거만으로 쓴 30~40초 대본·화면 계획 초안을 만든다. 초안까지만 쓴다 — 승인은 사람이 기존 화면에서 한다.

## 0단계 범위
- 만든 것: 마이그레이션 `0060_drinks_develop.sql`, 워커 `engine/drinks_develop.py`, 수동 실행 워크플로 `drinks-develop.yml`, 설정 `DRINKS_DEVELOP_*`.
- **실제 모델·Jev 호출은 0건이다.** 모든 모델 호출은 주입 함수이고, 테스트는 가짜를 넣었다. 실제 프롬프트가 쓰는 대본·추출 품질은 아직 본 적이 없다.

## 흐름 (승인은 두 번, 둘 다 사람)
1. 소재 → `근거 초안` 요청. 워커가 이 소재에 **이미 붙은 출처**(운영자가 붙여넣은 글 포함)와 승인된 수집원 글을 읽고, 출처마다 모델이 주장+원문 인용을 뽑는다.
2. **코드가 인용이 원문에 글자 그대로 있는지 대조**한다(공백·대소문자만 무시, 줄임표·짧은 인용·풀어쓰기는 탈락). 통과한 주장이 3건 미만이면 아무것도 쓰지 않고 `evidence_insufficient` 로 멈춘다.
3. 통과하면 근거 초안이 저장된다(support_review 는 `not_reviewed`, 핵심 메시지 한 줄은 비어 있음). 운영자가 기존 화면에서 채우고 승인한다.
4. 편성 뒤 `제작안 초안` 요청. 승인된 근거의 핵심 주장만으로 모델이 대본을 쓰고, 코드 검사(`drinks_script_check`)를 돌린다. 막히면 **딱 한 번** 다시 쓴다. 그래도 막히면 저장하지 않고 `blocked`(검사 결과는 요청 기록에 남음).
5. 장면 → 근거 → 원문 인용 대조표는 요청 기록의 `result.source_table` 에 있다(제작안 본문에는 DB 검증기가 지우는 칸이라 못 넣는다). 시청자 결론 한 줄은 제작안 `notes` 에 들어간다.

## 근거를 찾는 곳 — 지금은 사실상 운영자가 붙인 출처
- **Europe PMC 는 꺼져 있다**(`DRINKS_DEVELOP_EUROPEPMC_ENABLED=False`). 사이트 robots.txt 가 `ai-train=no` 를 두고 ClaudeBot 을 막으며 API 약관을 확인하지 못했다. 코드와 시험은 있다.
- 공식 출처 목록(`DRINKS_DEVELOP_OFFICIAL_SOURCES`)은 **2026-11-02 부터 5곳 13쪽이다**(운영자 등록 승인, 판정 근거 `docs/주류_근거출처_후보_2026-11-02.md`). `terms_verified: True` 가 없는 항목은 쓰지 않는다. 쪽이 고정이라 보관·개봉 후·왜 안 상하나·왜 시큼한가는 여전히 안 채워지고, 그런 소재는 `not_for` 로 집어 들지 않아 모델을 부르지 않고 근거 부족으로 멈춘다.
- 그래서 근거 부족일 때 운영자가 할 일: 소재 화면 [출처 추가]로 공식·전문 출처의 **원문을 붙여넣어 근거 역할로** 등록 → 다시 요청. 워커의 `evidence_insufficient` 메시지가 읽은 출처, 건너뛴 출처와 이유(본문 없음·후기·질문 신호 역할 등)를 알려 준다.

## 비용 장치
- 결재(`drink_develop_budgets`)가 없으면 워커는 모델을 **한 번도 부르지 않는다**(`budget_missing`). 결재 상한 ≤ $10, 기간 ≤ 30일, 결재자 말 원문 필수.
- 모델 호출마다 가잡기 → 호출 → 확정/해제. DB 가 ⓐ 결재 남은 금액 ⓑ **요청 1건 $0.50** ⓒ 요청당 호출 20번을 센다. 값은 SQL `drinks_develop_limits()` 와 `config` 가 같아야 한다(시험이 대조).
- 가잡기 금액은 상한(입력 추정+출력 상한, 결제 실패 시 대체 모델 단가 중 큰 값). 확정은 실제 사용량, 모르면 예상 금액. 비용은 `drink_cost_entries` 가 아니라 요청 행 `cost_usd` 와 `drink_develop_holds` 에 남는다(그 표의 FK 가 제작 작업 전용).
- 워커가 가잡기 뒤에 죽으면 그 금액은 결재에서 계속 차지된다(덜 쓰는 쪽으로 틀린다).

## 1단계 결재를 여는 법
운영자 결재 함수 `drinks_open_develop_budget({cap_usd, stage, purpose, days?, approver_words})` — 상한은 처음엔 $1 안팎, `approver_words` 에 운영자의 승인 문장 원문. 요청 때 `budget_id` 를 넣는다. 화면 연결은 웹 쪽 작업이다. 워크플로는 `GITHUB_DISPATCH_TOKEN` 이 있으면 대시보드가 깨우고, 없으면 Actions 탭에서 수동 실행한다.

## 미검증
- 실제 모델이 뽑는 주장·인용의 통과율, 대본이 첫 시도·재작성 뒤에 검사를 통과하는 비율. 프롬프트는 실측 전이다.
- Jev 근거 판정(`DRINKS_DEVELOP_JEV_ENABLED`, 기본 꺼짐)과 그 비용은 원장에 안 잡힌다(센트 미만 추정).
- 주장 문장의 **뜻**이 인용을 넘었는지는 코드가 숫자만 본다. 의미 검토는 운영자의 `support_review`.
- 한국어 소재에는 Europe PMC 영어 검색어가 없어 건너뛴다. 수집원 글 매칭은 소재 낱말 단순 포함이다.
- `drinks_script_check.check()` 는 `source` 칸이 없으면 `plan_spec` 의 `sources`(출처 표기 숫자)를 읽지 않는다 — 워커는 우회해 `source` 로 주지만, 제작 워커(`drinks_produce`)는 같은 문제를 그대로 안고 있다.
- `docs/drinks-pilot/gi-sake-v1.json` 은 지금 검사를 통과하지 못한다(엔진 규칙 이전 사례).
- 실제 Supabase 에는 0060 이 적용되지 않았다(PGlite 로만 검증).

되돌리기: 표 3개·뷰·`*develop*` 함수 drop, 워크플로 삭제. 기존 함수는 건드리지 않았다.

## 형식 고르기와 내용 승인 한 번 (2026-11-02) — 총괄계획 §6 ⓒⓓ, §7 결정 2

**한 줄:** 소재 발견함에서 [이걸로]를 누르면 근거 초안 → 대본 초안이 이어서 만들어지고, 소재의 **내용 승인** 탭에서 [승인] 한 번으로 근거와 대본이 함께 승인된다. 마이그레이션 `0064_drinks_single_approval.sql` 은 **파일만 있고 운영 DB 에 적용하지 않았다**(적용은 따로 결재).

### 이제 어떻게 돌아가나
1. **[이걸로](`/drinks/discover`).** 후보마다 추천 형식과 이유가 보인다. 운영자는 제목·질문·주종을 직접 쓰고 형식·편성 주차를 고른다. 누르면 소재로 올리고, 형식 의도를 적고, 근거 초안 요청을 넣는다. **돈은 이 단계에서 나가지 않는다.**
2. **이어 만들기(워커).** 근거 초안이 성공하면 같은 트랜잭션에서 대본 요청이 들어간다. 대본은 **아직 승인되지 않은 근거**로 쓰고 `drafted_from_unapproved` 표시가 붙는다. 대본 결론 한 줄이 핵심 메시지 초안으로 채워진다.
3. **내용 승인 탭.** 근거표(원문 인용), 주장별 뒷받침 확인, 핵심 메시지, 편성 평가 점수, 대본, 장면 지시, 금액, 이어 만들기 상태를 한 화면에서 본다. 조건이 하나라도 안 맞으면 [승인]이 잠기고 이유가 나온다.
4. **[승인].** 근거 승인 → 편성 → 대본 승인을 **한 트랜잭션**으로 한다. 안쪽은 기존 함수(`drinks_review_action`·`drinks_select`·`drinks_plan_action`) 그대로라 검사가 줄지 않고, 하나라도 실패하면 전부 되돌아간다.

### 형식(의도)과 기존 칸의 대응
| 의도 | `selected_formats` | 지금 |
|---|---|---|
| 설명형 `explainer` | `video` | 이어 만들기 + 한 번 승인 |
| 카드뉴스 `card` | `carousel` | 0065 전: 근거 초안까지 만들고 멈춘다. 0065 뒤: 이어 만들기 + 한 번 승인(`docs/deviation-drinks-card-reels.md`, 운영 적용 전) |
| 밈형 `meme` | 없음 | 의도만 적는다. 근거·대본을 만들지 않는다. 밈 제작 엔진은 아직 없다 |

`drink_topics.selected_formats` 값은 그대로 `video`·`carousel` 만 받는다. 의도는 새 표 `drink_topic_picks` 에 있다. 편성(`status='selected'`)은 [승인] 때 일어난다 — 승인되지 않은 근거로는 편성할 수 없다는 0050 규칙을 지키기 위해서다.

### 안전 장치
- **승인 전 대본은 제작·지출로 못 간다.** `drinks_plan_renderable`(0053), `drink_plans_guard`·`drinks_plan_action`(0050)을 고치지 않았다. 시험이 렌더 요청·제출·표 직접 수정 모두 막히는 것을 확인한다.
- **표시 없는 대본 요청은 0060 그대로 `review_not_approved`.** 승인 전 근거로 쓰려면 요청에 `draft_evidence` 표시, 설명형 의도, 결재가 모두 있어야 한다.
- **근거를 고치면 대본이 무효.** 주장 문장·인용·핵심 주장 선택·필수 주장이 바뀌면 트리거가 그 대본을 차단한다(풀 수 없다). 승인 직전에 값(`evidence_content_hash`)으로 한 번 더 대조한다. 대본을 쓰는 중에 근거가 바뀌면 워커에게 취소를 걸고, 저장도 거절한다.
- **무효로 치지 않는 것:** 주장별 확인(`support_review`)·핵심 메시지·점수. 이것들은 사람이 승인 화면에서 채우는 칸이다.
- **주장별 확인은 자동으로 채우지 않는다.** 핵심 주장의 확인이 안 끝나면 필수 조건 검사가 [승인]을 막는다.
- **결재가 없으면 모델을 안 부른다.** 근거 단계에서 `budget_missing` 으로 멈추고 대본 요청도 들어가지 않는다. 근거 뒤에 결재가 닫혀도 이어 가지 않고 이유를 남긴다.
- **돈 쓰기 전에 멈춤.** 핵심 주장의 인용이 원문과 안 맞는 등 사람이 채워서 해결되지 않는 결함이 있으면 대본을 요청하지 않는다(`evidence_not_usable`).
- **워커는 승인·제출·편성 함수를 부르지 않는다.** 소스 검사 시험이 감시한다.

### 형식 추천 규칙(`web/lib/drinks/formatRecommend.ts`)
- 설명형: 질문이 왜·원리를 묻고, 승인 수집원에서 걸린 글이 2개 이상이고, 합쳐 1,200자 이상.
- 카드뉴스: 비교·보관·선택·이슈이고 글 1개 이상. 왜·원리 질문인데 글이 1개이거나 분량이 모자라면 여기로 내린다.
- 밈형: 트렌드 보드의 밈 카드일 때만. 발견함 후보에는 추천하지 않는다.
- 못 읽은 값이 있거나 글이 0개면 `unknown` — 이유를 말하고 운영자가 직접 고른다.
- 문턱은 `engine/config.py` 와 시험으로 묶었다. **1,200자는 실측 없는 첫 값이다.** 글 개수는 질문 낱말이 걸린 글을 대강 센 것이고(한 화면 후보 50개까지), 진짜 판정은 근거 초안의 글자 단위 인용 대조다.

### 아직 안 되는 것 · 미검증
- **운영 DB 미적용.** 실제 Postgres 로는 돌려 본 적 없고 PGlite 시험만 했다. 적용 전에는 화면에서 [이걸로]가 `schema_missing` 으로 실패한다(옛 흐름은 그대로 동작하도록 읽기 코드가 표 없음을 처리한다).
- **실제 모델로 이어 만들기를 돌려 본 적 없다.** 전부 가짜 응답·직접 호출이다. 비용 실측은 2단계 결재 뒤다.
- **금액은 기록만 한다.** [승인]이 `approved_amount_usd` 를 남기지만 결재(`drink_spend_approvals`)를 열지 않는다. 영상 구매가 연결되면 이 금액을 결재 금액으로 잇는다.
- **장면 지시의 §3-4 칸**(`visual_claim_ko` 등)은 있으면 보여 주지만, 지금 `drinks_validate_plan` 이 저장 때 지운다. 설명형 대본 작업(ⓐ)에서 그 칸을 보존해야 화면에 나온다.
- **카드뉴스·밈은 한 번 승인이 안 된다**(위 표). 대본 문장을 승인 화면에서 직접 고치는 기능도 없다 — 대본 검사를 다시 돌릴 길이 없어서 뺐다. 지금은 다시 만들거나, 승인 뒤 영상 탭에서 새 버전을 쓴다.
- **Apify 형식 참고는 연결하지 않았다.** [이걸로]는 Apify 를 부르지 않는다(결정 1 의 클릭 승인은 코드가 생긴 뒤의 일이다).
- 후보 임시 점수(`discovery-v1`)를 소재의 경량 점수로 옮긴다. 5축 편성 평가는 승인 화면에서 사람이 매긴다 — 후보에 없는 축을 지어내지 않는다.

### 되돌리기
`0064_drinks_single_approval.sql` 머리말의 순서대로: 0060·0061 함수 정의를 다시 실행 → 트리거·새 함수 drop → `drink_topic_picks` 와 새 칸 drop. 이미 승인된 근거·대본은 평범한 승인 기록이라 그대로 쓸 수 있다. 화면은 표가 없으면 옛 흐름으로 돌아간다.
