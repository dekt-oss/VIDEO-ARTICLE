# 주류 소재 자동 개발 (0단계) — 2026-10-30

**한 줄:** 운영자가 고른 소재에 대해 워커가 ① 원문 그대로 인용이 붙은 근거 초안, ② 그 근거만으로 쓴 30~40초 대본·화면 계획 초안을 만든다. 초안까지만 쓴다 — 승인은 사람이 기존 화면에서 한다.

## 0단계 범위
- 만든 것: 마이그레이션 `0060_drinks_develop.sql`, 워커 `engine/drinks_develop.py`, 수동 실행 워크플로 `drinks-develop.yml`, 설정 `DRINKS_DEVELOP_*`.
- **실제 모델·Jev 호출은 0건이다.** 모든 모델 호출은 주입 함수이고, 테스트는 가짜를 넣었다. 실제 프롬프트가 쓰는 대본·추출 품질은 아직 본 적이 없다.

## 흐름 (승인은 두 번, 둘 다 사람)
1. 소재 → `근거 초안` 요청. 워커가 이 소재에 **이미 붙은 출처**(운영자가 붙여넣은 글 포함)와 승인된 수집원 글을 읽고, 출처마다 모델이 주장+원문 인용을 뽑는다.
2. **코드가 인용이 원문에 글자 그대로 있는지 대조**한다(공백·대소문자만 무시, 줄임표·짧은 인용·풀어쓰기는 탈락). 통과한 주장이 3건 미만이면 아무것도 쓰지 않고 `evidence_insufficient` 로 멈춘다.
3. 통과하면 근거 초안이 저장된다(support_review 는 `not_reviewed`, 핵심 메시지 한 줄은 비어 있음). 운영자가 기존 화면에서 채우고 승인한다.
4. 편성 뒤 `제작안 초안` 요청. 승인된 근거의 핵심 주장만으로 모델이 대본을 쓰고, 코드 검사(`drinks_script_check`)를 돌린다. 막히면 **딱 한 번** 다시 쓴다. 그래도 막히면 저장하지 않고 `blocked`(검사 결과는 요청 기록에 남음).
5. 장면 → 근거 → 원문 인용 대조표는 요청 기록의 `result.source_table` 에 있다(제작안 본문에는 DB 검증기가 지우는 칸이라 못 넣는다). 시청자 결론 한 줄은 제작안 `notes` 에 들어간다.

## 근거를 찾는 곳 — 지금은 사실상 운영자가 붙인 출처
- **Europe PMC 는 꺼져 있다**(`DRINKS_DEVELOP_EUROPEPMC_ENABLED=False`). 사이트 robots.txt 가 `ai-train=no` 를 두고 ClaudeBot 을 막으며 API 약관을 확인하지 못했다. 코드와 시험은 있다.
- 공식 출처 목록(`DRINKS_DEVELOP_OFFICIAL_SOURCES`)은 **비어 있다.** 식약처·국세청·공공데이터포털은 공공누리 유형을 항목마다 운영자가 확인해야 한다. `terms_verified: True` 가 없는 항목은 쓰지 않는다.
- 그래서 근거 부족일 때 운영자가 할 일: 소재 화면 [출처 추가]로 공식·전문 출처의 **원문을 붙여넣어 근거 역할로** 등록 → 다시 요청. 워커의 `evidence_insufficient` 메시지가 읽은 출처, 건너뛴 출처와 이유(본문 없음·후기·질문 신호 역할 등)를 알려 준다.

## 비용 장치
- 결재(`drink_develop_budgets`)가 없으면 워커는 모델을 **한 번도 부르지 않는다**(`budget_missing`). 결재 상한 ≤ $10, 기간 ≤ 30일, 결재자 말 원문 필수.
- 모델 호출마다 가잡기 → 호출 → 확정/해제. DB 가 ⓐ 결재 남은 금액 ⓑ **요청 1건 $0.50** ⓒ 요청당 호출 20번을 센다. 값은 SQL `drinks_develop_limits()` 와 `config` 가 같아야 한다(시험이 대조).
- 가잡기 금액은 상한(입력 추정+출력 상한, 결제 실패 시 대체 모델 단가 중 큰 값). 확정은 실제 사용량, 모르면 예상 금액. 비용은 `drink_cost_entries` 가 아니라 요청 행 `cost_usd` 와 `drink_develop_holds` 에 남는다(그 표의 FK 가 제작 작업 전용).
- 워커가 가잡기 뒤에 죽으면 그 금액은 결재에서 계속 차지된다(덜 쓰는 쪽으로 틀린다).

## 1단계 결재를 여는 법
운영자 결재 함수 `drinks_open_develop_budget({cap_usd, stage, purpose, days?, approver_words})` — 상한은 처음엔 $1 안팎, `approver_words` 에 운영자의 승인 문장 원문. 요청 때 `budget_id` 를 넣는다. 화면 연결은 웹 쪽 작업이다. 워크플로는 `GITHUB_DISPATCH_TOKEN` 이 있으면 대시보드가 깨우고, 없으면 Actions 탭에서 수동 실행한다.

## 미검증
- 실제 모델이 뽑는 주장·인용의 통과율, 대본이 첫 시도·재작성 뒤에 검사를 통과하는 비율. 프롬프트는 실측 전이다.
- Jev 근거 판정(`DRINKS_DEVELOP_JEV_ENABLED`, 기본 꺼짐)과 그 비용은 원장에 안 잡힌다(센트 미만 추정).
- 주장 문장의 **뜻**이 인용을 넘었는지는 코드가 숫자만 본다. 의미 검토는 운영자의 `support_review`.
- 한국어 소재에는 Europe PMC 영어 검색어가 없어 건너뛴다. 수집원 글 매칭은 소재 낱말 단순 포함이다.
- `drinks_script_check.check()` 는 `source` 칸이 없으면 `plan_spec` 의 `sources`(출처 표기 숫자)를 읽지 않는다 — 워커는 우회해 `source` 로 주지만, 제작 워커(`drinks_produce`)는 같은 문제를 그대로 안고 있다.
- `docs/drinks-pilot/gi-sake-v1.json` 은 지금 검사를 통과하지 못한다(엔진 규칙 이전 사례).
- 실제 Supabase 에는 0060 이 적용되지 않았다(PGlite 로만 검증).

되돌리기: 표 3개·뷰·`*develop*` 함수 drop, 워크플로 삭제. 기존 함수는 건드리지 않았다.
