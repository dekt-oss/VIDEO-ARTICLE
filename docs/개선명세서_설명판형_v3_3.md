## 0. 결론

이번 개선의 핵심은 다음 한 줄이다.

> **숫자를 예쁘게 보여주는 영상을 넘어서, “어느 증권사가 어떤 이유로 무엇을 전망했는지”를 화면과 나레이션에서 명시적으로 보여주는 리포트 해석 영상으로 강화한다.**

즉 앞으로 하루 리포트 하나 explainer는 다음 질문에 반드시 답해야 한다.

1. **누가 그렇게 말했는가?**  
   - 예: 유안타증권 리포트
2. **무엇을 근거로 그렇게 봤는가?**  
   - 예: 데이터센터 전력기기 수요 확대, 신규 수주 증가
3. **그래서 어떤 숫자를 전망했는가?**  
   - 예: 올해 신규 수주/매출/영업이익 증가
4. **그 전망이 투자자에게 왜 중요한가?**  
   - 예: 목표주가 상향, 밸류에이션 부담, 확인 포인트

설명판형 포맷 자체는 유지한다.  
다만 앞으로는 **근거 보드(EVIDENCE_BOARD)와 증권사 주장 귀속 문장**이 없으면 리포트 해석 영상으로 승인하지 않는다.

또한 고정 초 단위로 영상을 억지로 맞추지 않는다.  
길이는 “질문에 답하는 데 필요한 비트 수”를 기준으로 결정한다.

## 1. 이번 개정이 필요한 이유

v3.2 방향은 전반적으로 타당했다.

- 웹툰형 → 설명판형 전환
- 원문 분석 선행
- depth_core / core_thesis / watchpoint
- source_mode
- 설명판과 차트 중심
- 한·영 자산 공유

그러나 실제 샘플 리뷰 기준으로 다음 한계가 드러났다.

### 1-1. 숫자는 보이지만 논리의 출처가 약하다

현재 영상은 다음을 잘 보여준다.

- 목표주가 변화
- 신규 수주 규모
- 현재 주가와 목표주가
- 밸류에이션 수치

하지만 시청자는 다음이 궁금하다.

- 이 해석은 **영상 제작자의 의견인지**, **증권사 리포트의 주장인지**
- 목표주가를 올린 **핵심 근거가 정확히 무엇인지**
- 신규 수주가 **매출·이익 증가로 어떻게 연결되는지**
- 밸류에이션이 **왜 부담인지, 어떤 조건이면 정당화되는지**

즉 **“숫자 제시”는 성공했지만 “주장 귀속과 근거 명시”는 약했다.**

### 1-2. 리포트를 실제로 읽었다는 증거가 화면에 더 필요하다

출처 라벨만으로는 부족하다.  
앞으로는 최소 1회 이상, 가능하면 2회 이상 아래를 화면에 보여줘야 한다.

- 증권사명
- 리포트 제목 또는 핵심 문장
- 페이지 번호 또는 표/그림 번호
- 핵심 근거 문장
- 해당 문장에서 추출한 숫자

즉, **영상이 기사 요약이 아니라 실제 리포트 해석이라는 증거가 화면에서 보여야 한다.**

### 1-3. 고정 초 단위는 운영상 유연성을 해친다

기존 v3.2는 이미 가변 길이로 완화했지만, 여전히 길이 밴드가 강하게 제시되어 있다.  
사용자 판단처럼 앞으로는 초 단위 하드 규칙보다 아래가 더 중요하다.

- 필요한 비트가 다 들어갔는가
- 핵심 답이 중간에 완결되는가
- 반복과 장식이 없는가
- 이탈을 유발할 만큼 장황하지 않은가

따라서 본 v3.3은 **“초 단위 목표”보다 “비트 수 기반 길이 정책”**을 채택한다.

## 2. 포맷의 기본 정의 (유지)

### 2-1. 채널 한 줄 정의

> **증권사·산업·기업 리포트에서 주가와 산업을 움직일 핵심 논리 하나를 찾아, 어떤 기관이 왜 그렇게 봤는지 근거와 반론까지 짧고 이해하기 쉽게 설명한다.**

### 2-2. explainer는 병렬 버전으로 유지

```text
version_type = "explainer"
```

- 기존 경로를 대체하지 않는다
- 리포트 공장의 신규 버전 중 하나로 유지
- image_sequence 경로는 비교군과 폴백으로 보존

### 2-3. 기본 미학 유지

- 설명판 중심
- 코드 렌더 차트와 대형 숫자 중심
- 실사 맥락 컷은 보조
- 웹툰/만화는 기본 경로에서 제외
- 다크 금융 에디토리얼 톤 유지

## 3. 신규 핵심 원칙

### P1. 주장 귀속 원칙 (Attribution First)

핵심 근거나 전망을 말할 때는 **“누가 그렇게 봤는가”**를 명시한다.

#### 권장 나레이션 형식

- “유안타증권은 **데이터센터 전력기기 수요 확대**를 이유로 LS일렉트릭의 수주 증가를 예상했습니다.”
- “이 리포트는 **북미향 수주 증가**가 올해 매출 성장의 핵심이라고 봤습니다.”
- “증권사는 **수주 잔고의 매출 전환 가능성**을 목표주가 상향의 근거로 제시했습니다.”

#### 금지 형식

- “LS일렉트릭은 올해 매출이 증가합니다.”  
  → 누가 말한 것인지 불명확
- “목표주가가 오를 겁니다.”  
  → 근거와 귀속이 없음
- “수주가 많아서 좋아 보입니다.”  
  → 해석 수준이 낮음

### P2. 근거 보드 의무화 (Evidence Mandatory)

`FULL_REPORT` 또는 `PARTIAL_REPORT` 기반 영상은 다음을 반드시 포함한다.

```text
EVIDENCE_BOARD >= 1
```

권장:

```text
EVIDENCE_BOARD >= 2
```

이 보드는 단순 출처 표기가 아니라, **리포트 안의 핵심 문장 또는 표/차트를 실제로 보여주는 장면**이다.

### P3. 숫자에는 비교 기준이 있어야 한다

대형 숫자 또는 주요 숫자는 단독으로 쓰지 않는다.

- 1.09조 원 → 무엇과 비교해 의미가 있는가
- 48.6배 → 왜 높은가 / 무엇과 비교해 높은가
- 30만 원 목표주가 → 무엇이 바뀌어서 산정됐는가

즉, **숫자 → 비교 기준 → 의미** 세트를 기본 구조로 한다.

### P4. 질문보다 주장 문장이 더 선명해야 한다

기존 `depth_core.question`은 유지하되, 수치형 리포트에서는 질문만큼이나 `report_claim_summary`가 중요하다.

예:

> 유안타증권은 데이터센터 전력 수요 확대를 근거로, LS일렉트릭의 신규 수주와 매출 증가를 전망했다.

이 문장이 영상의 중심축이 된다.

### P5. 길이는 비트 수로 결정한다

더 이상 “무조건 몇 초”를 우선하지 않는다.  
길이는 다음으로 결정한다.

- 질문 1개
- 핵심 주장 1개
- 핵심 근거 2~3개
- 메커니즘 1개
- watchpoint 1개

이 구성이 자연스럽게 끝나는 길이가 정답이다.

## 4. 콘텐츠 구조 — v3.3 핵심 강화

### 4-1. explainer_profile 도입

explainer는 한 종류가 아니라 3개 프로필로 나눈다.

```jsonc
{
  "explainer_profile": "NUMERIC | MECHANISM | EVENT"
}
```

#### A. `NUMERIC`
적합 소재:
- 목표주가 상향
- 실적
- 수주
- 성장률
- 밸류에이션

핵심 질문 예:
- 목표주가가 왜 계속 올라가나?
- 이 수주 숫자가 왜 중요한가?
- 현재 밸류에이션이 부담인가?

핵심 화면:
- NUMBER_BOARD
- CHART_BOARD
- EVIDENCE_BOARD

#### B. `MECHANISM`
적합 소재:
- 공급망
- 산업 구조
- 수요 전이
- 실적 전환 논리

핵심 질문 예:
- 왜 이 산업 변화가 이 회사 실적에 연결되나?
- 어떤 메커니즘으로 수주가 매출이 되나?

핵심 화면:
- MECHANISM_BOARD
- EVIDENCE_BOARD
- CHART_BOARD

#### C. `EVENT`
적합 소재:
- 규제
- 정책
- 신규 계약
- 인수합병
- 수출 제한

핵심 질문 예:
- 왜 이 이벤트가 중요하나?
- 누가 수혜/피해를 보나?

핵심 화면:
- HOOK_BOARD
- EVIDENCE_BOARD
- COMPARISON_BOARD

### 4-2. 수치형 리포트의 기본 논리 구조

`NUMERIC` 프로필의 기본 구조는 다음을 따른다.

1. **숫자 또는 변화 제시**
2. **그 숫자가 의미 있는 이유 설명**
3. **증권사 리포트의 핵심 근거 제시**
4. **그 근거가 매출/이익/목표주가로 이어지는 메커니즘 설명**
5. **현재 가격 또는 리스크와 연결**
6. **확인할 지표 제시**

즉:

```text
변화 → 근거 → 메커니즘 → 전망 → 부담/조건 → watchpoint
```

### 4-3. 필수 핵심 문장: `report_claim_summary`

새 필드 추가:

```jsonc
{
  "report_claim_summary": {
    "speaker": "유안타증권",
    "statement": "데이터센터 전력기기 수요 확대를 이유로 LS일렉트릭의 신규 수주와 매출 증가를 전망했다.",
    "fact_refs": ["F1", "F3"],
    "page_refs": [3, 5]
  }
}
```

규칙:

- 모든 explainer 영상은 `report_claim_summary`를 가져야 한다
- 이 문장은 영상 본문에서 최소 1회 **직접 또는 요약형으로 화면에 나타나야 한다**
- 영상의 중간 핵심 보드 또는 EVIDENCE_BOARD에서 사용한다

### 4-4. 메커니즘 비트 의무화

순수 단신성 뉴스가 아닌 이상, explainer는 다음 중 하나를 반드시 포함한다.

```text
원인 → 수주/매출 전이 → 이익/목표가 또는 밸류에이션
```

수치형 영상에서 이 비트가 없으면 “숫자 나열형”으로 남기 쉽다.

## 5. 보드 시스템 업그레이드

### 5-1. 기존 보드 유지

- `HOOK_BOARD`
- `NUMBER_BOARD`
- `CHART_BOARD`
- `EVIDENCE_BOARD`
- `WATCHPOINT_BOARD`

### 5-2. EVIDENCE_BOARD를 상향

기존 정의에서 한 단계 강화한다.

#### 필수 구성
- 증권사명
- 리포트 제목 또는 핵심 주장 요약
- 발행일
- 페이지 번호 또는 그림/표 번호
- 핵심 근거 문장 또는 표/차트 일부
- 하이라이트 1~2개

#### 목적
- “이 영상은 실제 리포트를 읽고 만들었다”는 증거 제공
- 숫자의 출처 제시
- 핵심 주장 귀속 명시
- 기사 요약과 차별화

### 5-3. 신규 보드: `CLAIM_BOARD`

수치형 리포트에 특히 유용한 신규 보드.

#### 역할
- 증권사 또는 리포트의 핵심 주장 1문장을 화면에서 선명하게 제시
- 너무 많은 원문을 보여주지 않고 핵심만 압축

#### 예시
- “유안타증권: 데이터센터 전력기기 수요 확대 → LS일렉트릭 수주·매출 성장 전망”
- “리포트 핵심: 북미향 전력기기 수요가 올해 실적 추정치 상향의 근거”

#### 권장 사용 위치
- HOOK 뒤
- 첫 번째 EVIDENCE_BOARD 전
- 또는 EVIDENCE_BOARD 직후 요약 정리용

### 5-4. 신규 보드: `VALUATION_BOARD`

PER, PBR, EV/EBITDA 등 밸류에이션 숫자를 단독 경고로 끝내지 않기 위한 보드.

#### 포함 요소
- 현재 밸류에이션
- 비교 기준 (과거 평균 / 경쟁사 / 성장률 / 추정치)
- 왜 부담인지 또는 정당화 가능한 조건
- 확인 포인트

#### 예시 구조
- “2026F PER 48.6배”
- “과거 평균 대비 높은 구간”
- “수주만이 아니라 이익률 개선이 동반돼야 정당화 가능”

### 5-5. 신규 보드: `REPORT_REASON_BOARD`

영상 제작자의 해설이 아니라 **증권사 리포트의 이유를 정리하는 보드**

예시:
- “왜 유안타증권은 좋게 봤나?”
  1. 데이터센터 전력 수요 확대
  2. 신규 수주 증가
  3. 실적 추정치 상향 가능성

이 보드는 숫자와 이유를 연결하는 중간 다리 역할을 한다.

## 6. 숫자 규칙 강화

### 6-1. number_claim 스키마 추가

```jsonc
{
  "number_claims": [
    {
      "value": "1.09",
      "unit": "조원",
      "label": "1분기 신규 수주",
      "comparison_basis": "연간 목표 | 전년 동기 | 과거 평균 | 컨센서스 | 경쟁사",
      "comparison_value": "",
      "why_significant": "",
      "fact_refs": ["F1"],
      "page_refs": [4]
    }
  ]
}
```

### 6-2. 대형 숫자 사용 조건

아래 중 2개 이상이 없으면 대형 숫자 보드 주인공으로 쓰지 않는다.

- 비교 기준
- 비교 값
- why_significant
- fact_refs
- page_refs

### 6-3. 금지 패턴

- “신규 수주 1.09조 원”만 크게 보여주고 끝냄
- “PER 48.6배”만 보여주고 위험하다고 말함
- “목표주가 30만 원”만 보여주고 왜 그런지 말하지 않음

### 6-4. 권장 패턴

#### 패턴 A
- 숫자
- 비교 기준
- so_what

#### 패턴 B
- 숫자
- 증권사 근거
- 메커니즘

#### 패턴 C
- 숫자
- 부담 요인
- 확인할 조건

## 7. 길이 정책 — 초 단위 하드 규칙 완화

### 7-1. 새 원칙

길이는 초 단위보다 **비트 수와 정보 완결성**을 기준으로 판단한다.

### 7-2. 기본 비트 구성

권장 비트 수:

- 훅: 1
- 핵심 주장: 1
- 근거: 2~3
- 메커니즘: 1
- 리스크/부담: 0~1
- watchpoint: 1

즉 보통 **6~8비트**가 기본 골격이다.

### 7-3. 길이 판정 기준

다음 기준을 통과하면 길이는 허용한다.

- 질문이 완결됐는가
- 주장 귀속이 명확한가
- 숫자와 비교 기준이 충분한가
- 메커니즘이 설명됐는가
- watchpoint가 존재하는가
- 반복 컷이 아닌가
- 장황하지 않은가

### 7-4. 운영상 참고 범위

참고 차원에서만 아래 범위를 둔다.

- 간결형: 짧은 explainer
- 표준형: 일반적인 explainer
- 확장형: 메커니즘이 많은 explainer

단 **최종 승인 기준은 초 단위가 아니라 완결성**이다.

```text
■ 리포트 귀속 규칙
- 증권사 리포트의 전망·주장은 "누가, 무엇을, 왜"의 형태로 요약한다.

- 가능하면 실제 리포트의 문장, 표, 차트 일부를 보여주고 출처·페이지를 표기한다.
```

## 9. 게이트 강화

### 9-1. Source Gate 추가 조건

차단 조건 추가:

- `FULL_REPORT` 또는 `PARTIAL_REPORT`인데 `report_claim_summary` 없음
- `NUMERIC` 프로필인데 `number_claims` 없음
- `EVIDENCE_BOARD = 0`
- 숫자형 핵심 주장이 fact/page 근거 없음

### 9-2. Content Depth Gate 추가 검사

- 주장 귀속이 명확한가
- 증권사 이유가 제시됐는가
- 수치가 비교 기준과 함께 설명됐는가
- 메커니즘 비트가 존재하는가
- watchpoint가 면책과 분리됐는가

### 9-3. Visual Gate 추가 검사

- EVIDENCE_BOARD에 증권사명과 페이지 정보가 보이는가
- CLAIM_BOARD가 과도한 텍스트 덩어리가 아닌가
- VALUATION_BOARD가 숫자만 보여주고 끝나지 않는가
- 리포트 원문이 너무 작거나 흐리지 않은가

- 결론이 “각자의 판단” 같은 추상 문장으로 끝나지 않는가

## 12. LS일렉트릭류 수치형 리포트의 권장 서술 템플릿

### 템플릿 A — 기본형

1. **훅**
   - “목표주가가 1년 동안 9번 올랐습니다.”

2. **핵심 질문**
   - “도대체 무엇이 이렇게 바뀐 걸까요?”

3. **리포트 핵심 주장**
   - “유안타증권은 데이터센터 전력기기 수요 확대를 이유로, LS일렉트릭의 신규 수주와 매출 증가를 전망했습니다.”

4. **근거**
   - “실제 리포트에서는 1분기 신규 수주 1.09조 원을 핵심 근거로 제시했습니다.”

5. **비교 기준**
   - “이 숫자는 연간 목표 대비 어느 정도이고, 전년 대비 어떤 흐름인지가 중요합니다.”

6. **메커니즘**
   - “수주가 늘면 수주잔고가 쌓이고, 이후 매출과 이익으로 전환됩니다.”

7. **밸류에이션**
   - “다만 현재 밸류에이션은 이미 미래 기대를 상당 부분 반영하고 있습니다.”

8. **watchpoint**
   - “다음 분기에도 신규 수주와 이익률이 같이 올라오는지 확인해야 합니다.”

### 템플릿 B — 귀속 강조형

- “이건 시장 전체의 막연한 기대가 아니라, **유안타증권 리포트의 주장**입니다.”
- “이 리포트는 **A라는 이유로 B를 예상했고**, 그래서 **목표주가를 C로 제시했습니다.**”

### 템플릿 C — 밸류에이션 균형형

- “좋은 수주 흐름은 분명하지만, 현재 주가는 그 기대를 상당 부분 먼저 반영하고 있습니다.”
- “핵심은 수주 증가가 실제 이익 증가로 이어지는지입니다.”

## 14. 최종 운영 원칙

1. **설명판형 포맷 자체는 유지한다**
2. **수치형 리포트는 이 포맷이 가장 적합하다**
3. 다만 앞으로는 **숫자 카드 영상이 아니라 리포트 근거 명시형 해석 영상**으로 한 단계 더 올린다
4. 핵심은 시각 효과보다 **증권사 주장 귀속 + 리포트 근거 + 숫자의 의미 설명**
5. 길이는 초 단위보다 **완결성**을 기준으로 결정한다
6. “유안타증권은 ~한 이유로 ~를 전망했다” 같은 문장이 explainer의 중심축이 된다
