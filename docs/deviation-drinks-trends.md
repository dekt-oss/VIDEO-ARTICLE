# 주류 동향 수집 — 커뮤니티 언급 순위·반응·이슈 (2026-10-29)

운영자 요청: "주류 커뮤니티도 수집에 추가. 언급 많은 주류를 소재와 같이 보여줘. 긍정/부정도 점수화. 제품 말고 주류 이슈도 수집."

## 무엇을 하나
- **커뮤니티 언급 순위**: 술 전문 네이버 카페 글(검색 결과의 제목·요약)에서 제품 사전(약 80개 제품·브랜드)에 있는 이름을 찾아 최근 7일 언급 글 수로 순위를 매긴다. 화면 `/drinks/trends`.
- **반응(긍정/부정)**: 언급마다 Jev 에게 "글쓴이가 이 제품을 좋게 말하나"를 묻고 점수 = 2p−1(−1~1). +0.2 초과 긍정, −0.2 미만 부정.
- **주류 이슈**: 네이버 뉴스 검색(주세 개정·규제·가격 인상·수입 등 11개 검색어)에서 술 이야기인 기사만(`is_relevant`) 최근 14일 목록으로.
- 워커 `python -m engine.drinks_trends` 는 `drinks-collect` 워크플로의 **맨 끝 단계**(`continue-on-error`)라 수집을 막지 않는다.

## 커뮤니티 목록과 측정
2026-10-29 네이버 API HUB 로 술 검색어 10개 × 카페글 2,000건을 받아 카페별 글 수를 셌다. 실제 술 커뮤니티만 골라 `config.DRINKS_COMMUNITY_CAFES`(12곳)에 넣었다: 위스키 코냑 클럽 629 · 숙성주작소 207 · 내가사케 110 · 우리술·국술 81 · 슬기로운 위스키 생활 42 외. 와인·맥주 카페는 운영자 범위(사케·전통주·위스키) 밖이라 뺐다. 목록 밖 카페 글은 버린다.

## 반응 점수의 정체
- Jev 의 한 판정(`decide.noul`, 차단기·실패 시 None 규칙 그대로). **판정을 못 하면 null — 화면에 '판정 없음'**, 추측해 채우지 않는다. 평균에서도 빠진다.
- 실행당 상한 300건(`DRINKS_TRENDS_JEV_MAX_PER_RUN`). 못 물은 언급은 다음 실행이 다시 집는다(14일 안).
- 비용: 판정 1건 ≈ 입력 수백 토큰이라 **한 실행 1센트 미만으로 예상 — 실측 전이라 미검증**. 채점·편성에는 쓰지 않고 소재 신호로만 보여준다.

## 0059 (운영 적용은 운영자 승인)
새 표 2개(`drink_trend_posts`, `drink_trend_mentions`)·보기 2개·워커 함수 3개만 추가한다(기존 객체 변경 없음, 되돌리기는 파일 머리말). 공개 역할 접근 없음, 대시보드는 서버에서 service key 로 읽는다. **0059 가 없으면** 화면이 "0059 가 운영 DB 에 아직 없습니다"를 보이고, 워커는 기록 실패 건수만 세고 계속한다.

## 미검증 (정직하게)
1. **실제 네이버 뉴스 응답** — 필드(`originallink`·`pubDate`)는 문서·기존 커넥터 기준으로 짰고 실호출은 아직 안 했다. 카페 응답의 `postdate` 유무도 확인 전(없으면 게시일 대신 수집일로 센다).
2. **Jev 반응 정확도** — 한국어 은어·반어("가성비 폭망")·중립 질문글에서 맞는지 잰 적 없다. 사람이 몇십 건 표본으로 대조하기 전에는 순위 정렬에 쓰지 않는다.
3. **사전 커버리지** — 사전에 없는 제품은 잡히지 않는다. 짧은 이름('지평'·'려')은 오탐 때문에 일부러 뺐다. 첫 운영 주 뒤 눈으로 보고 늘린다.
4. 검색 요약만 보므로 글 전체의 반응과 다를 수 있다. 같은 사람이 여러 글을 쓰면 중복으로 센다.
5. 워크플로의 Jev 키(`JEV_*` env)는 다른 작업에서 넣는다 — 그 전에는 점수가 전부 '판정 없음'이다.
