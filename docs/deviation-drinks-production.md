# 주류 공장 C단계 — 영상 우선·카드뉴스 병행 제작 (2026-10-23)

명세 §7(production_jobs·media_assets·asset_manifests·deliverable_assets·output_reviews)·§8.3·§12.
마이그레이션 `0053_drinks_production.sql`(0052 위, 어디에도 미적용). 브랜치 `claude/drinks-factory-phase-c`.

## 흐름

선정 소재 + 승인된 근거 → 공통 기획(A) → 영상 / 카드 제작안(A, 형식별 독립 승인) → **렌더 요청**(입력 고정) →
워커가 렌더 → **불변 파일 묶음**(manifest) → **최종 파일 검수**(형식별, 사람). 공유되는 것은 핵심 주장·근거·브랜드뿐이고,
대본·장면·페이지·버전·승인은 형식마다 따로다 — 카드만 다시 렌더해도 영상 묶음·승인은 그대로다(테스트·e2e 확인).

## 표(0053)

| 표 | 지키는 것 |
|---|---|
| `drink_production_jobs` | 입력 = 제작안 승인 해시 + 근거 승인 해시 + 렌더러 버전. 같은 제작안·같은 입력의 활성 작업 1개(중복 요청 = 같은 작업). 임대 토큰 없으면 기록 불가, 임대 만료 = 실패(늦은 결과 저장 안 함). 끝난 작업 불변 |
| `drink_media_assets` | 파일 불변(상태만 stored→deleting→deleted). 저장 위치는 `drinks/` 또는 `local:` 만. 같은 위치에 다른 내용 금지. 검수 대기·승인 묶음의 파일은 정리 상태로 못 바꿈 |
| `drink_asset_manifests` · `drink_manifest_assets` | 묶음·구성 불변. 영상 = 최종 영상 1 + 커버 1, 카드 = 제작안 페이지 수만큼 1..n 연속. 이 작업이 등록한 파일만 |
| `drink_output_reviews` | 묶음 1:1. pending → approved / changes_requested / blocked. 승인 = 형식별 체크리스트 전부 확인 + **그 순간** 제작안 미차단·근거 유효(트리거가 직접 UPDATE 도 막음). blocked 는 풀 수 없음 |
| `drink_cost_entries` | append-only. 작업·시도·공급자·모델별. 공유 파일 비용은 파일당 한 번 |
| `drink_output_validity`(뷰) | 승인 기록과 **지금 사용 가능**을 따로 — 근거 철회 뒤 승인 묶음은 "승인됨·지금 사용 불가" |

근거 철회·권리 변경 처리: 대기 작업은 워커가 시작할 때 취소(비용 쓰기 전), 진행 중 작업은 파일·비용을 보존하고 검수를 blocked 로,
이미 승인된 묶음은 기록을 남기고 현재 사용 불가로 표시. 렌더 요청도 그 순간 거부한다.

## 영상 — 기존 엔진 재사용

- 어댑터 `engine/drinks_render.py::plan_to_directive` 가 영상 제작안(scenes[])을 엔진 지시서 모양(cuts[])으로 바꾸고
  `render.render_directive_local` 을 부른다 — 엔진의 TTS → 컷 mp4(Ken Burns·패닝) → ASS 자막 → 조립·음량 정규화를 그대로 탄다.
- 논문 전용 경로를 우회하지 않고 **닿지 않게** 했다: directive_id 없이 부르므로 자산 캐시·논문 원장·논문 표에 쓰지 않는다.
  `version_type='image_sequence'`(photo 는 영상 생성 필수 경로라 쓰지 않음), `motion_source`·실사 계약 필드를 켜지 않는다.
- 엔진에 없던 것(신규): 커버(Pillow), 장면 유형 표기, 결과 검사(ffprobe 해상도·길이·오디오, 무음 감지, 글자 잘림, 없는 글자).
- **장면 유형 표기**: 장면 카드마다 "연출 장면 · 실제 제품·시설 촬영 아님" / "설명용 도해 · 실제 공정을 단순화함" / "정리 카드".
  검수 체크리스트에 "장면 유형이 보인다"·"실제 제품·제조 과정으로 오해될 장면이 없다"가 필수 항목이다.

## 유료 실행

**꺼져 있다.** 렌더 요청의 `paid` 는 `paid_disabled`(예산 미설정)로 거부되고, 워커는 유료 공급자(이미지·영상·유료 TTS)가 켜져 있으면
렌더를 거부한다. 지금 렌더 = 로컬 대체 이미지(Pillow 장면 카드) + 무료 TTS(edge-tts) + ffmpeg. 비용 원장에는 $0 기록이 공급자별로 남는다.
유료 그림으로 바꿀 때 쓸 문장은 컷의 `visual_prompt` 에 이미 들어 있다(지금은 쓰이지 않음).

★ **대체 이미지 렌더는 목표 화풍(3D 도해·실사감·시네마틱) 품질 검증이 아니다.** 검증된 것은 제작안 → 장면·음성·자막·합성 → 세로 영상·커버
→ 파일 묶음 → 검수 흐름이다.

## 저장·정리(GC)

- 파일은 비공개 버킷 `drinks` 의 `drinks/{job}/…`(Supabase) 또는 로컬 검증 폴더(`local:`). 업로드는 upsert 하지 않는다(덮어쓰기 금지).
- 기존 정리(`engine/storage_gc.py` sweep·purge_after_upload, 웹 휴지통 purge)는 공개 버킷 `renders` 의 논문·리포트 지시서 폴더만 걷는다.
  주류 파일이 걸리지 않음을 **드라이런 테스트**로 못박았다(`tests/test_drinks_gc_guard.py`, 실제 삭제 0). 주류 파일 정리는 아직 연결하지 않았다.
- 버킷은 0053 이 storage 스키마가 있을 때만 만든다(비공개).

## 릴스 파일 규격(2026-10-28)

주류 릴스 mp4 를 무료로 로컬 렌더해 인스타 릴스 규격(Meta IG User Media 문서 v26.0)과 대 봤더니 세 군데가 어긋나 있었다. 근거: `docs/진단_주류릴스엔진_2026-10-28.md` §2~§3.

- **소리 샘플링 96 kHz** (규격 상한 48 kHz): 마지막 단계 `loudnorm` 이 내부에서 샘플링을 크게 올리고 AAC 가 그대로 96 kHz 로 저장했다. `-ar 48000` 으로 고정했다(`config.OUTPUT_AUDIO_SAMPLE_RATE`).
- **moov 가 파일 뒤쪽** (규격: 앞): `-movflags +faststart` 를 어디에도 안 붙였었다. 이제 붙인다.
- **표지가 PNG** (규격: JPEG): `cover.jpg`(JPEG, 품질 92)로 바꿨다. 저장 확장자는 mime 표(`drinks_produce.MIME_EXT`)로 정한다. DB 는 0053 이 이미 `image/jpeg` 를 허용해 마이그레이션이 없다. 카드뉴스 쪽 PNG 는 그대로다.
- **검사 추가**: `render_video` 의 qa 가 규격을 직접 잰다. 경고 코드: `reel_audio_rate_over_48k`, `reel_moov_not_first`, `reel_duration_out_of_range`, `reel_width_over_1920`, `reel_fps_out_of_range`, `reel_video_codec`, `reel_audio_codec`, `reel_file_too_big`, `reel_cover_not_jpeg`, `reel_cover_too_big`. 기준표는 `config.DRINKS_REEL_SPEC`. 측정값은 `qa.reel_spec` 에 남는다. **경고일 뿐 작업을 막지 않는다.**

조립 함수(`build_loudnorm_command`·BGM 두 변형·`build_speed_command`)는 논문·리포트(유튜브) 라인과 같이 쓴다. 48 kHz 와 faststart 는 유튜브에도 해가 없고, 그쪽 동작은 이 두 옵션 말고는 바뀌지 않는다.

**(미검증)** 옛 파일(96 kHz, moov 뒤)을 인스타가 실제로 거절했는지는 확인하지 못했다. 첫 실제 릴스 게시에서 확인한다.

## 릴스 2차 묶음(2026-10-28)

1차(파일 규격)에 이어 `docs/진단_주류릴스엔진_2026-10-28.md` §6 의 2~5번을 같은 날 처리했다. 전부 돈이 들지 않는다(무료 경로·코드 검사뿐).

- **무료 경로에도 대본 검사(경고)**: 영상 작업은 렌더 전에 `drinks_script_check.check` 를 돌려 결과를 검수 화면의 `qa.script_check` 와 경고 코드(`script_check_blocked`·`script_check_warned`)로 남긴다. 막힘이 있어도 작업은 성공한다(먼저 완성 — 차단은 유료 경로만, 거기는 그대로 사기 전에 멈춘다). 검사기가 예외로 죽어도 영상은 나가고 `script_check_error` 만 남는다.
- **슬라이드 릴스(`card_page`, 0057)**: 장면에 `card_page: N`(1~20 정수)을 적으면 같은 소재의 가장 최근 **승인되고 지금도 쓸 수 있는** 카드뉴스 묶음의 N쪽이 그 장면의 그림이 된다(LLM·비용 0). DB 는 두 함수만 다시 정의했다 — `drinks_validate_plan`(card_page 보존, 범위 밖이면 `invalid_plan`)·`drinks_start_render`(작업에 `card_pages [{position, storage_key, mime}]`, 없으면 `[]`). 둘 다 0054 정의를 복사해 더했고 `set search_path = public, pg_temp`(0056 방식)를 정의 안에 적었다. 워커는 계획이 쓰는 쪽만 꺼내 1080×1350 쪽을 1080×1920 브랜드 배경 가운데에 **자르지 않고** 놓고 장면 유형 배지·쪽 번호는 위쪽 띠에 얹는다. 쪽이 없으면 글자 카드로 되돌아가고 `card_page_missing` 경고. 산 그림(유료)이 있는 장면은 그쪽이 우선. 파일 출처 표기는 `provenance.images = "card_pages"` — `rights` 는 DB 허용 목록 때문에 `generated_local` 그대로다.
  - 되돌리기: 0054 의 `drinks_start_render`·`drinks_validate_plan` 정의를 다시 실행(그다음 0056 의 반복문 한 번 더). 저장된 `card_page` 는 워커가 못 받으니 무시된다.
  - ★ 알려진 한계: 엔진이 모든 스틸에 켄번스 줌(최대 1.18배)을 걸어 카드 쪽 가장자리가 최대 7~8% 잘릴 수 있다. 카드 여백 안에 글자가 있는지 눈으로 본다. 줌 없는 정지 컷은 엔진(`render.py`) 변경이 필요해 이번엔 안 했다.
- **템포·자막 앵커**: 주류는 TTS +10% 위에 조립 끝 1.2× 가 또 걸려 5.9음절/초였다. 이제 기본 `DRINKS_PLAYBACK_SPEED = 1.0`(속도는 TTS 한 곳, 실측 4.9음절/초)이고 자막 앵커는 릴스(0.68, `DRINKS_CAPTION_PLATFORM`)다. 렌더 qa 에 `speech_rate`(음절·최종 길이·음절/초·배속·TTS 속도)가 남고 5.5 를 넘으면 `speech_rate_fast`. **운영자 귀 판정 대기** — 느리면 `DRINKS_PLAYBACK_SPEED` 환경변수로 조정.
- **소음·캡션 한도**: 범례가 없는 지시서(주류 나열식)에서 "색 코드가 어긋나 범례를 그리지 않는다" 경고가 찍히던 것을 범례가 실제로 있을 때만 찍도록 했다(`render.py` 한 줄). 캡션 검사에 인스타 한도(2200자·해시태그 30·멘션 20, `DRINKS_CAPTION_LIMITS`)를 넣어 `caption_too_long`·`hashtags_over_limit`·`mentions_over_limit` 이 막힘이 되고, 발행 워커는 이때 멈추며 사유에 코드가 들어간다.
