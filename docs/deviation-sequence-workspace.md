# 편차 기록 — 작업 화면을 시퀀스 한 장으로 (2026-09-17)

> **운영자 지시:** "초안생성 → 지시서생성 굳이 이 과정을 하나로 통합하자 한 거였는데
> 그냥 화면만 가로 분할해서 이분만 되어 있어. … 지시서는 시퀀스별로 영상 구성하게 해주고.
> 대신 초안생성과 같은 시퀀스의 주제와 내용 흐름은 한글로 같이 표현하고 세부수정도 가능하게."

## 1. 무엇이 잘못돼 있었나

2026-09-11 에 ④초안·⑤지시서를 "한 화면"으로 합쳤다고 기록했지만, 실제로 한 것은
**가로 2분할**이었다(`work-panes`: 왼쪽 대본 · 오른쪽 지시서). 두 칸은 **같은 영상의 두 표현**
인데 따로 놓여 있어서, "이 나레이션이 어느 화면에 붙나"를 사람이 눈으로 이어 붙여야 했다.
합친 것이 아니라 **나란히 둔 것**이다.

## 2. 데이터는 이미 시퀀스였다

지시서 `header.visual_sequences` 가 처음부터 이 구조를 담고 있었다.

```
SEQ1  MECHANISM_SEQUENCE   world=TABLETOP_LAB (뇌 모형 + 파란/노란 토큰)
  S1 cut_refs[3]     observable_change="모형이 놓이고 토큰이 기본 분포로 깔린다"
  S2 cut_refs[4,6]   observable_change="파란 토큰이 줄고 노란 토큰이 늘어난다"
  S3 cut_refs[7]     observable_change="V1 피질 표면 자체가 변형된다"
SEQ2  REALITY_ANCHOR       world=RESEARCH_LAB (fMRI 스캔 2장)
  S4 cut_refs[1,2,5] / S5 cut_refs[8,9]
```

그리고 컷마다 `narration_ko` 가 있다. **새로 만들 것이 없었다 — 화면이 이 구조를 버리고
컷을 한 줄로 늘어놓고 있었을 뿐이다.**

## 3. 바꾼 것

| 자리 | 전 | 후 |
|---|---|---|
| 본문 | `[대본 \| 지시서]` 가로 2분할 | **시퀀스 카드 세로 한 장** |
| 나레이션 | 왼쪽 칸(대본) | 컷 옆, **시각 지시와 같은 줄** |
| 대본 칸 | 있음 | **없앰**(운영자 결정) — 렌더는 원래 지시서 나레이션으로 나간다 |
| 컷 편집기 | 본문 | 접힌 `<details>` 로 보존(효과·전환·모션 프롬프트) |

편집 가능한 것 넷(운영자가 고른 전부):
1. **한글 나레이션** — `cuts[].narration_ko`
2. **시각 지시** — 단계의 `observable_change` · 컷의 `visual_prompt`
3. **시퀀스 주제·세계** — `world.style`·`lighting`·`background`, `entities[].visual_identity`
4. **컷 묶음** — 컷을 다른 단계로 옮긴다(`stage.cut_refs`)

## 4. 설계에서 조심한 것

- **컷을 잃어버리지 않는다.** 어느 단계도 안 가리키는 컷은 "묶이지 않은 컷"으로 내보낸다.
  없는 컷을 가리키는 단계는 `⚠ 없는 컷을 가리킴`으로 드러낸다. 같은 컷을 두 단계가 가리키면
  앞 단계에만 넣는다(두 곳에 같은 나레이션이 뜨면 어느 쪽이 정본인지 알 수 없다).
- **시퀀스가 없는 지시서**(comic·image_sequence·옛 photo)는 전부 `loose` 로 떨어져 평평한
  목록이 된다. 화면에 분기를 두지 않는다 — 판정은 `lib/work/sequenceView.ts` 한 곳이 진다.
- **저장은 보낸 것만 덮어쓴다.** `visual_sequences` 를 안 보내면 header 의 그 값은 그대로다.
  시퀀스가 원래 없던 지시서에는 빈 배열을 보내지 않는다(없는 것과 비어 있는 것은 다르다).
- **승인된 지시서는 읽기 전용**이다(`status !== 'draft'`).

## 5-1. 후속 (2026-09-17 같은 날, 운영자 재지시)

운영자가 두 가지를 더 짚었다.

**① "이런 컷들도 위에 시퀀스랑 합쳐서 하나로 만들어줘."**
처음 판에서는 옛 컷 편집기를 접힌 `<details>` 로 **남겨 뒀다**(기능을 잃지 않으려고). 그런데
같은 컷이 두 군데 있으면 어느 쪽을 고쳐야 하는지 매번 헷갈린다 — 합치자고 한 취지와 반대다.
그래서 컷 편집기를 **없애고** 그 내용을 시퀀스의 컷 행으로 들여왔다:

```
컷 3 · 6초 · 🎬 영상 · 기전 도해 · mechanism · 주장 C07 · ✓ 근거 1 · 묶음[▼]
  한글 나레이션 [수정]            │  이 컷의 화면 [수정]
  ▸ 이 컷 더 보기 — 움직임 · 효과 · 전환   [수정]
```

**② "승인렌더 버튼은 아직도 안보이는데??"**
맞다. 앞선 수정은 **승인 게이트가 막은 경우만** 버튼을 지켰고, 운영자가 보던 논문이 걸린
경우(대본이 지시서보다 새로움)는 주 버튼을 `지시서 재생성` 으로 바꾸고 승인 경로를 ▾ 안에
숨겨 뒀다. 운영자 결정은 **"항상 [승인 → 렌더] 를 둔다"** 였는데 절반만 지킨 것이다.

이제 **지시서가 draft 이면 주 버튼은 언제나 [승인 → 렌더]** 다. 낡았다는 사실은
⚠ 경고 + **주 버튼 옆에 보이는 별도 [지시서 재생성]** 버튼으로 알린다. 숨기지 않는다.

실측:
```
6b2d092a  변경사항 저장 | ⚠ 승인 → 렌더 (3D 그래픽) | 지시서 재생성 (3D 그래픽)
decff117  변경사항 저장 | ⚠ 대본 확정 + 승인 → 렌더 (3D 그래픽)
e826a5fa  변경사항 저장 | 대본 확정 + 승인 → 렌더 (3D 그래픽)
리포트 a2348c26(만화식) 변경사항 저장 | 승인 → 렌더 (만화식)
```
별도 "컷 (9)" 목록은 사라졌다(문자열 검색 0건).

## 5-2. 후속 2 (2026-09-17, 운영자 재지시 3건)

**① "번호 순서인 초안생성이랑 영상지시서 따로 구분 필요 있겠나? 통합해."**
머리의 단계 표시가 아직 `④ 초안 검수 / ⑤ 영상 지시서 / ⑥ 렌더 결과` 셋이었다. 화면은 이미
한 장이고 발주도 한 번에 나가는데 머리에만 두 칸이 남아 "지금 어느 단계인가"를 쓸데없이
묻게 만들었다. **둘로 합쳤다** — `1 영상 지시서 / 2 렌더 결과`.
  · `no` 는 5 로 두어 옛 주소 `?step=4`·`?step=5` 가 둘 다 이 단계로 들어온다(실측 200).
  · 화면에 보이는 번호는 **순서**(1·2)다. `no` 를 그대로 찍으면 "①②가 어디 갔지"가 된다.

**② "세부내용 수정하는게 없는데? 제목을 이렇게 수정하고 싶어."**
발행 제목 칸은 **원래 편집 가능**했다. 그런데 [제목 저장] 버튼을 `dirty` 일 때만 보여 줘서,
고치기 전에는 저장 수단이 안 보였다 — 그래서 읽기 전용 상자로 읽혔다.
버튼을 **항상 두고** 고친 것이 없으면 비활성으로 둔다("제목 저장 (고친 내용 없음)").
"✏️ 아래 칸을 직접 고칠 수 있습니다" 안내도 덧붙였다.

**③ "전체적인 늬앙스를 수정하도록 요청하는 것도 필요해. 이전에 있던 건데 없어진 거라서."**
맞다. **내가 없앴다.** 대본 칸(`ReviewClient`)을 걷어내면서 그 안에 있던
[이 요청으로 다듬기]가 같이 사라졌다. 시퀀스 화면 위에 접힌 패널로 되살렸다 —
`✍️ 이 방향으로 다시 만들기 — 전체 뉘앙스·말투·강조점`. 적은 방향을 `instruction` 으로 실어
대본과 고른 버전의 지시서를 **함께** 다시 만든다. 사실은 Fact Sheet 범위 안에서만 바뀐다.

실측(로컬 dev, 두 공장): 단계 `1 영상 지시서 / 2 렌더 결과`, 뉘앙스 패널 있음,
제목 저장 버튼 항상 표시, 옛 `?step=4`·`?step=6` 주소 200.

## 5-3. 후속 3 (2026-09-17, 운영자 재지시 3건)

**① "제목 바꿔서 저장했는데 원래 제목 그대로 되면서 '고친 내용 없음'이라고 뜹니다."**
**저장은 됐다**(DB 확인: `청각을 잃으면 진짜 시각이 강화된다?? 그 이유는?!!`).
화면이 저장 직후 **스스로 옛 값으로 되돌렸다.** 가장 나쁜 종류의 거짓말이다.

원인: 되살리기 `useEffect` 의 deps 에 `dirty` 가 있었다.
```
저장 성공 → dirty true→false → 그 변화가 effect 를 다시 깨움
        → 그때 props(initialKo)는 아직 서버를 다시 읽기 전 = 옛 제목
        → 옛 제목으로 덮어씀
```
고침: 판단을 `web/lib/work/reseed.ts` 로 빼고(순수 함수·검사 6건), deps 에서 `dirty` 를 뺐다.
저장에 성공하면 **저장한 값을 앞당겨 기억**하고, 서버가 그 값을 들고 올 때까지 들어오는
props 를 무시한다(`afterSave` → `awaitingServer`). `router.refresh()` 로 서버를 따라오게 한다.

**② "보여주는 시퀀스 컷 순서도 뒤죽박죽인데? 흐름 순으로 정렬되게끔."**
시퀀스로 묶어 보여 줬기 때문이다. 영상은 컷 1→9 로 재생되는데 시퀀스는 그 사이를 **오가며**
짜인다. 그래서 화면에는 3,4,6,7 다음에 1,2,5,8,9 가 왔다 — 읽는 순서 ≠ 보는 순서.

이제 **재생 순서를 축으로** 삼는다(`buildFlowLayout`). 연속된 컷이 같은 단계면 한 덩어리로
묶고 머리말을 한 번만 낸다. 세계 설정은 그 시퀀스가 **처음 나올 때만** 보여 준다.

실측(논문 6b2d092a):
```
SEQ2 · S4 — 현실   컷 1, 2
SEQ1 · S1 — 기전   컷 3
SEQ1 · S2 — 기전   컷 4
SEQ2 · S4 — 현실   컷 5
SEQ1 · S2 — 기전   컷 6
SEQ1 · S3 — 기전   컷 7
SEQ2 · S5 — 현실   컷 8, 9
```

**③ "실제로 구현하는 영문 지시서는 숨기고 한글 위주로 보여줘."**
영문 칸을 **언제나 접는다**(`KoBox`). 한글이 없는 옛 지시서도 펼치지 않는다 — 펼치면 화면이
다시 영어로 뒤덮인다. 대신 `⚠ 한글 설명 없음 — 영문 보기` 한 줄로 알린다.
실측: 영문 상자 35개 중 펼쳐진 것 **0**.

★ **나레이션만은 예외**다. `narration_ko` 는 설명이 아니라 **그대로 음성으로 나가는 정본**이라
  접지 않고 늘 펼쳐 둔다. 나머지(세계·단계·화면·움직임)는 영문이 정본이고 한글은 설명이다 —
  그래서 한글은 읽기용이고, 고치려면 영문을 펼치거나 [✍️ 이 방향으로 다시 만들기]를 쓴다.

## 6. 아직 안 한 것

- **컷 전역 순서 바꾸기**(재생 순서)는 넣지 않았다. `cut_no` 가 `cut_refs` 의 키라, 순서를
  바꾸면 참조를 함께 옮겨야 한다 — 따로 다룬다. 지금 되는 것은 **묶음 변경**이다.
- **"논문을 고르면 바로 지시서"**(초안 단계를 아예 안 보이게)는 다음 단계다. 지금도 한 번에
  만들어지지만(0046 연쇄), 후보 목록의 버튼 문구와 흐름이 아직 "초안 생성"이다.
- 화면 캡처를 남기지 못했다(브라우저 창이 가려져 렌더가 안 잡혔다). 구조는 DOM 수로 확인했다.

그대로 둬도 무해하다(보내지 않으면 아무 일도 안 한다).
