## ★ 후속 (2026-08-03) — 0.25 로 승격 완료

운영자가 이 문서의 분포를 보고 **"0.25 로 낮추고 승격"** 을 결정했다. 반영된 것:

- `visual_contract.CORE_MIN_AREA_FILL = 0.25` **신설** → `config.EXPLAINER_CORE_MIN_FILL`
- `board_layout.evaluate_layout` 의 `core_underfilled` 가 **warn → fail**
- 픽셀 기준 `visual_contract.CORE_MIN_FILL` 은 **0.30 그대로** — 면적과 픽셀은 다른 척도라
  상수를 쪼갰다(글자 획은 픽셀로 4~5% 밖에 안 나온다). 공유 상수를 내렸다면 `validate_frame`
  의 픽셀 경고까지 말없이 함께 느슨해졌을 것이다.
- `config.EXPLAINER_CORE_TARGET_FILL = 0.70` **제거** — 읽는 코드가 0곳인 죽은 상수였고
  아래 표대로 21컷 전부 미달이라 도달 불가능한 값이다. 남겨 두면 오해만 만든다.
- `render.py` 의 `board_qa_out` 에 **`layout_fail` 추가** — 승격하면 `core_underfilled` 가
  `layout_warn` 에서 빠지므로, 이 줄이 없으면 승격과 동시에 기록이 눈이 먼다.

### 정정 1 — 아래 권고 2의 "하위 2컷뿐"은 틀렸다

보드별 표를 다시 계산하면 0.25 미만은 2컷이 아니다: CHART 0.2115(1컷) + NUMBER 중앙값이
0.2395 라 최소 2컷 + HOOK 최소 0.2202 로 1~2컷 → **21컷 중 4~6컷**(0.30 기준의 6컷과 큰 차이가
없다). **이 범위는 표에서 계산한 추정치다** — 원본 컷별 값을 다시 뽑지 않았다. 확정하려면
`python3 scripts/measure_core_fill.py directives.json` 을 다시 돌려야 한다.

다만 결정은 뒤집히지 않는다. 아래 "렌더가 아예 안 되는 컷 4개"가 보여주듯 **저장된 지시서
4건 중 3건은 지금도 렌더가 안 된다.** 컷 하나가 실패하면 잡 전체가 실패하므로, 승격의 실질
피해는 이미 죽어 있는 지시서에 몰린다.

### 정정 2 — 데모/골든 픽스처는 프로덕션 대표값이 아니다

승격 착수 시 `tests/golden/board_render_hashes.json` 의 `core_fill`(0.0725~0.5462, 11종 중
10종이 0.25 미만)을 보고 "데모 보드가 무더기로 막히겠다"고 판단했는데 **틀렸다.** 그 값은
골든 테스트가 해시 안정성을 위해 따로 만든 최소 픽스처의 것이다. 실제
`scripts/preview_board.py` 의 `DEMO_CUTS` 5종을 그려 재면 **0.3064~0.5462 로 전부 통과**한다:

| 데모 컷 | core_fill |
|---|---|
| HOOK_BOARD | 0.3064 |
| CHART_BOARD | 0.3922 |
| WATCHPOINT_BOARD | 0.4527 |
| NUMBER_BOARD | 0.4727 |
| EVIDENCE_BOARD | 0.5462 |

그래서 `tests/test_visual_contract.py` 의 데모 게이트는 **손대지 않았고**, 골든 해시도
**재생성하지 않았다**(승격은 판정만 바꿨고 그리는 것은 그대로라는 증거).

재현:
```bash
python3 scripts/measure_core_fill.py                    # Supabase 직접
python3 scripts/measure_core_fill.py directives.json    # 뽑아 둔 JSON
```

대상: `report_directives` 중 `version_type='explainer'` **4건 / 컷 27개**
(그중 코드 보드 컷 21개 측정, 6개 제외).

## 권고 (2026-08-03 — 운영자가 **2번**을 선택, 승격 완료. 위 후속 절 참조)

1. **0.30 유지 + fail 승격** — 지금 재고의 28.6% 가 막힌다. 막힌 컷은 재생성으로 푼다.
   가장 단순하고, 빈 화면을 실제로 막는다.
2. **0.25 로 낮춘 뒤 승격** — 막히는 것은 하위 2컷뿐. 승격의 취지(진짜 빈 화면 차단)는
   지키면서 재고 충격이 거의 없다.
3. **숫자·차트 보드만 예외** — 그 두 보드는 구조적으로 면적을 덜 먹는다. 보드별 기준을
   두면 정확하지만 상수가 늘고 설명이 어려워진다.

★ 어느 쪽이든 **승격은 이 문서의 숫자를 보고 정한 뒤**에 한다. 지금은 기록만 켰다 —
`render_jobs.qa.board` · `report_render_jobs.qa.board`(0036)에 컷별 충전율이 쌓인다.
