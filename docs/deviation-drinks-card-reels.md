# 주류 카드뉴스 형식 엔진 — 2026-11-02

총괄계획 §4-2·§6 3단계의 **0원 부분**이다. 기획은 `docs/기획_릴스3형식_트렌드보드_v2_2026-10-31.md` §2-2·§2-3·§4·§7.
마이그레이션 `0065_drinks_card_reels.sql` 은 **파일만 있고 운영 DB 에 적용하지 않았다.** 공개 게시도, 유료 호출도 하지 않았다.

## 이제 어떻게 돌아가나
1. **[이걸로] → 카드뉴스.** 근거 초안이 끝나면 멈추지 않고(옛 `card_plan_not_built`) 같은 트랜잭션에서 대본 요청이 이어진다.
2. **카드 제작안 초안(모델, 개발 결재 안에서).** `engine/drinks_card_plan.py`. 5~8장 + 릴스 두 줄(`reel.hook_title`, `reel.share_line`). 코드 검사에 막히면 딱 한 번 다시 쓰고, 그래도 막히면 저장하지 않는다.
3. **내용 승인 탭 → [승인] 한 번.** 설명형과 같은 `drinks_approve_content` 다. 근거·편성·카드 제작안이 한 트랜잭션으로 승인된다. 금액을 받지 않는다(렌더 0원).
4. **제작 화면 → [렌더 요청](로컬·0원).** 제작안에 `reel` 이 있으면 파일 묶음에 카드 페이지 + 세로 영상 1개 + 표지 1개가 함께 든다. 검수 한 번(릴스가 든 묶음은 항목 2개 추가).
5. **발행 화면.** 같은 묶음으로 카드뉴스·릴스 발행 요청을 각각 만든다. 카드 묶음을 릴스로 올리면 음원이 필수다.
6. **게시 워커.** 음원을 다시 조회하고, 저장된 값을 그대로 `audio_configuration` 으로 보낸다. 못 붙이면 멈춘다.

## 약해지지 않은 안전 장치
- `drink_plans_guard`·`drinks_plan_action`·`drinks_plan_renderable`·`drink_review_evidence_edited`·`drinks_plan_coverage` 는 **고치지 않았다**(시험이 감시). 승인 전 카드 제작안은 렌더·제출 모두 막힌다.
- 표시 없는 대본 요청은 그대로 `review_not_approved` 이고 영상 전용이다. 결재가 없으면 모델을 안 부른다. 호출마다 가잡기·확정(`Ledger`)을 거친다.
- 근거 내용이 바뀌면 카드 제작안도 차단된다. 저장 때·승인 직전 값 대조도 같다. 워커는 승인·제출·편성 함수를 부르지 않는다.
- 설명형의 금액 검사와 옛 렌더 차단(`explainer_engine_not_wired`)은 그대로다.
- 옛 발행 요청의 승인 지문은 그대로다: 음원이 없으면 지문이 0055 와 글자까지 같다(시험이 대조).

## 기획과 다르게 정한 것
| 기획 | 구현 | 왜 |
|---|---|---|
| 카드 페이지를 세로 화면에 얹는다(0057 `card_page` 경로) | 같은 글을 1080×1920 안전 영역에 **다시 그린다.** 0057 경로는 그대로 두되 쓰지 않는다 | 4:5 를 그대로 얹으면 오른쪽 글자가 버튼 자리(120px)에 들어간다. 0057 은 나레이션 필수·영상 제작안 별도라 승인이 두 번이 된다 |
| 요청 상태 `audio_failed` | `paused` + `pause_code='audio_failed'` | 멈춤·재개·취소·화면이 이미 있다. 상태 표를 늘리면 옛 화면·집계가 다 바뀐다 |

| 승인 해시에 묶음 전체 | 고른 사람·시각은 뺐다 | 같은 음원을 다시 골라도 승인을 풀 이유가 없다 |
| 영상 볼륨 0~30(§7-4) | 기본 90/10, 범위 1~100(§7-3 표기) | 두 절이 어긋난다. 영상은 무음이라 지금은 값이 들리지 않는다. 첫 시험 게시에서 귀로 정한다 |

곁가지로 고친 결함 하나: **작성 중 발행 요청은 취소가 안 됐다**(0055 — 표 제약 `status='draft' 또는 지문 있음`에 걸린다). 음원이 없어 보류하는 길이 필요해 0065 의 가드가 취소 때 지문을 채운다.

## 아직 안 되는 것
- **운영 DB 미적용.** 적용 전에는 운영에서 지금처럼 `card_plan_not_built` 로 멈춘다. 이 코드가 먼저 배포돼도 옛 행동이 유지된다 — 단, `publish_board` 의 음원 칸은 비어 있어 카드 릴스 발행안을 만들 수 없다.
- **Facebook 로그인 연결 계정이 있어야 인스타 음원을 붙인다**(§7-3 4번). Instagram 로그인 연결 계정에서는 음원 저장이 `audio_connection_unsupported` 로 막힌다.
- **`licensed_mix` 는 계약만 있다.** 렌더에 음악을 까는 경로와 음원 파일이 없어, 파일 기록(`provenance.audio_mix='licensed'`)이 없으면 `licensed_mix_not_rendered` 로 거절한다.
- **앱에서 직접 음원 붙이기(수동 부착)** 는 화면 안내 문장뿐이다. 그렇게 올린 게시물을 요청과 잇는 길은 없다.
- **밈형 음원 필수 규칙**은 넣지 않았다(밈 엔진이 없다). 지금 음원 필수는 카드 묶음의 릴스뿐이다.
- 카드뉴스 탭(PlanTab)에서 새 버전으로 저장하면 릴스 묶음은 그대로 따라가지만, 훅 제목·저장 한 줄을 고치는 칸은 없다. 그 편집 저장에는 코드 검사도 돌지 않는다(옛 탭의 동작 그대로). 승인 화면에서 문장을 직접 고치는 기능도 없다(설명형과 같다).

## 미검증
- **실제 모델이 쓴 카드 대본을 본 적 없다.** 프롬프트 품질·검사 통과율·비용은 전부 미측정이다. 샘플 영상의 글은 사람이 쓴 시험 입력이다(`scripts/sample_card_reel.py`). 대본 품질은 샘플로 판정할 수 없다.
- **실제 Postgres 로 돌려 본 적 없다.** PGlite 시험만 했다.
- **Graph API 음원 호출(`GET /{audio_id}?user_id=`, `audio_configuration`)을 실제로 부른 적 없다.** 가짜 공급자·가짜 HTTP 만이다. 응답 칸 이름, 사용자/페이지 토큰 구분, 개발 모드 앱에서 부착 게시가 되는지는 시험 게시로만 확인된다(§7-2).
- **안전 영역 숫자**(아래 340px·오른쪽 120px)와 윗줄 위치는 관행값이다. 앱에서 안 봤다(§2-3). qa 에 `app_checked: false` 로 남는다.
- **발행·내용 승인 화면을 브라우저로 열어 보지 않았다.** 타입 검사·린트·순수 계산·DB 시험만 통과했다.
- 글자 수 상한(제목 26·본문 110·훅 24·한 줄 34)과 읽기 속도 초당 10자는 샘플 렌더로 잡은 첫 값이다.
