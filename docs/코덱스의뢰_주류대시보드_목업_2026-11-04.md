술째리고(주류) 인스타 릴스 대시보드의 **클릭 가능한 화면 목업**을 만들어 주세요.

## 0. 의뢰인(운영자)이 원하는 것 — 이것이 전부입니다

저는 개발자가 아니라 이 도구를 매일 쓰는 사람입니다. 지금 대시보드는 이렇게 느껴집니다:
- "소재 수집 → 내가 고르기 → 대본 → 영상 → 인스타 게시" 흐름이 있다고 하는데, 화면에서는 그 흐름이 안 보입니다.
- "선별 / 수집" 메뉴가 나뉘어 있는데 **내가 고를 것이 어디 있는지** 모르겠습니다. 수집은 되는 것 같은데 고를 수 있는 자리가 없습니다.
- 지금은 의미 없는 수집 결과 몇 개가 중구난방으로 흩어져 보이고, **내가 직접 개입하는 시점(소재 고르기 → 대본 → 영상화 → 게시)이 어디인지** 분명하지 않습니다.
- 주류는 형식이 3개(설명형 영상 / 카드뉴스 / 밈)라서, 고르는 것부터 만드는 것까지 **형식마다 다른 길**로 이어져야 합니다.
- 기존 논문·리포트 공장처럼 **소재를 고르면 → 디벨롭해서 → 영상이 나오는** 흐름으로 바꾸고 싶습니다.

그래서 원하는 결과물은 **"내가 아침에 들어와서 무엇을 보고, 무엇을 누르고, 그 다음 무엇이 보이는지"가 그림으로 보이는 목업**입니다. 백엔드 이야기는 목업이 마음에 든 다음에 듣겠습니다.

## 1. 만들 것

**A. 클릭 가능한 HTML 목업** — `docs/mockups/drinks/` 폴더, 정적 HTML + CSS(+ 최소 JS), 가짜 데이터. 빌드 도구·서버 없이 파일을 더블클릭하면 열려야 합니다. 폰 폭(390px)과 노트북 폭(1280px) 둘 다 보기 좋게.

화면 목록(각각 한 파일, 서로 링크로 이어짐):
1. `00-index.html` — 목업 안내 + "사장님의 하루" 시나리오 링크(§2)
2. `01-home.html` — **오늘 할 일.** 들어오면 제일 먼저 보는 화면. "지금 할 일 하나"가 크게, 그 아래 숫자 타일 2~3개, 이번 주 형식별 진행(설명형 0/1, 카드 2/5, 밈 1/3 같은 식)
3. `02-topics.html` — **소재 고르기.** 고를 것이 실제로 보이는 유일한 화면. 탭: 후보 / 내 소재 / 밈 카드. 후보 카드마다 질문 한 줄·추천 형식·근거 있음/없음·[이걸로] 버튼. [이걸로]를 누르면 형식(설명형/카드/밈)·주차 고르는 작은 창 → "대본 만드는 중" 상태로 넘어가는 모습까지
4. `03-work-explainer.html` — **설명형 작업공간.** 소재 하나의 끝까지가 한 화면. 위에 고정된 "지금 할 일" 바(버튼 하나) + 아래로 단계가 순서대로: 근거·대본 보고 승인 → 금액 결재 → 영상 구매 → 후보 2개 보고 하나 고르기 → 조립 → 검수(체크리스트) → 캡션·시각 넣고 게시 승인 → 예약. **각 단계가 지금 어디까지 왔는지**가 한눈에 보여야 합니다. 상태를 바꿔 볼 수 있게 상단에 "상태 보기 전환"(예: 승인 대기 / 구매 중 / 후보 고르기 / 검수 / 게시 승인) 토글
5. `04-work-card.html` — **카드뉴스 작업공간.** 카드 4~8장 미리보기 → 승인 → 제작(0원) → 산출물 확인 → **음원 고르기(필수)**·캡션·시각 → 게시 승인 → 예약
6. `05-work-meme.html` — **밈 작업공간.** 밈 카드(인스타에서 뜨는 형식) 또는 소재에서 시작 → 글 2~3줄 → 승인 → 렌더 → (자동 게시 가능) 캡션·시각 → 예약 / (박자 맞춰야 하는 밈) "앱에서 음원 붙여 올리세요" 안내 → 올린 뒤 주소 적기
7. `06-publish.html` — **발행·성과.** 이번 주 예약 달력(07:00~23:30 칸), 게시된 것·실패한 것, 성과 숫자(조회·저장·공유)
8. `07-blocked.html` — **막혔을 때.** 돈 결과를 모르는 경우, 근거가 철회된 경우, 음원이 없는 경우, 예약 시각이 창 밖인 경우 — 화면이 어떻게 멈추고 무엇을 하라고 말하는지. 4가지 상태를 토글로

**B. 사장님용 설명서 1장** — `docs/mockups/drinks/README.md`, 쉬운 한국어, 전문용어 없이:
- "지금 화면 → 새 화면" 비교표(메뉴 이름·무엇이 어디로 갔나)
- "사장님의 하루" 시나리오(§2)를 목업 화면 번호와 함께

**C. 백엔드 설명은 맨 뒤에 짧게** — README 끝 "뒤에서 필요한 것" 절. 사장님이 읽을 필요 없는 부분이라고 표시. 새 DB 표/뷰가 필요한지, 새 서버 함수가 필요한지, 기존 버튼이 그대로 재사용되는지만 항목으로. 상세 설계는 하지 마세요.

## 2. 목업이 반드시 담아야 하는 시나리오 — "사장님의 하루"

각 단계가 어느 화면·어느 버튼인지 목업에서 실제로 클릭해 따라갈 수 있어야 합니다.

1. 아침에 들어온다 → **오늘 할 일 하나**가 보인다(예: "위스키 유통기한 — 대본이 완성됐습니다. 승인하세요"). 누른다.
2. 작업공간이 열리고 **근거표·대본·금액**이 보인다 → [승인]. 설명형이면 다음에 **[결재 열기 $N]** 이 나타난다(승인과 결재는 다른 버튼이다 — 이 점은 꼭 그대로).
3. 돌아와서 **소재 고르기** → 후보 목록(수백 건 중 첫 페이지, 전체 수·고를 수 있는 수 표시) → 하나 골라 [이걸로] → 형식 "카드뉴스" 선택 → "대본 만드는 중" 표시.
4. 밈 카드 탭 → 카드 하나 [쓰자] → 밈 작업공간에서 글 2줄 확인 → [승인].
5. 어제 승인한 카드뉴스가 **제작 완료** → 작업공간에서 카드 8장 미리보기 → 음원 고르기 → 캡션 → 내일 12:00 → [승인 요청] → [승인] → [예약].
6. 설명형 하나가 **영상 후보 2개**를 사 왔다 → 두 영상을 보고 하나 [이 장면으로] + 이유 한 줄.
7. 어느 작업이 **"돈 결과를 모름"**으로 막혀 있다 → 홈이 그것을 맨 위에 올린다 → 무엇을 확인하고 어떻게 닫는지 안내가 보인다.
8. 발행·성과 → 이번 주 달력에 예약 3개 → 지난주 게시물 성과.

## 3. 지켜야 할 규칙 (목업에서도)

- **승인 ≠ 결재 ≠ 제작 시작 ≠ 게시 승인 ≠ 예약.** 각각 따로 누르는 버튼이다. 하나로 합쳐 그리지 마세요. 단, 같은 화면 안에서 순서대로 안내한다.
- 설명형 검수는 생략하지 마세요: 후보 합격/불합격 → 하나 선택 + 이유 → 조립 → 과정 검수 3항목 → 품질 검수 6항목 → 산출물 승인. 체크리스트는 실제 항목 이름을 쓰세요(`web/lib/drinks/explainerQueue.ts` 의 PROCESS_CHECKS·QUALITY_CHECKS).
- 카드뉴스 릴스는 음원 없이는 게시 승인 요청이 안 된다. 설명형 캡션에는 'AI 생성 영상' 한 줄이 꼭 있다. 예약 시각은 07:00~23:30 만.
- 박자에 맞춰야 하는 밈은 웹에서 자동 게시하지 않는다 — "앱에서 붙여 올리기" 수동 길을 정상 경로로 그린다.
- 밈은 두 출발점이 있다(인스타 트렌드 카드 / 소재). 둘 다 그린다.
- 돈이 드는 버튼([결재 열기]·[구매 요청]·밈 카드 [쓰자]의 정밀 분석)에는 금액과 상한이 버튼 옆에 보인다.
- 가짜 데이터는 실제 주제를 쓰세요(위스키 유통기한, 사케 라벨 정미율, 생막걸리와 살균막걸리 등 — `docs/주류_질문지도_v1_2026-10-29.md` 참고). 숫자는 가짜라고 표시.
- 한국어. 메뉴·버튼 이름은 지금 저장소 어휘를 따르되 더 쉬운 말이 있으면 바꾸고 바꾼 이유를 README 에 적으세요.
