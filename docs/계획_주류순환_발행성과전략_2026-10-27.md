# 결재 문서 — 주류 공장 순환 고리(③ 인스타 발행 · ④ 성과 수집 · ⑤ 전략 수정) · 2026-10-27

> 운영자 지시: "영상 만드는 건 둘째치고 소재 수집과 인스타 카드뉴스 및 릴스 업로드 자동화 및 결과 수집 및
> 전략 수정으로 이어지는 순환 시스템 구축부터. 너무 영상에 집착 말고."
>
> **이 문서로 승인받을 것:** 아래 설계대로 ③④⑤ 를 만든다. **돈이 드는 단계는 없다**(LLM·그림·영상 호출 0회).
> 실제 인스타 계정 연결·첫 게시·운영 DB 적용·머지는 이 결재에 들어 있지 않다 — 각각 따로 묻는다.

## 1. 한 바퀴의 모양

```
① 수집·발견·선정(있음) → ② 카드뉴스 렌더·검수(있음) ─────────┐
        ↑                                                  ↓
⑤ 전략 제안 → 운영자 확인 → 다음 선별 순서에 반영    ③ 발행 요청: 작성 → 승인(묶음 지문) → 예약
        ↑                                                  ↓
④ 성과 스냅샷(게시 후 24h·72h·7d, 받은 지표만) ←─── 발행 워커(공급자: 가짜 → 나중에 Meta 공식 API)
```

사람이 하는 일은 셋뿐이다: **게시 승인**(정확한 파일·계정·캡션·시각을 보고), **돈 결재**(이번엔 없음), **전략 변경 확인**.

## 3. 일부러 안 하는 것

- **실제 인스타 게시·계정 연결** — 계정 유형·연결 방식이 정해지고, 첫 게시를 비공개/시험 계정으로 승인받은 뒤에.
- 자동 반영 — 전략은 제안만, 운영자가 확인해야 바뀐다. 무인 승인·DM·광고·게시물 자동 삭제 없음(명세 §11).
- 무인 예약 실행 크론 — 워크플로 파일은 **수동 실행만** 넣고, 일정(cron) 켜기는 따로 승인.
- 캡션 자동 생성(LLM) — 지금은 운영자가 쓰고, 워커가 원문에 없는 숫자·양·권고를 코드로 검사해 걸리면 게시하지 않고 `paused`.
- 릴스는 이번 묶음에서 **상태 기계만** 받는다(영상 묶음 = 최종 영상 + 커버). 카드 → 슬라이드 릴스 변환은 다음 묶음.

## 4. 어떻게 확인하나(완료 기준)

로컬에서 **한 바퀴가 테스트로 증명**된다 — 실제 Postgres 문법으로 도는 PGlite 위에서 Python 워커가 직접 돈다:
수집(가짜 피드) → 소재·근거 승인 → 카드 렌더(진짜 PNG) → 검수 승인 → 발행 요청 작성·승인·예약 → 가짜 공급자로 게시
→ 24h/72h 성과 스냅샷 → 전략 제안(처음엔 표본 부족) → 표본이 차면 가중치 제안 → 운영자 반영 → 다음 후보 순서가 바뀐다.
그리고 늦은 예약 `paused`, 타임아웃 `unknown` → 재게시 안 함 → 조회 대조로 `published` 정정, 계정 외부 ID 불일치 중단,
지문이 다르면 승인 거부, 없는 지표를 0 으로 안 채움을 각각 테스트한다.

## 5. 운영자에게 하나만 묻는 것(명세 §16.3)

**술째리고 인스타 계정은 무엇이고 어떻게 연결하나요?** — 비즈니스/크리에이터 중 무엇인지, 페이스북 페이지에 연결돼 있는지
(→ Facebook Login 경로) 아니면 인스타만 쓰는지(→ Instagram Login 경로), Meta 개발자 앱이 있는지.
이 답이 오기 전에는 가짜 공급자로만 돈다.
