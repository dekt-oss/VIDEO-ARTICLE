# 기획서 — 원리 기반 시각화 (v1)

> **제안 요지:** 논문·리포트에서 **원리를 먼저 데이터로 뽑고**, 그 원리의 성질에 따라
> **3D 도해냐 실사냐를 규칙으로 결정**한다. 지금은 컷을 짜면서 즉흥적으로 정하기 때문에
> 화면이 설명을 못 하고 나레이션을 그림으로 받아쓴다.
>
> 상태: **리뷰 대기**. 착수 전 §9 열린 질문 3개에 대한 결정이 필요하다.

---

## 1. 문제 — 실측

실사형 지시서(2026-08-21, 유일한 실물) 의 MECHANISM 컷 4개를 전수 검사했다.
**2개만 설명하고, 2개는 나레이션을 그림으로 옮긴 것**이었다.

### 설명한 컷 (2/4)

**컷 5** — 인과 사슬이 화면에 있다
> *데이터센터 부하 화살표가 송전선을 압도 → 탄소 구름이 쌓임 → 그리드 안정성 게이지 바늘이 적색으로*

나레이션("배출량이 늘고 유연성이 흔들린다")의 **왜**를 화면이 대신 말한다.

**컷 8** — 양방향 흐름으로 "기회"의 구조를 보여준다
> *태양광·풍력 → 데이터센터 / 데이터센터 → 그리드(수요반응 되먹임)*

### 설명 못 한 컷 (2/4)

**컷 3** — 원리가 아니라 **목차**다
> *"세 개의 분석 기둥을 화살표로 연결: 부하 행동 / 전력 공급 구성 / 글로벌 수요 동향"*

나레이션이 "연구진은 A, B, C를 분석했다"이니 화면도 상자 3개를 그렸다. 정보량 0.

**컷 6** — **지도**다
> *"일부 지역이 빨갛게 표시된 단순 세계지도"*

*어디*는 보여주고 *왜*는 안 보여준다.

### 더 큰 결함 — 핵심 주장에 원리 컷이 없다

훅은 **"AI가 똑똑해질수록 지구는 더 뜨거워진다"**인데,
`AI 연산 ↑ → 데이터센터 전력 수요 ↑ → 화석연료 발전 ↑` 이 사슬이 **한 번도 화면에 안 나온다.**
컷 5는 그 *결과*를 보여주지 *원인*을 보여주지 않는다. 시청자가 훅을 이해할 화면이 없다.

## 2. 원인 — 결정 순서가 거꾸로다

지금 파이프라인은 지시서 단계에서 LLM 에게 **컷마다 네 가지를 동시에** 시킨다:

1. 이 컷이 무엇을 말할지(나레이션)
2. 무엇을 보여줄지(visual_prompt)
3. 어떤 매체로(visual_role = MECHANISM/REALITY)
4. 움직일지(motion_source)

입력은 **나레이션 텍스트뿐**이다. 그러면 화면은 필연적으로 **말을 삽화로 옮기는 쪽**으로 수렴한다 —
"세 가지를 분석했다" → 상자 3개. 형식상 다이어그램이니 계약도 통과한다.

계약은 *형식*("단면·분해·흐름을 그려라")만 정하고 *대상*("무엇의 원리인가")을 안 정했다.
그래서 모델은 안전하고 값싼 선택을 한다. **이건 모델의 잘못이 아니라 설계의 잘못이다.**

## 3. 제안 — 원리를 1급 산출물로 올린다

Fact Sheet 와 지시서 사이에 단계를 하나 넣는다.

```
   현재 :  Fact Sheet → 대본 → 지시서(원리·매체를 즉흥 결정) → 렌더
   제안 :  Fact Sheet → 대본 → [원리 추출] → 지시서(원리를 배분) → 렌더
                                   ↑ 신설
```

지시서 단계의 질문이 바뀐다:

| | 질문 |
|---|---|
| 지금 | "이 나레이션에 어울리는 그림은?" |
| 제안 | **"이 원리 3개를 어느 컷에 어떻게 배분하지?"** |

원리가 데이터로 먼저 존재하면, 화면은 말을 따라가는 대신 **원리를 지고** 간다.

### 부수 효과
- **만화식·웹툰도 좋아진다.** 원리를 아는 만화는 장식이 아니라 설명이 된다.
- **비용이 준다.** 설명 못 하는 컷에 프리미엄 모델을 쓰지 않는다.
- **매체 결정이 근거를 갖는다**(§5).

## 3-1. ★ 선행 조건 — 원문 없이는 원리가 없다

**이 기획의 성패는 원리 추출 알고리즘이 아니라 "무엇을 읽히는가"가 정한다.**

실측(2026-08-28):

| | 논문 라인 | 리포트 라인 |
|---|---|---|
| 추출에 들어가는 입력 | **초록 평균 1,569자** (최대 4,359) | **원문 전문 평균 10,903자** |
| 전문 확보 장치 | **없다** — `papers` 에 전문 컬럼 자체가 없다 | `engine/report_source.py` → `report_sources` |
| 최근 30일 수집 | 1,718편 (초록 100%, arXiv 링크 20.7%) | 25건 중 21건 `full_text` |

초록은 **결과 요약**이다. "무엇을 발견했다"는 있고 **"왜 그렇게 되는가"는 대개 없다.**
원리는 본문의 방법·메커니즘·논의 절에 있다. 그러니 초록만 읽혀 놓고 원리를 뽑으라 하면
모델은 있지도 않은 것을 지어내거나(환각) 결과를 되풀이한다 —
**§1 의 "상자 3개"와 "지도"가 정확히 그 증상이다.** 계약을 아무리 고쳐도 입력이 없으면 안 된다.

### 그래서 원문 확보가 §0 보다 앞선다

| 경로 | 대상 | 예상 확보율 |
|---|---|---|
| arXiv 전문(HTML/PDF) | arXiv 논문 | 링크 보유분 100% (전체의 ~21%) |
| OpenAlex `best_oa_location.pdf_url` | OA 논문 | 미실측 |
| PMC 전문 XML | 생의학 OA | 미실측 |
| Unpaywall(DOI) | OA 일반 | 미실측 |

**비 OA 논문은 원문을 받을 수 없다.** 즉 원문 확보율이 이 기획의 **적용 가능 범위 상한**이고,
그 숫자를 모른 채 설계를 확정할 수 없다. §10 의 0단계가 이것을 먼저 잰다.

### 확보 못 한 논문은 어떻게 하나
`source_depth` 를 논문 라인에도 도입해(리포트 라인과 같은 방식) **코드가 글자 수로 판정**하고,
`abstract_only` 인 논문은 **실사형 대상에서 제외**한다(§6 G2 와 같은 논리).
초록만으로 3D 도해를 만들면 반드시 목차형이 나오고, 프리미엄 모델 값만 나간다.

## 4. 원리 추출 — 무엇을 뽑나

논문·리포트에서 **시각화 가능한 원리 단위(mechanism unit)** 를 0~4개 뽑는다.

```jsonc
{
  "mechanism_id": "M1",
  "kind": "CAUSAL",              // §4-1
  "title": "AI 연산 증가가 화석연료 발전을 늘리는 경로",
  "steps": [                      // 화면에 그려질 실제 요소
    "AI 모델 학습·추론 연산량 증가",
    "데이터센터 전력 수요 급증",
    "청정에너지 배치 속도가 못 따라감",
    "부족분을 화석연료 발전이 메움"
  ],
  "claim_ids": ["C02", "C03"],   // 환각 방지 — 원장 근거
  "grounding": "stated",          // §4-2
  "camera_visible": false,        // §5 매체 판단의 입력
  "carries_primary": true         // 핵심 주장을 설명하는가
}
```

### 4-1. 원리의 종류 (`kind`)

| 종류 | 뜻 | 화면 |
|---|---|---|
| `CAUSAL` | 원인 → 결과 사슬 | 요소가 순서대로 이어지며 나타남 |
| `STRUCTURE` | 무엇이 무엇 안에 있는가 | 단면·절개·분해 |
| `PROCESS` | 단계·순서 | 조립·진행 |
| `COMPARISON` | 전후·대조군 | 나란히 놓기 |
| `SCALE` | 크기·규모 대비 | 두 대상을 같은 화면에 |
| `FLOW` | 무엇이 어디로 흐르는가 | 경로 추적 |

**이 6개 밖은 원리가 아니다.** "세 가지 요인", "지역 분포", "연구 개요"는 목차이지 원리가 아니며
`kind` 를 못 받으므로 추출 단계에서 걸러진다. §1 의 컷 3·6 이 정확히 여기서 죽는다.

### 4-2. 근거 수준 (`grounding`) — 환각 방지 불변식과의 접점

| 값 | 뜻 | 허용 |
|---|---|---|
| `stated` | 논문이 그 인과·구조를 **직접 서술**했다 | ✅ |
| `structural` | 논문이 다루는 대상의 **자명한 물리 구조** (배터리에 분리막이 있다 등) | ⚠ §9-1 |
| `inferred` | 우리가 만든 설명·비유 | ❌ 금지 |

**숫자는 예외 없이 Fact Sheet 만** 쓴다. 화면의 모든 수치·출처는 지금처럼 `overlay_plan`(코드 그래픽)이
그리고, 생성 모델은 숫자를 절대 그리지 않는다. 이 불변식은 건드리지 않는다.

## 5. 매체 판단 — 규칙으로 결정한다

지금은 LLM 이 컷마다 감으로 고른다. 원리의 성질에서 **파생**시킨다.

> **판단 기준 한 줄: 이것을 카메라로 찍을 수 있는가?**

| 원리의 성질 | 예 | 매체 |
|---|---|---|
| 내부·단면·미시 — **찍을 수 없다** | 배터리 분리막, 세포 내 경로, 지반 층 | **3D 도해** |
| 시간 변화를 한 화면에 | 전후 비교, 누적 | **3D 도해** |
| 추상 관계 — 물리적 실체가 없다 | 수요-공급 균형, 되먹임 루프 | **3D 도해** |
| 규모·현장 — **실재를 증명해야** | 데이터센터 크기, 실험 장비, 임상 현장 | **실사** |
| 숫자·출처 | 어떤 수치든 | **코드 그래픽** (생성 금지) |

### 경계 사례
둘 다 가능하면 **그 컷이 지고 있는 부담**이 정한다.
- 원리를 지는 컷 → 3D (설명이 임무다)
- 신뢰를 지는 컷 → 실사 (이건 진짜 있는 일이다를 앵커한다)

### 컷 배분 규칙
- 원리 하나는 **1~3컷**을 쓴다. 단계가 많으면 나눠서 쌓아 올린다.
- 같은 원리의 컷들은 **연달아 붙이고 같은 매체**를 쓴다 → I2V 연쇄가 실제로 걸린다.
  (현재 결함: 매체가 컷마다 튀어 연쇄가 0회다. `docs/deviation-photo-3d-quality.md` 참조)
- 실사 컷은 **훅·마무리·현실 앵커**에 배치한다.

## 6. 게이트 — 안 지켜지면 막는다

계약에 적기만 하고 검사하지 않으면 §1 이 반복된다.

| # | 게이트 | 위반 시 |
|---|---|---|
| G1 | 핵심 주장(`primary_claim_id`)을 설명하는 원리 컷이 **최소 1개** | 승인 차단 |
| G2 | 원리 단위가 **0개**인 논문 | 실사형 발주 자체를 경고·차단(§7) |
| G3 | MECHANISM 컷인데 연결된 `mechanism_id` 가 없음 | 경고 → 재생성 |
| G4 | 같은 원리의 컷들이 흩어져 있음 | 경고(연쇄가 안 걸린다) |

### G2 가 중요한 이유 — 어떤 논문은 원리가 없다
순수 상관연구·설문·벤치마크 표에는 그릴 원리가 없다. 그런 논문에 실사형을 쓰면
**반드시 §1 의 목차형 도해가 나온다.** 사전에 판정해 만화식으로 돌리는 편이 결과도 비용도 낫다.
이 게이트는 품질 장치이면서 동시에 비용 장치다.

## 7. 파이프라인 변경점

| 위치 | 변경 |
|---|---|
| `engine/paper_source.py` (신설) | **논문 원문 확보**(arXiv·OA·PMC). `papers.source_depth` 판정. §3-1 |
| `engine/mechanism.py` (신설) | 원리 추출. 입력 = **원문 전문** + Fact Sheet, 출력 = mechanism units |
| `drafts` 또는 신규 컬럼 | 추출 결과 보관 (마이그레이션 1건) |
| `engine/directive.py` | 지시서 프롬프트에 원리 주입 · 컷에 `mechanism_id` 필드 |
| `supabase/functions/generate-directive` | 같은 변경 이식 (`tests/test_prompt_sync.py` 가 감시) |
| `engine/render.py` | 이미 배선됨 — `visual_role` 로 화풍·모델이 갈린다 |
| ⑤ 화면 | 원리 목록과 컷 배분을 보여주고, G1~G4 위반을 표시 |

**리포트 라인도 같은 틀**을 쓴다. 어휘만 다르다 — 밸류에이션 논리, 수급 구조, 실적 드라이버가
`CAUSAL`·`STRUCTURE`·`COMPARISON` 에 각각 대응한다.

## 8. 비용·리스크

| | |
|---|---|
| 추출 LLM 호출 | 편당 1회 추가, 약 **$0.01~0.03** |
| 렌더 비용 | **변화 없음** (컷 수 동일). 설명 못 하는 컷에 프리미엄 모델을 안 써 오히려 준다 |
| 마이그레이션 | 1건(추출 결과 보관 컬럼) |

### 리스크

**R1. 원리 추출이 틀리면 화면 전체가 틀린다.** 지금은 컷 하나가 나쁘면 컷 하나가 나쁘지만,
원리가 잘못되면 그 원리를 쓰는 2~3컷이 함께 틀린다. → G1~G4 와 ⑤ 화면 노출로 사람이 본다.

**R2. `structural` 근거의 환각 위험**(§9-1). 논문에 없는 구조 지식을 화면이 주장하게 된다.

**R0. 원문 확보율이 낮으면 기획 전체의 적용 범위가 좁아진다**(§3-1). 비 OA 논문은 받을 수 없다.
0-A 가 이 숫자를 먼저 잰다.

**R3. 추출 가능한 논문이 생각보다 적을 수 있다.** G2 가 자주 걸리면 실사형을 쓸 논문이 줄어든다.
→ 0-B 가 전문/초록을 비교해 잰다.

## 9. 열린 질문 — 결정이 필요하다

### 9-1. `structural` 근거를 허용할 것인가
배터리 단면을 그리려면 "양극·음극·분리막이 있다"를 알아야 하는데, 그건 Fact Sheet 에 없을 수 있다.
**엄격히 막으면 3D 도해를 거의 못 그린다. 열면 논문에 없는 주장이 화면에 나간다.**

- (A) 금지 — 불변식 유지. 대신 실사형을 쓸 논문이 크게 준다.
- (B) 허용 + 표시 — ⑤ 화면에 "이 도해는 논문 밖 구조 지식을 씁니다"를 띄우고 사람이 승인. **권장**
- (C) 자유 허용 — 반대. 검증 안 된 화면이 나간다.

숫자는 어느 경우에도 Fact Sheet 만이다.

### 9-2. 원리가 없는 논문을 어떻게 할 것인가
- (A) 실사형 발주를 **차단**하고 만화식을 권한다. **권장**
- (B) 경고만 하고 운영자가 강행할 수 있게 한다.

### 9-3. 원리 추출을 어느 단계에 둘 것인가
- (A) 대본 **뒤**(제안서 기준) — 대본이 정한 서사를 원리가 뒷받침한다. 변경 범위가 작다.
- (B) 대본 **앞** — 원리가 서사를 이끈다. 결과는 더 좋을 수 있으나 대본 파이프라인을 건드린다.

## 10. 실행 순서

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| **0-A. 원문 확보율 실측** | 기존 논문 100건에 arXiv·OA·PMC 경로를 돌린다 | 전문 확보 비율·평균 글자수. **이 숫자가 기획의 상한이다** |
| **0-B. 추출률 실측** | 전문을 확보한 논문 20건 + 초록만인 20건에 추출을 돌려 **비교** | 전문이 실제로 원리 품질을 올리는지. 차이가 없으면 원문 확보를 접는다 |
| 1 | `engine/mechanism.py` + 스키마 + 보관 | 순수 로직 테스트 |
| 2 | 지시서가 원리를 소비 (엔진 → 엣지) | `test_prompt_sync.py` 통과 |
| 3 | 게이트 G1~G4 | 위반 케이스 테스트 |
| 4 | ⑤ 화면에 원리·배분·위반 표시 | |
| 5 | **실물 비교** — 같은 논문을 새 방식/옛 방식으로 각각 렌더 | 나란히 놓고 판정 |

**0단계를 먼저 하는 이유:** 추출률이 낮으면 이 설계 전체가 무의미하다.
코드를 쓰기 전에 그 숫자를 봐야 한다. LLM 호출 20회, 약 $0.5, 반나절.
