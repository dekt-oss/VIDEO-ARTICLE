# 실측 — 보드 골든 해시는 왜 로컬에서 항상 빨간가 (2026-09-17)

> **한 줄:** 골든이 낡은 게 아니다. **기준값은 리눅스(CI)에서 만든 것이고, 윈도우에서는
> 원리상 맞을 수 없다.** 그런데 검사가 그 사실을 모른 채 "화면이 바뀌었다"고 말하며
> **기준값을 갱신하라**고 안내했다 — 그대로 따르면 CI 가 빨개지고 검사가 죽는다.

## 0. 왜 이 문서를 쓰나 — 함정이 이미 한 번 작동했다

PR [#5](https://github.com/dekt-oss/VIDEO-ARTICLE/pull/5) 본문에 이렇게 적었다.

> 그 1 실패는 `test_board_render_golden.py` 로 **이 변경과 무관한 기존 결함**이다.
> 골든 해시가 2026-08-20 이 마지막인데 `board_render.py` 가 2026-09-03 에 한 번 더 바뀌었고,
> 이 테스트는 폰트 없는 리눅스 CI 에서 항상 스킵돼 드러나지 않았다.

**두 문장 다 틀렸다.** 아래가 그 정정이다. 틀린 채로 머지돼 남아 있으므로 여기 적어 둔다.

## 1. 무엇을 쟀나

### ① 코드 드리프트가 아니다 — 기준값을 만든 그 시점의 트리도 자기 기준값과 어긋난다

기준값을 커밋한 바로 그 커밋(`68b4f1f1`, 2026-08-20 00:22)의 트리를 통째로 꺼내
윈도우에서 돌렸다.

```
git archive 68b4f1f1 | tar -x -C <scratch>
python -m pytest tests/test_board_render_golden.py -q
→ FAILED (보드 11종 전부)
```

그리고 그때 나온 "실제" 해시가 **오늘 트리의 "실제" 해시와 한 글자도 다르지 않다.**
(예: `CHART_BOARD` = `f830bab2ffb82591…` — 8/20 트리와 오늘 트리가 같은 값)

→ 2026-09-03 `board_render.py` 변경(`451deac0`, Q3 애니메이션 계약)은 **그리는 코드를
한 줄도 안 건드렸다**(diff 확인: 관측 함수 추가와 `BoardResult` 필드 2개뿐).
`config.py` 변경도 보드 렌더에 닿지 않는다(`OVERLAY_NUMBER_FONT_SIZE` 72→110 은
`photo_contract`·`subtitles` 만 읽는다).

### ② Pillow 버전도 아니다

같은 8/20 트리를 Pillow 11.3.0 과 12.3.0 으로 각각 돌려 해시를 대조했다.

```
diff out_pil12.txt out_pil11.txt   → 차이 없음
```

→ 의존성 업그레이드 가설도 탈락. (그래서 `Pillow` 를 핀으로 박지 않았다 — 근거가 없다.)

### ③ 남는 것은 텍스트 셰이퍼다

```
python -c "from PIL import features; print(features.check('raqm'), features.check('harfbuzz'))"
win32 / Pillow 12.3.0 → False False
```

`.github/workflows/golden-refresh.yml` 머리말이 **처음부터 이렇게 적어 뒀다**:

> 해시는 실행 환경을 탄다 — 윈도우 로컬 Pillow 에는 raqm/harfbuzz 가 없어 글자 배치가
> 리눅스와 미세하게 달라, 로컬에서 기준값을 만들면 CI 가 그날로 빨개진다.

즉 **이미 알려져 있었고, 문서화돼 있었고, 검사 파일에만 안 적혀 있었다.**
그 워크플로 파일은 실패를 보는 순간에 아무도 열지 않는 파일이다.

### ④ CI 는 폰트가 없지 않다 — 대조는 CI 에서 돌고 통과한다

`preflight_fonts()` 는 시스템 폰트가 아니라 **저장소의 `assets/fonts/`** 를 본다
(`visual_contract.py:180`). 그 파일 7개는 커밋돼 추적되고 있으므로 CI 체크아웃에도 있다.

CI 의 skip 11건은 폰트가 아니라 **ffmpeg/ffprobe 가 없어서** 건너뛰는 것들이고, 수가 정확히 맞는다:

| 파일 | 게이트 | 건수 |
|---|---|---|
| `test_clip_fit_ffmpeg.py` | 모듈 전체 `ffmpeg`+`ffprobe` | 8 (6+1+1) |
| `test_q1_q4_render_qa.py` | `ffmpeg` | 2 |
| `test_clip_candidates.py` | `ffmpeg` + 실측 클립(한 함수에 겹쳐 있다) | 1 |
| **합** | | **11** |

node·npx 게이트(`test_edge_twin_parity` 3 · `test_polish_twin_parity` 1 ·
`test_edge_function_parses` 5)는 ubuntu 러너에 node 가 깔려 있어 **건너뛰지 않는다.**
윈도우 로컬에는 ffmpeg 도 있어서 skip 이 1건(실측 클립 없음)뿐이었다 —
그 **차이 10건**을 보고 "CI 가 폰트를 못 찾는다"고 잘못 읽었다.

## 2. 무엇을 고쳤나

| 자리 | 전 | 후 |
|---|---|---|
| `test_board_render_is_pixel_stable` | 윈도우에서 **항상 실패** | 기준 환경(linux)이 아니면 **건너뛴다**. 사유에 "판정은 CI 가 한다 / 기준값을 갱신하지 말 것" |
| 실패 메시지 | "골든 JSON 을 갱신하라" | "Actions → golden-refresh 워크플로로 다시 만들라. 손으로 고치지 말라" |

| `tests/make_golden.py` | 어디서든 돈다 | 리눅스가 아니면 **거부**(탈출구 `GOLDEN_ALLOW_ANY_PLATFORM=1`) |
| `tests.yml` skip 가드 | 건수만 출력 | `-rs` 로 **이름·사유까지** 로그에 남긴다 |

## 3. 왜 이렇게 골랐나 (선택지와 버린 이유)

- **기준값을 윈도우 값으로 갱신** — 버렸다. CI 가 그 즉시 빨개진다. 원인을 모르고
  초록으로 만드는 최악의 처방이고, 실제로 이번에 그렇게 할 뻔했다.
- **검사를 지운다**(설명판형은 2026-08-28 폐기 형식이다) — 버렸다. 보드 렌더 경로는
  옛 explainer 지시서 재생용으로 **살아 있다**(CLAUDE.md). CI 에서는 지금도 정상 작동한다.
- **`raqm` 유무로 가른다** — 버렸다. 기준 환경에 raqm 이 있는지 확인하지 않은 채로 쓰면,
  CI 에서도 조건이 거짓이 되어 대조가 **조용히 사라질** 수 있다. `sys.platform` 은 확실하다.

## 4. 되돌리는 법

`tests/test_board_render_golden.py` 의 `BASELINE_PLATFORM` 게이트 2개(`skipif`)와
`tests/make_golden.py` 의 플랫폼 거부를 지우면 종전 동작(윈도우에서 빨간 채로 남음)으로
돌아간다. 돌릴 이유는 하나뿐이다 — **윈도우와 리눅스가 같은 픽셀을 내게 된 경우.**
그때는 이 문서 §1-③ 을 다시 재서 확인하고 지운다.

## 5. 남은 것

- **윈도우에서는 보드 화면 변경을 스스로 검증할 수 없다.** 화면을 의도적으로 바꾸면
  PR 을 올려 `golden-refresh` 가 붙여 주는 산출물로 확인해야 한다. 그것이 설계대로다.
- 이 대조가 지키는 대상은 **폐기된 설명판형 보드**다. 언젠가 보드 렌더 경로를 정말로
  걷어낸다면 이 검사도 같이 걷는다 — 지금은 경로가 살아 있으므로 남긴다.
