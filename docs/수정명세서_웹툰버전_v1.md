> `docs/deviation-webtoon-b1-removal.md`.

## 0. 한 줄 요약

카메라 이동(zoom_in / zoom_out / return)을 **이미지 생성이 아니라 크롭**으로 만드는 영상 버전.
새로 생성하는 것은 **장면**이고, 컷은 그 장면에서 잘라낸다.

기존 `comic`(만화식)과 **병행**한다. 같은 논문으로 둘 다 만들어 나란히 비교하는 것이 목적이다.

---

## 1. 왜 필요한가

1차 샘플에서 확인된 것:

- 이미지 모델은 "같은 대상을 더 가까이"를 지키지 못한다. 확대 컷을 새로 생성하면 다른 물체가
  나오고 스케일이 붕괴한다(주먹 → 바위 → 주먹).
- 반면 **컷1↔컷8 구도 반복은 성립했다.** 구도를 지정하는 것은 되고, 연속 확대가 안 된다.

→ 확대·축소·복귀는 크롭으로 처리하면 연속성이 100% 보장되고 생성 호출이 0이라 비용도 0이다.

---

## 2. 컷 스키마 델타

선택 필드 **2개**만 더한다. 둘 다 기본값이 있어 저장된 모든 지시서가 그대로 유효하다.

| 필드 | 형태 | 규칙 |
|---|---|---|
| `crop` | `{"cx": 0~1, "cy": 0~1, "scale": 1.0~CROP_MAX_SCALE}` 또는 `null` | `asset_strategy ∈ ASSET_STRATEGY_REUSE` 컷에서만 유효 |
| `tone_grade` | `none \| warm \| red \| cool \| desaturate` | 기본 `none`. enum 밖은 드롭 + 로그 |

`source_scene` 같은 새 어휘는 두지 않는다 — "이 컷이 쓰는 이미지"의 진실원은 이미
`asset_strategy` + `base_asset_ref` 다(편차 기록 §6).

**장면 4장 / 파생 4컷의 표현:**
`asset_strategy=new_asset` 컷 4개 + `reuse_crop|reuse_zoom` 컷 4개.
같은 장면을 쓰는 컷들은 `visual_reuse_group` 을 공유한다.

### 정규화 (Python `engine/directive.py` + TS 엣지 트윈, 양쪽 동일)
- `cx`·`cy` → `[0.0, 1.0]` 클램프, 기본 `CROP_DEFAULT_CENTER`
- `scale` → `[CROP_MIN_SCALE, CROP_MAX_SCALE]` 클램프, 기본 `CROP_MIN_SCALE`
- `scale <= CROP_MIN_SCALE` 이면 `crop = null` (할 일 없음 — diff·해시를 깨끗이)
- **클램프가 일어나면 `header.mode_warnings` 에 `crop_clamped#<cut_no>`.** 조용히 삼키지 않는다.
- `asset_strategy` 가 재사용이 아니면 `crop`·`tone_grade` 를 떨어뜨린다
- **`validate_reuse_refs` 가 참조 무효로 `new_asset` 강등할 때 `crop`·`tone_grade` 도 비운다.**
  남기면 갓 생성한 새 이미지가 잘린다 — 참조 깨짐보다 알아채기 어려운 사고다.

## 3. 크롭 수학 (`engine/crop.py`)

순수 함수(`crop_box`·`grade_params`)는 PIL 을 모른다. PIL 은 `derive_image` 안에서만 지연 import 한다
— Pillow 없는 환경(수집·채점 잡)에서 import 해도 깨지지 않아야 하고, 크롭 수학은 그런 환경에서도
테스트가 돌아야 한다.

**2단계로 계산한다.**

**ⓐ 원본에서 가장 큰 중앙 9:16 부분 사각형을 먼저 잡는다.**
레거시 자산은 1024×1024 라 바로 1080×1920 으로 리사이즈하면 찌그러진다. 정사각형은 9:16 보다
**넓으므로** 좌우를 깎는다. 원본이 이미 9:16 이면 무연산이다(§4 이후의 정상 경로).

**ⓑ 그 사각형 안에서 `1/scale` 크기의 박스를 `(cx, cy)` 중심에 놓는다.**
박스는 9:16 비율을 유지하므로 리사이즈에서 다시 찌그러지지 않는다.
박스가 경계를 넘으면 **밀어 넣는다 — 줄이지 않는다.** 줄이면 지시서가 요청한 배율이 조용히
바뀌어 "2.2배 확대"가 1.7배가 된다.

리사이즈는 `RENDER_WIDTH × RENDER_HEIGHT`(1080×1920)로 `LANCZOS`.
톤 그레이딩은 `Image.blend(원본, 단색, alpha)`.

**상한:** `CROP_MAX_SCALE = 2.5`. 초과하면 업스케일 뭉개짐이 눈에 띈다. 실측 후 조정한다.

## 4. 종횡비 — 프롬프트가 아니라 파라미터

1차에서 8장 전부 1024×1024 로 나온 직접 원인이다. 프롬프트의 `"vertical 9:16"` 은 무시된다.

`_image_request_body` 의 `generationConfig` 에 싣는다. **실시간·Batch 가 이 함수를 공유**하므로
한 곳만 고치면 양쪽이 고쳐지고, 반대로 여기서 빠뜨리면 양쪽이 함께 틀린다.

⚠ **필드 경로가 확정적이지 않다.** 공식 문서에 두 형태가 나오고 레퍼런스에는 둘 다 없다.
→ `config.IMAGE_ASPECT_CONFIG_SHAPE` 로 두 형태를 모두 지원하고,
`IMAGE_ASPECT_RATIO_PARAM=false` 로 즉시 되돌아간다.

**믿지 않고 잰다.** `_gen_still` 이 생성 직후 `PIL.Image.open(p).size` 를 재고 9:16 이 아니면
에러 로그 + `render_assets.meta.aspect_mismatch=true`. **예외는 던지지 않는다** — 던지면 유료
호출이 재시도된다.

## 5. 화풍 앵커와 부정어

**부정어가 핵심이다.** 없으면 모델이 실사 쪽으로 되돌아간다(1차 실패의 직접 원인). 문구는
지시서 v2 §3 원문 그대로 쓴다 — 바꾸면 그 검증 결과와 연결이 끊긴다.

```
NOT photorealistic, no 3D render, no lens flare, no depth of field,
no cinematic photography, no realistic texture
```

두 겹으로 넣는다.
1. `VERSION_GUIDANCE["webtoon"]` — LLM 에게 지시(Python·TS 양쪽)
2. `engine/providers/image.py` — LLM 이 무시해도 프로바이더가 구조적으로 덧붙인다

그리고 `"high detail"`(실사 유도)을 webtoon 에서만 `"clean flat colors"` 로 바꾼다.

**comic 의 프롬프트 문자열은 바이트 단위로 불변이다.** A/B 비교에서 화면 설계 말고 다른 변수가
끼면 판정이 무의미해진다.

**지속 오브젝트:** 편을 관통하는 주 오브젝트는 **단순하고 특징적인 형태**로 고른다(구체·원반 등).
불규칙한 바위처럼 특징 없는 형태는 생성 모델이 컷마다 다르게 그린다.

**스타일 레퍼런스 이미지는 이번 범위 밖이다**(편차 기록 §3). 화풍 일관성은 `global_style`
접두사 + 부정어가 책임진다.

## 6. 렌더 배선

`engine/render.py:_reuse_base_image` 가 파생을 수행한다.

1. 기존 조기 반환은 그대로(참조 없음·전략 불일치·기준 파일 없음 → 평소대로 생성)
2. 크롭도 톤도 없으면 예전처럼 `shutil.copyfile`(기존 재사용 컷의 동작 불변)
3. 있으면 `crop.derive_image()`
4. **어떤 예외가 나도 잡아서 기준 이미지 복사로 강등한다.** 파생 실패가 유료 생성으로 이어지면
   안 된다 — 이것이 이 기능의 안전 속성이다.

**영상 컷의 첫 프레임도 이 경로를 탄다.** 그리고 그 스틸을 `asset_index` 에 남긴다 — 뒤 컷이
영상 컷을 `base_asset_ref` 로 가리킬 수 있어야 한다(루프 컷이 정확히 이 경우다).

**비용:** 파생 컷은 `_gen_still` 에 들어가지 않으므로 캐시 조회·업서트·원장 기록·생성 호출이
전부 없다. 비용 0 이 구조적으로 보장된다. 언어 독립도 유지(파일 연산에는 locale 이 없다).

**후속 주의:** 파생 컷을 `render_assets` 에 캐시하려면 `assemble.content_hash` 에
`crop`·`tone_grade` 를 **먼저** 넣어야 한다(같은 기준·다른 배율의 키 충돌).

## 7. 버전×언어 동시 발주

### 요청/응답 형태
```
POST /api/directive-generate
  { paper_id, version_types: ["comic","webtoon"] }        # version_type 단수는 별칭
  → 202 { ok, results: [{version_type, status, warn?}] }

POST /api/directive-approve
  { directive_ids: [...], langs: ["ko","en"], force? }    # directive_id 단수는 별칭
  → 200 { ok, results: [{directive_id, version_type, queued, langs, blocked?, error?}] }
  → 409 만: **모든** 지시서가 차단됐을 때
```

**실패 의미론:** 하나가 차단돼도 배치를 중단하지 않는다. `triggerRender()` 는 마지막에 한 번만
부른다(워커가 큐 전체를 폴링한다).

### 비용 규칙 — 언어는 곱하지 않는다
이미지·Veo 는 언어 독립 캐시라 두 번째 언어가 $0, TTS 는 edge-tts 로 $0.
**총액은 버전 수로만 늘어난다.** 모달에 그 사실을 한 줄로 명시한다.

`RENDER_BUDGET_CAP_USD` 는 잡 단위 가드다 — 2버전×2언어에 총액 상한은 없고, 확인 모달이
운영자가 총액을 보는 유일한 지점이다.

## 9. 판정 (사람이 한다)

이 버전의 목적은 두 질문에 답하는 것이다.

1. **웹툰체 + 부정어가 화풍 일관성 문제를 해결하는가**
2. **크롭 방식이 카메라 이동 문제를 해결하는가**

같은 논문으로 `만화식×KO` / `웹툰×KO` 를 뽑아 나란히 놓고 판정한다.
판정 전까지 어느 쪽도 기본값으로 만들지 않는다.
