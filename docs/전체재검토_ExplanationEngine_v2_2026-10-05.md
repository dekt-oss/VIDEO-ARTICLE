# Explanation Engine v2 — 기획안 대비 전체 재검토 (2026-10-05)

> 운영자 지시: "처음 기획안 내 의도랑 다른 방향으로 간 거 있나 없나 다시 체크하고 그다음 1번 진행."
> 기준: `docs/작업지시서_ExplanationEngine_v2.md`(기준일 2026-10-01). 대상: main 브랜치(2026-10-05, PR #115 까지).
> 방법: 기획안 전 절을 읽고 단계별로 코드와 대조(파일·줄 증거). 두 갈래로 나눠 확인한 뒤 핵심 주장은 직접 다시 확인했다.

## 0. 한 줄 결론

기획안의 목표는 **"요약해 읽는 영상 → 원리까지 이해시키는 설명 영상"**이었다. 지금 V2 는 **"틀리지 않게 읽어 주는 영상"**
까지만 왔다. 사실 검증·숫자 처리·성적표 같은 **안전장치**는 대부분 있지만, 기획안이 "가장 중요한 단계"라고 한
**생각하는 단계(Phase 3)** 와 그 위에 서야 할 **이야기 구성·말하기·화면 연결**이 비어 있거나 반대로 갔다.

## 1. 단계별 대조표

판정: ✅ 맞음 · 🟡 일부 · 🔴 다른 방향 · ⬜ 없음. "누가"는 처음 만든 쪽(코덱스) 또는 이 세션의 내 수정.

| 기획안 단계 | 판정 | 기획안 의도 | 실제 | 누가 |
|---|---|---|---|---|
| Phase 0 기준 감사 | 🟡 | 논문·리포트 각 3+3~5편, 10개 축, 조회율 등 기록 | 6편, 10개 축 채점은 함. 비트 수·숫자 수·렌더 비용·시청 지속률 기록 없음, 사람이 렌더를 본 적 없음 | 코덱스 |
| Phase 1 원문 깊이 관문 | 🟡 | 깊이에 따라 설명 단위 수·깊이를 코드가 제한, 얕으면 줄이거나 원문 확보 | 깊이 → 모드 계산은 됨. "원문은 있으나 원리 없음 → 한 단계 낮춤", "원문 확보" 없음. 논문은 단위 수 상한 0(무제한). 줄이라는 판정이 실제로 줄이지 않고 중단만 함 | 코덱스 |
| Phase 2 근거 묶음 | 🔴 | 공통 주장 종류(측정 사실·저자 해석·회사 가이던스·애널리스트 추정·전망·가설…)와 인과 강도·근거 등급 | 공통 종류 없음(원래 값 그대로 통과). 리포트 주장은 인과 강도·등급·불확실성이 비어 있음 → 사실과 전망을 종류로 못 가름 | 코덱스 |
| **Phase 3 생각하는 단계** | 🔴 | **가장 중요한 단계.** 시청자 질문·관심 이유·통념·반전·단계별 질문과 답·화면에 꼭 보일 것·이야기 틀(왜/실험/맞교환, 동인/병목/밸류/역발상) | Fact Sheet 주장에 역할 이름표만 붙임. 질문은 모든 논문 "이 연구는 무엇을 보여 주는가?" 고정. 이야기 틀 선택 없음. 모델 호출 없음 | 코덱스 |
| Phase 4 선행 개념 | 🔴 | 시청자가 모를 개념을 먼저 풀기(원문 → 용어집 → 외부 → 없으면 범위 축소). 용어집 후보 PBR·HBM·상관/인과 등 | 자동으로 찾지 않음 — 누가 넘겨 줄 때만. 용어집 2개(유전학 용어)뿐 → 리포트는 늘 0개 | 코덱스 |
| Phase 5 이야기 구성 | 🔴 | 생각 결과로 HOOK→설정→갈등→설명→근거→의미→한계. **금지: "연구 소개→방법→숫자→숫자→한계" 나열** | 주장 역할을 단계 이름으로 바꿔 원문 순서로 나열 — 금지한 모양 그대로. 막는 검사 없음 | 코덱스(+ 내 첫 질문 고정 교정이 악화) |
| Phase 6 말하기 | 🔴 | 1차 초안 + **별도 2차 다듬기**(호흡·명사형·논문 문체·연결·용어·숫자·TTS). 목표 문체는 "지렛대처럼" 비유 | 대본 지시가 **비유 금지**. 2차 다듬기 함수는 있지만 **아무도 부르지 않음**. 문체 검사는 경고뿐 | 코덱스(+ 내 검사 강화가 원문 복사를 부추김) |
| Phase 7 의미 충실도 | 🟡 | 의미 단위 대조, "모든·유일" 범위 강화 차단, 사실형/수사형 훅 구분, 독립 검증관 | 대부분 있음. 단 범위 강화 검사는 원문이 아니라 계획 문장과만 비교. 검증관은 같은 회사 저가 모델 | 코덱스 |
| Phase 8 복잡도 관문 | 🔴 | "경고했으니 됐다" 금지 — 두 편 분할은 발행 금지/승인, 숫자 과다는 대본 재생성 | 중단만 하고 재생성·길이 축소는 없음. **두 편 분할은 이제 구조상 절대 안 나옴** | **내 수정(PR #111)** — V2 대본 길이로 모드를 고르게 바꾸면서 분할 판정이 사라짐 |
| Phase 9 기존 화면 계획 재배선 | 🔴 | **새 화면 스키마를 만들지 말 것.** 설명 단계 → 주장 → 논리 번호 → 기존 Stage → 변화로 끝까지 잇기 | 새 간이 화면 계획을 만들었고(렌더 불가), 내가 만든 다리는 그걸 거의 버리고 기존 생성기가 장면을 새로 지음. 설명 단계 번호 자체가 없음. 논리 번호는 나중에 글자 대조로 다시 붙임(비교 자료 전용) | 코덱스(새 스키마) + **내 설계(다리)** |
| Phase 10 장면 전환 | ⬜ | 설명 관계로 전환 결정(질문→답=하드컷, 전체→부분=밀어 들어가기…) | 계획 칸만 있고 다리가 버림. 렌더는 컷을 그냥 이어 붙임 | 코덱스 |
| Phase 11 설명 렌더러 | 🟡 | 코드가 그리는 상태 변화(이동·경로·흐름 입자·층 분리·카운트업) | 글자 카드 등장·숫자 카운트업·정지 그림 줌/팬·막 걷기. 이동·경로·흐름·층 분리 없음 | **내 작업(S1~S5)** — 범위를 글자 움직임으로 좁게 잡음 |
| Phase 12 분야별 의미 표시 | 🟡 | 관측/모델/가설/은유, 실적/가이던스/추정/전망/시나리오/리스크를 화면에서 구분. 실사 관찰 vs 원리 도해 vs 은유 엄격 구분 | 숫자 카드 이름표만(낱말 규칙). 표현 방식은 늘 "원리 도해" 상수 | 코덱스 + 내 작업(S5) |
| Phase 13 품질 관문 | 🟡 | 다섯 질문, 마지막은 "선언한 변화가 실제 픽셀로 나왔나" | 다섯 단계 성적표는 있음. 픽셀 변화 확인은 없음(일반 움직임 경고만 읽음) | 내 작업 |
| Phase 14 성과·A/B | ⬜ | 장면 시각 ↔ 시청 지속 곡선 연결, 실험 A/B/C | 없음 | — |
| §19 출시 | 🟡 | `EXPLANATION_ENGINE_V2` 스위치, 그림자 비교, 10~20% 제한 출시 | 스위치 없음. 그림자 비교는 수동 명령. 저장 옵션으로 대시보드에 들어감 | 내 작업 |

| 기준 | 상태 |
|---|---|

**13개 중 온전히 맞는 것 2개.**

## 2. 왜 첫 리뷰에서 못 걸렀나 (내 책임)

1. **리뷰 범위를 좁게 잡았다.** 처음 받은 일은 "코덱스가 만든 Phase 11(비교 실행 도구, PR #99)을 리뷰"였다. 나는 그 PR 의 코드가
   **안전한지**(DB 쓰기·비용 장부·ID 검사·파일 덮어쓰기)만 봤다. 그 도구가 비교하는 대상, 즉 **Phase 2~10 이 기획안 의도를
   지켰는지**는 "앞 단계 문서에 완료라고 적혀 있다"는 이유로 그대로 믿었다. 기획안 §5(Phase 3)을 코드에 대어 본 적이 없다.
2. **"통과"를 "완료"로 봤다.** 이후 작업은 거의 전부 "막히지 않고 끝까지 나오게"였다(숫자 교착·훅 충돌·길이·오탐). 막힘을
   풀 때마다 "기획안이 원한 결과인가"를 묻지 않았다. 기획안 §20 이 금지한 "CI 통과를 품질 검증으로 간주"를 내가 했다.
3. **내가 방향을 더 틀었다.** 첫 질문을 핵심 질문으로 되돌리는 교정(첫 3초를 죽임), Phase 8 을 V2 대본 길이로 바꾸며 두 편
   분할 판정을 없앤 것, 새 화면 계획을 버리고 기존 생성기에 맡긴 다리, 화면 움직임을 글자 카드로 좁힌 것 — 넷 다 내 결정이다.
4. **결과물을 기획안 목표 문장에 대어 보지 않았다.** 대본이 나왔을 때 "§23: 따라가다 보니 원리까지 이해됐다"에 맞는지 한 번만
   물었어도 파일럿 첫날(10-04) 알았을 것이다.

앞으로의 규칙: **단계를 끝낼 때마다 기획안의 해당 절과 §23 목표 문장에 결과물을 대어 본다. 통과 여부가 아니라 의도 일치를 보고한다.**

## 3. 고치는 순서 (기획안 §23 우선순위: 원문 → 설명 → 말하기 → 화면 → 렌더)

| 순서 | 할 일 | 상태 |
|---|---|---|
| ① | **Phase 3 생각하는 단계** — 콘텐츠마다 모델이 질문·관심 이유·통념·반전·이야기 틀·단계별 질문과 답·화면을 설계, 코드는 근거 연결만 확인(`engine/explanation_reasoning.py`) | **세 편 미리보기 중** — 운영자 판정 후 진행 |
| ② | Phase 4 — 생각 결과의 "먼저 풀 개념"을 자동 선행 개념으로, 원문 근거 없으면 용어집 필요 표시 | 대기 |
| ③ | Phase 5 — 비트를 생각 결과의 **설명 단계**로 만든다(단계 번호 부여) | 대기 |
| ④ | Phase 6 — 대본은 단계별 질문·답으로 쓰고 비유 허용, **2차 다듬기를 실제로 연결** | 대기 |
| ⑤ | Phase 9 — 설명 단계 번호를 기존 생성기 장면·Stage 까지 실어 보낸다(나중 글자 대조 대신), 실제 지시서로 회귀 시험 | 대기 |
| ⑥ | Phase 8 — 숫자 과다는 재생성, 두 편 분할 판정 되살리기 | 대기 |
| ⑦ | Phase 10~12 — 전환을 렌더에, 상태 변화 움직임(이동·경로·층 분리), 표현 방식 구분 | 대기 |
| ⑧ | §19 스위치·제한 출시, Phase 14 분석 | 대기 |

PR #116(첫 질문·순서·말투 교정)은 ①~④가 대체하므로 머지하지 않는다.
