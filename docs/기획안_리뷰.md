## 0. 총평

전반적으로 **구현 가능한 수준으로 잘 분해된 명세**다. 특히 다음이 강점이다.

- **P0(선별) / P1(초안)을 한 코드베이스 안에서 분리 측정**하고, 각각 정량 합격기준(8절)을 제시 → 검증 루프가 명확.
- **환각 방지 3단계 분리**(사실추출 → 대본 → 자기검증, 5절). 원문을 통째로 던지지 않고 단계마다 앞 단계 출력만 재료로 쓰는 설계는 LLM 콘텐츠 파이프라인의 정석.
- **비용 통제 구조**: 1차 필터로 99% 버린 뒤 80~150편만 LLM 채점 → 하루 호출량 예측 가능.
- **최소 클라우드 구성**(Supabase + Vercel)과 "메타데이터만 저장(PDF 링크만)"으로 용량/비용을 변수에서 제거.
- **재사용 vs 신규개발 경계**(5-4)와 **범위 밖 항목**(렌더링·TTS·발행·cron) 명시 → 스코프 크리프 방지.

아래는 그대로 두면 구현 단계에서 막히거나 잘못 구현될 수 있는 지점이다. **정정 필요 → 설계 갭 → 보안/운영 → 사소 보완** 순.

## 1. 정정 필요 — 사실관계

### 1-1. OpenAlex 인증 모델 (명세 2-1, 7절)
명세는 OpenAlex를 "API 키 필요(무료, 일 $1 크레딧)"로 적었다. **이는 사실과 다를 가능성이 매우 높다.**

- OpenAlex는 **API 키 없이 무료**로 쓸 수 있고, 요청에 `mailto=you@example.com` 파라미터를 붙이면 **polite pool**(더 안정적인 응답)로 라우팅된다.
- "일 $1 크레딧"은 OpenAlex의 과금 모델이 아니다. **다른 서비스(예: 일부 상용 학술 API)와 혼동된 것으로 보인다.**

**조치:**
- 구현 착수 시 OpenAlex 공식 문서로 인증/레이트리밋 정책을 **반드시 재확인**.
- 환경변수를 `OPENALEX_API_KEY` → **`OPENALEX_MAILTO`** 로 교정(7절 반영).
- 레이트리밋(무인증 기준)을 코드의 호출 간격·페이지네이션에 반영.

## 2. 설계 갭 — 구현 전 해소 필요 (★ 결정 항목)

### 2-1. ★ 1일차 신호 공백 — 1차 필터의 구조적 결함 (명세 2-4)
명세의 1차 필터는 **"화제성 신호(HN/Reddit)가 하나라도 붙은 논문만 통과"**, 신호 0건이면 **"피인용 상위 + 최신순 폴백"**이다. 그런데:

- **"어제 발행"된 논문은 24시간 내 HN/Reddit buzz가 거의 0**이다(화제는 발행 후 며칠 뒤에 붙는다).
- **갓 발행된 논문은 `cited_by_count`도 0**이다(피인용은 수개월~수년 누적).
- 결과: 신선 논문에 대해 **1차 필터(buzz)도 폴백(피인용)도 둘 다 거의 작동하지 않는다.** 매일 폴백만 타거나, 통과 0건이 될 위험.

이는 "하루치 신선 논문에서 재미있는 걸 고른다"는 제품 핵심과 정면으로 부딪힌다.

**권장 재설계 (셋 중 조합):**
1. **수집 윈도우 확대:** "어제 1일" → **최근 3~7일 롤링 윈도우.** buzz가 붙을 시간을 벌어준다.
2. **buzz를 통과 필수조건이 아니라 가점으로:** 1차 필터는 "초록 존재 + 언어(영/한)"만으로 통과시키고, buzz는 점수 ⑤와 정렬에만 반영. 의외성·이해가능성·일상연결성은 **buzz 없이도 LLM이 초록만으로 매길 수 있다.**
3. **1차 필터 모수 상한 관리:** 윈도우를 넓히면 채점 모수가 커지므로, "발행 최신순 + (있으면)buzz 가점"으로 상위 N편(예: 150편)만 LLM 채점에 넘기는 컷오프를 config로.

→ **M0에서 윈도우 길이와 1차 필터 통과조건을 확정**해야 한다.

### 2-2. ★ buzz 매칭 방향이 순환적 (명세 2-3)
명세 2-2는 "HN/Reddit에서 **논문 도메인/arxiv 링크로 query**"라고 적었다. 하지만 **어떤 논문이 화제인지 알아야 그 링크로 검색**할 수 있다 → 의존성 순환. 또한 papers가 수만 편이면 편당 검색은 비현실적.

**권장 순서(역방향):**
1. r/science 등 **최신 글 목록을 먼저 수집** → 글 본문/링크에서 **DOI·arXiv ID를 추출**.
2. HN Algolia는 `arxiv.org`·`doi.org` 등 **도메인으로 최근 24h 글을 긁어** 동일하게 링크 추출.
3. 추출한 식별자를 **정규화**해서 `papers.external_id`와 **조인** → 매칭된 논문에 `buzz_raw` 부착.

**추가로 명세에 빠진 규칙:**
- **DOI 추출 정규식** 및 **arXiv ID 패턴**(`arXiv:2401.xxxxx`, `/abs/2401.xxxxx`).
- **URL 정규화**(스킴/`www`/쿼리스트링/트레일링 슬래시 제거, 소문자화).

### 2-3. ★ Vercel(서버리스) → Python 엔진 트리거 갭 (명세 6, 9)
명세상 **P0 엔진은 로컬 수동 실행**인데, 대시보드의 **"초안 생성" 버튼(P1)**은 Vercel에 배포된 Next.js가 누른다(6절 `/api/generate-draft`). **Vercel 서버리스 함수는 사용자의 로컬 파이썬 프로세스를 직접 호출할 수 없다.** 이 트리거 경로가 명세에 비어 있다.

**선택지:**
- **(a)** P1 파이프라인을 **TypeScript로 포팅**해 Vercel 함수에서 직접 실행(Anthropic SDK는 TS도 지원). 장점: 엔드투엔드 클라우드. 단점: 엔진 이중 구현.
- **(b)** 파이썬 엔진을 **별도 서비스/서버리스**(예: 컨테이너·함수)로 호스팅하고 대시보드가 HTTP로 호출.
- **(c)** 대시보드는 `drafts`에 **요청 행만 기록**(또는 `decisions.status='picked'`을 큐로 사용)하고, **로컬 엔진이 주기적으로 폴링**해 처리 후 결과를 다시 적재.

→ **P0 단계 최단경로는 (c).** 추가 인프라 0, 기존 "로컬 수동 실행" 전제와 일치. P2(cron 클라우드화) 때 (a)/(b)로 승격. **M0에서 확정.**

### 2-4. ★ 타임존 미정 (명세 2, 4)
"어제"가 **UTC 기준인지 KST 기준인지** 명시되지 않았다. 이는 수집 윈도우 경계와 `daily_batch.batch_date` 키에 직접 영향(중복 배치/누락 발생 가능).

**조치:** config에 **`TIMEZONE`(예: Asia/Seoul) 고정**, 수집 윈도우·배치 날짜 계산을 모두 이 기준으로 통일.

## 3. 보안 · 운영

### 3-1. 시크릿 분리 (명세 7)
`SUPABASE_SERVICE_KEY`(서비스 롤 키)는 **RLS를 우회**하므로 **서버사이드(API 라우트/엔진)에서만** 사용해야 한다. **클라이언트 번들에 절대 노출 금지**(Next.js에서 `NEXT_PUBLIC_` 접두사 금지, 서버 컴포넌트/route handler에서만 참조).

### 3-2. 단일 사용자 인증의 공개 URL 노출 (명세 4, 6)
Vercel 공개 URL + 매직링크는 **누구나 이메일만 넣으면 가입/로그인**할 수 있다. 사용자가 1명이므로:
- Supabase Auth에 **허용 이메일 allowlist** 적용(또는 매직링크 발송을 허용 이메일로 제한).
- 모든 테이블에 **RLS 정책**으로 인증 사용자만 접근 + 본인 데이터로 제한.

### 3-3. ④ 학술중요성 보정 데이터 출처 (명세 3-2)
"과학 보도(EurekAlert) 픽업 +1"의 **신호를 어디서 가져오는지** 소스가 명세에 없다(2절 수집 소스에 EurekAlert 없음). 보정을 켜려면 이 신호의 수집 경로가 필요. → P0에서는 **보정 off로 시작**(명세도 on/off 비교를 제안하므로 일치)하고, 보정용 소스는 후속 결정으로.

## 4. 사소 보완 (작업계획서 횡단 항목으로 반영)

- **재실행 멱등성:** 같은 날 엔진을 두 번 돌려도 중복 적재/배치 깨짐이 없어야 함(`external_id` unique + upsert, `daily_batch` 재생성 전략).
- **레이트리밋·재시도:** arXiv 3초 간격(명세 명시), OpenAlex 폴라이트풀, LLM 호출 지수 백오프. JSON 파싱 실패 1회 재시도(명세 3-3) 외에 **API 5xx/타임아웃 재시도**도 필요.
- **언어 판별:** 1차 필터의 "영어/한국어" 판정에 경량 언어감지 라이브러리 지정 필요.
- **⑤ buzz 정규화 방식 미정(명세 3-1):** 0~10 변환식(로그 스케일 / 일별 min-max 등)을 **config 상수로** 명시.
- **관측성:** 일일 실행 요약 로그(수집 건수, 필터 통과 건수, 채점 성공/실패, 배치 결과)를 남겨 합격기준 측정에 활용.
- **자기검증 한계 명시(명세 5-3):** 문장↔Fact Sheet 매핑도 LLM 단계라 매핑 자체가 틀릴 수 있음 → "빨간 깃발은 **사람 검수 보조**" 임을 UI/문서에 명시(명세 의도와 이미 일치).
