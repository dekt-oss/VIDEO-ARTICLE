# 스킬 안내판 (skill-router)

이 스킬은 **판정 절차만** 담는다. 상황별 스킬 목록·말하는 형식·사용자 명령의 **정본은 `.claude/shared/SKILL-MAP.md`** 다
(Codex 도 같은 파일을 읽는다 — 여기 목록을 복제하지 않는다).

## 순서
1. **`.claude/shared/SKILL-MAP.md` 를 읽는다.** 없으면(배달 전) 이 저장소 `.claude/skills/*/SKILL.md` 의 `description` 만으로 판정한다.
2. **이 저장소에 실제로 있는 스킬만** 후보로 본다: `ls .claude/skills/`. 지도에 있어도 폴더가 없으면 뺀다.
3. 지금 요청·상황을 지도 4절 표의 **작업 열과 증상 열 둘 다**와 맞춘다(작업을 시작할 때는 작업 열, 문제를 진단할 때는 증상 열이 주로 맞는다).
   표에 없는 스킬(프로젝트 전용 — `managed-skills.txt` 에 없는 것)은 그 `SKILL.md` 의 `description` 과 맞춘다.
   표에서 맞는 게 애매하면 후보 스킬의 `description` 을 직접 읽어 확인한다(표보다 `description` 이 정본).
4. 지도 2절 대로 한다: 무료는 알리고 진행(4개 이상이면 지금 단계에 맞는 3개), 무료끼리 방향이 갈리면 묻는다.
   - 점검표 성격 스킬끼리는 같이 써도 서로 충돌하지 않는다 → 묻지 말고 알린다.
   - **유료(돈이 드는 실행)는 그 항목을 지목한 명시적 승인 전에는 시작하지 않는다.** "알아서"·침묵·다른 지시는 승인이 아니다.
     이미 승인한 범위(스킬·대상·횟수·금액 상한) 안이면 다시 묻지 않는다.
5. 고른 스킬을 실제로 부른다(Skill 도구). 알리기만 하고 안 쓰면 안 된다.
6. 상황이 바뀌면(새 증상·두 번째 실패) 1번부터 다시. 같은 스킬을 같은 단계에서 두 번 알리지 않는다.
7. 끝 보고의 "어떻게 해결했나"에 `사용한 스킬: …` 한 줄.

## 하지 말 것
- 맞는 스킬이 없는데 억지로 고르기. 0개면 조용히 진행한다.
- `work-completion-report` 를 알리기(항상 쓰는 것이라 소음이다).
- 알림 문구를 길게 쓰기. 한 줄이면 된다.
- 사용자가 "알림 꺼"라고 한 뒤에 알리기 — 단, 방향이 갈리는 질문과 💰 승인 질문은 꺼도 묻는다.
- 유료를 "알아서"·추천 1번 기본값·침묵으로 시작하기.
- 이 저장소에 폴더가 없는 스킬을 알리거나 `사용한 스킬` 에 적기.

## 예
- 사용자: "가격 페이지에 아무것도 안 떠" → `🔧 스킬: error-vs-empty-audit — 실패가 '빈 결과'로 숨었는지부터 봅니다`
- 사용자: "임계값 0.4 를 0.5 로 올려 줘" → `🔧 스킬: value-duplication-drift-audit, magic-number-audit — 같은 값이 다른 곳에도 있는지, 근거가 있는지 봅니다`
- 사용자: "Gemini 연동이 가끔 실패해" → 방향이 갈린다:
  ```
  이 상황에 맞는 스킬이 있습니다:
    1) log-driven-integration-debug — 로그를 먼저 보이게 하고 원인을 한 가설씩 좁힘  ← 추천
    2) gemini-structured-output-guard — Gemini 설정(thinking·쿼터·잘림)부터 점검
  번호로 답하시거나 "알아서"라고 하시면 1번으로 진행합니다.
  ```
