# 완료 보고 전 검증 게이트 (video-article)

## 왜
과거 사례: 초안 워커 워크플로를 **추가·병합**하고 "완료"라고 보고했으나,
정작 워크플로가 실행되지 않아 **초안은 하나도 생성되지 않았다**. 사용자가 원한 결과
(초안 생성)는 미해결인데 진행 상황(병합)을 해결처럼 전달했다. 이걸 반복하지 않는다.

## 철칙
1. **"코드 병합/배포/PR 생성"은 "동작/해결"이 아니다.** 둘을 절대 같은 문장에서 뭉개지 않는다.
2. **사용자에게 보이는 최종 결과를 증거로 확인하기 전에는 "완료/해결/됩니다"라고 쓰지 않는다.**
   확인 못 했으면 그 문장에 반드시 "(미검증)"을 붙이고, 무엇을 어떻게 확인해야 하는지 명시한다.
3. 실행할 수 없어서 검증이 막혔으면(키·권한·네트워크 부재 등) **막혔다는 사실과 남은 검증 단계를
   명확히 밝히고 끝낸다.** "아마 될 것"으로 완료 처리 금지.

## 결과별 검증 방법 (이 저장소)
보고 전에 아래 중 해당하는 증거를 실제로 확보한다.

- **초안 생성**: Supabase `drafts` 테이블에 해당 `paper_id` 행이 생겼는지, `draft_requests.status`가
  `done`으로 바뀌었는지 SQL로 확인. 워크플로를 돌렸다면 Actions 로그에 `draft 생성: paper=… scenes=…`가
  찍혔는지 확인. 큐가 아직 `queued`면 **미완료**.
- **채점**: `scores`에 0점·`red_flag`가 아닌 실제 점수/`one_liner_ko`가 채워졌는지 SQL로 확인.
  전부 0점이면 채점 실패(원인 로그 확인).
- **수집**: `papers` 행 수가 실행 후 증가/갱신됐는지 확인.
- **대시보드 표시**: 배포(READY) 확인 + 실제 URL/프리뷰에서 해당 화면이 의도대로 보이는지 확인.
  빌드 성공은 "표시 정상"의 증거가 아니다.
- **워크플로 추가**: 파일 병합만으로 끝이 아니다. GitHub이 워크플로로 **등록**했는지,
  **실행 가능/실제 실행**됐는지까지 확인해야 "동작"이라 말할 수 있다.

## 보고 형식
완료 보고 시 항상 두 가지를 분리해서 쓴다:
- **검증됨**: 어떤 증거로 확인했는가 (SQL 결과 / 로그 줄 / 화면 / 테스트).
- **미검증·남은 것**: 아직 관찰하지 못한 최종 결과와, 그것을 확인하는 구체적 방법·주체.

## 완료 보고 템플릿 (필수 — 작업이 끝날 때마다 이 네 덩어리로 쓴다)

사용자 요청: "무슨 문제를 어떻게 수정했고, 그 결과 어떻게 되었고, 그 결과는 이런 테스트로
확인할 수 있다 — 쉬운 언어로." 코드를 안 읽는 사람이 그대로 읽고 이해할 수 있어야 한다.
아래 네 소제목을 **그대로** 쓴다(순서 고정, 소제목 이름 변경 금지).

### 무슨 문제였나
증상부터 쓴다 — 사용자가 화면에서 본 것. 그다음 진짜 원인 한 문장.
함수명·변수명·스택트레이스를 나열하지 않는다. 파일 이름은 "어디를 고쳤는지" 알려줄 때만.

### 어떻게 고쳤나
바꾼 것 한두 문장 + 왜 그 방법인지 한 문장. 고친 파일은 최대 2~3개만 이름을 댄다.
"~를 리팩터링했다" 같은 뭉뚱그린 표현 금지 — 무엇이 달라졌는지 결과로 쓴다.

### 지금 어떻게 됐나
**되는 것**과 **아직 안 되는 것**을 반드시 나눠 쓴다. 위 철칙 2가 여기 그대로 적용된다:
머지·배포·PR 은 "된 것"이 아니라 "아직 안 된 것" 칸에 들어간다.
사용자가 눌러야 할 버튼이나 넣어야 할 키가 남았으면 그것도 여기 적는다.

### 이렇게 확인하세요
사용자가 **직접 밟을 수 있는** 절차를 순서대로. 화면 경로, 눌러야 할 버튼, 보여야 할 결과.
SQL·명령어를 쓸 거면 복붙 가능한 형태로 주고, 무엇이 보이면 성공인지 한 줄로 덧붙인다.
내가 이미 돌린 검증(테스트 이름·통과 개수·조회 결과)은 여기 맨 끝에 따로 붙인다.

### 쉬운 언어 규칙
- 전문용어를 꼭 써야 하면 처음 한 번은 괄호로 풀어 쓴다: "워크플로(자동 실행 스크립트)".
- 화살표 연쇄(`A → B → 실패`)·약어·조각 문장 금지. 완결된 문장으로 쓴다.
- 숫자는 구체적으로: "여러 건" 대신 "5건", "최근" 대신 "07-27·07-29".
- 사과·자책·장황한 서론 없이 바로 본론.

### 언제 생략하나
한 줄 질문에 답만 하는 턴, 파일 하나 읽어주는 턴처럼 **고친 게 없는 작업**에는 쓰지 않는다.
코드·설정·데이터를 바꿨거나, 여러 단계를 거친 조사·수정 작업이면 항상 쓴다.
